# 实验产物（原始数据）

**这个目录进版本库**（`.gitignore` 里曾经忽略它，2026-09-23 改成入库）——原始实验产物是后面写论文时
画图、做表的唯一来源，只留在某一块硬盘上不叫"保留"。

**保留策略**：

1. **不删除、不覆盖**。新实验**新开目录**，不改动已有目录里的文件——即使那次实验的结论后来被否证
   （例如 `w1_reaccept` 那次因为中途改了代码而作废），也原样留着并在下面注明。
2. 一次运行 = 一个 `.json`（`sweep.py` 的产物）；一次扫描 = 一个目录。
   **汇总 `.log` 不一定与目录同名**：调参期的批次日志一次跑好几个分支、结果分散到好几个目录
   （见下面「批次日志」一节），所以按名字找 log 会漏。`sweep_results/` 里每个入库的 `.log`
   都在本文件里有交代——这是这份清单要保证的事。
3. **数据集不在这里**。`data/`（MNIST、SHD，共约 557 MB）按计划书 §12.1 不入库，复现方式是
   `uv run python scripts/download_data.py <名称>`（逐文件校验 + 打印 SHA-256）。

## 怎么读一个 json

一次运行的全部产物，键名与含义：

| 键 | 含义 |
| :--- | :--- |
| `seed` | 种子 |
| `mean_steps` | **验收口径**：最终权重上 10 个贪心回合的平均步数 |
| `min_steps` / `max_steps` | 那 10 个回合的最小/最大步数 |
| `offset` / `sigma` / `offset_ratio` | 成功偏移、成功信号标准差、两者之比（§七 判据 < 0.10） |
| `elapsed_s` | 墙钟（秒） |
| `peak_mb` | 显存峰值（CPU 跑时为 0） |
| `peak_mean_steps` / `peak_episode` | 训练途中贪心评测的最好值（**只作诊断**，验收不看它） |
| `curve` | 每 50 回合的评测点——**论文画曲线用的就是它** |
| `config` | 这次运行的完整配置（与文件名里那串对应） |

### W4（跨模态检索）的基准运行

预注册：[`retrieval_procedural_prereg.md`](retrieval_procedural_prereg.md)（先于数据）。
实验说明：[`research/retrieval/README.md`](../research/retrieval/README.md)。

| 目录 | 内容 |
| :--- | :--- |
| `retrieval_procedural/` | 第一轮（外积 Hebb）：程序生成配对集（144 条）上的 5 个种子 |
| `retrieval_delta/` | 第二轮（delta 规则）：同样的数据/切分/种子，只换联想规则；预注册见 [`retrieval_delta_prereg.md`](retrieval_delta_prereg.md) |

每个 `seedN.json` 的键：

| 键 | 含义 |
| :--- | :--- |
| `chance_r1` | 1 / 测试集条数——**读 R@1 时对着它读**，不是对着 50% 读 |
| `control_within` | 同模态检索（读法 a）：文本 / 图像各自的身份保持 |
| `bus_direct` | 零联想对照：两路总线输出直接比余弦 |
| `bus_associated` | 验收线：外积 Hebb 联想之后的 R@1 / R@5（含两方向与均值） |
| `hyperparameters` / `loo_best_r1` | 训练集留一法选出的组合与分数（⚠️ 见下） |

⚠️ **`hyperparameters` 里的 η 与 λ 是并列里的第一个，不是"选出来的最优"**：两个都只是
全局缩放，余弦不变 → 网格上所有点同分。这条写进了 `research/retrieval/README.md`。

汇总（5 种子均值）：外积 Hebb **R@1 = 0.141 / R@5 = 0.528**；delta 规则 **R@1 = 0.359 / R@5 = 0.845**；随机 0.034。**两轮都没到 50% 的验收线。**

### 批次日志（一个 `.log` 覆盖多个目录）

所以下面这五个 `.log` 没有同名目录——它们的用处是「那次批跑一共跑了什么、每段在哪个目录」：

## 写论文时怎么用

- **要画曲线** → 用 json 里的 `curve`（每 50 回合一个评测点），不要用 `.log` 里的汇总行。
- **要报中位数/最小值** → 用 `.log` 的汇总表，或自己从目录里的 json 聚合（口径见上面「怎么读」）。
- **要报"验收"数字** → 只用 `step14_confirm`（全新种子 45–64）。`step13_lr001` 那批（25–44）
  是**用于调参**的种子，两批都过线，但两批之间约 26% 的差距本身就是结论的一部分（选择效应），
  这一点写在 W3 README 的「当前结论」里。
- **引用任何数字时**，连同**它出自哪个目录**一起写——这就是这份清单存在的理由。
