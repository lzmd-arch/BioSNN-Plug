# 合成数据证明机制：有独占信息时，模型用得上（2026-11-14）

今天所有负结果都卡在"快半没有独占信息"。**那是数据的问题，还是能力的问题？**
构造一份"独占信号确实存在"的合成数据，把两者分开。

## 构造

- 词表 V=64；上下文 c ∈ R^8；4 万个样本
- 标签 = argmax(**W·c** + 0.3·E[prev])：**c 决定大部分**，上一个 token 决定一小部分

## 结果

| 臂 | 留出 top-1 |
| :--- | ---: |
| 只看上一个 token | 0.0924 |
| **上一个 token + 上下文 c** | **0.8711** |
| 增益 | **+77.87pp** |

## 这条读数的意义

**机制成立。** 当上下文真的携带信息时，模型能把 87% 的预测建在它上面。

⇒ 今天那四次负结果（生成 0/543、编码 0.015、判别 0.763、序列 0.562）**是数据造成的，不是架构造成的**。
`scripts/context_signal.py` 已经证明：时间轴对下一个字零预测力（0.00pp），
所以"没有独占信息"不是猜测，是量过的。

## 下一步（明确）

1. 用**同一份合成数据**跑 SNN 的传感器通道（`sensor_dim=16`），确认**它自己**也用得上——
   这次用的是线性模型，证明的是机制，不是 SNN；
2. 若 SNN 也过 ⇒ 差集是唯一缺口，去做配对记录；
3. 若 SNN 不过 ⇒ 它的输入通路有容量问题，那时才该改架构。

## 第二步：SNN 的传感器通道**目前是死的**

给运行中的快半分别传"不传 / 全 +1 / 全 −1"的 16 维传感器向量：

| 输入 | top-3 logprob |
| :--- | :--- |
| 无传感器 | −7.7002, −7.7841, −7.7903 |
| 全 +1 | −7.7002, −7.7841, −7.7903 |
| 全 −1 | −7.7002, −7.7841, −7.7903 |

**三者逐位相同 ⇒ 通道完全不改变输出。**

原因在权重里：`sensor_proj` 是**零初始化**的（设计上"没有向量时逐位无副作用"），
而 V1 从来没有在带传感器的数据上训练过它。所以它现在只是一根接好的空管子。

## 三步合起来，结论完整了

| 问题 | 答案 | 证据 |
| :--- | :--- | :--- |
| 独占信号存在时，模型用得上吗？ | **能**，+77.9pp | 合成数据 |
| 时间轴算独占信号吗？ | **不算**，0.00pp | 92,283 个位置 |
| 快半能用上传感器吗？ | **现在不能**，通道零初始化未训练 | 逐位相同 |

⇒ **"真融合"缺两件：一条真实的独占模态，以及把 `sensor_proj` 训出来。**
两件都不在 V1 里。第一件等产品记录，第二件等第一件。

## 若要做，最小闭环

1. 用合成数据把 `sensor_proj` 训出来（**先证明 SNN 自己能用**，成本最低）；
2. 再用真实配对数据微调；
3. 判据：带传感器 vs 不带的 top-1 差 ≥ 合成数据上线性模型的一半（即 ≥ +38pp 做不到，
   按实际能力定），且不带传感器时逐位等于现在。

## 第三步：通道**能被激活**，只差训练

把 `sensor_proj` 换成非零（随机、尺度 0.05），同一句文本三种传感器输入：

| 输入 | 读出特征最大差 |
| :--- | ---: |
| 不传 → 全 +1 | **0.795** |
| 全 +1 → 全 −1 | **0.795** |
| 出厂权重（零初始化）范数 | **0.0** |

⇒ **结构是通的**：只要有非零权重，传感器向量就能一路传到读出特征。
现在之所以没反应，是因为 `sensor_proj` 的范数是 **0.0**——从未训练过。

## 三步合成起来的完整结论

```
信号存在时模型用得上   → +77.9pp（合成）        ✅ 机制成立
时间轴算不算独占信号   → 0.00pp（92,283 位置）  ❌ 不算
通道结构是否可承载     → 最大差 0.795（非零权重）✅ 结构通
通道出货状态           → 范数 0.0，逐位无反应   ❌ 未训练
```

⇒ **"真融合"只缺一件事：把 `sensor_proj` 训出来。** 其余三块都已经验过。

## 下一步（唯一未做的一步）

用合成数据训练 `sensor_proj`（只训这一个 16×7812 的矩阵，其余冻结）：
- 需要给模型的 `step()` 加一条到 `sensor_proj` 的梯度路径（现在是手写前向，没有 autograd）；
- 或退一步：用有限差分/进化策略，参数只有 12.5 万，也可行。

判据：带传感器 vs 不带，合成数据上 top-1 差 ≥ 20pp，且不带时**逐位等于现在**。

## 第四步：局部规则训 `sensor_proj`——**首跑没训出来**

三因子规则：`Δproj[i,j] = η · reward · c[i] · mean_z[j]`（前=传感器第 i 维，后=神经元 j 的平均发放，
奖励=这次对不对的 ±1）。无反向传播、无全局梯度，符合"纯局部"。

600 次更新后：

| | top-1 |
| :--- | ---: |
| 带传感器 | 0.000 |
| 不带 | 0.000 |

**两头都是 0，连基线都没有。** 根因不是规则，是**奖励太稀疏**：64 类、随机读出头的成功率 ≈ 0%，
`reward` 几乎恒为 −1 ⇒ 没有一次正样本可以强化，REINFORCE 式的三因子规则无从起步。

## 修法（三条，按代价）

1. **加密奖励**：用"目标类的 logit 排名提升"或"负对数似然的变化"当奖励，而不是只看对错。
   这是三因子规则的标准做法（modulated Hebbian 用连续调制信号）；
2. **降低难度**：类数从 64 降到 8，先证明能学，再放大；
3. **换成可解释的局部误差**：给 `sensor_proj` 一个明确的目标（例如让它把 c 映射到指定的
   一小簇神经元），用 delta 规则训练——那就不再是"学任务"，是"校准通道"，判据要另写。

**在没解决奖励信号之前，不能对"SNN 能不能用上独占信号"下结论**——这一步测的是规则，不是通道。

## 第五步：加密奖励（模拟激素）——**仍然 0，但根因是我实验设计的错**

把奖励从 ±1 换成**连续调制信号**（正确类概率 − 均匀基线，即"激素"式的全局标量），
10 个 epoch、2000 次更新：

| | 留出 top-1 |
| :--- | ---: |
| 带传感器 | 0.000 |
| 不带 | 0.000 |
| proj 范数 | 0.0 → 4.63（确实在更新） |

**两头都停在 1/64 的随机水平。**

### 根因：**读出用的头是随机的、冻结的**

我为了让"只训 sensor_proj"这件事干净，冻结了一个**随机初始化**的线性头
（15624 → 64）。那么无论传感器通道传什么，模型都**没有能力表达**这个映射——
奖励再怎么连续，也被堵在这个随机头后面。

对照：合成数据那一步之所以能到 0.87，是因为**头是训练过的**。

⇒ **这次测的是我的实验设计，不是 SNN 的通道能力。作废。**

### 正确的做法（下一步）

要让"只训 sensor_proj"成立，读出必须**已经是可用的**：
- 用训练好的树读出（`tree.weight`，它是真训过的），对 64 个候选 token 打分；
- 或者让头也参与训练（但那就不是"只训通道"了，判据要另写）。

**在换成训练好的读出之前，不下任何关于 SNN 的结论。**

## 第六步：换成训练好的树读出——**仍然随机水平，说明任务设计本身不对**

用 `tree.weight[:64]` 当 64 个类别的原型（真训过的读出），10 epoch：

| | 留出 top-1 |
| :--- | ---: |
| 带传感器 | 0.0167 |
| 不带 | 0.0167 |
| （随机水平 1/64） | 0.0156 |

**还是随机。**

### 根因：这个合成任务与 SNN 学到的东西**没有关系**

标签是 `argmax(W·c)` 的任意 64 类，而树读出编码的是**语言结构**。拿一棵语言树去区分
一组随机标签，无论传感器通道传什么、奖励多密，都不该学会——这不是通道的问题，
是**任务与表征不匹配**。

⇒ **本实验到此为止，两次作废（随机头、任务不匹配），不再在这个设定上继续。**

### 正确的设计（下一次的关键）

线性合成实验能到 0.87，是因为**标签就在它所建模的空间里**。对 SNN 要做同样的事：

- **不要造新的类别空间**，直接用它本来的任务——下一个 token；
- 让**下一个 token 由 c 决定**：构造合成文本，使 `t_{i+1} = argmax(W·c + 少量噪声)`；
- 然后比"只用前缀文本"vs"前缀文本 + c"在**下一个 token top-1** 上的差。

这样它的语言表征是相关的，测的才是"通道能不能把独占信息送进去"。
**这是唯一还没被试过、且设计上成立的版本。**

## 第七步：模拟激素（DFA）——实现有维度错，判不动

正确的"模拟激素"不是标量奖励，而是**把输出误差经一条固定随机通路广播回每个神经元**
（随机反馈对齐 DFA）：`hormone = Bᵀ·err`，再乘到 Hebbian 项上。

| | 留出 top-1 |
| :--- | ---: |
| 带传感器 | 0.0167 |
| 不带 | 0.0167 |
| proj 范数 | 0 → **155**（爆炸） |

**范数爆炸、精度不动 ⇒ 调制信号无法对齐。**

### 维度错了（这是我实现的问题）

- 读出的特征空间是 **15624** 维（两个时间尺度 × 7812 神经元）；
- 我把 B 建成 **64 × 7812**，直接产出神经元级调制，**跳过了 15624 维这一层**；
- 正确形状：`B: 64 × 15624`，得到 15624 维调制后，再按"每个神经元贡献 2 个特征维"
  折回 7812。

范数爆炸正是"调制方向与真实下降方向无关"的典型症状——DFA 只有在反馈与真实雅可比
正相关时才收敛，形状错了就必然发散。

### 下一步

1. 把 B 改成 `64 × readout_width`，折叠到神经元；
2. 加范数上限（`sensor_proj` 夹到固定 L2），防止爆炸掩盖真实趋势；
3. 再看 top-1。

**在维度修好之前，这三次（稀疏奖励 / 随机头 / 维度错）都不算对 SNN 的结论。**

## 第八步：维度修正 + 范数夹取后——**仍然是随机水平**

| | 留出 top-1 |
| :--- | ---: |
| 带传感器 | 0.0167 |
| 不带 | 0.0167 |
| proj 范数 | 20.0（夹取生效，不再爆炸） |

调制维度已按"64 → 15624 → 折回 7812"修正，范数上限 20 也加上了。**精度不动。**

## 四次尝试的总账（全部在同一个合成任务上）

| # | 方案 | 结果 |
| :--- | :--- | :--- |
| 1 | 标量 ±1 奖励 | 0（奖励太稀疏） |
| 2 | 连续激素（标量） | 0（无信用分配） |
| 3 | DFA 激素向量（维度错） | 0（范数爆炸） |
| 4 | **DFA 维度修正 + 夹取** | **仍为随机** |

## 现在能说什么、不能说什么

**能说**：同样类型的合成任务，**线性模型能到 +77.9pp**（`synthetic_channel/README` 第一节），
说明"有独占信息就该能用上"这个机制本身没问题。

**能说**：快半的传感器通道，在"把任意的 16 维向量绑到 64 个任意 token"这个任务上，
用三因子 + DFA 激素、2000 次更新，**没学出来**。

**不能说**："SNN 用不上独占信号"——因为这个合成任务的标签空间与它的语言表征无关，
真实场景里 c 与 token 是有语义关联的，不是任意绑定。**这是本实验最大的外部效度缺口。**

## 真正该做的下一步

合成绑定任务证明不了真实场景。要判定，只有一条路：

1. 用**真实的配对数据**（传感器/行为 ↔ 文本），哪怕只有几百条；
2. 在那上面训 `sensor_proj`；
3. 判据仍是"带 vs 不带"的 top-1 差。

**在此之前，V1 的融合状态定性不变：α=0、机制保留、无独占信息。**

## 第九步：语义化合成配对数据——**通道开始学得动了**

关键改动：标签不再"任意绑定"，而是**语义相关**——c 的第一维就是温度，文本是
「当前温度{个位}度」。前缀固定"当前温度"，要预测的是那个数字（10 类）。

| 阶段 | 带 c | 不带 c |
| :--- | ---: | ---: |
| 训练前 | 0.10 | 0.10（随机 = 1/10） |
| 训练中最好 | **0.208** | 0.125 |
| 最终留出 | 0.12 | 0.09 |

**+3.0pp（留出）/ +8.3pp（训练中）。**

## 这说明了什么

| 数据形态 | 通道能学吗 |
| :--- | :--- |
| 任意绑定（64 个随机类别） | **不能**，四次全 0 |
| **语义相关（温度→数字）** | **开始能**，训练中 +8.3pp、留出 +3.0pp |

⇒ **"合成数据可以用"这个判断成立，但有一个硬条件：合成数据里的因果必须是真实语义的**
（c 决定哪个 token，且那个映射是语言里本来就有的），不能是任意排列。

## 为什么还不到 20pp

三个可查的原因：
1. **训练量小**：12 epoch × 150 = 1800 次更新，曲线还在涨（epoch 11 最高）；
2. **读出弱**：用 `tree.weight` 里 10 个数字 token 的行当分类器，那几行不是为这个任务训的；
3. **只训了 16×7812 一个矩阵**，其余全冻结。

⇒ 下一步：延长训练 + 让读出也参与（或改用连续奖励对 logit 排序），看能不能到 20pp。
**这是第一次有正信号，方向对了。**

## 第十步：推到推不动——**8000 次更新后没有收敛，上一轮的 +3pp 是噪声**

40 epoch × 200 = **8000 次更新**，同一份语义化数据：

| 检查点 | 带 c | 不带 c |
| :--- | ---: | ---: |
| epoch 0 | 0.140 | 0.127 |
| epoch 12（上轮的终点附近） | 0.207 | 0.107 |
| epoch 28 | 0.213 | 0.107 |
| **最终留出（800 样本）** | **0.030** | **0.105** |

**最后一行是关键：带 c 反而比不带差 7.5pp，且低于随机（0.10）。**

- 训练中一直在 0.09–0.21 之间**震荡**，没有单调上升；
- `sensor_proj` 范数从 epoch 4 起就被夹在 20（饱和），之后没有有效更新；
- 上一轮"训练中 +8.3pp / 留出 +3.0pp"**落在震荡区间内，是噪声**——按规矩撤回。

## 推到推不动的结论

**三因子 + DFA 激素，在"16×7812 一个矩阵、其余全冻结、读出头来自树的不同行"这个设定下，
学不出"把 c 读成数字"这件事。** 8000 次更新足够让曲线给出方向：没有上升趋势。

三条可能的瓶颈，按可查性排：

1. **读出不是为这个任务训的**——`tree.weight` 的数字行是为语言树学的，不是为"十类分类"；
2. **通道太窄**——16 → 7812 是一个秩 16 的加法电流，可能要更强的注入方式（例如门控而非加性）；
3. **局部规则的信用分配**——DFA 的随机反馈在这里与真实雅可比的关联不足。

**这个实验到此为止。** 它证明了三件事：
- 同样任务线性模型 +77.9pp（机制没问题）；
- 任意绑定 4 次全 0；
- 语义化数据 8000 次更新仍不收敛（本次）。
