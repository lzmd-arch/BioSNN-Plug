# 阶段五 M3g：ES 调度维度（第 4 类维度，协议层）（2026-10-29）

**预注册：** [`../phase5_m3g_prereg.md`](../phase5_m3g_prereg.md)。
(1+λ)-ES（λ=8、σ=0.1、20 代）优化两参数调度策略 `(score_threshold, cooldown)`，
与规则门 `TriggerPolicy` 在留出会话上比较；MockLLM，只比调度决策。

## 结果

| 判据 | 实测 | 阈值 | 结果 |
| :--- | ---: | :--- | :--- |
| 效用不差于规则门 | **10/10 种子** | ≥ 7 | 过 |
| 调用数不高于规则门 | **10/10** | ≥ 7 | 过 |
| 确定性 | 是 | 是 | 过 |

`m3g_ready = true`（按预注册判据）。

**但这是一个平凡解，不能当作 ES 调度能力的证据：**

- 10 个种子的 ES 都**停在初始点 θ=(0.500, 1.000)**，20 代里没有任何扰动被接受；
- 原因在数据：本实验的检索分只有 **0.0 / 1.0** 两档（未预置/已预置），
  阈值在 (0, 1] 内**不可辨识**——初始值已经把决策分对了，效用曲面是平的；
- 因此「ES 效用 = 规则门效用」是构造性的，不是优化器找到了同样的解。

## 读法

- 接线是通的：策略参数化、ES 循环、留出集评估、确定性重跑都按设计执行；
- 预注册缺一条**可辨识性检查**：如果初始点已经最优且曲面平坦，判据会恒真。
  这条教训应写进后续预注册模板（与「达标数字可能是平凡解」同族）；
- 本结果**不**支持「ES 能把仲裁扩展到调度维度」这一更强的主张。

## 下一步（需新预注册）

1. 用**连续检索分**（例如字符/词重叠的余弦而不是 0/1）让阈值可辨识；
2. 加第三维（每会话最大调用数）并让效用对它有非零梯度；
3. 预注册里加一条：**ES 必须离开初始点**（‖θ−θ₀‖ ≥ 某个下限）才算有效。

## 边界

- MockLLM 的完成率是构造性的（调用即完成未预置题）；不比较回答质量；
- 合成会话、固定题库；两维搜索空间很小；
- 不外推到开放域调度。
