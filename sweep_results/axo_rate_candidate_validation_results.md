# 速率路径候选子集验证：结果

预注册：[`axo_rate_candidate_validation_prereg.md`](axo_rate_candidate_validation_prereg.md)。

## 一句话

**按真实稀疏点积排候选后，n≤2,000 时 M=1,000 就能 100% 与全量扫描一致；n=10,000
时只有 M=5,000 达到 99%（22.5 ms），更小的 M 只有 96–97%。50,000 还没有在真实
文本上验证。**

## 结果表（真实文本放大语料，100 个探针）

| n | 最佳 M（≥99%） | 一致率 | 查询 | 全量扫描 |
| ---: | ---: | ---: | ---: | ---: |
| 200 | 100（全部） | 1.0000 | 0.30 ms | 0.19 ms |
| 500 | 200 | 1.0000 | 0.37 ms | 0.71 ms |
| 1,000 | 1,000 | 1.0000 | 1.40 ms | 1.00 ms |
| 2,000 | 1,000 | 1.0000 | 1.52 ms | 6.99 ms |
| 10,000 | **5,000** | **0.9900** | **22.47 ms** | 35.46 ms |

- n=1,000 时 M=500 是 0.99，M=1,000 才 1.0；n=2,000 时 M=500 是 0.97。
- n=10,000 的 M=1,000 / 2,000 分别是 0.97 / 0.96；只有 M=5,000 到 0.99。
  也就是说，10k 上“≥99% 且 ≤100 ms”只有 **M=5,000** 这一档成立，而且相对全量
  扫描只快约 1.6 倍。
- 排序改成**加权点积**（而不是共享位数）是必要的：未加权时 10k 最好只有 0.98。

## 怎么读

1. **候选子集在 2k 以内是干净的加速**：M=1,000、100% 一致、1.5 ms，比全量快 4.6 倍。
2. **10k 开始退化**：候选上限要开到语料的一半（5,000）才保住 99%；这已经不算
   “候选子集”了，更像“近似全量”。更小的 M 会漏掉真正的 top-1。
3. **第三轮 50k 单探针的 48 ms / top-1 一致不能当作普遍结论**：那份是随机合成码、
   一个探针；真实文本在 10k 上就已经需要 M=5,000。50k 需要单独验证，且要更多探针。
4. **它属于速率路径**：候选子集只是先缩小范围，再算原来的一步 W；脉冲没有参与。

## 判据执行

| 预注册条件 | 实测 | 结论 |
| :--- | :--- | :--- |
| top-1 一致率 ≥ 0.99 | n≤2,000：M=1,000 通过；n=10,000：仅 M=5,000 通过 | **有条件通过** |
| 单次查询 ≤ 100 ms | 所有档都远低于 100 ms | **通过** |
| 推荐最小 M | n≤2,000 → 1,000；n=10,000 → 5,000 | 已给出 |

## 下一步

- **50k 真实文本验证**：需要比 166 条更大的真实库，或至少更多探针；当前 10k 的
  趋势说明候选上限会随 n 增长，不能假设 50k 用 M=2,000 就够。
- **更好的候选排序**：目前是加权点积；可以试 top-m 图邻居、ANN、或两阶段
  （先粗排再精排）。目标是把 10k 的 M 从 5,000 降下来。
- **接进 Axo**：只有在 50k 上把“≥99% + ≤100 ms”做稳之后，才考虑接进速率召回路径；
  现在还不是时候。

## 50,000 条（真实文本放大语料，50 个探针）

| M | 一致率 | 查询 | 候选占比 |
| ---: | ---: | ---: | ---: |
| 2,000 | 0.8600 | 16.42 ms | 4% |
| 5,000 | 0.9600 | 34.04 ms | 10% |
| 10,000 | 0.9800 | 64.80 ms | 20% |
| 12,000 | 0.9800 | 51.37 ms | 24% |
| **15,000** | **1.0000** | **69.05 ms** | 30% |
| 18,000 | 1.0000 | 79.80 ms | 36% |
| 20,000 | 1.0000 | 90.93 ms | 40% |

全量扫描在两次运行里分别是 **195.84 ms / 170.26 ms**（机器负载有波动）。

- **最小可用档是 M=15,000**：100% 一致、69 ms，约为全量扫描的 2.5 倍加速。
- M=10,000 / 12,000 只有 98%，不满足预注册的 99%。
- 50k 的候选占比要开到 30% 才保住 99%——这已经不是“小候选”，更像“近似全量”。
  要把它做成真正的加速，需要更好的粗排（图邻居/ANN/两阶段），而不是继续加 M。
- 这是**真实文本的放大语料**，不是真实 5 万条记忆；50 个探针，1 条差异就是 2 pp，
  所以 98% 与 100% 之间的边界有采样噪声。

## 速率路线收尾（2026-10-18）

- **最小可用 M = 14,000**：50k 上 100% 一致，单次约 92 ms（同一轮机器负载下全量
  扫描 226 ms）。M=13,000 只有 98%。
- 15,000 仍在 100% 内，且在此前一轮是 69 ms；**运行间延迟波动很大**（机器负载），
  所以推荐留一档余量：**固定 M=15,000**。
- 全量扫描的优化尝试：`einsum` + `reduceat` 版 transpose 仍需约 122 ms，**压不进
  100 ms**；候选子集是 50k 上唯一能过线的路线。
- 自适应候选（按 top-1/top-2 边际扩展）失败：所有探针都触发扩展，比固定 M1 更慢。
- **结论**：速率路径的最终配置是固定候选 M=15,000（最小实测 14,000），100% 一致、
  均值约 70–90 ms；p95 约 106 ms。没有接进 Axo——还没有确定的消费者与延迟预算。
