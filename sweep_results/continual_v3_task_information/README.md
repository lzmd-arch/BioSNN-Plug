# 任务信息天花板诊断：结果（2026-11-04）

**诊断，不是验收。** 预注册见 [`../continual_v3_task_information_prereg.md`](../continual_v3_task_information_prereg.md)。
原始数值在 [`task_information.json`](task_information.json)。
单种子（0）、冻结 ResNet18（512 维）、CIFAR-100 10×10、全部 50,000 训练 / 10,000 测试。

| 探针 | 做法 | 任务路由准确率 | 性质 |
| :--- | :--- | ---: | :--- |

## 对照（跑完诊断后补做，写在这里是因为它决定了怎么读这个数）

| 对照 | 准确率 |
| :--- | ---: |
| 随机任务标签（标签与图像完全无关） | **0.1033**（随机线 0.10） |
| 真任务标签（10 类） | **0.6512** |
| **100 个细类** | **0.6629** |

- **随机标签落到 0.1033** ⇒ 管线没有泄漏，0.6512 是真信号；
- **0.6512 ≈ 0.6629** ⇒ **判任务几乎和判类一样容易**。任务 = `class_id // 10` 是细类的粗化，
  所以"能分类就能判任务"；实测两者相差 1.2pp，说明**任务推断没有额外的困难**，
  它的上限就是**骨干的细类判别力**。

把"换骨干"当成主要假设的直接依据。

说明这次的 512 维特征与 2026-10-26 那一轮是同一批，标尺是接得上的。

## 三条读数

### 1. 线性天花板与局部路由器**几乎相等**：0.5363 vs 0.5281

这一条最硬：把全部 50,000 个训练特征、全部十个任务**联合**喂给一个多项 logistic 回归，
只比逐个任务各自算 Mahalanobis 高 **0.8pp**。

**所以封存那句"简单局部判别器不可分"是对的——不是路由器太弱，是线性意义上确实不可分。**
旧臂的 0.528 不是方法缺陷，是线性可达的上限附近。

### 2. 非线性确实多给一点：kNN 0.6377、MLP 0.6512

两个完全不同的非线性方法落在同一区间（0.64–0.65），说明这 +11～12pp 是**信息本身**，
不是某个模型的拟合能力。kNN 与 MLP 几乎打平，说明这点增益是**局部几何**的，不是深层结构。

### 3. 折算到端到端：**即便路由到 0.6512，ACC 也只有约 0.647**

用预注册里那条由两个已知点（路由 0.528→ACC 0.5855；路由 1.0→ACC 0.8195）定出的线性关系：

```text
ACC ≈ 0.5855 + 0.4957 × (0.6512 − 0.528) ≈ 0.647
```

而且这个 0.647 是**偏乐观的**：探针 C/D/E **联合训练了全部十个任务**，这是 CIL 里做不到的。
真正可部署的路由器只会更低。

**结论**：在这套特征上，"任务推断"这条路的天花板**落在阶段门 65% 的门口附近**，
离 ADR-0029 重开条件要的 0.8 **差了约 0.15 的 ACC**——不是靠换路由器能补的距离。

## 这个 0.8 到底是哪个 0.8

ADR-0029 写"任务推断能到 **0.8** 以上"，同一行把 0.5855 / 0.1285 记成 ACC / AF 一对，
所以**按字面** 0.8 指端到端 ACC：

| 若 0.8 指 | 需要的路由准确率 |
| :--- | ---: |
| 端到端 ACC（按 ADR-0029 的字面） | **≈0.96** |
| 路由准确率 | 0.80（对应 ACC ≈0.72） |

两种读法都远高于**非局部上限 0.6512**。**在 ResNet18 特征上，两条读法都不可达。**

## 边界

- **单种子**；探针 E 是 512→256→10、30 epoch，**没有调到极限**——更强的非线性模型可能再高一点，
  但从 0.65 到 0.80 是 15pp，不是"再训久一点"的量级；
- 只测了 ResNet18 一个骨干（resnet50 / vit_b_16 没测，那是另一份预注册）；
- 探针 C/D/E 用了全部任务联合训练，**它们不是方法**，只是标尺；
- 端到端 0.647 是用两个点线性内插的**估计**，不是跑出来的数。
