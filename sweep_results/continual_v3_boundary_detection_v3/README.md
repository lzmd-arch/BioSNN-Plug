## 我错在哪：v1 里"看得见"不等于"检得出来"

v3 的立项理由是"原始统计量能看见 1000 与 4000，白化看不见"——**这个理由不成立。**

| 统计量 | 1000 处的值 | 4000 处的值 | 对应的流级阈值 |
| :--- | ---: | ---: | ---: |
| raw（v1/v3） | 0.1659 | 0.1583 | **0.1802** |
| whitened（v2/v3） | 4.0118 | 4.0596 | **4.1550** |

**两个统计量在这两个位置上都低于自己的流级阈值。** v1 之所以"检出"它们，是因为它用的是
**单位置** 99.5 分位（0.1373），那个阈值在一条流上要扫 987 个位置——**它必然放过一批噪声**。
所以 v1 对 1000/4000 的"检出"，和它那 5 次误报是**同一个机制**，不能算真检出。

**这是我这轮最该记住的一条**：一个被更松的阈值捞出来的信号，换个阈值就没了，
它本来就不比噪声高。

## 真正的结论

在**流级 1% 误报率**下：

- 9 个任务边界里，**7 个明确高于噪声**（4.24–4.47 对噪声上限 4.19）；
- **2 个（任务 0→1、任务 3→4）与噪声不可分**——不是"还差一点调参"，是信号本身不够；
- 换段内打乱顺序，检出数在 **6–8** 之间摆动，F1 0.80–0.94。

**E-5 不过说明这条结果也不稳定**：同一个方法换个打乱种子，段数就在 6 到 8 之间变。

## 边界

- 仍是**流上的边界检测**，不是逐样本任务推断；仍按到达顺序分配；
- 单特征空间（ResNet18）、单任务集、无调参；
- E-3 的 0.1006 依旧不是检测器的度量（段数≠9 时顺序分配必然错位）。
