# 真实文本 50k：AISHELL-3 转写上的召回

**日期：2026-10-26。** 这不是个人记忆库，也不是 substrate 的同簇拼接放大。

## 数据来源与边界

- 语料：AISHELL-3 公开中文语音转写，`D:\Projects\_scratch_ui\aishell3_full.jsonl`，
  **83,079 行、80,407 条去重文本**，sha256 `05ab53f0…`。语料不复制进仓库。
- 过滤：去掉空白与长度 < 6 的条目；固定种子 0 从池中抽 **50,000** 条。
- 长度：中位 11 字、p95 21 字、max 39 字——比典型“记忆正文”短，这是语音转写
  的分布，不是个人记忆的分布。
- 查询：从 50,000 条里固定抽 100 条，每条**去掉 30% 字符**（保留 ≥4 字），期望是
  原条目。它量的是真实文本上的候选/召回鲁棒性，**不是语义相关性金标准**；字符
  丢字天然偏向词法通道。
- 嵌入：本机 Ollama `nomic-embed-text`（768 维），50,000 条约 **399 s**
  （7.98 ms/条），一次回填 0.28 s。

## 语义路径（真实 nomic 向量）

| 项目 | 实测 |
| :--- | ---: |
| 50k 嵌入 | 399.1 s（7.98 ms/条） |

| hit@1 / hit@8 / MRR | 0.850 / 0.920 / 0.872 |
| 候选 vs 全量 top-1 / top-8 一致率 | **1.000 / 1.000** |

语义并集在这份“字符丢字”查询上比纯词法低（hit@1 0.91 → 0.85）。**不能据此说
语义通道变差**：查询就是把原文挖掉字符，词法是天然优势；这份语料也没有语义相关
性金标准。它只能说明候选并集没有改变全量扫描的排序（一致率 1.0），以及真实
50k 的延迟量级。

## 与合成 50k 的对比

| 项目 | substrate 放大 50k | AISHELL-3 真实 50k |
| :--- | ---: | ---: |
| 词法索引构建 | 3.5–5.0 s | **2.3 s** |
| 纯词法召回 | 91 ms | **83 ms** |
| 词法+语义召回 | 2.59 s（机器有重活） | **0.17 s** |
| 全量扫描 | 8.8 s | 1.8–2.1 s |

绝对耗时不能直接横比：AISHELL 文本更短、机器负载不同；但两边的候选与全量排序
一致率都是 1.0，说明 1,000 条精确 Jaccard 候选在真实文本分布上同样没有丢结果。
