# 预注册：换骨干重测任务信息天花板（2026-11-04）

**状态：判据先落盘。** 接 [`continual_v3_task_information_prereg.md`](continual_v3_task_information_prereg.md)
（G-3 中间地带，非局部最好 0.6512）。

## 跑之前发现的对照，改变了问题的读法

写完上一份诊断后补了两个对照（同一个 MLP、同样的训练），**先记在这里，因为它们决定了本轮怎么读数**：

| 对照 | 准确率 |
| :--- | ---: |
| 随机任务标签（10 类，标签与图像完全无关） | **0.1033**（= 随机线 0.10） |
| 真任务标签（10 类） | **0.6512** |
| **100 个细类** | **0.6629** |

**0.6512 ≈ 0.6629。** 也就是说：**任务路由的准确率几乎等于"能认出这是哪个 CIFAR 类"的准确率。**
任务 = `class_id // 10`，是细类的粗化，所以"能分类 → 就能判任务"，而实测两者几乎相等，
说明**判任务没有额外的困难，它的上限就是特征的细类判别力**。

这把问题的性质说清楚了：**任务推断的上限 ≈ 骨干的 CIFAR-100 分类力**。
ResNet18 在 CIFAR-100 上（冻结特征）是 0.663，所以它的任务路由卡在 0.65 不是巧合。

## 本臂要回答什么

**换一个分类力更强的骨干，任务路由能不能过 0.80？**

## 设计（跑之前定死）

- 骨干：**resnet50（2048 维）**、**vit_b_16（768 维）**，都是 `research/continual/frontends.py`
  里已支持的，ImageNet1K V1 冻结、CIFAR resize 224、L2 归一化——与 resnet18 完全同一口径；
- 每个骨干跑**同一套探针**：A 原型 / B 全协方差 / C logistic / D kNN / E MLP，
  外加**对照 B（100 细类 MLP）**，用来把"任务路由"和"分类力"放在一起看；
- 单种子（0），与上一轮一致。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **H-0** | 前置：新骨干确实更强 | 至少一个骨干的 100 细类准确率 > **0.75** |
| **H-1** | 换骨干解决得了 | 某骨干的非局部任务路由 ≥ **0.80** |
| **H-2** | 换骨干解决不了 | 全部骨干的非局部任务路由 < **0.70** |
| **H-3** | 中间 | 0.70 ≤ 最好 < 0.80 |
| **H-4** | 机制成立 | 每个骨干上，任务路由 ≥ 细类准确率 − **0.05** |

**H-4 是这轮的关键**：如果它在三个骨干上都成立，那"任务路由 ≈ 分类力"就从一次巧合变成一条规律，
**任务推断的可行性可以直接由骨干的分类准确率预测**，不必再逐个跑。

## 预期

**倾向 H-1 成立：ViT-B/16 有机会过 0.80。** 理由：ViT-B/16 的冻结特征在 CIFAR-100 上通常显著高于
ResNet18，而按 H-4，任务路由会跟着细类准确率走。**若 ViT 的细类准确率到 0.85，任务路由大概率也在
0.83 上下。**

若 H-3/H-2 成立（换骨干也不行），那这条路的结论就变成"**任务推断受限于特征分类力，而分类力要靠
训练而非换骨干**"——那是另一个方向。

## 边界

- 换骨干**会改变基准的含义**（`frontends.py` 自己写着这条）：本臂测的是"特征空间里有多少任务信息"，
  **不是**"CIL 的 ACC 会提高多少"。CIL 的 0.5855 是 ResNet18 下测的，不能与新骨干混报；
- 单种子；探针 E 仍是 512/768/2048→256→10，没有为每个骨干调容量；
- 只测三个骨干，不外推到其他预训练模型。

## 成本

特征提取：resnet50 约 3 分钟、vit_b_16 约 10–15 分钟（60,000 张 224×224 前向）；
五个探针每个骨干约 5 分钟。**合计约 40 分钟。**
