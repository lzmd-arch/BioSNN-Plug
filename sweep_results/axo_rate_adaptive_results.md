# 50k 速率路径：固定候选 vs 自适应候选（结果）

预注册：[`axo_rate_adaptive_prereg.md`](axo_rate_adaptive_prereg.md)。

## 一句话

**固定 M=15,000 是唯一在 50k 上达到 100% top-1 一致的档（均值 79.7 ms，p95 105.6 ms）；
基于分数边际的自适应候选失败——所有探针的边际都低于阈值，100% 展开，反而比固定档
更慢。**

## 结果

真实文本放大语料，50,000 条，50 个探针，50% 丢位；全量参考 153.24 ms。

| 臂 | 一致率 | 平均 M | 平均查询 | p95 |
| :--- | ---: | ---: | ---: | ---: |
| 固定 M=10,000 | 0.98 | 10,000 | 73.15 ms | 121.02 ms |
| **固定 M=15,000** | **1.00** | 15,000 | **79.72 ms** | 105.61 ms |
| 自适应 τ=0.05 | 1.00 | 15,000 | 170.52 ms | 229.75 ms |
| 自适应 τ=0.10 | 1.00 | 15,000 | 155.37 ms | 206.64 ms |
| 自适应 τ=0.20 | 1.00 | 15,000 | 164.75 ms | 232.72 ms |

- **自适应展开率 100%**：top-1 与 top-2 的相对边际在所有探针上都低于 τ（最高 0.20），
  所以每个查询都先算 M0 再算 M1，成本翻倍，比固定 M1 慢一倍。
- 固定 M=15,000 的均值低于 100 ms，但 **p95 是 105.6 ms**，略超预注册的“单次
  ≤100 ms”线；如果按 p95 判，这一档也不算严格通过。
- M=10,000 只有 98%，不满足 99%。

## 怎么读

1. **分数边际不是不确定性的好信号**：它没有区分“M0 已经够”与“需要扩展”的探针，
   于是自适应退化成“永远扩展”。要让它有用，需要换一个信号（例如比较 M0 与 M0/2
   的 top-1 是否稳定，或看 top-1 是否落在候选边界附近）。
2. **固定 M=15,000 是当前最好的速率配置**：100% 一致、均值 79.7 ms、约全量扫描的
   1.9 倍加速；但候选占 30%，不是“小候选”，p95 也刚过线。
3. **50k 的全量扫描本身压不到 100 ms**：`einsum` 版约 153 ms，瓶颈是 transpose 的
   `bincount`（70 ms）；纯 numpy 下换不出数量级。
4. 这是**真实文本放大语料**，不是真实 5 万条记忆；50 个探针，1 条差异 = 2 pp。

## 判据执行

| 预注册条件 | 实测 | 结论 |
| :--- | :--- | :--- |
| 一致率 ≥ 0.99 | 固定 M=15,000 / 自适应：1.00；固定 M=10,000：0.98 | 固定 15k 通过 |
| 单次查询 ≤ 100 ms | 固定 15k 均值 79.72 ms，p95 105.61 ms | **均值通过，p95 略超** |
| 自适应平均 M 低于 15,000 | 三种 τ 都是 15,000，展开率 100% | **失败** |

## 下一步

- **如果要接进 Axo**：目前只有固定 M=15,000 可用；均值 80 ms 量级、p95 106 ms。
  先确认目标消费者的延迟预算，再决定是否值得接。
- **要真正降低 M / p95**：需要更好的粗排（图邻居、ANN、两阶段），而不是分数边际
  自适应；或者把 transpose 从 `bincount` 换成更快的结构（例如预分块的稀疏矩阵）。
- 不建议在没有新粗排的情况下继续调 τ；这一轮的信号已经说明它没有区分度。
