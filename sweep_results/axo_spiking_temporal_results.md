# 脉冲时序读出：结果

预注册：[`axo_spiking_temporal_prereg.md`](axo_spiking_temporal_prereg.md)。
本文件包含原始配置与随后的配对/阈值稳健性检查（后者是探索性的，不是新预注册）。

## 一句话

**首次发放时刻的延迟码让 LIF 在 θ=0.5 上比线性首次越阈码高 10.3 pp（0.6308 vs
0.5280），并在 8 个稳健性条件中的 5 个保持 +5 pp 以上；但不是全线赢，θ=0.3 时会
打平甚至输，θ=0.5/0.7 上优势更稳。**

## 原始结果（同会话相邻轮，θ=0.5，107 对）

| 臂 | A→B | B→A | 平均 |
| :--- | ---: | ---: | ---: |
| `linear-a095` | 0.5047 | 0.5234 | 0.5140 |
| `linear-a098` | 0.5140 | 0.5421 | 0.5280 |
| **`lif-a095`** | **0.6262** | **0.6355** | **0.6308** |
| **`lif-a098`** | **0.6262** | **0.6355** | **0.6308** |
| `alif-b1-r09` | 0.6262 | 0.6355 | 0.6308 |

- LIF 比最好的线性高 **+10.28 pp**，超过预注册的 +5 pp 胜线。
- A→B / B→A 两列接近（0.626 / 0.636），不是“总选第一个”的偏置。
- ALIF 与 LIF 完全同分；适应项在这里没有额外作用。
- 线性臂的首次越阈平均在第 1.5 步，LIF 在第 3.4 步；LIF 更晚，却更准——说明有用的
  不是“早”，而是**相对时刻的排序**。

## 稳健性检查（探索性）

| 配对方式 | θ | 线性最好 | LIF 最好 | Δ |
| :--- | ---: | ---: | ---: | ---: |
| 相邻轮 | 0.3 | 0.7150 | 0.7150 | 0.00 pp |
| 相邻轮 | 0.5 | 0.5280 | **0.6308** | **+10.28 pp** |
| 相邻轮 | 0.7 | 0.4533 | **0.5654** | **+11.21 pp** |
| offset 37 | 0.3 | 0.6799 | 0.6311 | −4.88 pp |
| offset 37 | 0.5 | 0.5335 | **0.5884** | **+5.49 pp** |
| offset 37 | 0.7 | 0.4390 | **0.5030** | **+6.40 pp** |
| offset 83 | 0.5 | 0.5274 | **0.5915** | **+6.41 pp** |
| offset 120 | 0.5 | 0.5610 | 0.5915 | +3.05 pp |

- **5/8 个条件达到 +5 pp 以上**；1 个打平（θ=0.3 相邻轮）；1 个输（θ=0.3 offset 37，
  −4.88 pp）；1 个 +3.05 pp（不到线）。
- 优势在 **θ=0.5/0.7** 上更稳定；θ=0.3 时线性已经很高（0.68–0.72），脉冲追不上或
  打平。阈值是两种读出共用的，没有为各自的模型单独调——这是这套比较的一个边界。
- 配对方式从相邻轮换到 offset 37/83/120，优势没有消失（除了 θ=0.3），说明不是某一组
  配对的特例。

## 怎么读这个正信号

1. **它只证明“时序读出里有顺序信息”**，不证明静态补全/序列遍历/噪声任务会有增益；
   那些轮的末态读出仍然输。
2. **它不是实用替代**：同任务上“只看第一步输入”的 `rate-first` 是 **0.9268**，远高于
   0.6308。时序码比线性时间码好，但仍然远不是最好的顺序读出。这个任务里“读第一步”
   本身就是强基线，所以这 10 pp 不能被写成“脉冲适合 Axo 的顺序任务”。
3. **阈值依赖明显**：θ=0.3 时优势消失；θ=0.5/0.7 更稳。两种模型共用阈值，没有各自
   调参；更严格的比较应该给每个读出自己的阈值预算。
4. 数据是 107 对同会话相邻轮 + 几组确定性 offset 配对；不是自然语言时间流。

## 下一步

- **确认**：在独立配对/独立任务上复现（例如不同的 offset 集合、加噪的输入、或真正
  需要顺序而非“读第一步”的任务）；同时给两种读出各自的阈值调参预算。
- **不要接进 Axo**：它还没有超过 `rate-first`，也不适用于静态/遍历任务；目前只是
  “时序码方向值得继续”的证据。
- 如果继续，优先找一个**读第一步不够**的任务（目标不是第一个输入，而是由顺序决定的
  第三个结果），否则这个正信号无法变成产品能力。
