# 液态 LIF 探针（W2 协议）：五种子 0.8754，主判据不过（2026-10-29）

**预注册：** [`../liquid_lif_prereg.md`](../liquid_lif_prereg.md)
（**定稿于 2026-10-28，在本轮任何液态 LIF 数据之前**）。
只把 W2 的固定 τ=20 换成**由本神经元局部发放率现算的液态 τ**：

```
r_i(t) = γ·r_i(t−1) + (1−γ)·z_i(t)        γ = 0.9
τ_i(t) = 1 / (a + b·r_i(t))，clamp [5, 20]   a = 1/20、b = 0.15
α_i(t) = exp(−1/τ_i(t))
v_i(t) = α_i(t)·v_i(t−1) + I_i(t) − thr·z_i(t−1)
```

`a、b、γ` 与 τ 计算**不在任何参数/优化器/`requires_grad` 路径上**（AST 守卫）。其余完全复用 W2：
sMNIST、250 epoch、batch 64、n_rec 256、lr_in = lr_rec = 1e-2、lr_out = 5e-2、threshold 0.62、beta=0。

## 读法

- 预注册里写死的假说是：**sMNIST 是规整网格，液态 τ 的增益预期小**。结果与之相符——
  在规整、低时间结构的输入上，把时间常数交给局部发放率**没有带来收益，反而略掉**；
- 按预注册的「不做」条款：主判据不过 → **记负结果并归档**，不调 `a/b/γ`、不调 τ 范围、
  不调判据；只有主判据通过才预注册第二轮**事件流数据**（DVS/耳蜗）探针——本轮不做，也不外推；
- **不能**据此说「液态 LIF 没用」：这只说明**在这个数据集、这个协议**下没有收益。事件流数据
  才是液态时间常数的用武之地，这一条是下一步的**前提**，不是本轮结论。

## 边界

- 冻结 α 轨迹的 e-prop：ε_v 递推用当步 `α_i(t)`，但**忽略了 `∂α/∂z`** ——本轮不是对液态递推的
  精确梯度（预注册已写明；`frozen-α` 梯度对照见 `research/eprop/tests/test_liquid.py`）；
- 与 W2 的对照不是同一台机器上的同批运行（W2 的数字是历史值），但协议逐项相同；
- **耗时不可比**：本轮从 15:07 起与 GPU 队列里的 v2（事件优先级第二轮）**并发**在同一张 8 GB 卡上
  （`gpu_queue.sh` 用 `kill -0 <Windows PID>` 判断液态是否结束，在 Git Bash 下看不到那个 PID，
  于是提前放行）。准确率由种子决定、不受争用影响；**`elapsed_s` 与显存峰值反映的是争用后的环境**；
- 显存峰值 1,414.7 MiB，§6.2 的 8 GB 硬约束未触发降级路径。

## 下一步
