# 算力：两把能用的刀、四把不能用的（2026-11-10）

**预注册**：[`research/sel/prereg-lm-speed-to-1day.md`](../../research/sel/prereg-lm-speed-to-1day.md)
**原始数据**：`../lm_eprop_bench/speed_*.json`、`../lm_eprop_p1/{s2,s3,s4,s5}_*.json`

## 一句话

此前所有"训 1B 要多少天"的账都按 **10 TFLOPS** 算——那是这张卡 **fp32 SIMT** 的实际水平。
这一轮把六把刀逐个量了一遍：**两把能用**（`addmm`+补零 **1.27×**、fp32 主权重+低精度镜像 **1.37×**），
**一把又省又赚**（读出头 4→2：**算力减半、top-1 +1.17pp**），**三把不能碰**
（低精度存储、低秩读出、异质膜 τ）。**最终结论是"1 天"在这个架构上不成立**——
因为 1B 里 80% 是读出，而读出恰好是唯一压不动的那一项。

## 一、硬件实测（RTX 5060，8 GB）

| 形状 | fp32 | bf16 | 比 |
| :--- | ---: | ---: | ---: |
| 8,192³（峰值参考） | **12.6 TFLOPS** | **35.1 TFLOPS** | 2.8× |
| 读出 `(256,16384)@(16384,3001)` | 10.0 | 16.3 | 1.62× |
| 同上，**V 补到 3008** | — | **33.6** | **3.36×** |

**V=3001 不是 8 的倍数，cuBLAS 在 bf16 下会掉出张量核**（16.3 → 33.6 只要把列补到 3008）。
补出来的列不进 softmax、不进 argmax ⇒ **输出逐位不变**。fp32 下补零无收益（SIMT 本来就不按 tile 对齐）。

## 二、S1：`addmm` + 补零 —— **1.27×，逐位精确** ✅

原来的读出更新是 `w_out.add_(features.T @ gradient)`：先物化一个 `(M,V)` 的 fp32 临时（197 MB），
再整表读一遍写一遍。改成 `addmm(..., beta=1, out=w_out)` 把它并进 GEMM。

| 配置（N=4,096、V=3,001、batch 256、4 个 τ） | tok/s | 相对 | 峰值显存 |
| :--- | ---: | ---: | ---: |
| 之前 | 19,987 | 1× | 768 MiB |
| **+ `addmm`（不补零）** | **25,838** | **1.29×** | **467 MiB** |
| + 补零（仍 fp32） | 25,367 | 1.27× | 467 MiB |

**守卫**：同种子 4,000 步，fp32 补零 + `addmm` 是 **top-1 0.2325 / CE 4.489**，
P1 原值是 **0.2322 / 4.489** ⇒ 差 +0.03pp，来自 `addmm` 的 fp32 求和顺序。
`tests/test_vocab_padding.py` 在 CPU 上验的是**逐位相等**。

## 三、S2：低精度 —— **存储崩，镜像无损**（本轮最重要的机制发现）

### 3.1 低精度"存储"不过（负结果）

| 4,000 步 | fp32 | bf16 存储 | fp16 存储 |
| :--- | ---: | ---: | ---: |
| top-1 | **0.2325** | 0.1213 | 0.1562 |
| CE | **4.489** | 6.061 | 5.761 |
| CE 形状 | 单调降 | 6.517→6.061（慢一半） | 5.760→**5.725→5.734→5.761（平台）** |

判据是"top-1 掉 ≤0.5pp"，实测 **−11.1pp（bf16）/ −7.6pp（fp16）** ⇒ **默认关**。

**fp16 的尾数比 bf16 细 8 倍却同样崩**，所以**不是尾数位数的问题**。两者共有的机制是：
**这个局部规则没有动量、没有二阶状态，权重本身就是那个累加器**，而低精度存储每步都把它舍一次。
BP 的 bf16 训练能活，是因为它有 fp32 master 加 Adam 的二阶状态在替它平均。

### 3.2 低精度"镜像"无损，1.37×

**fp32 主权重不动，另存一份 bf16 镜像供两次矩阵乘读，每步刷新。**

| 4,000 步 | fp32 | **fp32 主权重 + bf16 镜像** |
| :--- | ---: | ---: |
| top-1 | 0.2325 | **0.2324**（−0.01pp） |
| CE | 4.489 | **4.489** |

| 吞吐（工作点） | tok/s | 相对 fp32 | 峰值显存 |
| :--- | ---: | ---: | ---: |
| fp32（S1 之后） | 25,367 | 1× | 467 MiB |
| **镜像 bf16** | **34,741** | **1.37×** | 561 MiB |
| 镜像 fp16 | 30,051 | 1.18× | 561 MiB |
| （对照）bf16 **存储** | 50,528 | 1.99× | 373 MiB |

**代价是镜像本身**：`copy_(master)` 每步读 197 MB fp32、写 98 MB bf16，约 2.3 ms/步。
把刷新周期放到 T 步可以摊薄，但那是**近似**（前向用最多 T 步前的权重），要另立预注册去验。

## 四、S3：读出头 4 → 2 —— **又省又赚** ✅

| 步数 | 4 抽头（基线） | **2 抽头（τ=2,128）** | 差 |
| :--- | ---: | ---: | ---: |
| 4,000 | 0.2325 / 4.489 | **0.2451 / 4.417** | **+1.3pp** |
| 8,000 | 0.2657 / 4.198 | **0.2774 / 4.126** | **+1.17pp** |

**两个指标同向，两个预算都成立。** 完整曲线（4,000 步）：

| 抽头数 | 1（同质 τ） | **2（τ=2,128）** | 4（τ=2,8,32,128） |
| :--- | ---: | ---: | ---: |
| top-1 | 0.1835 | **0.2451** | 0.2325 |

**在 2 处见顶，4 已经回落。** 这**修正了 R8 的"读出维度是杠杆、regime 无关"**——
那句是拿 1 vs 4 抽头得出的，现在完整曲线是 1 → 2 → 4 = 0.1835 → 0.2451 → 0.2325。
最合理的解释是**过拟合**：4096 特征 × 3,001 词表 = 12.3M 参数，对 33k 对而言；2 抽头只有 6.1M。

### 4.1 异质膜 τ 补不回来（负结果）

| 4,000 步 | top-1 | CE |
| :--- | ---: | ---: |
| 1 抽头 · 同质膜 τ | 0.1835 | 4.768 |
| 1 抽头 · **异质膜 τ**（4 组，τ∈[5,500]） | 0.1776 | 4.772 |
| 4 抽头 · 同质膜 τ | 0.2325 | 4.489 |
| 4 抽头 · **异质膜 τ** | 0.2237 | 4.547 |

两处都是负的。"把时间多样性搬进神经元、省掉读出抽头"**不成立**：
读出抽头给的是**每个神经元几组独立的输出权重**，膜时间常数给的是一组权重看不同的动态，两者不等价。

**顺带修了两个 G2 的实现 bug**（此前从没跑过）：
① `tau_vec` 用连续块而 `group_ids` 用交错下标，痕迹按错误的 τ 衰减；② 分组路径根本不维护
`eps_in`，**`w_in` 完全没学**。守卫见 `tests/test_tau_groups.py`。

## 五、S4：低秩 —— **输入可以，读出不行**

| 臂（8,000 步） | top-1 | CE | 对基线 0.2657 / 4.198 | 判据 ≤1pp |
| :--- | ---: | ---: | ---: | :--- |
| 只低秩**读出** r=512 | 0.2526 | 4.816 | **−1.3pp / +0.62** | ✗ |
| 只低秩**输入** d=256 | 0.2595 | 4.270 | **−0.62pp / +0.07** | ✅ |

⇒ 此前"低秩 −1.2pp"那笔账**全部归读出**。**低秩输入（1.7×）可以拿，低秩读出不行。**
这一条很硬：1B 的读出就是 `M·V`，压不动它等于压不动总账。

## 六、S5：分抽头归一化 —— 实现比假设重要

假设：全局 NLMS 用**一个标量** `norm` 归一化全部 M 个特征，一个抽头活动大就把别的抽头的步长一起压小；
按抽头分组归一化（脑区局部抑制的计算对应物）应当更公平。**零算力成本。**

**第一版实现把步长放大了 G 倍**：全局版每步的修正量是 `Σ_g g/G = g`，
少了这个 `1/G` 就变成 `Σ_g g = G·g`。实测 CE 从 8.0 一路涨到 **18.1**（发散），
不是"分组没用"，是**实现错了**。修完 `1/G` 之后，`norm_groups=4` 与全局版的 CE 相差 <0.5%。

**验证它归零**：`norm_groups=1` 与 `2/4` 的权重模长比是 1.000 / 1.003 / 1.021
（若少了 `1/G` 会是 ~G 倍）。守卫见 `tests/test_norm_groups.py`。

> **一条值得记的教训**：最初的冒烟配置神经元根本不发放，`features` 恒零，
> 三种分组给出**逐位相同**的损失——看起来"通过"，其实什么都没测到。
> 现在的守卫强制网络发放，并断言"分组确实改变了权重"。

## 七、1 天的账：被读出钉死

每 token 的 MAC（1B 取 N=40,000、V=5,000）：

| 配置 | MAC/token | 相对 | 判据 |
| :--- | ---: | ---: | :--- |
| K=4 稠密（原状） | 1,800 M | 1× | — |
| **K=2 + 低秩输入** | **811 M** | **2.2×** | ✅ 两条都过 |
| K=2 + 低秩读出 + 低秩输入 | 186 M | 9.7× | ✗ 读出 −1.3pp |
| K=1 + 低秩（异质 τ） | 58 M | 31× | ✗ 异质 τ −0.6~−0.9pp |

**能拿的组合只省到 811 M MAC。**

外推必须交代吞吐是怎么取的，这一条最容易自欺：**bench 的步级有效吞吐只有 7.7 TFLOPS**
（镜像版、N=4,096/V=3,001；matmul 只占一步的 60%，其余是逐元素），而**matmul 本身的峰值是 33**。
1B 的形状（M=80k、V=5k）里 matmul 占比更高，有效的数会落在两者之间。**所以给区间，不给点**：

| | @7.7 TFLOPS（bench 步级，保守） | @20 TFLOPS（1B 形状估计） |
| :--- | ---: | ---: |
| K=4 稠密 · 20B token | 108 天 | 42 天 |
| **K=2 + 低秩输入 · 20B token** | **49 天** | **19 天** |
| K=2 + 低秩输入 · **1 天能跑** | **0.41 B token** | **1.1 B token** |

**⇒ "1 天"不是一个时间目标，是一个规模目标。** 在 8 GB 上，1 天要么是
**~0.4–1.1B token 的 40k 神经元模型**，要么是 **20B token 的 ~2k 神经元模型**。
Chinchilla 那套 1B×20B 在这个架构上**凑不齐**——因为 1B 里 80% 是读出，
而读出正好是唯一压不动的东西（低秩、低精度存储、事件驱动、候选剪枝，四条路都试过，全负）。

## 八、分桶：2.6× 但质量没过关（负结果）

`--bucket-lengths` 把批内最长/均值从 3.06× 压到 1.17×（填充浪费降 2.6×），
但同种子 2,000 步：随机批 0.1926 / 4.833，分桶 **0.1770 / 4.957** ⇒ **−1.56pp，3 倍于门槛** ⇒ 默认关。

**最可能的机制（未验）**：分桶后每批长度几乎相同，每步的有效 token 数在"全短/全长"之间摆动 ~3 倍，
而学习率是逐更新的、不随 token 数缩放 ⇒ 有效步长在抖。可测的下一步：池子从 10 放到 100。

## 九、边界（四问清单）

1. **是预算截断吗？** 质量守卫是 4,000 / 8,000 步，**峰值未到** ⇒ 所有 Δ 是**下界**。
   2 抽头的 16,000 步对照已排（与 P1 的 0.2973 同预算）。
2. **是跨语料/跨预算比较吗？** 吞吐是同机同形状的前后对比；质量是**同语料、同预算、同种子**。
   只有"1 天的账"是外推，且**按实测吞吐**而非理论峰值。
3. **是单边指标吗？** 2 抽头**两边都赢**；bf16/fp16 存储**两边都输**；低秩读出**两边都输**；
   低秩输入 top-1 −0.62pp 而 CE +0.07 —— **这一条是单边的，赢的是 CE**。
4. **cos 先验？** 无关（本轮没有余弦）。

**未做的**：2 抽头在 16,000 步上的确认（已排队）、镜像刷新周期 T>1、分桶池子放大后的重测、
以及"1 天 = 2k 神经元 × 20B token"这个配置本身一次都没跑过。
