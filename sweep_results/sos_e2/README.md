# 脉冲 SoS 的 E2：三臂全灭，但原因是**状态表示把迷宫压成了 16 个格子**（2026-11-02）

**预注册：** [`research/sos/prereg-e2.md`](../../research/sos/prereg-e2.md)

## 判决

| 臂 | reward | confirm 成功率 | 访问熵 |
| :--- | :--- | ---: | ---: |
| A 过程 | `−surprisal` | **0.000** | 1.100 |
| B 稠密外部 | 近了 +1 / 远了 −1 | **0.000** | 2.633 |
| C 稀疏外部 | 到达 +1 | 0.060 | 2.773 |

| 判据 | 结果 |
| :--- | :--- |
| E2-0 A 不许退化 | ✗ **A 退化**（熵 1.100 < 0.5×2.773 = 1.387） |
| E2-1 稀疏臂可用 | ⚠️ **平凡通过**（C 0.060 ≥ 0.5×B = 0） |
| E2-2 H1：A 优于 C | ✗ 不成立 |

`h1_supported = false`。

## 两个必须写清楚的问题

### 1. E2-1 的判据在 B=0 时是空的

它写成"C ≥ 0.5×B"，B 一旦是 0，任何 C 都过。**这是判据的缺陷**，不是结果。
下一版要么改成绝对门槛，要么先确认 B 学得动。

### 2. 真正的原因：状态表示把整个迷宫压成 16 个状态

策略的状态键是「相对终点的位移，裁剪到 [−3,3]²」。11×11 迷宫里 dx、dy 最大到 9，
一裁就只剩 **(0..3)² = 16 个键**。121 个格子映射到 16 个状态——
**策略根本分不清自己在迷宫的哪儿**，B 臂拿稠密奖励也学不动。

这不是"方法不行"，是实现错了。

## 诊断

把学习率从 0.05 降到 0.0005，B 臂成功率 0.000 → 0.065——**仍然几乎不动**。
所以不是学习率的问题；换成不裁剪的状态键才是。

## 处理

不调超参救场。按预注册的死亡条件另写
[`prereg-e2-v2.md`](../../research/sos/prereg-e2-v2.md)：状态改成**不裁剪的相对位移**，
并把 advantage 按 episode 归一化（回报量级 ±100，直接乘 0.05 的学习率会把策略一步打饱和）。
