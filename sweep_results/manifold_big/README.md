## 三、头号发现：`to_ball` 饱和，双曲臂等于欧氏臂

`to_ball(x, kappa=1.0)` 原来是：

```python
unit(x) * torch.tanh(kappa * x.norm(dim=1)) * 0.95
```

标准化后的 4096 维特征，**模长中位数 63.99**，而 `tanh(63.99)` 在 float32 下**就是 1.0**。
于是每个点都被压到半径 **0.95** 的同一个球面上（实测 min = max = 0.95）。

此时

```
d_poincare(u,v) = arccosh(1 + 2‖u−v‖² / ((1−0.9025)(1−0.9025)))
                = arccosh(1 + c·‖u−v‖²)
```

是欧氏距离的**严格单调函数** ⇒ `argmin` 完全相同 ⇒ **同一张混淆矩阵**。
逐种子数字一模一样，不是巧合，是代数恒等式。

⇒ **`manifold_big` 从来没有比较过双曲几何与欧氏几何。** 四种几何实际只有三种
（euclid ≡ poincare）。

**已修**：`kappa` 默认取 `1 / median(‖x‖)`，让 `tanh` 落在有区分度的区间
（中位点 tanh(1) ≈ 0.76）。修后半径分布 0.710–0.739 —— **半径随点变化**，
分母 `1−‖u‖²` 因此不同，双曲距离不再是欧氏距离的单调函数。
守卫测试：`tests/test_instrument.py::test_to_ball_does_not_saturate`。

⚠️ **本目录 `result.json` 是修复前跑的**，所以 poincare 那一列不可用。
**没有重跑** —— 因为即使修好 `to_ball`，G-0 仍会不过（见下），重跑买不到结论。

## 四、为什么 G-0 不过

读出是**零参数最近原型**（类均值 + 距离）。这与 `spatial_dim` 是同一套仪器、
同一个 n / 入度，那边四条格点臂也是 0.115–0.122（底板 0.125）。
**两个独立实验一起复现了同一件事：在这个规模上，零参数原型读出够不到任务。**

同任务族、同一天花板下，MLP 读出是 0.229（`bio_all` 的 `off`），
而 `hyperbolic_readout` 用**学出来的 2 维投影** + 距离，在 K=4 能到 0.414。
⇒ 差别在"有没有学一个投影"，不在"用哪种距离"。

## 五、重开需要什么

1. 先修量具（`to_ball` 已修、已有守卫），
2. 换够得着天花板的读出（**学出来的投影**，不是类均值），
3. 写成**新的预注册** —— 不能拿这份作废结果改 G-0 的后果。
