# M6at：**维度匹配的二次读出 —— 低维状态的内在维度是 ~4，二次再加 +0.12；高维仍救不回**

## 缘起（用户指出 `m6as` 的展开与状态维度不匹配）

> 二次读出和高维状态在维度上真的匹配吗？

**不匹配。** `m6as` 在 64 维上做全二次展开（2080 维），但状态的**内在维度小得多**；
若流形维度是 `m`，二次函数最多张成 `m(m+1)/2` 维 ⇒ **2080 维里绝大部分是噪声。**

**修法**：先 PCA 到 `m`，再做二次；而且**线性臂与二次臂必须用同一个 `m`**
（第一版线性用 64 维、二次只用 m 维 —— 两边不是同一个输入空间，已修）。

## 结果（3 种子，`per_fam=96`）

| regime | 64 维线性 | **PCA-4 线性** | **PCA-4 二次** | m=8/16/32（线性/二次） |
| :--- | ---: | ---: | ---: | :--- |
| **全局（低维）** | **0.101** | **0.451** | **0.571** | 0.554/0.564、0.554/0.562、0.556/0.564 |
| 高维（PR 64） | 0.462 | 0.271 | 0.168 | 0.293/0.181、0.389/0.208、0.424/0.233 |

| 判据 | 结果 |
| :--- | :--- |
| AT-0 发放在窗内 | 过 |
| AT-1 存在匹配的 m 使二次 > 线性 +0.15 | **不过**（高维档最好 −0.102） |
| AT-2 增益随 m 先升后降 | 高维档**单调变差**（−0.102 → −0.191），峰值在端点 |

## 一、低维档：三个数说明三件事

```
0.101  →  0.451  →  0.571
64维线性   PCA-4线性   PCA-4二次
```

1. **信息压在 ~4 维里** —— 64 维线性（0.101）几乎全被噪声淹没，PCA 到 4 维后 **4.5 倍**；
2. **那 4 维上的编码是强非线性的** —— 二次再加 **+0.12**；
3. **内在维度 ~4–8** —— m 从 8 到 32 几乎不变（0.554–0.564）。

**⇒ 今晚所有"低维状态可解码 0.42–0.53"的数字都被 64 维线性读出低估了。
真实可读信息在 0.57 以上。**

## 二、高维档：二次在每个 m 上都更差

−0.102（m=4）、−0.113（m=8）、−0.181（m=16）、−0.191（m=32）。
**维度越高，二次伤害越大** —— 因为超过内在维度之后，二次项全是噪声。

**⇒ "用非线性救高维"这条路方向是错的。**

## 三、限定

- 3 种子；`per_fam=96`（768 样本）；
- PCA 用训练集统计（无泄漏）；
- 二次用的是**所有 ≤2 次单项式**（含平方项），未做特征选择；
- 全局臂带 `p_long=0.5`（与 `M6t` 基线不同），所以它的"64 维线性 0.101"低于 `M6t` 的 0.53
  —— 但那更说明**读出方式**的影响有多大。
