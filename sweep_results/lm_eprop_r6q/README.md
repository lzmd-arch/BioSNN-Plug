# R6q：真语料 + 窄读出——**缩了更差（−1.04pp），2×2 塌缩成一条线**（2026-11-08）

**预注册**：[`research/sel/prereg-lm-r6q-real-corpus-narrow-readout.md`](../../research/sel/prereg-lm-r6q-real-corpus-narrow-readout.md)
**原始数据**：[`r6q.json`](r6q.json)
**基线**：[`../lm_eprop_r0b/README.md`](../lm_eprop_r0b/README.md) 大折第 8,000 步

## 一句话

在真语料大折、8,000 步上，把读出从 **1,024 缩到 256**（参数 1.25M → 0.31M）：
Δ 从 −10.12pp 掉到 **−11.16pp**，**改善 −1.04pp**。

- **R6q-1（要 +3pp）：严重不过**；
- **R6q-2（≤ −1pp 判"两 regime 同向"）：−1.04pp，边缘触发**——四个评测点**全部**低于基线，方向明确。

⇒ **"缩读出"在两个 regime 里都是毒药**：合成 A 语料 −3.74pp、真语料 −1.04pp。
**"参数/数据比只在记忆化区成立"这条解释出局。**

## 三件必须一起说的事

### 1. 不是单点噪声：四个评测点全都低于基线

2,000 / 4,000 / 6,000 / 8,000 步分别低 1.16 / 1.66 / 1.88 / 1.05pp。单点有 ±0.6–0.9pp 的抽样噪声，
**四个点同向**说明这是真的退化，不是抖动。

### 2. 2×2 塌缩：容量方向与 regime 无关

| regime | 缩容量 | 扩容量 |
| :--- | :---: | :---: |
| 合成 A（容量约束区） | **−3.74pp**（R3 臂 a） | **+4.88pp**（R4） |
| 真语料（记忆化区） | **−1.04pp**（R6q） | R8 待测 |

原假设是"真语料上读出参数过剩（2.5M 参数背 3.4 万字），缩了应该更好"。
**实测相反。** 所以 R0b 的过拟合**不是读出容量造成的**——要找的是表征层或任务本身。

### 3. 幅度差 3.6 倍，但方向一致

合成语料 −3.74pp、真语料 −1.04pp。差异的合理解释：合成语料的基线（0.2203）比真语料（0.0657）高得多，
**天花板高的地方，容量更值钱**。这与 R4 的结果（合成语料上扩容量 +4.88pp）一致。

## 执行说明

这一轮**同时跑了两个副本**（两个排队脚本都等到了 R5 的结束标记，各自启动了一次 R6q）。
两个进程写同一个日志、同一个 tag，日志里能看到一处交错。**两次结果逐位相同**
（0.0552 / −0.1116 / `firing_rate` 0.04013），所以数据可信；但这暴露了排队脚本没有互斥的问题，
之后已合并成**单一收尾链**（`queue_final.sh`：基线补曲线 → R8）。

## 边界

- **单折、单种子、13 对测试（噪声 ±0.6–0.9pp）**——−1.04pp 就在噪声边缘，这也是为什么 R6q-2 只是"边缘触发"；
- 8,000 步在过拟合区（CE 从 2,000 步起上升）；
- 字符级 next-token，**不代表能闲聊**。

## 对路线的影响

1. **"参数/数据比"这条解释结束**：缩读出在真语料上也不帮忙；
2. 2×2 只剩**一个空格**：真语料 × 扩容量（R8，已排队）；
3. 若 R8 也是正的，整张图会简化成一句话——**"读出维度是杠杆，regime 无关"**，这比"两个 regime 方向相反"更简洁，也更容易写进论文。
