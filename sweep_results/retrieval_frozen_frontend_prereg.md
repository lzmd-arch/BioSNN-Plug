# 预注册：跨模态检索第九轮——冻结预训练前端（真实数据）

**定稿时间：2026-10-17，在这一轮的任何数据之前。**

## 为什么要有这一轮

第八轮（真实数据，现有编码器）的结果是决定性的：**kNN 的 R@1 = 0.002，随机 0.001**。
24×24 灰度、三帧帧差的事件编码，与逐 token 的句子 embedding 之间，**没有可用的跨模态信号**。

这一轮换的是**前端**，不是学习规则：

| 模态 | 之前 | 现在 |
| :--- | :--- | :--- |
| 图像 | 24×24 灰度 DVS 帧差 | **ResNet18（ImageNet 权重，冻结）→ 512 维** |
| 文本 | 逐 token 的句子 embedding + top-k | **整句 nomic-embed-text（冻结）→ 768 维** |

## 为什么这是允许的，而且不是"作弊"

仓库的边界写得很清楚（README「感知层允许冻结预训练前端」）：判据是**参数进不进梯度**，
不是模型大不大。文本侧一直是冻结的 nomic；图像侧改用冻结 ResNet 是**对称处理**，
不是放宽标准。

⚠️ 但必须说清它改变了什么：**两端都不共享预训练对齐**（ResNet 与 nomic 从未一起训练），
所以"把两个模态接起来"这件事**仍然完全落在联想层**。这一点是这一轮有意义的全部原因——
若换成 CLIP 同时编码图与文，对齐已经由预训练完成，局部规则就没有事可做，那才是作弊。

## 设计

| 维度 | 取值 |
| :--- | :--- |
| 数据 | Flickr8k 官方切分（train 6000 / test 1000），第 0 条 caption |
| 图像前端 | torchvision `resnet18(weights=IMAGENET1K_V1)`，eval、`no_grad`、224×224、ImageNet 归一化，取 avgpool 后 512 维 |
| 文本前端 | Ollama `nomic-embed-text`，**整句**编码（不是逐 token），768 维 |
| 表示 | 两者各自 L2 归一化后直接喂给联想层（**不经过 `biosnn-bus` 的随机投影**——这一轮问的是前端，不是总线） |
| 读出 | `ridge`（线性上界）、`delta`（局部）、`knn`（非参数上界） |
| 种子 | 5 个（切分固定为官方切分，种子只影响 delta 的顺序与特征随机性） |

## 判据

* 若 **delta（局部规则）R@1 ≥ 0.50** → 第二阶段的验收线在真实数据上达成；
* 若 ridge/knn 远高于 delta → 瓶颈回到"局部规则太弱"，这是继第三轮之后第二次把问题定位到规则；
* 若三者都低 → 前端仍不够，下一步是更强的单模态编码器（不是换 CLIP）。

## 边界情况

* **特征缓存到 `data/flickr8k/`**，第二次运行不再重算（ResNet 与 Ollama 都慢）。
* 图像特征在 GPU 上算；本机 RTX 5060 8GB，resnet18 batch 64 足够。
* 与合成集**不可比**：候选数 1000、随机 0.1%。
