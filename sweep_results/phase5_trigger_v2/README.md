## 补充诊断（**在看到 A/B 分歧之后**加的；只用于解释，不参与判据）

单个 10/10 划分只给一次抽样。把 20 段随机重划 500 次（种子 20261102，脚本
[`../../scripts/diagnose_phase5_trigger_v2.py`](../../scripts/diagnose_phase5_trigger_v2.py)），
看误触发率与命中率各自怎么分布：

| 流 | 目标轮 `R5` 均值 | 背景轮 `R5` 均值 | 误触发率 均值 / sd / [5%, 95%] | ≤ α 的划分 | 命中率 均值 / sd | ≥ 0.50 的划分 |
| :--- | ---: | ---: | :--- | ---: | :--- | ---: |
| 真实 | 0.1875 | 0.0937 | **0.100** / 0.040 / [0.040, 0.167] | 56% | 0.385 / 0.077 | **9%** |
| 合成 | 0.1442 | 0.0971 | **0.104** / 0.055 / [0.027, 0.207] | 55% | 0.188 / 0.049 | 0% |

三条读数：

1. **误触发率的均值正好落在 α 上**（真实流 0.100，合成流 0.104）。conformal 保证的是
   `E[误触发率] ≤ α`，这一条**成立**。
2. **但单个划分的抖动很大**：真实流 sd 0.040，90% 区间 [0.040, 0.167] 跨了四倍。
   A 方向的 0.153 与 B 方向的 0.067 相差 0.086 ≈ 2.1 个单划分 sd（两个方向不独立，只作量级参考）——**A/B 的分歧正是划分噪声本身**，
   不是两种不同的世界。
3. 纯二项噪声在 150 个测试负例上只有 sd 0.0245；实测 0.040 是它的 1.6 倍。
   多出来的是**校准分位数本身也在抖**（10 段校准只给 150 个负例去估 90% 分位）。

## 读法

### 1. 主因是打分函数太弱，而且这一条是稳健的

预注册把 T-2 不过解释成「打分函数太弱」。数据全票支持：两个方向 0.420 / 0.380，
500 次随机划分里**只有 9%** 能把命中率做到 0.50，均值 0.385。
`R5` 在留出半上的 AUC 是 0.719 / 0.797（M3p 全 20 段池化 0.757），信号确实在，但不够密。
**conformal 不会造出分数里没有的信息**：它只保证误触发率，命中率的上限由分数本身决定。

### 2. T-1 的失败不是「分布漂移」，是「这条判据在这个样本量上不可认证」

预注册给了两种失败解释：T-1 过而 T-2 不过 → 打分太弱；T-1 也不过 → 分布漂移。
主方向 A 的 T-1 确实不过（0.153），但**第二种解释不被数据支持**：500 次随机划分的误触发率
均值是 0.100，正好等于 α；0.153 只比均值高 1.3 个 sd。反向 B 更是 0.067，通过。

所以第三种解释才是对的：**10/10 的划分不足以认证 α = 0.10 的误触发率**。
判据仍然判「不过」——判决没有改，改的是「为什么不过」。这不是调阈值让它变绿：
没有任何一个数字因为这句话而改变。

### 3. T-3 的 11/20 是一次平手，不是崩盘

逐段看，conformal 阈值与「校准段上调出来的固定阈值」的池化 F1 是 0.447 vs 0.430（A）与
0.481 vs 0.511（B），互有胜负，逐段 11/20。基线是按 F1 挑的，conformal 不是为 F1 优化的
——它买的是误触发率的保证（而且如上所述，这个保证在 10 段的粒度上测不准）。
两条门在 F1 上打平，本身是个值得记住的读数：**conformal 的代价不是精度，是它在 F1 上不占便宜**。

### 4. T-4 的对照流没造出「本应容易」的难度——fixture 设计错了

设计意图：目标轮换成另一个话题的句子，`R5` 应当明显更高，于是这条对照应当「过」。
实测目标轮 `R5` 均值 0.144 vs 背景 0.097，只差 **0.047**（真实流是 0.094）。
原因是模板共用：两个话题的句子用同一批句式，只换话题词，嵌入空间的相似度被句式主导，
话题词带来的差异被压掉了。

这条对照因此**只能验证误触发那一半**（它的误触发均值 0.104，同样落在 α 上），
**不能验证命中那一半**。作为 fixture 的设计教训记在这里：合成对照要造「容易」，得让目标轮的
**句式**也不同，而不只是换名词。

### 5. 这一版真正的产出

- 判据本身是**可用的**：分位数实现正确（校准内 0.093 = 14/150）、均值落在 α 上；
- 但它**在现有语料规模上分辨不出 0.10 与 0.15**：实测 sd 0.040，要把 95% 区间压到 ±0.03
  （sd ≈ 0.015）需要约 **7 倍**的段数（≈140 段）。这是下一轮做评估设计时的硬约束；
- 触发器仍然 `not ready`，且**失败点被定位到打分函数**，不是判据、不是阈值、不是分布漂移。

## 边界

- 20 段、每段 5 个正例、`qwen3-4b` 生成、目标轮由脚本安排；不是开放域对话；
- 这一版**没有测脉冲触发**（`SpikingTrigger`），测的是规则门换成 conformal 阈值之后的行为
  ——「脉冲触发器不行」不能从这份结果里读出来；
- conformal 的 ≤ α 保证是**边际**的（对校准/测试的可交换性取期望），不是每段都成立；
  逐段误触发率（主方向中位 0.167、最大 0.267）就是这条差别的具体形态；
- T-3 的基线是按池化 F1 选的单一阈值，属于「调一次、到处用」的朴素做法；换成别的基线
  （例如按召回选）会得到不同的逐段计数，但两份预注册都没这么定，不做事后替换。

## 不说明什么

- **不说明 conformal 没用**：它的误触发控制在本批数据上成立（均值 = α）；
- **不说明触发路线整体不可行**：只说明 `R5` 这一类「与最近 5 轮的余弦距离」的分数在真实流上
  不够密，做到 0.50 命中需要的分离度它给不出；
- **不说明应该放宽 α**：把 α 从 0.10 放到 0.20 能让命中率好看，但那是把问题从「命中不够」
  换成「误触发太多」，两边都不是可用状态。
