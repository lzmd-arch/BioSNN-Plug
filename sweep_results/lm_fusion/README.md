# 融合：机制建成了，但文本-only 条件下 α* = 0（2026-11-12）

## 一、做了什么

真正把两个模型的分布合起来（`scripts/fuse_eval.py`）：

```
score(token) = log q_qwen(token) + α · log p_snn(token)
      ↓  并集上 softmax → argmax → 一个 token
```

- 千问的词表**一个字节不动**，只在输出侧叠加；
- 跨分词器靠**字符串前缀归并**：千问的候选"同时"，把我们这边所有是它前缀的 token 概率加总；
- **α 是唯一旋钮**。

## 二、结果：α* = 0，而且是**剂量–反应**关系

留出分片、40 个位置：

| α | top-1 | 真值平均 log p |
| ---: | ---: | ---: |
| **0（千问单独）** | **0.2250** | **−10.651** |
| 0.1 | 0.2250 | −10.675 |
| 0.25 | 0.2000 | −11.082 |
| 0.5 | 0.1000 | −12.980 |
| 1.0 | 0.0750 | −18.443 |

**任何 α>0 都更差，而且差得单调。** 这比"没提升"更强——是一个**有剂量–反应的零结果**：
SNN 的分布里没有可用信息，投入越多破坏越大。

配套的 `F-0`（30 个位置）：**"千问错而 SNN 对" = 0/30**。

## 三、为什么——以及这条结论的**适用范围**

**因为两边吃的是同一份公开语料。** 同一分布上的更弱模型，偏离就是噪声。

**但这条结论只对"文本-only 的 SNN"成立。** 产品里的 SNN 还能读**环境数据与多模态**
（温度、气体、光照、噪声、屏幕、设备状态），而**这些数据不出设备，云端永远拿不到**。

⇒ 融合的正确形态是：

```
p(下一个 token | 文本, 传感器)   ← SNN 独有
q(下一个 token | 文本)           ← 千问
fused = q + α·log p_snn
```

**α 只有在 SNN 拥有千问没有的信息时才可能 > 0。** 本文测的是"没有那份信息"的基线——
**它是传感器通道的对照组**，不是"融合永远不行"的判决。

## 四、必须写死的边界

**配对的（传感器, 文本）数据今天不存在**，只能靠产品跑起来积累。
在那之前传感器向量为 0，融合就退化成本文这个测量。

**所以现在的正确表述是**：融合是一个**机制上成立、当前混合权重最优值为 0** 的组合模型；
它的增益取决于一条尚未有数据的输入通道。
