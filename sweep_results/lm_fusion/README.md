# 融合：机制建成了，但文本-only 条件下 α* = 0（2026-11-12）

## 一、做了什么

真正把两个模型的分布合起来（`scripts/fuse_eval.py`）：

```
score(token) = log q_qwen(token) + α · log p_snn(token)
      ↓  并集上 softmax → argmax → 一个 token
```

- 千问的词表**一个字节不动**，只在输出侧叠加；
- 跨分词器靠**字符串前缀归并**：千问的候选"同时"，把我们这边所有是它前缀的 token 概率加总；
- **α 是唯一旋钮**。

## 二、结果：α* = 0，而且是**剂量–反应**关系

留出分片、40 个位置：

| α | top-1 | 真值平均 log p |
| ---: | ---: | ---: |
| **0（千问单独）** | **0.2250** | **−10.651** |
| 0.1 | 0.2250 | −10.675 |
| 0.25 | 0.2000 | −11.082 |
| 0.5 | 0.1000 | −12.980 |
| 1.0 | 0.0750 | −18.443 |

**任何 α>0 都更差，而且差得单调。** 这比"没提升"更强——是一个**有剂量–反应的零结果**：
SNN 的分布里没有可用信息，投入越多破坏越大。

配套的 `F-0`（30 个位置）：**"千问错而 SNN 对" = 0/30**。

## 三、为什么——以及这条结论的**适用范围**

**因为两边吃的是同一份公开语料。** 同一分布上的更弱模型，偏离就是噪声。

**但这条结论只对"文本-only 的 SNN"成立。** 产品里的 SNN 还能读**环境数据与多模态**
（温度、气体、光照、噪声、屏幕、设备状态），而**这些数据不出设备，云端永远拿不到**。

⇒ 融合的正确形态是：

```
p(下一个 token | 文本, 传感器)   ← SNN 独有
q(下一个 token | 文本)           ← 千问
fused = q + α·log p_snn
```

**α 只有在 SNN 拥有千问没有的信息时才可能 > 0。** 本文测的是"没有那份信息"的基线——
**它是传感器通道的对照组**，不是"融合永远不行"的判决。

## 四、必须写死的边界

**配对的（传感器, 文本）数据今天不存在**，只能靠产品跑起来积累。
在那之前传感器向量为 0，融合就退化成本文这个测量。

**所以现在的正确表述是**：融合是一个**机制上成立、当前混合权重最优值为 0** 的组合模型；
它的增益取决于一条尚未有数据的输入通道。

## 五、U-2（用户头）：这个人的先验对下一个 token 有没有预测力——**没有可测的增益**（2026-11-12）

真库 **218 条**记忆：按时间前 80% 训练（174 条 / **54,233 token**）、后 20% 留出（40 条），
在留出段上逐个位置向本地 SNN 服务要 top-k，比 `score = log q + γ·log u` 给真值的概率质量。
**只有 60 个计分位置**（`scripts/u2_user_head.py`）。

| γ | 真值平均 log p |
| ---: | ---: |
| **0.0** | **−15.3873** |
| 0.5 | −15.4624 |
| 1.0 | −15.6081 |
| 2.0 | −15.9093 |

**判据 U-2 不过**：最优 γ 就是 **0**，而且 γ 越大越差、**单调**。

**四个限定语（缺一条就不许进结论段）**

1. **样本量**：60 个位置，脚本**没有记逐位置值**，所以这个排序的显著性**未建立**。
   正确表述是「**没有可测的增益**」；「用户头有害」**不成立**——那需要另一次记录逐位置
   数值的重跑。**脚本已改**：`u2_user_head.py` 现在存逐位置 log p 并打印配对标准误——
   但这次跑的是改之前的版本，所以本节数字仍只有均值（新版路径尚未执行过，服务已停）。
2. **跨语料**：不涉及——同一个人的同一批记忆，按时间 80/20 切。
3. **单边指标**：只有平均 log p，没有 top-1 / 命中率；口径是"真值前缀的概率质量"，
   不是逐 token 准确率。
4. **先验未兑换**：不涉及——这是直接测量，不是拿代理指标推的 Δ。

**一个可检验、但尚未验证的机制解释**：54,233 token 对 32k 级词表，平均每 token 计数约 1.7；
`log_prior = log(counts / total)` 在这份稀疏计数上基本是噪声，γ>0 等于把分布往
"这个人偶尔用过一次的字"上推。**要证伪它，得先有更多数据，再跑同一口径**——这不能当结论。

**这是冷启动证据，不是长期结论。** 真实使用按 10⁵–10⁶ token/天积累，比这里的 5.4 万高
两到三个数量级；数据到位后 U-2 可按同一判据重跑（判据不改）。

## 六、**V1 快半上的 α 重测：α\* = 0.05，似然 +1.27 nats（2026-11-14）**

**为什么必须重测**：前面所有 α 结论（α\* = 0、剂量–反应）都是在**旧的快半**上测的
（SkyPile 语料、旧 32k 子集、旧树）。V1 换了语料、词表、树，top-1 从 ~0.10 涨到 **0.110**，
**融合的结论不能直接沿用**。

**协议**：真库 218 条记忆、按时间取后 40 条留出；逐位置取前 80 字作上下文，
真值 = 后面的内容；慢半 = Qwen3-4B Q4_K_M（llama-server，logprobs + top_logprobs=20）；
快半 = `serve_snn` `/complete` top-10；并集上算 `log q + α·log p`，比真值前缀的概率质量。

### 58 个计分位置

| α | 真值平均 log p | 相对 α=0 | top-1 |
| ---: | ---: | ---: | ---: |
| 0 | −12.386 | — | **0.2586** |
| **0.05** | **−11.117** | **+1.2684 nats** | 0.2414 |
| 0.1 | −11.196 | +1.1901 | 0.2069 |
| 0.25 | −11.906 | +0.4800 | 0.1897 |
| 0.5 | −13.881 | −1.4955 | 0.1034 |

**26 个位置的小样本给出同样的形状**（α\* = 0.05，+1.4033 nats；top-1 0.2692 → 0.2308）。
两次独立样本方向一致。

### 这条结果推翻了什么、没推翻什么

**推翻**："α\* = 0" 是**旧快半**的结论，**不能**再当作 Semprea 的普遍性质。
在 V1 上，融合在**似然口径**上确实有增益，量级 +1.27 nats（真值的概率质量提高约 3.6 倍）。

**没推翻**：**top-1 是下降的**（0.2586 → 0.2414，−1.7pp），而且 α 越大掉得越多。

⇒ 这是历史九种脱钩形状之外的**第十种**：

> **融合让分布更"对"（真值拿到更多质量），同时让 argmax 更"错"。**

含义很具体：快半加进来的是**"可能性"**，不是**"首选"**。
**对候选补全（用户从几个里挑）有用；对直接取第一位生成有害。**

### 四问

1. **预算截断？** 否——固定 58 个位置，不是训练曲线；
2. **跨语料？** **是**：快半在 FineWeb-2 上训练，评估用的是**真库里的用户记忆**。
   这正是产品的目标分布，但要写明不是同分布；
3. **单边指标？** **是**——**似然赢、top-1 输**。所以上表两列都给，不许只报 log p；
4. **先验未兑换？** 不涉及（直接测量）。

### 由此确定的默认值

- `fusion.alpha = 0.05`（似然最优）；
- **取 argmax 生成时用 α = 0**——这是同一份测量给出的另一条建议，写进 model card。

### 更正（同日，更大样本）：**"似然换 top-1"的权衡不成立**

上表的重测用了 58 个位置，读到 α=0.05 时 top-1 从 0.2586 掉到 0.2414。**那是 15 vs 14 —— 差一个位置**，
我把它读成了结构性权衡，还配了一个实物例子。**过度解读。**

用两个独立样本重测（34 与 52 个位置）：

| α | 52 位置的 mean log p | top-1 |
| ---: | ---: | ---: |
| 0 | −14.955 | **0.1154（6/52）** |
| 0.02 | −13.552 | **0.1154（6/52）** |
| **0.03** | **−13.558（+1.40 nats）** | **0.1154（6/52）** |
| 0.05 | −13.585 | **0.1154（6/52）** |
| 0.07 | −13.630 | 0.0769（4/52） |

**α ≤ 0.05 时 top-1 一个都不差；α ≥ 0.07 才开始掉。** 34 位置的样本给出同样的结论。

⇒ **正确结论**：融合在 α∈[0.02, 0.05] 的平台上**白拿似然**（真值概率质量约 4 倍），
top-1 不变。**默认 α = 0.03。**

⇒ **撤回**："第十种脱钩形状（分布更对、argmax 更错）"——那是单样本噪声。

### 变体扫描（34 位置）

| 变体 | mean log p | top-1 |
| :--- | ---: | ---: |
| α=0 | −15.423 | 0.1176 |
| α=0.03 | −13.243 | 0.1176 |
| **C 熵门 H>1.5** | **−13.197** | 0.1176 |
| B 快半置信门 τ=−4 | −14.334 | 0.1176 |
| D top-1 冻结 | −13.239 | 0.1176 |

- **快半置信门让似然变差**（把弱候选去掉反而丢了信息）；
- **熵门略好 0.05 nats**，但在噪声内，**不值得增加复杂度**；
- **top-1 冻结没有必要**——top-1 本来就没变。

### 方法论教训（写死）

在这个样本量（26–58 个位置）上，**差 1–2 个位置就是 ±2pp**。我连续三次基于这个量级
做结构性解读（"首位见顶"、"CE/top-1 脱钩"、"似然换 top-1"），三次都被更大样本推翻。
**这个量级只够看方向，不够判形状。**

## 七、"能不能比千问 4B 强"：**有空间，但抓不到（2026-11-14）**

用户的目标：Semprea-4.5B 的能力要**超过单独的 Qwen3-4B**。
这需要一件事：**快半在千问错的地方对**。用 52 个缓存位置直接算：

| | 命中 |
| :--- | ---: |
| 慢半 top-1（= 千问单独） | **6 / 52**（0.115） |
| 快半 top-1 | 3 / 52（0.058） |
| 两边都对 | 0 |
| 只有慢半对 | 6 |
| **只有快半对（F-0）** | **3** ← 旧快半是 **0/30** |
| 两边都错 | 43 |
| **oracle 上限** | **9 / 52（0.173）** |

**两条结论**：

1. **互补性从 0 变成了 3**——V1 的快半确实在千问栽跟头的地方对过；
2. **oracle 上限比千问单独高 +5.8pp**——这是"可能更强"的**上界**，不是可达值。

### 手调的仲裁门抓不住它

规则：慢半 top-1 的 logprob < τ **且** 快半的首选与慢半不同 **且** 快半领先第二名 ≥ margin
⇒ 改用快半的首选。

| | 调参集（26） | 留出集（26） |
| :--- | ---: | ---: |
| 基线 | 1 | 2 |
| 最好门 | 3（+2，in-sample） | **3（+1）** |

**留出集上只多 1 个位置——噪声量级。判"抓不到"。**

### 所以现在能说 / 不能说

**能说**：F-0 > 0（旧快半是 0），oracle 上限 +5.8pp。
**不能说**：Semprea 比千问 4B 强——**没有一条可用的仲裁规则证实这一点**。

### 要真正超过千问，缺的是这三样（按代价排）

1. **数据量**：52 个位置不够。目标 **≥500**（每个位置一次 Qwen 前向，约 1 小时）；
   有了它，仲裁门的 +1 才有统计意义；
2. **学出来的仲裁器**，而不是手调阈值——在留出集上调、在第二个留出集上评；
3. **更强的快半**（或让它在"用户记忆"这个分布上再练一点）——现在它的 top-1 只有 0.058，
   F-0 那 3 个命中是它能力的上限附近。

## 八、更正：上面所有融合结论都只在 **8 字上下文**上成立（2026-11-14）

**怎么发现的**：重跑 F-0 时换了位置口径（上下文 20–256 字），快半 top-1 命中从
`3/52` 掉到 **0/1222**。差异太大，不像模型问题，去查了取数。

**根因是一条静默退化的采样循环**（`scripts/fuse_alpha_v1.py`）：

```python
step = max(len(text) // max(args.positions // max(len(holdout), 1), 1), 1)
for start in range(8, len(text) - 2, max(step, 4)):
```

`--positions 60` 配 40 条留出 ⇒ `positions // holdout = 1` ⇒ `step = len(text)`
⇒ `range(8, len-2, len(text))` **只产出 `start=8` 一个位置**。

**三个缓存都核对过**，`context` 长度的唯一值都是 `[8]`：

| 缓存 | 条数 | 上下文长度 |
| :--- | ---: | :--- |
| `alpha_v1.raw.json` | 52 | **8（唯一值）** |
| `alpha_v1_cache.raw.json` | 34 | **8（唯一值）** |
| `alpha_v1_big.raw.json` | 52 | **8（唯一值）** |

### 所以要重新标注适用范围

| 已写下的结论 | 实测口径 | 正确适用范围 |
| :--- | :--- | :--- |
| α=0.03 白拿 +1.40 nats、top-1 不变 | 8 字上下文 | **仅限 8 字** |
| F-0 = 3/52、oracle +5.8pp | 8 字上下文 | **仅限 8 字** |
| 手调仲裁门"抓不到" | 8 字上下文 | 同上 |
| 旧快半的 α\* = 0、剂量–反应 | 8 字上下文 | 同上 |

**这不是说那些测量是错的**——数字是真的，只是它们描述的是"极短上下文"这一个工况。
一句"在 8 字上下文上融合有增益"是对的；一句"融合有增益"是**过度概括**。

### 真实上下文长度上的重测

留出 543 个位置（116 条记忆，上下文 20–256 字，按条目聚类 bootstrap）：

- 快半 top-1 命中：**0 / 543**；
- 融合 α=0.03 的 top-1：**−0.92pp（95% CI [−1.77, −0.19]）**——**含 0 之外，是真降**；
- 训练集里"换到快半会变对"的位置数：**0** ⇒ 学出来的仲裁器**无定义**（不是"无效"）。

### 这条更正改变了什么

**V1 的融合不能声称"超过千问 4B"**，在真实上下文长度上它连持平都做不到。
8 字工况下的那点互补性，只对**候选补全**（用户刚敲了半句、上下文很短）有意义，
对**对话**没有。

⇒ 产品的正确用法：**候选补全可以开融合；对话路径应当 α=0**。
