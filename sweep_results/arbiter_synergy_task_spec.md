# 任务规格：协同性基准（Hebbian ↔ e-prop 原生点）

**交付时间：2026-10-18（本周）。状态：规格，不是结果；先于任何数据。**

## 裁决背景（照抄，避免走样）

> ① 共享接口方案否——语义变形，只可作为标注清晰的 counterfactual arm；
> ② 优先级反转——协同性基准（Hebbian↔e-prop 原生点，单方失败混合才行）是 P0；
> ③ 三方混合与调度维度维持阶段五不动；
> ④ 43 条测试通过的基础设施保留，冲突判定的 per-row cosine 与 retention 联合报告照旧。

**"原生点"指什么**：两条线本来就共享的那一处权重——`784 → 256` 的输入映射
（`ib_hebbian` 存 `${(256, 784)}$`、`eprop` 存 `${(784, 256)}$`，数值同步，见 `shared_synapse.py`）。
不新建接口，不做形状投影，不用"把 R-STDP 的更新压到这个形状上"那种语义变形的做法。

## 一、任务要满足的三条硬性要求

| 要求 | 判据（先写死） | 为什么 |
| :--- | :--- | :--- |
| **H 单独失败** | 纯 Hebbian 臂的测试准确率 **≤ 随机 + 5 pp** | 否则"混合更好"可能只是 H 已经够了 |
| **E 单独失败** | 纯 e-prop 臂 **≤ 随机 + 5 pp** | 同理 |
| **混合成功** | 混合臂 ≥ **max(两臂) + 10 pp**，且 5 个种子的 95% 区间不与该最大值重叠 | 这是"协同"的定义，不是"某一边略好" |

三条**必须同时**成立。任何一条不成立，本基准就退回设计阶段，**不得**改判据去迁就结果。

## 二、任务设计：少标签 + 结构被破坏的 sMNIST

### 数据

| 维度 | 取值 | 理由 |
| :--- | :--- | :--- |
| 数据 | sequential MNIST（784 步），沿用 W2 的任务与预处理 | 复用已验证的管线 |
| **输入变换** | 固定随机置换（种子入配置）**或**固定随机正交旋转（二选一，预注册时定死） | 破坏"像素相关性 ↔ 标签"的局部结构 |
| 标签比例 | **1% / 5% / 10% / 100%** 四档（分层抽样，种子固定） | 唯一能在两边都制造失败的因素 |
| 无标签数据 | 其余 99% / 95% / 90% 仍**参与训练**，但只对 Hebbian 有效（无监督） | 这是 H 的用武之地 |
| 测试 | 全量测试集，不做变换（但同样经过输入变换） | 口径统一 |

### 为什么这样能让两边都失败

* **H 单独**：输入被置换后，Hebbian 的 IB 目标只能找出**输入自身的**相关结构，与标签无关；
  它没有误差信号去把结构对准任务 ⇒ 准确率停在随机附近。
* **E 单独**：e-prop 能用误差塑造输入权重（能适应置换），但它**只用那 1–10% 的标签**；
  样本太少 ⇒ 欠拟合/过拟合，同样停在随机附近。
* **混合**：H 从**全部 100% 数据**里提出结构（无标签也能用），E 用少量标签把这套结构
  **对准任务**——两者在**同一组权重**上竞争，由仲裁器按 `alpha` 混合。

⚠️ **这不是"先 H 后 E"的流水线**：两条更新都作用在同一张 `784 → 256` 上，由仲裁器逐步混合。
若实测发现"固定 `alpha=1`（纯 e-prop）也能行"，那说明标签比例还不够低——**按预注册调低比例重测，
但不得在看到结果后才改判据**。

## 三、臂（每个 label 比例下各跑一遍）

| 臂 | 配置 | 作用 |
| :--- | :--- | :--- |
| **H** | `alpha ≡ 0`（只用 Hebbian 更新） | 单独失败判据 |
| **E** | `alpha ≡ 1`（只用 e-prop 更新） | 单独失败判据 |
| **MIX** | `alpha` 由 ES 仲裁器学 | 协同判据 |
| **MIX-冻结** | `alpha` 固定 0.5 | 对照：混合本身（而非"选边"）是否有用 |
| **联合上界** | 100% 标签、纯 e-prop | 上界：任务的难度参照 |

⚠️ `alpha ≡ 0 / 1` 是**退化臂**，它们的 `retention` 无意义——报告里必须标注，不许拿它们
去算"冲突事件减少比例"。

## 四、指标（每臂每比例每种子）

| 指标 | 定义 |
| :--- | :--- |
| 准确率 | 测试集，5 种子，报中位数 + 四分位区间（**沿用播种修复后的口径**） |
| 协同量 | `acc(MIX) − max(acc(H), acc(E))`，单位 pp |
| 冲突事件比例 | per-row cosine（`ConflictReport.conflict_fraction` 的"步"口径） |
| `retention` | 混合后两规则各自成分还剩多少——**与冲突一起报**，防 `alpha→0` 的平凡解 |
| `alpha` 轨迹 | 逐阶段采样（每 N 步一次），看它是否收敛到边界 |

## 五、必须做的消融（否则"协同"不可信）

1. **零更新对照**：把 Hebbian 的更新置零（`alpha` 仍由 ES 学）——若结果与 MIX 相同，
   说明"协同"是假的。
2. **打乱标签对照**：把少数标签随机重排后再训练——若 MIX 仍高，说明 MIX 没在用标签。
3. **标签比例曲线**：随标签比例上升，`acc(E)` 应当追上 `acc(MIX)`；若始终不追，说明 E 的
   实现有别的问题，先查实现。
4. **置换 vs 不置换**：不置换时三臂应当都能到高位（H 本来就是 W1 的强项），这是"置换确实起了作用"
   的证据。

## 六、成本与排期

* 单臂单种子：sMNIST 784 步、256 宽，量级与 W2 的 30-epoch 运行相当（**先跑 1 个种子探针量时**，
  不外推——台账实测慢 1.61× 的教训）。
* 5 臂 × 4 个标签比例 × 5 种子 = 100 次训练。**先做 1 个比例（1%）× 5 臂 × 2 种子**验证设计，
  确认三条硬性要求的方向后再铺开。
* 若 1% 档三臂都停在随机，先查"标签是否真的只用 1%"，再查 H 的无监督部分是否真的在更新。

## 七、这份规格**不**声称什么

* 不声称 H 与 E 在生物上真的通过同一个突触协同——这是**基准设计**，不是神经科学主张。
* 不涉及第三阶段的 R-STDP 反事实臂（排在基准结果之后）、不涉及三方混合与调度维度（阶段五）。
* 不复用 `alpha→0` 平凡解的任何说法——协同判据是"超过两臂最大值 10 pp"，不是"冲突减少"。
