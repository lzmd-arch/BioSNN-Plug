## 判读

按计划里先写死的规则：

1. **H1（优化失败）不成立**：任务 2 起 `train` 与 `oracle` 都在 0.22–0.34，明显高于随机线；
   读出确实在学。
2. **H2（跨类干扰）部分成立，但不是"旧类压住新类"**：当前类 logit（0.12–0.14）比旧类
   （0.01–0.02）高，当前任务样本上旧类没有占优。`seen` 低主要是**联合 10t 类问题本身更难**
   ——同一份 logits，只在本任务 10 类里 argmax 是 0.23–0.34，在全部已见类里 argmax 就掉到 0.03–0.11。
3. **H3（超参）成立一部分**：`eta=0.1 × 20` 把 task-2 oracle 从 0.228 抬到 0.339（+49%），
   但 `eta=0.1 × 100` 与 `eta=0.5` 全部塌到随机线。工作点在稳定性边缘，**不是"再训久一点就好"**。

## ⚠️ 顺带发现的方法论问题：正式矩阵的口径

诊断里 task-2 出现了两个数：**联合 20 类 0.114** 与**本任务 10 类 0.228**。正式 runner 的
`matrix[t, i]` 填的是"前 i+1 个任务的累计类集"准确率，而 `summarise` 按预注册定义把它当
"任务 i 单独"的准确率。两者不是同一个量——所以**正式运行的 ACC/AF 不是预注册定义的那两个量**。

处置：runner 已改为按 `tasks[i]` 逐个评测（commit `1850a9b`）；正式协议将用
`formal_corrected/` 重跑，原 `formal/` 保留并标注更正。**在修正结果出来之前，不要再引用
0.1984 / 0.0091 作为 ACC/AF。**

## 正式 CIL 结果（同一天，`formal_cil/`）

修正矩阵口径后的正式运行（5 种子）：**ACC 0.0876 / AF 0.290**；末行
`[0, 0, …, 0, 0.28]`，旧任务**全部归零**。这把 H2 钉实了：不是"联合问题更难"，
是**灾难性遗忘**——每个任务单独（oracle）能到 0.28–0.38，一旦不提供任务 id，旧任务被
后续任务完全覆盖；AF 0.29 就是遗忘量。
