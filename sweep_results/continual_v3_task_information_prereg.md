# 预注册：任务信息天花板诊断（2026-11-04）

**状态：判据先落盘，代码随后。** 诊断，不是验收；**不改任何阶段门，不新增路由器。**

## 为什么现在做这个

[`continual_v2_task_inference_strong_prereg.md`](continual_v2_task_inference_strong_prereg.md) 的
决策规则已经写过：两臂都不过 → **封存边界结论**，"不再在这根轴上加码"。封存的原文是：

> 在**本征特征空间**里，CIFAR-100 的十个任务不是**简单局部判别器**可分。

这句话的适用范围是**方法**（简单局部判别器），不是**信息**。在决定"这根轴到底还要不要投"之前，
先量一件事：**十个任务的身份，在冻结 ResNet18 特征里到底还有多少。**

现在的证据链是断的：

- 全协方差 Mahalanobis 路由 **0.528**、ACC 0.5855；
- 但那个"判别式分类器"臂（最终路由 0.100）是**顺序 CIL 训练**的 delta 头，它**自己的旧行也被覆盖**
  （逐步路由 1.000、最终 0.100）——它测的是"顺序训练下路由器会不会忘"，不是"特征里有没有任务信息"。

**从来没测过"联合训练一个足够强的分类器能到多少"。** 本诊断补这一格。

## 设计（跑之前定死）

特征：冻结 ResNet18（ImageNet1K V1、avgpool、512 维、CIFAR resize 224），与协议一致。
数据：CIFAR-100，10×10 按类 id 升序；任务标签 = `class_id // 10`。

五个探针，全部**只判任务 id（10 分类）**，在**测试集**上算准确率：

| 探针 | 做法 | 性质 |
| :--- | :--- | :--- |
| **A** 原型 | 最近任务原型（欧氏） | 局部（复现旧臂的口径） |
| **B** 全协方差 | shrinkage 0.1 的逐任务 Mahalanobis | 局部（旧臂，**用来对齐 0.528**） |
| **C** 线性 | 多项 logistic 回归（L2，Adam，全量 50k） | **非局部、联合训练** |
| **D** kNN | k=5，余弦 | 非局部、非参数 |
| **E** 非线性 | MLP 512→256→10 | 非局部、联合训练 |

**C/D/E 都用了全部任务的数据一起训练**——这在 CIL 里做不到。它们**不是方法，是标尺**：
回答"信息在不在特征里"，不回答"能不能在线做到"。

## 顺带要算清的一件事：ADR-0029 的"0.8"是哪一个 0.8

ADR-0029 的重开条件写的是"任务推断能到 **0.8** 以上"，而同一份 ADR 的上一行把
"任务推断最好 **0.5855 / 0.1285**"记成 ACC/AF 一对——所以**按字面**，0.8 指的是**端到端 ACC**。

用现有的两个点（oracle 路由 1.0 → ACC 0.8195；Mahalanobis 路由 0.528 → ACC 0.5855）线性内插：

```text
ACC ≈ 0.5855 + 0.4957 × (路由 − 0.528)
```

- 若 0.8 指**端到端 ACC** → 需要路由 **≈0.96**；
- 若 0.8 指**路由准确率** → ACC 只到 ≈0.72。

**这两个读法差了整整 0.16 的路由精度。**本诊断只测信息，不裁决这个歧义——
但结论要连同这个数一起报，让重开条件的可达性有据可依。
