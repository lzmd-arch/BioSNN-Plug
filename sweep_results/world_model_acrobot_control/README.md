# 世界模型在 Acrobot 上的控制：基线、前瞻深度、一个失败的护栏（2026-11-12）

**为什么换到 Acrobot**：CartPole 上 3 步前瞻已顶到 500 的回合上限，**再优化也测不出来**。

**协议**：Acrobot-v1，随机动作采集 60 回合训练；测试 10 回合；5→3 种子；指标为**回报**
（每步 −1、到 500 截断，越接近 −100 越好）；预测器为 `ridge_quadratic`。

## 结果一：它能工作，而且比 CartPole 更能分出高下

| 种子 | h=3 | **h=10** | h=20 | copy_last（各 h） |
| ---: | ---: | ---: | ---: | ---: |
| 0 | −339 | **−261** | −500 | −500 |
| 1 | −500 | **−178** | −445 | −500 |
| 2 | −445 | **−95** | −379 | −500 |

- **h=10 是拐点**：中位约 **−178**（理论下限约 −100）；
- **copy_last 在所有深度上都是 −500**（一次都没成功）——增益来自模型本身，不是搜索；
- **h=20 崩溃**：二次特征在数据范围外指数发散，rollout 溢出成 inf（有 `RuntimeWarning` 为证）。

## 结果二：数据量是隐藏变量

同一配置下，训练 40 回合时 h=3 是 −500（全败）；**60 回合时 h=3 就降到 −339**。
**样本量没到之前，"方法不行"是误判。**

## 结果三：状态裁剪是**负结果**

针对 h=20 的溢出，加了标准护栏——把预测状态裁到训练数据的逐维范围内。

| 种子 | h=10 无裁剪 | h=10 有裁剪 |
| ---: | ---: | ---: |
| 0 | −261 | −287 |
| 1 | −178 | −220 |
| 2 | **−95** | **−310** |
| 中位 | **−178** | **−287** |

**裁剪让它更差了。** 原因不是实现问题，是假设错了：**随机策略采的数据覆盖不到目标区域**，
把预测裁到训练范围内，等于**禁止规划器想象"荡上去"**——而"荡上去"正是这个任务的全部。

⇒ 正确结论：**护栏不能按"见过的状态范围"裁，得按"物理可行范围"裁**，或者干脆靠
更好的模型 + 不确定性估计来处理外推。这一条记为负结果，不做默认。

## 四问

1. **预算截断？** 否——固定 10 回合 × 3 种子，回合到 500 截断是任务定义；
2. **跨环境？** 只在 Acrobot，**不外推**回 CartPole 或其他任务；
3. **单边指标？** 是（回报）；因此上表同时给了 h 扫描与 copy_last 控制臂的绝对值；
4. **先验未兑换？** 不涉及。

## 下一步（按证据排序）

1. **on-policy 补数据**：随机策略覆盖不到目标区域，这是目前最明显的短板。
   DAgger 在 h=3 / 40 回合时没救回来（−500），**但那时 h 和样本量都不是最优**，要用 h=10 + 60 回合重做；
2. **不确定性估计**（集成）：用分歧度决定"敢不敢信这么远的预测"，替代已被证否的裁剪；
3. **模型类**：二次拟合器在 Acrobot 上的 NMSE 已明显变差，可试三次项。

**不声称**：不声称解决了 Acrobot（−178 离 −100 还差），不声称这套护栏可以推广。

---

## 结果四：on-policy 补数据（DAgger）——**平均更差**

按"用 h=10 + 60 回合"的正确配置重做（第一轮是在 h=3/40 回合下做的，那个配置本身不对）。
做法：用当前策略跑 `episodes` 个回合，把轨迹并进训练集，重新拟合，再评。两轮。

| 种子 | 基线 | 第 1 轮 | 第 2 轮 |
| ---: | ---: | ---: | ---: |
| 0 | −260.7 | −500.0 | **−176.3** |
| 1 | −178.2 | −471.0 | **−500.0** |
| 2 | −94.9 | −123.9 | **−146.8** |
| **均值** | **−177.9** | — | **−274.4** |

**平均更差 96.4**，而且**极不稳定**：种子 0 有改善（−260 → −176），种子 1 直接崩到 −500
（一次都没成功）。

### 为什么失败（可检验的解释）

朴素的 DAgger 把策略轨迹直接拼进训练集，会带来两个已知问题，这里都没做防护：

1. **分布收窄**：策略访问的状态集中在"当前模型已经擅长"的区域，拼进去之后模型在别处更差；
2. **没有验证门**：每轮都无条件采用新模型，没有"在留出的随机策略数据上更好才采纳"这一关，
   于是一次坏拟合就会一路带下去（种子 1 的第 2 轮）。

### 下一步（若要继续）

- **加验证门**：每轮在留出的随机策略数据上算一步 NMSE，只有变好才采纳新模型；
- **加权**：on-policy 数据降权，而不是等量拼接；
- **混合策略**：采数据时按比例混入随机动作（β-mixed），避免轨迹过度集中。

**不声称**：不声称 DAgger 对世界模型无效——只测了这一种最朴素的实现，且没有验证门。

---

## 结果五：加了验证门与 β-混合之后——**所有候选都被否决**

按上面"下一步"的前两条做了：采数据时掺 30% 随机动作（β-混合），且每一轮都要在**独立的
留出集**（20 回合随机策略，与训练集不相交）上比一步 NMSE，**只有变好才采纳**。

| 种子 | 基线 NMSE | 候选 NMSE | 判定 | 回报 |
| ---: | ---: | ---: | :--- | ---: |
| 0 | **0.0504** | 0.0535 | 否决 | −260.7（不变） |
| 2 | **0.0422** | 0.0477 | 否决 | −94.9（不变） |

**每一轮、每个种子，候选都比现有差。**

⇒ on-policy 数据**没有改善一步预测**；不加门时它还会毁掉控制（上一节 −177.9 → −274.4）。
加门之后系统变成"原地不动"——**这比变坏诚实，但也不是优化**。

### 这条结论的边界（必须写出来）

**验证集本身有偏**：我用的是**随机策略**的留出回合，而基座模型正是用随机策略数据训的。
所以这道门天然偏向"不要动"。更公平的做法有两种，都没做：

1. 验证集用**混合策略**（随机 + 策略）采，或在**控制器实际访问的状态**上评；
2. 干脆用**控制回报**本身当采纳准则（但那是拿测试集调参，需要另设留出种子）。

⇒ 现在能说的是：**在"随机策略状态上的一步预测"这个口径下，on-policy 数据有害**；
不能说的是"DAgger 对世界模型无效"。

## 结果六：10 轮迭代，两种准则，两个结论

### 准则 A：一步 NMSE（混合验证集）

第 1 轮**三个种子全部采纳**（NMSE 0.172–0.178 → 0.146–0.148），**控制当场崩**：

| 种子 | 基线 | 第 1 轮后 | 末轮 |
| ---: | ---: | ---: | ---: |
| 0 | −260.7 | −500.0 | −500.0 |
| 1 | −178.2 | −500.0 | −500.0 |
| 2 | −94.9 | −181.2 | −205.4 |
| **均值** | **−177.9** | — | **−401.8** |

**一步 NMSE 降 15%，回合长度从 125 步掉到 0 步。**

### 准则 B：控制回报（开发种子 7，不参与报告）

| 种子 | 基线 | 末轮 | 采纳轮数 |
| ---: | ---: | ---: | ---: |
| 0 | −260.7 | **−260.7** | 0 / 10 |
| 1 | −178.2 | **−178.2** | 0 / 10 |
| 2 | −94.9 | **−94.9** | 0 / 10 |
| **均值** | **−177.9** | **−177.9** | **0 / 30** |

**30 次候选，全部否决。** 系统原地不动——比准则 A 的崩塌诚实，但**不是优化**。

### 结论

| 准则 | 结果 | 说明 |
| :--- | :--- | :--- |
| 一步 NMSE | **崩塌**（−177.9 → −401.8） | 预测更准 ≠ 决策更好 |
| 控制回报 | **不动**（0/30 采纳） | on-policy 数据在本模型类上没有可采纳的改善 |

**两条合起来**：在这个二次拟合器 + 3 步前瞻的管线里，**on-policy 补数据不是可用的优化手段**——
用错准则会毁掉控制，用对准则则什么也换不来。

**不声称**：不声称 DAgger 本身无效。只测了"同一模型类 + 同一搜索 + 朴素拼接"。
模型类升级（三次项/小网络）与不确定性估计都还没试。
