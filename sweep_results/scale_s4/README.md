# 规模实验 S4：**S1/S3 的"显存上限"是评测批次造成的，不是模型**（2026-11-03）

**预注册：** [`research/scale/prereg-s4.md`](../../research/scale/prereg-s4.md)

## 一句话

**16,384 神经元训练一次 update 只要 130 MiB；S3 里那 7,489.5 MiB 几乎全部来自"一次预测 1000 个测试样本"。**

## 实测

| 配置 | 峰值 |
| :--- | ---: |
| update，n_rec=8192，batch=8 | 81.0 MiB |
| update，n_rec=8192，batch=1 | 43.4 MiB |
| update，n_rec=16384，batch=8 | **129.9 MiB** |
| update，n_rec=16384，batch=1 | 54.8 MiB |
| **predict，n_rec=16384，n=100** | 769.3 MiB |
| **predict，n_rec=16384，n=200** | 1,494.1 MiB |
| **predict，n_rec=16384，n=500** | 3,721.7 MiB |
| **predict，n_rec=16384，n=1000** | **7,309.0 MiB** |

预测的峰值**严格线性于测试样本数**（约 7.3 MiB / 样本）。

## 判据

| # | 判据 | 门槛 | 实测 | |
| :--- | :--- | :--- | :--- | :--- |
| **S4-0** | 账要对得上 | 主项之和 ≥ 实测峰值 90% | update 129.9 + predict 7,309.0 = **7,438.9 vs 7,489.5（99.3%）** | ✅ |
| **S4-1** | batch 8→1 峰值 ≤1/4 | ≤ 0.25 | **0.42**（129.9 → 54.8） | ✗ |
| **S4-2** | 指出主项 | — | **预测批次的缓冲区**（16k × 1000 样本，7,309 MiB） | ✅ |

S4-1 不过：update 的显存**不是**纯 batch 线性（有一份约 40 MiB 的固定开销）。如实记。

## 这推翻了 S1 与 S3 的结论（**必须改口**）

| 结论 | 当时写的 | 实际 |
| :--- | :--- | :--- |
| S1 | 稀疏 8192 吃 767 MiB、"≈0.48 MiB/神经元" | 那 767 MiB 是 **predict 200 样本**；update 只要 **81 MiB** |
| S3 | 16384 吃 7,489.5 MiB、"8 GB 上的终点、硬上限约 17.5k" | 那 7,489.5 MiB 是 **predict 1000 样本**；**update 只要 130 MiB** |

**所以"16k 是 8 GB 上的终点"是错的。** 8 GB 限制的是**一次评测多少样本**，
不是模型能有多大。按 130 MiB 的 update 开销线性外推，训练侧 **8 GB 可以放到几十万神经元**
（这还不算 eval；eval 分批就行）。

**根因**：`predict` 把整批测试样本一次性喂进时间循环，中间状态是
`(n_samples, n_rec)` × 28 步；1000 × 16384 × 28 × 4B ≈ 1.8 GB，乘上自动求导/中间量就是 7.3 GB。

## 下一步（S5 之前先把话说清）

1. **S1/S3 的"资源"表要作废重测**——用固定的小评测批次（例如 100）重跑，
   得到的才是模型本身的规模曲线；
2. 若 update 真能在几十万神经元上跑，那"规模"这条轴**远没有到头**，ADR-0031 的整个
   前提要重估；
3. 评测分批是一个**实现改动**，要单独预注册（它改变的可比性）。

## 不做的事

- 这一轮不改实现；只记录"上限在哪里"这件事的账是错的。
- 不把"训练只要 130 MiB"直接写成"能放到 500k"——那要另测，且 eval 分批、时间、收敛都要看。
