# 预注册：前端验收口径——caption 内容词的线性探针

**定稿时间：2026-10-17，在这一轮的任何数据之前。**

## 为什么需要它

第十轮把验收线重述成恢复率之后，留下一个明确的洞（计划书 ㉟）：

> 恢复率把「规则好不好」和「前端好不好」分开了，**但只给前者定了标准**。

前端现在没有任何验收口径：两套编码都可以说"我们只是要求信息被保住"，而"保住"没有定义。
这一轮补的就是那个定义。

## 定义：图像特征里能不能**线性读出** caption 的内容

对 caption 里出现频率最高的一批**内容词**（去掉停用词），训练一个**线性探针**
（岭回归，闭式解），从**图像特征**预测该词是否出现在这张图的 caption 里，在测试集上算 AUC。

**要它成立的前提**：图像特征若真的承载了 caption 所描述的语义，那么"这张图里有没有狗"
应当是**线性可分**的——这是表示学习的标准探针（linear probing），不训练、无梯度回传。

## 设计

| 维度 | 取值 |
| :--- | :--- |
| 数据 | Flickr8k 官方切分；图像特征用第九轮缓存（ResNet18，512 维） |
| 词表 | train caption 中出现 **≥ 50 条**的内容词，按频次取前 **50** 个 |
| 停用词 | 内置一张小表（a / the / in / on / of / with / and / is / are / …），**不使用外部 NLP 库** |
| 标签 | 该词是否出现在该图第 0 条 caption 里（二值） |
| 探针 | 岭回归闭式解，λ ∈ {0.1, 1, 10}，**按 train 上 5 折 CV 选**（逐词） |
| 指标 | 逐词 AUC，报**中位数与均值**；另报词表规模与每词的正例数 |

## 判据

* **图像侧探针 AUC 中位数 ≥ 0.75** → 前端"承载了 caption 所描述的语义"，可视为合格；
* **AUC ≈ 0.5（随机）** → 图像特征与 caption 语义无关，前端不合格，换联想规则救不了；
* **文本侧同法自查**（从 nomic 整句特征预测同样的词）应当**接近 1.0**——若不高，说明探针
  本身写错了，先修探针再读图像侧的数字。

⚠️ **这是"必要性"检验，不是"充分性"**：AUC 高只说明图像特征里有语义，不保证跨模态可对齐
（两套空间的**对齐**仍是联想层的事，由恢复率衡量）。两个口径各管一半，不要混。

## 边界情况

* 词频阈值与 top-50 是先写死的；若某些词的正例少于 20 条，**剔除并在结果里写明剔了几个**。
* 探针是**线性**的：AUC 低不能排除"非线性可解"，所以这个口径给出的仍然是**下界**。
* 不引入 scikit-learn：AUC 自己按秩算，岭回归自己解。
