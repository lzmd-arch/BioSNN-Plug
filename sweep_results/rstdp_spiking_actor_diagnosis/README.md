# W3 诊断 A1：Actor 信用分配的符号检验（2026-10-26）

**诊断，不是验收。** 预注册（判据先于数据）见
[`../rstdp_spiking_actor_diagnosis_prereg.md`](../rstdp_spiking_actor_diagnosis_prereg.md)。
入口：`python -m research.rstdp_spiking.diagnose --experiment actor`（纯 CPU、确定性）。

**要问的**：正的成功信号 `S = R − V` 到达时，**被选中动作**那一列的权重增量是否真的比
另一列大？如果连这一点都不成立，`Δw = η·S·e` 就会把权重推向错误的方向——后面查 Critic
再多也没有意义。

## 协议（与预注册一致）

固定 20 组（特征、随机流），每组一个 25 步窗口、64 个特征；取该窗口里脉冲计数更大的
动作为"被选中"（与 `step` 的贪心选择同一条判据）；算 `pair_based_stdp` 的增量矩阵
`(64, 2)`，比较**两列的和**。

判据：被选中列的增量和 > 另一列，**20/20 成立**。

## 机制：第二因子与动作选择不同向

`pair_based_stdp` 是 **LTP − LTD**：

```
Δw_ij ∝ A+ · Σ_t  z_j(t) · x̂_i(t⁻)  −  A− · Σ_t  x_i(t) · ẑ_j(t⁻)
```

一个动作的发放越多，它既拿到更多 LTP（post 在前），也拿到更多 LTD（post 在 pre 之前）。
两者相减后，**"发放更多"并不蕴含"净增量更大"**；本组配置下 LTD 经常压过 LTP，甚至把
整列压成负数。而 `step` 选动作的依据恰好是脉冲计数，`apply_success_signal` 又用一个
**全局标量 S** 乘整条痕迹：

```python
weight += learning_rate * S * trace.value
```

于是"选中的动作"和"痕迹里长得快的动作"可以是两个方向。速率版没有这个问题，因为它的
后因子 `x · a` 里的 `a ∈ {0, 1}` 是动作门控且非负的——**脉冲版把"哪个动作"这件事丢掉了**。

## 这说明什么 / 不说明什么

- 说明：**Actor 更新路径的第二因子本身有问题**——不是 Critic 不够准，也不是学习率不对。
  按预注册，**A2（oracle EMA）不跑**：A1 失败时"Actor 路径可疑"已被证实，A2 只会重复
  同一个结论，白花 GPU；
- 不说明 STDP 作为生物模型错了，也不说明"该换回速率版"；它说明**痕迹进权重更新前，
  必须和动作选择的判据同向**；
- 不覆盖多步窗口之间的相互作用：本检验只看单窗口的资格增量，不模拟回合级累积。

## A2：oracle EMA（补跑，2026-10-26）

A1 失败时按预注册跳过；A1′ 通过后按
[修订 1](../rstdp_spiking_actor_diagnosis_prereg_amend1.md) 补跑，两臂都用
sign-consistent 痕迹。300 回合、Actor lr 1e-4、seeds 0/1、CPU。

| 种子 | EMA `best_steps` | TD `best_steps` | EMA − TD | EMA ≥ 30 |
| ---: | ---: | ---: | ---: | :--- |
| 0 | 38.6 | 29.7 | +8.9 | 是 |
| 1 | **10.0** | 39.5 | **−29.5** | 否 |

两条判据（两个种子都 `ema ≥ td + 20`，且 `ema ≥ 30`）**都没过**。
把 Critic 换成更简单的因果信号后 Actor 仍没学起来；seed 1 上 EMA 甚至低于 TD。
**Actor 路径本身仍可疑**，下一嫌疑是信用时域（回合级 S 摊到所有决策）或策略参数化。
详见 [`a2_oracle_ema/README.md`](a2_oracle_ema/README.md)。

## 下一步：已写好符号一致化的预注册

三条候选里，**动作门控 + 拆开 LTP/LTD** 被选为唯一机制（另外两条中，"优势化第二因子"
不改变符号比较，仍会在被选列更小时把它压低；"LTD 只作用于未选动作"单独用仍保留
有符号相加）。规则、A1′ 守卫与阶段 2 判据见
[`../rstdp_spiking_actor_fix_prereg.md`](../rstdp_spiking_actor_fix_prereg.md)：

- LTP / LTD 仍由同一个真实 Δt 窗口决定；
- 只给**被选动作列**累计两条非负痕迹；
- 正 S 只强化 LTP、负 S 只弱化 LTD，不引入新超参数。

**已执行：** A1′ 按修订口径 18/18（两个空窗口剔除）、负 20/20、门控 20/20；
阶段 2 的配对中位数 **+17.95 步**（门槛 +20，不过；8/10 变好），验收 0/10。
A2 也已补跑：oracle EMA 两条判据都不过（详见上节）。结论是"痕迹修好了，但不是唯一
瓶颈"；下一嫌疑从 Critic 转向**信用时域／策略参数化**。见
[`../rstdp_spiking_actor_fix/README.md`](../rstdp_spiking_actor_fix/README.md)。
