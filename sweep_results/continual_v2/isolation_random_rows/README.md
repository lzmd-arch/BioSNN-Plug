## 为什么全作废：随机行拿不到正信号

delta 规则对**非当前类**的目标是 0。随机抽到的 10 行里，大多数行：

- 不是当前任务的类 → 目标为 0；
- 权重还是 0 → logit 为 0 → 误差 `0 − 0 = 0`。

于是这些行**根本不更新**：跑门 `‖ΔW‖/‖W‖` 出现 **0.0**，后期整段权重没动时还会出现
NaN 分母。控制臂的"更新行数相同"只是名义上的——实际更新量远小于 P1，且学不到任务。

## 这否定了什么

- 否定的是**这个控制设计**，不是 P1 的代码；
- 它意味着预注册里的"对齐检验"**无法按原样执行**：不能用它来区分"按类对齐"与
  "更新更少"；
- 因此 P1 的结果只能写到"输出行冻结"，不能写到"按类对齐有效"。

## 可行的替代控制（下一份预注册再定）

要给随机块**同样的正信号**，最小改法是**标签重映射**：把当前任务的类映射到随机
10 个输出行上训练与评估（同一组行、同样的正目标，只有"哪些行"不同）。这测的是
"块的选择"而不是真实类别的遗忘，必须在评估口径里写清楚。另一个方向是**部分冻结**：
随机冻结 90% 的旧行、仍更新当前行与剩余旧行，比较遗忘的斜率。
