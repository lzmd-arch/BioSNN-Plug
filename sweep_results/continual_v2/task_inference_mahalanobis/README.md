## 路由混淆

最终一步各任务的正确路由率：**0.10–0.55**；任务 9 只有 **10%**，任务 7 吸引了大量
其他任务的样本（1000 个里 554 个正确，其余大量来自别的任务）。任务均值/方差在
ResNet 特征上高度重叠，对角 Mahalanobis 只把**最终一步**路由从 30.1% 抬到 35.1%，远不够（逐步对角线均值是 0.524，那是「每个任务在自己那一步」的均值，不是最终路由能力）。

## 结论（按预注册判读表）

阶段门不过、路由 <90%、oracle 过 → **简单局部路由仍分不开任务边界；边界结论成立**：

- **头/特征够用**（oracle 0.82，任务内对角线 0.71–0.87）；
- **瓶颈是任务边界本身**：在本征特征空间里，CIFAR-100 的十个任务不是由均值/方差
  可分的簇；用最近原型或对角 Mahalanobis 推断任务只能到 ~50%；
- 因此在这个配置下，**纯 CIL 需要任务边界信息**；不给任务 id、又只靠简单局部判别器，
  阶段门（ACC≥65、AF<8）达不到。这不是"任务推断不该做"，是"这两条局部路由不够"。

## 边界与下一步

- 本臂是**任务推断 CIL**，不是纯 CIL；纯 CIL 的已发布数字不变；
- 更强的任务判别器（全协方差 Mahalanobis、delta 训练的任务分类器、或允许监督的
  任务头）仍可试，但它们要么仍局部、要么引入更多任务边界监督；各自需要新预注册；
- 不把 oracle 的 AF=0 当作抗遗忘结果（头冻结 + 任务 id 已知，构造性）。
