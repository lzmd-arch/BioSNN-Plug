每个头的跑门用"最后一个 epoch 的相对权重变化"，实测 **0.0470–0.0479**，低于预注册的
**0.05**，所以 `void_seeds = [0..4]`。**按预注册，本轮没有可确认的结论。**

这不是头没学会：oracle 臂的同一批头在任务内做到 **0.82**（见
[`../task_inference_oracle/README.md`](../task_inference_oracle/README.md)）。这是**跑门
操作化错了**——从零初始化的头训到收敛后，最后一个 epoch 的相对变化本来就小
（约等于 η 的有效尺度），它不反映"更新有没有进权重"。预注册里"每头 `‖ΔW‖/‖W‖ ≥0.05`"
的本意是后者，但零初始化让分母不存在；实现选"最后一个 epoch"是一个判断，事后看是错的。
**不在事后改判据**：本轮数字只作探索性读数，确认性结论要新预注册（修正跑门 + 更强路由）。
