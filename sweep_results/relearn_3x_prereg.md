# 预注册：「规则改变后重学快 3×」的标准设计（2026-10-26）

**定稿时间：2026-10-26，在本实验的任何数据之前。** 本文件把计划书第 941 行的验收句
「规则改变后重新学习速度比从头训练快 3 倍以上」**操作化**；它不替代 ACC / AF 两条门，
也不改变阶段三的其它判据。

排期依据：预注册 v2 曾写「不在回放结果出来之前设计重学 3×」；回放结果已出
（[`continual_v2/README.md`](continual_v2/README.md)，方向对、幅度不够），设计现在开始。

## 1. 三个词的定义（先于数据写死）

| 词 | 定义 |
| :--- | :--- |
| **规则改变** | CartPole-v1 的物理规则从 `gravity = 9.8`（R0）改为 `gravity = 14.0`（R1）；其余参数全取 gymnasium 默认（杆长 0.5、质量 1.0 / 0.1、推力 10、最大 500 步）。**动作语义不变**——左推仍是左推 |
| **重学** | 保留 R0 上训练完的**完整 agent 状态**（Actor 权重、Critic 权重、基线），在 R1 上继续训练 |
| **从头训练** | 同架构、同种子、随机初始化，只在 R1 上训练 |
| **速度** | 达到固定性能阈值所需的**训练回合数**（样本效率），不是墙钟——墙钟依赖硬件，不能跨机器引用 |

为什么选重力而不是换动作映射：动作映射一翻，旧策略在 R1 上就是**反相关**的，测到的是
"先忘掉再学"，不是"带着旧知识重学"；重力 +43% 让旧策略**方向仍对、幅度不够**，
这才是"规则改变后重学"想量的迁移。为什么阈值取 **150 步**（不是验收的 200）：
两臂都要有机会在预算内达到，阈值太高会让从头训练臂右删失、比值无定义。

## 2. 协议

### 2.1 阶段 A：学会旧规则（R0）

- 配置：`research/rstdp/cartpole.py` 的**验收默认值**（最终配置：Boltzmann 行为策略、
  按采样概率中心化痕迹、逆温度 log 空间 1→40 退火、Actor 学习率末期 0.01×），
  800 回合，`greedy_eval_every=50`、`greedy_eval_episodes=3`；
- 种子：**65–74**（25–44 调参、45–64 验收，这三个批次都没用过 65–74，不做选择）；
- 掌握门：这一批 10 个种子的**最终贪心评测中位数 ≥ 200**（验收批次中位数 237.8）；
  单种子最终评测 < 150 的，在速度比较里记作作废（报数，不进入比值）。

### 2.2 规则切换与阶段 B

两臂都从**同一个 R1 环境种子**、**同一套阶段 B 调度**出发，唯一差别是初始权重：

| 项 | 重学臂 | 从头臂 |
| :--- | :--- | :--- |
| 初始权重 | 阶段 A 的最终权重（Actor + Critic + 基线） | 与阶段 A 同种子的随机初始化 |
| 环境 | R1（gravity 14.0），独立实例 | R1，同一实例配置 |
| 训练预算 | 800 回合 | 800 回合 |
| 调度 | 完整的 800 回合调度（退火 1→40、lr 末期 0.01×）**从头开始** | 同一套调度 |
| 评估 | 每 10 回合，5 个贪心回合，独立评估环境（也是 R1） | 同左 |
| 痕迹 | 每回合开始清零（与训练一致） | 同左 |

**为什么两臂都重跑完整调度**：重学臂若沿用"退火已到 40"的状态，它与从头臂就不是同一套
再学习程序，差异会混进"探索温度"；两臂都从调度起点开始，唯一变量才是初始权重。

### 2.3 速度的定义

- 记每次贪心评估的均值为 `curve[k]`（第 `10·(k+1)` 回合，5 个贪心回合的平均）；
- **达标时刻** = 第一次 `best_so_far(curve) ≥ 150` 的评估回合数（best-so-far 单调，
  避免"一次侥幸的尖峰"被当成学会）；
- 单种子比值 = `scratch_episodes / warm_episodes`；
- 主统计量 = 10 个种子的比值**中位数**；同时报 bootstrap 95% CI 与逐种子表。

## 3. 有效性门（任一不过，不出 3× 结论）

1. **阶段 A 掌握**：10 种子最终贪心评测中位数 ≥ 200；
2. **从头臂可达**：≥ 8/10 个从头臂在 800 回合内达到 150；否则判"该规则变化下预算不足"，
   报右删失数，**不换阈值、不补预算**；
3. **重学臂不是零样本**：阶段 B 第 0 回合（训练前）的贪心评测 < 150，至少 8/10 个种子；
   达到 150 的种子记为 `zero_shot`，从比值中剔除并单列——若超过 2 个，说明规则变化太弱，
   本次不宣称 3×（零样本迁移本身作为更强的观察单独报）；
4. **阈值非平凡**：从头臂达标回合数的**中位数 ≥ 100**；否则说明阈值太低，两臂都在
   早期就过线，比值没有意义；
5. **不"更快但更差"**：阶段 B 结束时（最后两个评估点的均值），重学臂 ≥ 从头臂 − 10 步。

## 4. 判据（先写死）

**通过**需同时满足：

1. 比值中位数 **≥ 3.0**；
2. 重学臂更快（比值 > 1）的种子 **≥ 8/10**；
3. 上述五条有效性门全过。

报告必须包含：逐种子表（阶段 A 最终步数、重学臂初值、两臂达标回合、比值、两臂末值）、
比值中位数与 bootstrap 95% CI、右删失与 `zero_shot` 的计数。**中位数 ≥3 但 CI 下界 <1 时，
只能写"点估计 3×、不稳健"**，不能写成通过。

## 5. 判读表（先写死）

| 观察 | 结论 |
| :--- | :--- |
| 重学臂更慢（中位比值 < 1） | **负迁移**：保留的旧策略在新规则下是阻力；记录并查"哪些权重/状态造成的" |
| 1 ≤ 中位比值 < 3 | 有正迁移但不到 3×；不宣称达标，报告幅度 |
| 中位比值 ≥ 3 且门全过 | **达标**（本句只覆盖"重学速度"这一条；ACC / AF 另算） |
| 有效性门 2 / 3 / 4 不过 | **不出结论**：分别记"预算不足 / 规则太弱 / 阈值平凡"，各自修订后**新预注册** |

## 6. 不做什么

- 不换阈值、不补预算、不换种子、不因某个种子好看就只报它；
- 不在看到 R1 结果后把重力改成别的值再来一次；若有效性门不过，**本文件的结果原样保留**，
  新规则写新预注册；
- 不把这套设计套到脉冲版 W3 上——脉冲版的 Actor 信用分配 A1 已失败
  （[`rstdp_spiking_actor_diagnosis/README.md`](rstdp_spiking_actor_diagnosis/README.md)），
  基座还不成立；
- 不把这条与 CL 的 AF / ACC 混报；三者是阶段三的三个独立判据。

## 7. 实现清单（代码先于数据，单独提交）

1. `run_trial` 接受环境参数（`gravity`），**训练环境与评估环境都必须用它**；加一个测试
   断言 `env.unwrapped.gravity == 14.0`（两个实例都查）；
2. 保存 / 载入 agent 状态（Actor、Critic、基线）：`return_agent=True` 已有，补一个
   `init_state=` 或 `initial_agent=` 入口；默认路径逐位不变；
3. 阶段 B 的"训练前评估"要走已有的贪心评测路径（`counts` 的贪心分支），单独记一个点；
4. 守卫测试：把刚初始化的状态存下再载入，同种子的贪心评测逐位相同；默认参数下的
   800 回合结果与 `git show HEAD:` 的版本同种子逐位相同（不用 stash）；
5. 跑前工作区必须干净（含未跟踪文件）；权重与逐次曲线先落 `data/`，再搬进
   `sweep_results/`。

## 9. 成本

单次 800 回合训练在本机约 4 秒（`step14_confirm` 的实测）；3 组 × 10 种子 ≈ 30 次运行，
加评估开销在分钟级。**便宜是它能在阶段三反复执行的前提**——3× 是验收门，不是一次性实验。
