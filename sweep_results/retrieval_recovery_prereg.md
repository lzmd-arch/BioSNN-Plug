# 预注册：跨模态检索第十轮——重述标准（恢复率）

**定稿时间：2026-10-17，在这一轮的任何数据之前。**

## 为什么要重述

前九轮把原标准（R@1 ≥ 50%）逼到了墙上：

| 数据集 | 最好结果 | 为什么 50% 不可达/无意义 |
| :--- | :--- | :--- |
| 程序生成配对集 | 局部规则 0.407 | 过 50% 的只有 kNN，而它**不学习**（记忆化） |
| Flickr8k（现有编码） | kNN 0.0015（随机 0.001） | 两套编码之间没有共同信号 |
| Flickr8k（冻结 ResNet+nomic，未对齐） | 线性上界 0.076 | **未联合训练**的两套特征，线性对齐的天花板就在这里 |

**50% 是个绝对值，它同时被三件事决定**：编码器强不强、编码器之间对不对齐、联想层好不好。
三者混在一个数里，无法归因——这正是前九轮反复卡住的原因。

## 新标准：恢复率

```text
恢复率 = (R_局部 − R_零联想) / (R_上界 − R_零联想)
```

* `R_上界`：**线性上界**（岭回归，非局部）——同一份表示下，"线性地看"能拿到的最高分；
* `R_零联想`：不做任何映射、直接比较两路表示（在维度相同时可算；维度不同时为随机基线）；
* `R_局部`：delta 规则（局部、有教师）。

**它量的是：在给定表示与给定天花板下，一个纯局部规则能捞回多少。**
这个量在数据集之间**可比较**，而且把"编码器好不好"从"规则好不好"里剥了出去。

## 设计

| 维度 | 取值 |
| :--- | :--- |
| 数据集 | 合成集（bus@256）与 **Flickr8k 冻结前端**（ResNet18 + 整句 nomic） |
| 读出 | ridge（上界）、delta（局部）、kNN（参考） |
| 目标 | **恢复率 ≥ 50%** 视为"局部规则拿回了线性上界的一半以上" |

⚠️ **这是一个新标准，不是把旧标准偷偷放宽**：旧标准（绝对 R@1）照旧在 README 里标 ❌，
不会因为恢复率高就改口。两者并列汇报。

## 计算量约束（先说好，免得事后超时）

Flickr8k 的训练集 6000 条，delta 的交叉验证网格按原样跑要数小时。所以**本轮固定**：

* `epochs ∈ {1, 3}`、`eta ∈ {0.01, 0.1}`、**3 折**（不是 5 折）；
* 这个缩小是**写在预注册里的**，不是跑不出来才改的。它会让 delta 的数字**偏低**（欠训练），
  因此恢复率是**下界估计**——报的时候要这么说。

## 判据

* 若两个数据集上的恢复率都 ≥ 50% → 说明"局部规则能拿回线性上界的一半以上"是一个
  **跨数据集稳定**的结论，可以作为第二阶段的新验收口径写进计划书；
* 若合成集高、真实数据低 → 结论是"局部规则擅长恢复语义相近的表示，对付不了两套独立训练
  的前端"，这同样是结论，且指向下一步（预对齐前端 + 局部微调）；
* 任何情况下都**不修改旧标准的记录**。
