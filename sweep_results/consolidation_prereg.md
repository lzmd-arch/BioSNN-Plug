# 预注册：巩固对比实验（ADR-0016 排的那半天）

**写于 2026-10-24，任何巩固数据产生之前。** 目的：回答"有巩固 vs 无巩固，延迟召回是否更好"，
并为阶段三那条 `AF < 8%` 提供第一块数据。

## 一、实验在哪做

在**持续学习基准**（`research/continual`，CIFAR-100-B0 10×10 类增量）里做——AF 就在这里量。

⚠️ **不在终端里做**：Axo 的 `run_consolidation` 是产品实现，能跑 ≠ 被验证（ADR-0016 的倒挂）。
本实验用**同一套语义**在基准里重实现一份最小版本，两边的参数与本文件对齐。

## 二、巩固做什么（**只用已存统计，不重放原始样本**）

每学完一个任务、评测之前，跑一轮"睡眠"：

| 操作 | 形式 |
| :--- | :--- |
| 原型再校准 | 逐类均值按该类计数做一次收缩：`μ_c ← (1-λ)·μ_c + λ·μ_all` |
| 共享协方差再估计 | 用累计二阶矩重算白化矩阵（不读原始特征） |
| 次数 | 固定 `S = 3` 轮，`λ = 0.02` |

**为什么不用重放原始样本**：基准的前提是"无回放、无正则"，加了重放就换了题目。
只用已存统计的巩固是**本地操作**，与"纯局部"的主张相容。

## 三、三条臂（每条 5 种子）

| 臂 | 配置 |
| :--- | :--- |
| **C0 无巩固** | 现行做法（`resnet18` 冻结前端 + 类原型 + 对角白化） |
| **C1 巩固** | 每任务后按上表跑 `S=3` 轮 |
| **C2 打乱巩固** | 与 C1 同样算力，但把类统计的顺序打乱（排除"多算了几遍"这个混淆） |

## 四、判据（先写死）

| 项 | 定义 | 门限 |
| :--- | :--- | :--- |
| 主指标 | **AF**（`metrics.summarise` 的遗忘量），C1 vs C0，按种子成对 | 中位数 **下降 ≥ 0.02**（绝对） |
| 次指标 | ACC，C1 vs C0 | 不得下降超过 0.01 |
| 对照 | C2 vs C1 | C1 必须显著优于 C2，否则收益来自"多算"而非"巩固" |

⚠️ **两个方向都成稿**：AF 不降也照报，并据此回答"巩固在这条任务上是否值得做"。

## 五、成本与执行

* 特征**已缓存**（`resnet18_train.npz` / `resnet18_test.npz`，重建于 2026-10-24）；
* 巩固本身只操作 d×d 与 d 的统计量（d=512），**不是 GPU 负载**——所谓"半天 GPU"主要是首次
  特征提取；缓存之后，三条臂 × 5 种子在 CPU 上是分钟级；
* 报告必须写明：**AF 的可比性**——每步候选类数在增长（10 → 100），逐行看矩阵才是正确读法
  （这条在 `sweep_results/continual_cifar100/README.md` 已经写过）。

## 六、这份预注册**不**声称什么

* 不声称巩固等价于生物睡眠；
* 不声称结论能推广到别的数据集或别的骨干（只做 ResNet18 冻结前端这一条）；
* 不声称"AF 下降"就等于"阶段三验收通过"——它只是那条验收标准的第一块数据。
