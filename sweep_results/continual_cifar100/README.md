## 三条被这组对照钉住的结论

1. **delta 读出在类增量下是错的工具**：每个新任务在它自己的阶段都停在随机（0.03–0.06），
   而旧任务几乎不掉——ACC 0.208 是"只学会了第一个任务"的产物。
2. **特征漂移是遗忘的主因**：同一套类原型，特征漂移时任务 1 从 0.392 崩到 **0.005**（AF 0.151）；
   冻结后只降到 0.133（AF 0.082）。
3. **天花板由特征决定，不由读出决定**：W1 特征封顶 ~0.2；换冻结 ResNet18 到 0.577，
   换 ResNet50（+ 共享协方差白化）到 **0.702**，任务 10 时各任务均匀落在 0.584–0.619。
   这条与文献里 frozen-feature CIL（FeCAM 一族）的区间相符，但**骨干不同不能直接对标**。

## 必须同时说的边界

* **AF 可比性问题**：`AF` 按预注册定义算，但每一步评测的候选类数在增长（10 → 100），
  所以"任务 1 从 0.803 掉到 0.47"**主要是分母变了**，不是真遗忘。矩阵逐行看才是正确读法。
* **ResNet18 那条改变了基准含义**：它测的是"任意强表示 + 局部原型记忆"，不是本仓的 Hebbian 表示。
  两条路线必须分开报。
* **与 PS-SNN 的 76.42% 不可直接比较**：架构、协议、评测口径都不同源。

## ⚠️ 更正（2026-10-24）：`resnet.json` 的 0.577 量错了特征层

用**旧的 1000 维缓存**（分类 `fc` 层的 logits，不是池化特征）可以逐位复现
`resnet.json` 的 **ACC 0.577 / AF 0.1195**。缓存校验当时只查 tag 与条数、不查维度，
所以这份 1000 维文件被当成 ResNet18 的特征用了。

**正确的 ResNet18 池化特征（512 维）给出 ACC 0.658 / AF 0.127**（`sweep_results/consolidation/`
的 C0 臂，2026-10-24 重建缓存后实测）。

处置：
* 本表 `resnet.json → 0.577` 那一格**保留但标注"量在 logits 上"**，不删——它是历史记录；
* 引用 ResNet18 冷冻前端时应改用 **0.658**，并注明特征层是 avgpool；
* `frontends.py` 的缓存校验已补上**维度**检查（tag / n / dim 三者一起），避免同类事故。
* ResNet50 的 2048 维缓存**不受影响**（维度本来就对），但它当前缺训练缓存，不能复跑。
