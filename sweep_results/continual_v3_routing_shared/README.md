原始数值：[`vit_shared/summary.json`](vit_shared/summary.json)。
ViT-B/16 特征、单种子（0）、与 `mahalanobis-full` 逐行同构，只有协方差的估计量换了。

**没有变好，方向是负的：路由 0.6783 → 0.6544（−2.4pp），ACC 0.7504 → 0.7290（−2.1pp）。**
而且这个幅度**和已知的种子噪声同量级**，所以能说的只有"没改善"，不能反过来说"共享协方差有害"。

## 我押错了，而且错得有意思

预注册里我押"共享协方差把参数/样本比降到 1/10，应当明显缓解估计误差"。**没发生。**

**最可能的解释：每个任务自己的协方差本身就是任务签名的一部分。**
768 维下用 5,000 条样本估 29 万个参数确实"估计不准"——但**那份不准里带着任务特有的结构**：
哪个方向散得开、哪个方向挤在一起，本身就是区分任务的线索。把它换成十个人共用的一个，
等于**把这条线索抹平**，只留下均值。

### 事后检验（用已存的两个混淆矩阵，**非预注册**）

| 臂 | 对角均值 | 行熵（越小越尖；上界 ln10=2.303） | 误判的去向 |
| :--- | ---: | ---: | :--- |
| `mahalanobis-full` | 0.6783 | **1.204** | **高度集中**：10 行里有 7 行的最强误判都指向**任务 1**（0.086–0.195） |
| `mahalanobis-shared` | 0.6544 | **1.344** | **分散**：最强误判落在任务 2/0/7/9/5/6/5/6/2/5，没有共同吸引子 |

**这和数据一致**：逐任务协方差把任务 1 变成了一个"吸引子"——它的协方差形状足够特别，
能把别的任务的样本吸过去；共享之后，**这个吸引子消失了**，误判变成弥散的一层。

换句话说：**逐任务协方差不是"估不准的噪声参数"，它带着任务身份。**
合起来等于把这份身份抹平，只剩均值。

⚠️ 这是**事后**的读数，不是预注册的一部分；它解释方向，不改变判定。

## 最重要的一条：这个幅度不足以判"有害"

两臂都是**单种子**，而我们今天在别处量到过**种子噪声 sd 2.2pp**（A3 补种：
0.873 / 0.906 / 0.917）。这里的差是 −2.1pp（ACC）与 −2.4pp（路由）——**落在噪声量级里**。

所以准确的结论是：

- **能说**：共享协方差**没有带来改善**，J-1/J-2 都不过；
- **不能说**：共享协方差比逐任务协方差差。要下这个结论，两臂各补 3 个种子。

## 边界

- 单种子；只跑了共享协方差一臂，没扫 shrinkage；
- 共享协方差在任务 t 上只用**已见任务**（增量口径），最终混淆矩阵那一步用的是全部十个任务的合并散布；
- 换骨干改变基准含义这条仍然成立，不与 ResNet18 的 0.5855 并报。

## 这条否掉了什么

**"路由器不行是因为协方差估不准"这个假设被否掉了。** 那意味着剩下 9.5pp 的差距
（0.6783 → 0.773）**不能靠"把同一个判别器估得更准"来补**——
要么找到任务特有的、比协方差更省参数的签名，要么承认这套特征里的路由就到这儿。
