原始数值在 [`boundary.json`](boundary.json)。单种子（0）、冻结 ResNet18、CIFAR-100 测试集、

**九个真边界全部检到，误差 ≤6 条；但另外多报了 5 次，F1 0.7826 差 1.7pp 没过 0.80。**
按预注册的"按到达顺序分配"，多余的段把路由彻底打乱（0.0834）。

## 三条读数

### 1. 信号很强：九个真边界全部命中，误差 ≤6 条

1000 条一段，检出位置是 994 / 1994 / 3004 / 3994 / 5004 / 5994 / 7004 / 8004 / 9014——
**误差全在 14 条以内，多数只有 4–6 条**。窗口是 64 条，也就是说检测器几乎在窗口一走完就报警了。

### 2. 5 次误报的根因：**按位置定阈值，控制不住整条流的误报数**

我最初把这条写成"训练集 5,000 条/任务估的零分布与测试段 1,000 条抽样波动不同"。
**补测之后发现那个说法是错的**，真因是别的：

在**无边界流**上（单个任务的 1,000 条测试样本独立重抽样成 10,000 条，没有任何真边界）：

| 试验 | 检出数 |
| :--- | ---: |
| 5 次独立试验 | **4 / 6 / 9 / 4 / 10** |
| 统计量最大值 | 0.145 / 0.162 / 0.167 / 0.161 / 0.160 |

**一个边界都没有的流，检测器照样报 4–10 次。** 所以问题不在"零分布估偏了"，
而在**多个比较**：预注册的阈值是**单个位置**的 99.5 分位（0.1373），
而一条流上要扫 **987 个位置**——按位置控制 0.5%，整条流就有 5 次左右的误报，与实测完全对上。
**这个设计从一开始就没有控制"每条流报几次"。**

### 2b. 而且真边界与零分布的最大值**重叠**

| 来源 | 统计量区间 |
| :--- | :--- |
| 9 个真边界 | **0.158 – 0.190** |
| 5 次误报 | 0.139 – 0.146 |
| 无边界流的最大值 | **0.145 – 0.167** |

真边界最低 **0.158**，无边界流的最大值可以到 **0.167**——**两个区间重叠**。
也就是说，**光把标定改对（按整条流的最大统计量定阈值）也不够**，阈值必须抬到 0.17 以上，
而那会漏掉 0.158 / 0.162 / 0.162 那三个真边界。**统计量本身要换。**

### 3. 按预注册的分配规则，多出的段把路由打穿了

预注册写死"第 k 段判给第 k 个任务，不用标签"。14 段 ⇒ 第 1 个误报（834）之后的所有段
整体错位，路由掉到 **0.0834**——这个数**不是检测器质量的度量**，是这条分配规则在段数对不上时的必然结果。
预注册自己也写了："若检出段数 ≠ 10，本方法退化，按实际段数报并如实标注。"

## 所以这一臂算什么

**算"差一点"的负结果，不算没希望：**

- **能说**：在按任务分块的评测流上，**任务边界的信号是清晰可检的**（9/9 命中、误差 ≤6 条、
  随机流对照只响 1 次）。这比逐样本任务推断的 0.6512 前景好得多；
- **不能说**：本设计达到了判据。D-0 / D-1 / D-2 三条都不过，按规矩照登；
- **不能说**："调一下阈值就行了"——阈值、窗口、峰半径都是预注册写死的，**不调**。

## 下一步要动的话（另写预注册，不在本文件里做）

1. **标定改成"每条流的最大统计量"**：现在的阈值是单位置 99.5 分位，控制不住整条流的误报数。
   正确的估计量是在**无边界流**上取 `max_i stat_i` 的分位数——这是换估计量，不是调阈值；
2. **换统计量**：真边界最低 0.158、无边界流最大值可到 0.167，**区间重叠**，光改标定不够。
   候选：两侧窗口各自的**稳定性**、能量距离/MMD 而不是均值差、更长的窗口；
3. **分配不必按顺序**：可以用检出段与已学任务原型做匹配——但那又把任务识别带回来了。

## 边界

- 单种子；只测 ResNet18、只测 CIFAR-100 10×10；
- **它利用评测流的分块结构**：一条流里必须有成段的同类样本，单张图给不出任务 id；
- 分配用**到达顺序**，不解决"新任务来时不知道是第几个"；
- 因此**不能**拿它声称纯 CIL 的 0.8 达到了。
