## 读法

1. **判据复现了，但优势没复现**：M3n 里 `R5`=0.7475（3/5 会话）、`Rmean`/`Rcentroid`=0.80/0.83（4/5）；
   新语料里 **`R5` 自己就有 0.840、5/5 会话全过**。按预注册的护栏：
   **「换分数有用」的证据必须是会话间的一致性，而这里 `R5` 的一致性最高**。
   所以正确的结论是：**M3n 的排序是语料特定的，不能写成「平均/质心比最大值好」**。
2. **两批语料的难度差了一档**：同一批分数在新语料上整体抬了 8–10 个点。也就是说，
   这条线上真正变化的量是**语料本身的难度**，不是分数族。
3. **每批语料都恰好有一段是坏的**：M3n 是会话 0（0.56–0.63），M3o 是会话 4（0.65–0.67）。
   `Rmean`/`Rcentroid` 在两批里都是"4/5 过线、剩下一段 <0.70"，`R5`/`Rall`/`Rz` 在新语料上
   反而更稳。**5 段对话不足以区分这些分数**——差异落在噪声里。
4. **触发器在新语料上是可用的**：命中中位 4/5、误触发中位 1、触发器 AUC 0.80–0.85。
   这是目前最好的一次组合结果，但**它建立在"新语料更容易"上**，不能拿来与 M3m 的
   1/5 折直接比好坏。

## 与 M3l / M3m / M3n 的关系

| 轮次 | 问的问题 | 答案 |
| :--- | :--- | :--- |
| M3l | M3k 的参数能不能搬到真实分数上 | 不能（每段只触发 1 次） |
| M3m | 在真实尺度上重标定参数能不能救 | 命中救回来了（3–5/5），但跨会话不稳、池化 AUC 0.7472 |
| M3n | 换分数能不能救 | 同一批上 `Rmean`/`Rcentroid` 过线（0.80/0.83） |
| M3o | 换一批语料还成立吗 | **判据成立，但优势不成立**——`R5` 自己就有 0.84 |

## 边界

- 两批语料都由同一个 `qwen3-4b` 管线生成、目标轮都由脚本安排；「复现」只在这条管线内成立；
- 每批 5 段 × 5 个正例，单段 AUC 的不确定度很大；两批的池化 AUC **不可直接比大小**（难度不同）；
- 触发器参数是 M3m 在**第一批**上选的，在第二批上没重标定——这既是边界，也是"参数搬得动"的一点证据；
- 不把本轮的 `true` 写成「分数问题解决了」：真正没解决的是**语料难度与会话间稳定性**。

## 下一步（需新预注册）

1. **加样本**：每批至少 20 段对话（≥100 个正例），才能让 5 个分数之间的差异离开噪声；
2. **定义难度**：把"目标轮与上下文高度相似"的会话单独标注，报**分层** AUC，而不是混在一起；
3. 在这两条之前，**不再比较分数、不再调触发器**。
