## 读法

1. **按损失选步比按输入幅度更糟**：v1（按输入活动）掉 **15.35pp**，v2（按每步损失）掉 **23.58pp**。
   ESPP §III-C 的两半（输入阈值 + 损失阈值）在这个实现里**都没有兑现"只跑 18–27% 的时间步仍保精度"**
   ——按损失那一半反而更伤。
2. **选中比例没达标**：请求 0.3，实测 **0.413**（v1 是 0.339）。原因是取 top-k 后用
   `per_step >= threshold` 建掩码，**并列的值会被一起算进去**；30 epoch 的训练早期逐时刻损失
   高度接近，并列很多。这一条本身就不满足判据，与精度结论独立。
3. **10/10 种子一致变差**，不是个别种子崩掉的假象；也没有 NaN/Inf（判据 3 过）。
4. 与 v1 并列看：**"少算更新"这件事本身就贵**——丢掉 60–70% 的学习信号，比按什么标准挑更重要。
   要想省算力又不掉这么多，得让**保留的那些步携带几乎全部的学习信号**，而不是简单 mask。

## 边界

- 只测 30 epoch、sMNIST、一个比例（0.3）；按预注册**没有**调 fraction 去凑判据；
- 「按损失选步」仍需前向算出每步损失，**不省前向成本**，只省权重更新；能效主张不由此得出；
- v1 的 0.7748/0.6213 是同一设备（CUDA）同协议的历史数字，本轮 baseline 0.7751 与之相差 0.03pp；
- 选中比例的并列膨胀会影响"省了多少"的解读：实测 0.413 是**掩码非零比例**，不是请求的 0.3。

## 下一步（需新预注册）

1. **改掩码口径**：按名次而不是按阈值建掩码（严格取 top-k，去掉并列膨胀），让请求比例与实测一致；
2. **改"值得算"的定义**：与其按单步损失，不如按**该步对最终损失的贡献**（例如只保留
   损失最大的一段连续窗口），或按 ESPP 原文的两阈值同时生效；
3. 在这两条之前，不把任何"省更新"的结果写成能效收益。
