# 预注册：触发判据 v3——换成表面线索分数，兼做语料混杂检验（2026-11-02）

**状态：判据先落盘，代码未写，数据未跑。**

## 为什么做这一版

v2（[`phase5_trigger_v2/README.md`](phase5_trigger_v2/README.md)）把失败定位到了打分函数：
`R5` 的命中率均值 0.385，500 次随机划分里只有 9% 能到 0.50；而误触发控制是成立的（均值 0.100 = α）。
v2 结尾写明下一步是**换分数族**：不再用相似度，改用「这一轮有没有具体信息」。

## 但这一版有一个必须先说清的混杂

M3p 的目标轮是**脚本安排**的。写这份预注册之前我看了两段对话（附录），目标轮几乎都是
「人名 + 日期 + 地址 + 引号」的事实句，非目标轮是「记得带个 X」式的泛化闲聊。
也就是说，**这批语料的目标轮在表面形式上就与背景不同**。

所以这一版不是「新方法有没有效」的检验，而是**语料混杂检验**：
如果一条零参数的表面规则就能过判据，那这 20 段测的是「这轮有没有具体事实」，
不是「该不该搜索」。这个结论本身有用——它决定下一批语料该怎么造。

## 分数（零参数，写死，跑之前不改）

`S(t)` = 下列四类正则命中的**总次数**（不是是否命中）：

1. ASCII 数字串：`\d+`
2. 中文数字 + 单位：`[一二三四五六七八九十百千万零两]+(?:月|日|号|点|分|楼|单元|层|岁|元|块|公里|小时|分钟)`
3. 星期：`周[一二三四五六日天]`、`星期[一二三四五六日天]`
4. 引号内容：`“[^”]*”`、`"[^"]*"`、`「[^」]*」`

不调权重、不筛模式、不按结果增删任何一类。

## 判据（与 v2 完全同值，只换分数）

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| T-1 | 真实流误触发率 | ≤ 0.10 |
| T-2 | 真实流命中率 | ≥ 0.50 |
| T-3 | 逐段 F1 ≥ 基线的段数 | ≥ 12/20 |

同一批数据（M3p 的 20 段，sha256 `ad1d278b…`）、同一划分（偶数校准）、
同一 α（0.10）、同一分位数取法（升序第 ⌈(n+1)(1−α)⌉ 小）、同一 T-3 基线
（校准段池化 F1 最大的固定阈值 + 两向交叉拟合）——全部照
[`phase5_trigger_v2_prereg_amend1.md`](phase5_trigger_v2_prereg_amend1.md)，一个字不改。

## 解释矩阵（跑之前写死，四种结果四种结论）

| 结果 | 结论 |
| :--- | :--- |
| T-1 过 **且** T-2 过 | 这 20 段**可被表面线索解开**。语料不测「该不该搜索」，只测「这轮有没有具体事实」。触发器**仍然 not ready**——它不能外推到一个目标轮不是事实句的开放域。表面规则可以留作产品启发式，但要在真实对话上另测。 |
| T-1 过、T-2 不过 | 连表面线索都不够密；语料的目标轮比抽查看到的更杂。 |
| T-1 不过、T-2 过 | 分数有信号但工作点控不住——多半是离散分数大量并列让 conformal 的 q 退化（q = 0 时「有任意一次命中就触发」）。这是判据层面的新问题，单独记。 |
| 两条都不过 | 表面规则与语料都对不上；先回头查语料，不再换分数。 |

**无论哪种结果，都不写成「触发器已解决」。** 这一条是硬约束。

## 诊断（不参与判据，但这一版真正的主菜）

1. **四格分解**：目标轮 / 背景轮 × 有命中 / 无命中，四个计数；
2. **分数直方图**：目标轮与背景轮各自的 `S(t)` 分布（0、1、2、3+）；
3. **逐段 AUC**：`S(t)` 在每段上的排序能力，与 v2 的 `R5` 逐段对照。

第 1 条直接回答「target 与 background 是不是只靠表面形式就分得开」。
如果四格里有两格是 0，那么这条语料的难度就是**结构性**的，与触发器算法无关。

## 不做的事

- 不改 α、不改划分、不改 T-1…T-3 的门槛；
- 不改分数——不因为某类模式命中少就删掉它，也不加第五类；
- 不在测试段上调任何东西；
- 不把这版的通过写进根 README 的阶段五状态当作「阶段五转正」。

## 边界

- 仍是 `qwen3-4b` 生成、脚本安排目标轮、20 段；
- 表面规则的命中是**字符串层面**的，它不知道这些数字指什么；
- 本版不测脉冲触发，测的是规则门换了分数之后的工作点行为。
