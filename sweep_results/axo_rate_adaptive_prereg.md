# 预注册：50k 速率路径的自适应候选

**定稿时间：2026-10-18。**
50k 固定候选：M=15,000 才 100% 一致（69 ms）；M=10,000 是 98%。全量扫描优化后仍
约 153 ms（`einsum`；瓶颈是 transpose 的 `bincount` 70 ms）。这一轮只回答：
**自适应候选能不能在保持 ≥99% 的同时，把平均候选数/延迟压到固定 M=15,000 以下？**

## 方法

- 语料：`benchmarks/substrate` 真实文本放大到 50,000 条；全局 `idf-2.0`、`k=64`。
- 探针：50 个等距样本，50% 丢位。
- 全量参考：`rate` 一步（`A·(Aᵀ(A·p))`），用同一套稀疏码。
- 候选：
  1. 一阶稀疏点积给全部行打分（`A·p`），取前 M0；
  2. 在候选子集上算二阶 `A·(Aᵀ(A·p))`；
  3. 计算 top-1 与 top-2 的相对边际 `(s1-s2)/max(s1, eps)`；
  4. 若边际低于阈值 τ，扩到 M1=15,000 重算。
- 固定对照：M=10,000 / 15,000。

## 判据

- **正确性**：与全量 top-1 逐探针一致率 **≥ 0.99**。
- **延迟**：单次查询 **≤ 100 ms**。
- **自适应价值**：在满足前两条的前提下，平均候选数 **低于 15,000**（即比固定
  M=15,000 更省）。
- 同时报：展开率（多少探针触发扩展）、平均 M、p95 延迟。

## 停止规则

- 只跑 τ ∈ {0.05, 0.10, 0.20} 与 M0=10,000，M1=15,000；不在看到结果后追加。
- 真实库不参与；只读语料。

## 边界

1. 50k 是真实文本的**同簇拼接放大**，不是真实 5 万条记忆。
2. 50 个探针；1 条差异 = 2 pp，边界有采样噪声。
3. 只做推理加速；不涉及脉冲、学习或 Axo 代码改动。
4. 墙钟时间是本机 numpy 的结果，换机器会变。

## 怎么被核验

`scripts/axo_rate_adaptive_candidate.py` 输出每个 τ 的一致率、平均 M、展开率、
平均/p95 延迟；全量参考在同一批探针上算。
