# 预注册：触发判据 v2——把「打分好不好」和「触发对不对」分开（2026-11-02）

**状态：判据先落盘，代码未写。**

## 前几轮到底错在哪

M3k–M3p 反复出现同一种翻车：换一个打分函数（Rmean、Rcentroid、R5…）在一批语料上变好，
换一批就没了。**根因是判据把两件事混在一起**：打分函数的排序质量（AUC）与触发器的
工作点行为（在哪个阈值上发、发几次）。AUC 高不等于触发对，反之亦然。

v2 的做法是把它们拆成两段，各自有独立判据。

## 新判据：一致性预测（conformal）控制误触发

**触发规则改成一个与数据分布无关的构造**，而不是一个调出来的阈值：

1. 在**校准集**上算触发器分数，取分位数 `q = 1 − α`（α 预先写死为 **0.10**）；
2. 运行时规则：分数 > q 就触发；
3. 一致性预测的性质：在校准集与测试集**可交换**的假设下，误触发率 ≤ α。

这条规则的要点是：**它不随语料调阈值**。如果换了语料误触发率就崩，说明可交换性假设不成立
（真实流与合成流分布不同）——这正好是我们想测的东西。

## 判据（跑之前写死）

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| T-1 | 真实流上的**误触发率** | ≤ 0.10（与 α 同值） |
| T-2 | 真实流上的**命中率** | ≥ 0.50 |
| T-3 | **逐段一致性**：20 段对话里，触发器 F1 ≥ 基线 F1 的段数 | ≥ 12/20 |
| T-4 | 合成流上同样跑一遍 | 作为对照，不设门槛；若合成流也崩，说明构造本身有问题 |

**T-1 与 T-2 必须同时成立**：只控制误触发可以靠"永不触发"做到（平凡解），
只追命中可以靠"每轮都触发"做到——两条一起看才排除了这两种平凡解。

## 数据与划分

- **真实流**：已有的 20 段真实对话（M3p 那批），按段划分：10 段校准、10 段测试；
- **合成流**：同样构造，10 + 10；
- 划分在跑之前固定，**同一次划分同时用于两种流**，不允许按结果挑划分。

## 怎么搭（跑之前定死）

- 打分函数**不换**：沿用 M3p 的 `R5`（最朴素的那个），因为这一版测的是**判据**不是打分；
- 校准集只用来定分位数，**不用来选打分函数、不用来调任何超参**；
- 判决一旦跨过阈值即触发一次；同一段对话内的重复触发按"每段最多一次"计。

## 预期

`R5` 在真实流上 AUC 0.7475，算不上强。若分布可交换，conformal 的误触发控制应当成立
（T-1 过），但命中率可能不够（T-2 不过）——**那说明问题是打分函数太弱，不是判据错**。
这正是 v2 要区分出来的结论：**判据可以把"分数不够"与"构造失效"分开**。

若 T-1 也不过，说明真实流与校准集不可交换（分布漂移），那要写进结论：
**在这批数据上，任何基于"校准一次、到处使用"的触发规则都不可靠。**

## 不做的事

- 不换打分函数（那是另一份预注册）；
- 不在测试段上调阈值；
- 不因为 T-2 不过就放宽 α。
