# 预注册：跨模态检索第八轮——真实数据（Flickr8k）

**定稿时间：2026-10-17，在这一轮的任何数据之前。**

## 它要回答什么

前七轮都在**程序生成配对集**上。那一轮得出的结论是：在合成集上「R@1 ≥ 50%」可以被
**记忆化**平凡满足，所以它不构成「局部学习成立」的证据。真实数据是唯一能让 50% 这条线
重新有意义的地方——文献里 Flickr8k 的 R@1 是一个可比的口径。

这一轮**不承诺达标**。先写清期望，免得事后找补：

> 本项目的图像侧是 **24×24 灰度、三帧、DVS 帧差编码**——它丢掉颜色、纹理与细节；
> 文本侧是**逐 token 的冻结句子 embedding**。用这样的前端去比文献里那些用 CLIP/ViT
> 整图编码的工作，50% **很可能够不着**。这一轮的价值是**一个真实数据上的数字**，
> 以及它与同一套上界探针的相对位置。

## 数据与协议（先写死）

| 维度 | 取值 | 理由 |
| :--- | :--- | :--- |
| 数据源 | jbrownlee/Datasets 的 GitHub Release：`Flickr8k_Dataset.zip` + `Flickr8k_text.zip` | 稳定直链、无需登录；**非官方分发**，仅作便利，许可见下载器的 `license_note` |
| 切分 | **官方** `Flickr_8k.trainImages.txt` / `Flickr_8k.testImages.txt` | 与文献口径一致，不自己重切 |
| 每图 caption | **第 0 条**（固定） | 一对多会让 R@K 口径变复杂，本轮不做 |
| 规模 | train ≈ 6,000 / test = 1,000 | 随机基线 = 1/1000 = **0.1%** |
| 预处理 | 灰度、缩放到 24×24、归一到 [0,1]；三帧（空 → 图 → 图） | 与合成集同一编码器，保证可比 |

## 读出方式（与前面几轮同口径）

## 判据与解释边界

* **报数，不设"必须过 50%"**。若过 50%，那是真实数据上的强结果，值得单独讨论；
  若不过，那是**前端的限制**，与合成集上"局部规则停在 0.41"是两件不同的事。
* 与合成集**不可直接比较**：候选数从 144 变 1000，随机基线从 3.4% 变 0.1%。
* 真实数据上**只看 R@1 与 R@5 的绝对值**，不看"比随机高几倍"——大候选池下这个比值会
  天然变大，容易制造虚假的成就感。

## 边界情况

* **下载体积大**（1.1 GB），且 `data/` 不入库；复现靠 `scripts/download_data.py flickr8k`。
* **许可**：图片版权归各 Flickr 用户；本仓库不镜像、不再分发。
* 若 test 集里缺图（官方 token 文件与图片包不完全对齐是已知情况），**跳过并计数**，
  在结果里写出实际参与评估的条数——不得静默改变分母。
