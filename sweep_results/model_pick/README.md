# 选型：千问 0.5B vs 淘宝 MNN-Pocket 0.3B

**日期**：2026-11-15
**用途**：融合模型的**底座**（人格与记忆核，不是云端生成器）。

## 结论：**选千问 Qwen2.5-0.5B-Instruct**

## 实测

| | qwen2.5-0.5b | mnn-pocket-0.3b |
| :--- | ---: | ---: |
| 参数 | 494 M | 303 M |
| 层数 / 隐藏 | 24 / 896 | 28 / 896 |
| 词表 | 151,936 | **65,536** |
| **bpc（原始网页文本）** | **3.81** | **10.42** |
| **bpc（我方对话数据）** | **4.37** | **7.69** |
| 训练吞吐（batch2×256） | 162 tok/s | 144 tok/s |
| 峰值显存 | 4.71 GiB | 4.57 GiB |
| 许可 | Apache-2.0 | Apache-2.0 |

**bpc = bits/char，按字符归一，跨分词器可比。** 越低越好。

两个模型都能正常生成中文（都做了生成冒烟，各自输出了通顺的自我介绍），
所以 7.69 不是"装坏了"，是**在中文上确实弱一档**：同样的字，它要多花 76% 的信息量。

## 判读

1. **质量差距大且方向一致**：两种分布（原始网页、我方对话）上都是千问明显更好；
2. **速度与显存几乎相同** ⇒ 没有"用小模型省资源"的收益；
3. **MNN-Pocket 的优势在部署不在训练**：65k 词表 + INT4 173 MB，
   对"手机端离线"是硬优势；对"我们要训一个人格核"不是；
4. 词表小会让**条件偏置更便宜**（`U·p` 成本 ∝ V），但这一项抵不过 1.76× 的质量差。

## 用途分配

| 场景 | 用谁 |
| :--- | :--- |
| **训练人格/记忆核** | **Qwen2.5-0.5B-Instruct** |
| 产品离线兜底（如果体积是硬约束） | MNN-Pocket-0.3B（173 MB INT4） |

## 边界

- bpc 只测了中文、只测了两批文本，**不是榜单**；
- 我们真正的判据是"训完之后身份与记忆的保真度"（I-1…I-7），本轮只做了**选底座**；
- 千问 0.5B 的词表大 2.3 倍，**训练与推理都更贵**，这一点在选择时是已知代价。
