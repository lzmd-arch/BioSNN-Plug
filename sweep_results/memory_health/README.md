## 二、真正的缺陷：**一半记忆的权重是 0**

| 分位 | 权重 |
| :--- | ---: |
| min | 0.000 |
| p25 | **0.000** |
| median | **0.000** |
| p75 | 0.428 |
| max | 1.000 |

**中位数和 25 分位都是 0** ⇒ 至少一半记忆已衰减到零权重。任何按权重加权的召回
对这些记忆等于完全不可见——**这比"46 条从未召回"严重得多**，而它此前没被量过。

**精确化（同日补测）**：`weight` 列是 REAL，值不是恰好 0，而是 **≈4e-21**
（如 `3.95e-21`）。所以 `weight>0` 会数出 336/336——**这是一个会骗人的计数**，
真正的分布要看数值量级：

| 分位 | 权重 |
| :--- | ---: |
| min | 3.95e-21 |
| p25 | ~1e-21 |
| **median** | **~1e-21** |
| p75 | 0.059 |
| max | 1.000 |

⇒ **指数衰减没有下限**，长时间未强化的记忆会一路下溢到数值上等同为零。
一条记忆即使被重新召回，乘上一个小于 1 的因子也**回不来**。

## 三、下一步

1. **看衰减规则**：什么条件下权重归零？是否认回了之后不回升？
   （`access_count==0` 的 46 条必然是 0；但中位数为 0 说明**被召回过的也有大量归零**。）
2. 若"归零"不可逆 ⇒ 是设计缺陷；若可回升 ⇒ 是参数问题。
3. 修之前先量：**按权重加权的召回 vs 不按权重的召回**，后者是不是更好。

## 四、权重到底该不该用：**它携带信号，坏的是无下限衰减**

同一套自检索（313 条记忆，各自用自己的词当查询），比两种排序：

| 排序 | top-1 | top-5 |
| :--- | ---: | ---: |
| **不加权**（纯词法重合） | 0.316 | **1.000** |
| **按权重加权** | **0.550** | 0.824 |

**结论是双向的，不能只看一半：**

- **权重携带信号**：top-1 从 0.316 抬到 0.550（+23pp），说明"常被用到/更重要的记忆"
  确实更该排前面；
- **但 top-5 从 1.000 掉到 0.824**：那半数 ≈1e-21 的记忆被彻底挤出候选。

⇒ **缺陷不是"用了权重"，是"衰减没有下限"。** 加权本身是对的，是它把下溢的记忆压死了。

### 修法与判据（写死）

1. 给权重设**下限**（如 0.05），或改成带夹取的加性衰减——目标是保住 top-1 的 0.550，
   同时把 top-5 拉回 1.000 附近；
2. **验收**：自检索 top-1 ≥ 0.550 **且** top-5 ≥ 0.98；
3. 过了之后再用端到端 20 题（当前基线 0→25%）复核真实收益。
