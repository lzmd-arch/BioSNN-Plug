# R3：缩读出——两臂都输，而且**都还没到平台**（2026-11-08）

**预注册**：[`research/sel/prereg-lm-r3-readout-width.md`](../../research/sel/prereg-lm-r3-readout-width.md)（含 2026-11-08 的规则③ v2 补注）
**原始数据**：[`r3_a.json`](r3_a.json)（臂 (a)）、`r3_b.json`（臂 (b)）
**上一轮**：[`../lm_eprop_r2/README.md`](../lm_eprop_r2/README.md)

## 一句话

**把读出从 1,024 宽缩到 256 宽，在合成 A 语料上净损失 3.7–4.0pp**（Δ 从 −6.16pp 掉到 −9.90 / −10.14pp，两臂 0/2 折赢）。
**但四折的 top-1 在 120 epoch 结束时都还在涨**（最后 5 个评测区间累计 +1.3 ～ +2.0pp），
所以这两个数是**下界**，不是"缩读出的天花板"。**N 不是变量**：读出宽度相同时，N=256 与 N=1,024 只差 0.24pp。

## 结果

基线 R2-A：N=1,024、读出 1,024、2 折、18,750 updates，**Δ = −6.16pp**（top-1 0.2203 vs bigram 0.2819），**没有曲线**。

| 臂 | N | 读出宽度 | 读出参数 | 折 0 | 折 1 | 均值 top-1 | 均值 Δ | 赢 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 基线 R2-A | 1,024 | 1,024 | 820k | — | — | 0.2203 | **−6.16pp** | — |
| (a) 整体缩 | **256** | 256 | **205k** | 0.1834 | 0.1824 | 0.1829 | **−9.90pp** | 0/2 |
| (b) 只缩读出 | 1,024 | **256** | **205k** | 0.1795 | 0.1816 | 0.1805 | **−10.14pp** | 0/2 |

**改善 = Δ(臂) − Δ(基线)**：臂 (a) **−3.74pp**、臂 (b) **−3.98pp**。

> 预注册里写的"651k / 2.6M"是按语料 2,544 个唯一字符算的；实际 runner 的 `MAX_VOCAB=800`，
> 词表是 **801**（`<unk>` + 800），所以真实读出参数是 **205k / 820k**。倍数（4×）不变，绝对数改了。

这是本轮最大的证据缺口，见下。

## 三件必须一起说的事

### 1. 绑定 Δ 的是**读出宽度**，不是神经元数

两臂读出参数相同（205k）、N 差 4 倍（256 vs 1,024），**终值只差 0.24pp**（0.1829 vs 0.1805），
小于折间差（同一臂两折差 0.1–0.4pp）。而读出宽度从 256 到 1,024（参数 4×）对应 **+3.7pp**。

**旁证**：同种子的 1,875 步探针里，N=1,024 的 top-1 是 **0.1457**、N=256 是 **0.1140**（+3.2pp）——
**N 的差别是学习速度，不是终值**。到 18,750 步两者收敛到同一水平。

### 2. 四个折的 top-1 都没到平台 ⇒ 两个 Δ 都是**下界**

按规则③ **v2**（CE 平台 k=5/ε=1% **∧** 最后 5 个区间的 top-1 累计变化 <0.5pp）：

| 折 | CE 平台 | 最后 5 个区间的 top-1 | v2 判定 |
| :--- | :--- | ---: | :--- |
| (a) 折 0 | 16,875 步 | +1.99pp | CE 平、top-1 未平 → **下界** |
| (a) 折 1 | 16,875 步 | +1.31pp | 同上 → **下界** |
| (b) 折 0 | 16,875 步 | +1.72pp | 同上 → **下界** |
| (b) 折 1 | **无**（11,250 步的 1.06% 打断连击） | +1.27pp | 同上 → **下界** |

**证据缺口已补（`r3_base.json`，2026-11-08 补测）**：给基线加上 `--eval-every 1875` 重跑，
**R2-A 的数字被逐位复现**（均值 0.2203、两折 0.2205 / 0.2200），并拿到了它的曲线：

| 评测点 | 1,875 | 3,750 | 7,500 | 11,250 | 15,000 | 18,750 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 基线 top-1（折 0） | 0.1457 | 0.1691 | 0.1960 | 0.2090 | 0.2137 | **0.2205** |
| 基线 test CE（折 0） | 4.722 | 4.522 | 4.371 | 4.279 | 4.223 | **4.184** |

**基线到 120 epoch 时也还在涨**（最后 5 个区间 +2.0pp），CE 也还在降（每区间约 0.5–0.9%）。

⇒ 结论更清楚了：**三方（基线、臂 a、臂 b）在 120 epoch 时都还远未收敛**，所以
"缩读出净损失 3.7–4.0pp"是一个**同预算下的比较**，不是天花板比较；
"多训能不能追上"对**两边**都未测。

### 3. 规则③ 这一轮被改了两处，且我先写错了一次

- **v1 的连击会被单个 1.06% 打断**：臂 (b) 折 1 因此判不出 CE 平台；
- **ε=1% 直接套到 top-1 上不可达**：21,602 个 token 上 top-1≈0.18 的二项标准误是 0.26pp（相对 1.5%），
  四折**没有一折**能过。所以 v2 把 top-1 换成绝对量（最后 5 个区间累计 <0.5pp ≈ 2×SE）。
- **我自己的错**：v2 初稿说臂 (a) "第 9,375 步就到平台、之后 top-1 多爬 +2.0pp"——把**第一个** <1% 区间
  当成了**连续 5 个**。按 k=5 重算，平台在 16,875 步，之后 top-1 只动了 +0.03 ～ +0.24pp。
  已在 `AGENTS.md` 里带"事实更正"保留，不静默改。

## 执行偏差与 provenance

1. **臂 (a) 的 JSON 把 `n_rec` 记成了 1,024**（`run_r1.py` 当时记的是模块常量，不是 `args.n_rec`）。已修。
   **用复现闭合**：同配置跑 1,875 步，`--n-rec 256` 精确落回臂 (a) 折 0 的第一个评测点
   **0.1140 / 5.0615**；`--n-rec 1024` 落在 **0.1457 / 4.7217**。所以"**(a) 确实跑的是 N=256**"，
   且那段 CUDA 代码同种子**逐位可复现**。
2. **臂 (b) 的 JSON** 由修好后的代码写出：`readout_width: 256`、`readout_dims: 256` 都在。
3. 两个 runner 现在都把**完整生效配置**写进 JSON（seed / eval_every / tau / tau_read / input_std / 语料名 / 数据路径），
   杜绝这类考古。

## 边界

- 两折、单种子；合成语料不是真实对话；字符级 next-token，**不代表能闲聊**；
- 臂 (b) 的"固定随机子集"是一个选择，换子集结论可能略变——**没有做多子集复本**；
- 未被读出的 768 个神经元拿不到学习信号（设计使然）；
- **基线没有曲线**（见上）。
