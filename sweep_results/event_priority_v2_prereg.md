# 预注册：事件优先级 v2——按**损失**而非输入幅度选时间步（2026-10-29）

**状态：判据先落盘，实现与运行随后。** 结果不得回改判据。

## 为什么重做

v1（`event_priority`）按**输入活动**取 top-k 时间步，选择 33.9% 的时间步时精度从
0.7748 掉到 0.6213（−15.35pp），`event_priority_ready=false`。差距清单记的原因是：
**按输入幅度选步会丢学习信号**——幅度大的输入步未必是误差大的步。

ESPP §III-C 的机制是**输入活动阈值 + 损失阈值**共同决定哪些时间步更新，实测只跑
18%–27% 的时间步。v2 只重做「损失」这一半：**按每步损失的大小选步**，看它是否比按
输入幅度选步更保精度。

## 做法（唯一改动）

- 复用 W2 的 sMNIST 协议与 `EPropLearner`；新增 `selective_mode="loss"`：
  - 每步损失 `ℓ_t = CE(softmax(ŷ_t), y)`（`loss_timesteps="all"` 的逐时刻交叉熵）；
  - 取 top-k 步（k = fraction · T），只让这些步的学习信号进入权重更新；
  - 其余与 baseline 完全一致（同种子、同超参、同 epoch）。
- 对照：直接引用 v1 的 baseline 0.7748 与 selective 0.6213（同协议 30 epoch、10 种子）。

## 判据（全部满足才 `event_priority_v2_ready=true`）

1. **精度保持**：10 种子均值相对 baseline 的下降 **≤ 2.0 个百分点**；
2. **确实选择性**：实测选中时间步比例 ≤ **0.35**（proof the switch is on）；
3. 两种子以上不能出现训练发散（loss 非有限）。

不过 → 记负结果，保留 v1/v2 两个数字，不再调 fraction 去凑判据。

## 边界

- 只测 30 epoch、sMNIST；不外推到 SHD/硬件；
- 「按损失选步」仍需要前向算出每步损失，**不省前向成本**，只省权重更新；
  能效主张不由此得出。
