# 规模实验 S5：**精度在 16k–32k 之间饱和，64k 反而略降**（2026-11-03）

**预注册：** [`research/scale/prereg-s5.md`](../../research/scale/prereg-s5.md)
**前置更正：** [S4](../scale_s4/README.md)（8 GB「上限」是评测批次造成的）

## 判决

| # | 判据 | 门槛 | 实测 | |
| :--- | :--- | :--- | :--- | :--- |
| **S5-0** | 分块之后放得下 | < 8,000 MiB | 最大 **3,204.5 MiB**（65,536） | ✅ |
| **S5-1** | 规模还在付钱 | `acc(65536) − acc(16384) > 2pp` | **−0.3pp** | ✗ |
| **S5-2** | 时间没爆 | ≤ 1.5 × 1,071 s | 1,349 s（1.26×） | ✅ |

## 四个点

| n_rec | 准确率 | 相对上一点 | 峰值（分块评测） | 耗时 |
| ---: | ---: | ---: | ---: | ---: |
| 8,192 | 0.774 | — | — | 1,101 s |
| 12,288 | 0.788 | +1.4pp | — | 1,083 s |
| 16,384 | 0.797 | +0.9pp | 7,489.5 MiB（**未分块**） | 1,071 s |
| **32,768** | **0.805** | **+0.8pp** | 1,682.6 MiB（分块 100） | 1,092 s |
| **65,536** | **0.794** | **−1.1pp** | 3,204.5 MiB（分块 100） | 1,349 s |

**64k 比 32k 低 1.1pp、比 16k 低 0.3pp。** 单种子下这是噪声量级，但它显然**没有**证明"更大更准"。

## 结论：这条轴到底给什么

| 阶段 | 每翻一倍的增益 |
| :--- | ---: |
| 1k → 8k | **≈ +5pp / 倍** |
| 8k → 32k | **+1.4 / +0.9 / +0.8pp** |
| 32k → 64k | **−1.1pp（无增益）** |

**容量在这条管线上约在 16k–32k 饱和，再往上不付钱。**

这与 S3 的"显存到顶"是**两件不同的事**：S4 已经证明显存不是瓶颈（训练 update 在 64k 上也只有 ~500 MiB 量级，
实测整轮峰值 3.2 GB 里大头仍是分块评测）。**我们是放得下但放大了没用。**

## 对主线的意义

ADR-0031 把主线定成"规模实验：精度随规模怎么长、代价多少"。**这个问题现在有答案了**：

- 精度：**1k → 8k 陡升（+14.6pp），8k → 32k 缓慢（+3pp），64k 无增益**；
- 代价：时间几乎恒定（`s/update` 不随 `n_rec` 长），显存由**评测批次**决定，不由模型决定。

所以"继续加宽"没有意义了，而**加宽之外的东西还没测**：fan-in、训练轮数、任务本身。
其中最可疑的是**训练预算**——所有结论都建立在 2 epoch 上，而 2 epoch 下 32k 才 0.805，
W2 的 256 神经元在 250 epoch 能到 0.8889。**饱和也许不是容量的饱和，是训练量的饱和。**

## 边界

- 2 epoch、单种子；16,384 的峰值是未分块评测的数（7,489.5 MiB），与 32k/64k 的分块数**不可直接比**；
- 64k 的 −1.1pp 在单种子噪声内，**不能**读成"越大越差"；
- 与 W2 的 250-epoch 数字不可比。
