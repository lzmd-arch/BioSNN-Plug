# 阶段四端到端 v6：单 bank vs 路由双 bank 的共存（2026-10-27）

预注册：[`stage4_e2e_v6_prereg.md`](../stage4_e2e_v6_prereg.md)。两臂都跑，判据一致；
不做事后挑臂。5 个种子。

## 结论

**两臂都没有 ready；这是一个清楚的权衡，不是单点失败。**

| 判据 | 门槛 | single（28 维） | dual（56 维，路由） |
| :--- | :--- | :--- | :--- |
| WM R² | ≥0.90 | **0.5274** ✗ | **0.9937** ✓ |
| WM 选择性 MSE | ≤0.10 | **0.3387** ✗ | **0.0046** ✓ |
| DPAR top-1 | ≥0.80 | **0.9620** ✓ | **0.9620** ✓ |
| 状态控制 | ≤0.35 | 0.2372 ✓ | 0.2352 ✓ |
| OOD AUROC | ≥0.75 | **0.8736** ✓ | **0.7823** ✓ |
| OOD 弃权 | ≥0.80 | **0.7932** ✗ | **0.6220** ✗ |
| **ready** | — | **false** | **false** |

读法：

- **路由双 bank 确实修好了 WM 干扰**：R² 0.527 → **0.9937**，MSE 0.339 → **0.0046**；
- **但它把 OOD 置信度打坏了**：AUROC 0.874 → **0.782**，弃权 0.793 → **0.622**；
- 单 bank 的 WM 失败（与 v4 同向），且弃权 0.793 也差 0.007；双 bank 的 OOD 弃权差得
  更多。**没有一臂同时满足共存和弃权。**

## 为什么双 bank 的 OOD 变差

- 双 bank 的 56 维状态里，bank D 的 28 维只装键值/查询；OOD 只改变 bank W 的 A/B；
- 成员分歧与一步惊喜是在**完整 56 维读出**上算的，bank D 的稳定分量稀释了 OOD 信号；
- AUROC 从 0.874 掉到 0.782，说明排序本身变弱，不只是阈值位置。

这不是“再调阈值”能修的：如果要把 OOD 拉回来，需要在 **bank W 单独**算置信度，
或让世界模型按 bank 分块；那是下一版的设计，不在本轮预注册里。

## 边界

1. 路由是**状态编码结构**，不是学习规则；bank 维度固定 28+28。
2. DPAR 仍是每幕独立建库；OOD 仍是 A/B ×3 尺度偏移。
3. 单 bank 的 WM 失败与 v4 同向；v5 的顺序组合 6/6 仍然成立，但它不能解决共存。
4. 没有一臂 ready；不把“双 bank WM 好”追认成共存成功。
5. 5 个种子、500 幕；单次运行 156.7 s；没有调 K/σ/阈值/覆盖率。

## 下一步

- **v7 候选**：双 bank + **bank W 单独的 OOD 置信度**（世界模型也按 bank 分块），
  预注册时把 OOD 信号限定在 bank W；这是对 v6 失败点的直接修复；
- 或者接受“共存需要顺序组合”（v5），把共享状态的干扰写成阶段四边界；
- 不要继续在 56 维联合置信度上调阈值；AUROC 0.782 已说明排序问题。
