# D1：rate-features 资格（2026-10-26）

**诊断，不是验收。** 预注册见
[`../../rstdp_spiking_credit_diagnosis_prereg.md`](../../rstdp_spiking_credit_diagnosis_prereg.md)。
D1 把 Spiking Actor 的 STDP 资格换成速率版形状的 `E ← λE + x_t·1[a_t]`
（连续群体特征 × 被选动作），δ_t 仍来自同一群体 Critic，其余全不动。

## 协议

units 64、bias 0.4、gain 8、warmup 10；seeds 0–9；CPU。对照是**已记录的
sign-consistent 10 种子**（同配置）与 pair-stdp（同配置）。

## 判读（按预注册表）

**不是资格形状/时域的问题。** 把第二因子换回速率版已验证的 `x·a`，Actor 没有学得更好，
反而低于 sign-consistent。所以"STDP 资格 vs 速率资格"不是这个瓶颈；下一嫌疑是
**脉冲编码 / 策略参数化**。

一个必须写下的机制解释：D1 的特征虽然是连续的，但**动作仍由 LIF 的脉冲计数决定**。
`x·a` 是对"线性 logits"的梯度形状，而本 Actor 的策略不是 `softmax(Wx)`，所以这条
资格与真正的策略梯度**不同向**——这本身就是"策略参数化"问题的一部分，而不是单纯的
"编码噪声"。

## 这说明什么 / 不说明什么

- 说明：换资格的代数形状救不了这个 Actor；问题更靠近"动作怎么从脉冲里选出来"；
- 不说明脉冲网络不可学：本诊断没有换策略参数化，也没有动 Critic；
- 不说明 rate 规则在速率版无效：速率版的策略是线性 logits，资格与策略同向，所以它能学；
- 不覆盖 D1b（脉冲计数版）——按预注册，D1b 只在"资格是瓶颈"时才跑，现在不跑。
