# 事件驱动 e-prop：推理规模冒烟（2026-10-29）

**性质：推理冒烟，不是训练规模实验，也不报精度。** 目的只是验证固定 fan-in 的稀疏表示
不再构造 N×N，前向能到 500k。输入 n_in=28、T=28、batch=1、fan_in=32、n_out=10；
脚本 `scripts/measure_event_driven_scale.py`，产物 `summary.json`。

## 结果

| n_rec | 稀疏权重数 | 前向耗时 |
| ---: | ---: | ---: |
| 10,000 | 320,000 | **0.09 s** |
| 100,000 | 3,200,000 | **0.83 s** |
| 500,000 | 16,000,000 | **5.02 s** |

- 500k 这一档没有再分配 500k×500k 的矩阵；w_rec 是 (N,32) 的稀疏值 + 索引；
- 这是 CPU 前向；没有 CUDA 参与；
- 时间随 N 近线性（0.09→0.83→5.02），与固定 fan-in 的预期一致。

## 能说什么 / 不能说什么

- **能说**：固定 fan-in 的事件驱动前向在 500k 规模上可跑，且不依赖 N² 存储；
- **不能说**：500k 的 e-prop **训练**可跑——本轮没有跑 update/gradient，也没有量训练峰值；
- 不能把 5 s 前向当成“500k 训练实验”；阶段四规模目标仍未验收；
- 小网络仍走无放回索引；N>4096 走向量化、允许重复的 fan-in（N≫k 时重复可忽略），
  这是规模路径的刻意取舍。

## 下一步

1. 在 10k/100k 上跑 1 epoch 的 event-driven update，量训练时间/峰值；
2. 若 100k 可行，再谈 500k 的训练（稀疏梯度、batch 与 trace 预算）；
3. 训练结果必须与 dense 同预算对照，不能只报前向。
