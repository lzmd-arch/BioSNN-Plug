# 预注册：任务路由用共享协方差（LDA 式）（2026-11-04）

**状态：判据先落盘。** 接 [`continual_v3_cil_vit/README.md`](continual_v3_cil_vit/README.md)
（ViT 特征上可部署路由 **0.6783**，端到端 **0.7504**，要 0.80 需路由 ≈ **0.773**）。

## 为什么是"共享协方差"，不是又一个路由家族

现在的 `mahalanobis-full` 给**每个任务**单独估一个 768×768 协方差，样本只有 5,000 条。
768 维下协方差有 29 万个自由参数、每任务 5,000 个样本——**估计误差大得离谱**，
即使 shrinkage 0.1 也只是止血。

这不是"再换一个判别器"（那条轴已经封存过），而是**给同一个判别器换一个更省参数的估计量**：
把**已见任务**的类内散布合起来估一个**共享**协方差（判别分析的标准做法），
样本量随任务数线性增长，到第 10 个任务时是 50,000 条。

## 设计（跑之前定死）

- **一臂**：`mahalanobis-shared`。在第 t 个任务上，协方差 = 任务 1..t 的**类内散布之和 / 总自由度**，
  shrinkage 0.1 拉向对角，+1e-6·I；所有任务**共用**这一个逆协方差做距离；
- 原型（任务均值）与其它一切**完全不变**，与 `mahalanobis-full` 逐行同构；
- 特征：ViT-B/16（已缓存）；单种子（0）；hidden 1 epoch、读出 20 epoch、batch 128。
- 对照**不重跑**：同配置的 `mahalanobis-full` 是 **0.6783 路由 / 0.7504 ACC**。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **J-0** | 前置：管线没变 | oracle 臂仍是 **0.9192 ± 0.005**（不重跑则核对记录值） |
| **J-1** | 路由显著提升 | `routing − 0.6783 ≥ 3pp` |
| **J-2** | 端到端有大进步 | `ACC ≥ 0.78` |
| **J-3** | 合理性：不越过联合上限 | `routing ≤ 0.7912`（本地路由器不可能超过联合训练的判别上限） |

**J-3 是自检**：如果共享协方差算出路由 > 0.7912，说明有泄漏（比如协方差用了测试样本），
本轮作废重查，不能当成好消息。

## 预期

**押 J-1 过、J-2 不确定。** 具体：路由 **0.70–0.74**，ACC **0.76–0.78**。
理由：共享协方差把参数/样本比降到 1/10 量级，应当明显缓解估计误差；
但它不改变"任务是按类 id 字母序切的、本身无可分结构"这件事，所以不会一步到 0.773。

若路由到 0.773 以上 → **端到端应跨过 0.80**，那 ADR-0029 的一条重开条件就满足了
（另一条"真实长序列"仍然缺）。

## 不做的事

- 不扫 shrinkage，不换成别的判别器家族；
- 不因为 J-1 不过就换特征或换种子；
- **不与 ResNet18 的 0.5855 并列成"同一基准的提升"**——换骨干改变基准含义，这条仍然成立。

## 成本

协方差 768²、10 个任务各求一次逆；delta 读出与上一轮相同。**约 15 分钟。**
