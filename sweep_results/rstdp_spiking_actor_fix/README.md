## 协议

`critic = pop`、`critic_rate = 0.1`、`pop_post = gradient`、均匀读出、行归一化、
units 64、bias 0.4、gain 8、warmup 10；seeds 0–9；**CPU**（记录臂在 CPU 上，见修订 1 §4）。

- **pair-stdp**：历史的有符号规则（默认）；
- **sign-consistent**：只给被选动作列累计 `E⁺/E⁻`，按 S 的符号选相位。

## 控制校验：pair-stdp 逐位复现记录臂

`seeds_pair_stdp` 的 10 个 `best_steps` 与 `sweep_results/rstdp_spiking/pop_gradient_10seeds/`
的逐种子值**完全相同**（65.6 / 81.3 / 55.1 / 61.3 / 147.5 / 55.0 / 23.3 / 47.9 / 36.0 / 24.5）。
所以两臂之间的差异不是配置、CPU/GPU 或代码漂移。

- 配对差值中位数 **+17.95 步**（bootstrap 95% CI **−0.30 … +29.20**）；
- 方向：**8/10** 个种子变好（门槛是 ≥7/10，过）；
- **机制标记（预注册）：配对中位数 ≥ +20 且 ≥7/10** → **不过**（17.95 < 20，且 CI 跨 0）；
- **验收门：中位数 ≥200** → **不过**（75.65；0/10 个种子过 200）。

⚠️ 本 harness 的 summary 只记步数，不记"成功偏移比"；预注册里那条偏移腿在这里
**没有测量**。步数 0/10 已足够判验收门不过，不能据此说偏移也没过或过了。

## 判读（按预注册的判读表）

A1′ 过、阶段 2 的机制标记不过 → **符号一致性不是（唯一的）瓶颈**。痕迹的方向已修好
（A1′ 18/18），但策略仍停在 50–100 步，离验收的 200 差得远。按判读表，下一嫌疑是
**Critic／信用时域**，另写预注册；不回头调 lr、宽度或回合数。

需要如实写下的两点：

- 改善的方向为正（8/10），但幅度**不稳**（CI 跨 0），不能写成"有效"；
- 它**不否定** A1 的诊断：被选列在旧规则下确实常为负；修掉这个符号问题后，
  剩下的瓶颈就不在痕迹的组合上了。

## 边界

- 只在默认群体 Critic 配置、10 个种子、CPU 上测过；不覆盖线性 TD 或其它工作点；
- CUDA 上的随机流与记录臂不同（修订 1 §4），CUDA 结果不参与比较；
- 没有调任何超参数；没有因为 seed 8 的 +64.5 就只报它；
- 本结果只覆盖"重学速度"之外的执行层训练，不涉及 CL 的 ACC / AF。
