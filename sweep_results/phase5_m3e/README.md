# 阶段五 M3e：真实嵌入上的情景写入与睡眠巩固（2026-10-29）

**预注册：** [`../phase5_m3e_prereg.md`](../phase5_m3e_prereg.md)（判据先于数据）。
**性质：协议层验证。** 本机 Ollama `nomic-embed-text` → M3c z-score+top-k 群体编码 →
SQLite 情景库（`biosnn_mcp.episodic`）→ M3d 睡眠噪声回放巩固。只连 `127.0.0.1`。

## 一次实现 bug（已修，记录在案）

第一次运行得到 **0 合并**：`_replay` 把每维噪声标准差取成 `σ·‖x‖`，768 维时总噪声范数
≈ **1.39×** 信号，回放余弦被压到 0.58，任何阈值都合并不了。修正为每维 `σ·‖x‖/√dim`
（总扰动 ≈ σ），并加了守卫测试（σ=0.05、128 维时回放余弦应 > 0.995）。**修的是实现，
不是判据或协议参数**；第一次的产物已删除，正式数字只来自修复后的这次。

## 读法

- **真实嵌入上，睡眠噪声巩固会误合并**：阈值取同义/异义分布的中点仍然太宽——
  8 条不同事实里有 6 对被并掉。这说明「中点阈值」这个标定规则本身不够，
  不是噪声太小（漂移 0.9988，几乎没扰动）；
- 同义合并 6/8 也说明：余弦阈值**同时**要满足合并与不误合并，在 nomic 嵌入的
  短句上做不到——两类分布的间隙（0.515–0.918）里挤着大量「相关但不同」的句子；
- 这是**协议层**的结论：没接真实记忆库、没做语义改写、没有睡眠生物学机制。
