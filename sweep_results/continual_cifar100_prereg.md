# 预注册：持续学习基准（CIFAR-100-B0，10 步类增量）

**定稿时间：2026-10-18，在任何数据之前。**

## 要回答什么

计划书 §七 第三阶段：**持续学习基准（CIFAR-100-B0 10 步增量，参考 PS-SNN 的 76.42%）**，
验收口径写的是「平均增量准确率 65%+，AF < 8%」。

本轮要回答的**不是**"我们能不能超过 76.42%"，而是：**这条流水线在类增量设定下会遗忘多少**。
参考值只用来定位，不是靶子——PS-SNN 的 76.42% 是它自己的架构在它自己的协议下得到的，
与本项目的感知层不同源，**不可直接对标**。

## 协议（先写死）

| 维度 | 取值 | 理由 |
| :--- | :--- | :--- |
| 数据 | CIFAR-100，100 类 | 计划书指定 |
| 划分 | **10 个任务，每任务 10 类**，类别顺序固定（按类别 id 升序分组） | "B0" = 均衡划分；固定顺序保证可复现与可比 |
| 每任务训练量 | 全量（每任务 500 张训练图 × 10 类 = 5,000） | 不设样本预算，避免与"少样本"混为一谈 |
| 测试 | 全量测试集（每类 100 张） | |
| 评估时点 | 每学完一个任务后，在**截至目前见过的所有类**上评测 | 类增量（class-incremental）的标准口径：测试时**不提供任务 id** |
| 特征 | **W1 感知层**（`research/ib_hebbian/`，3 层 × 1024，速率型 LReLU）| 复用第一阶段已验证的感知层；CIFAR 输入改为 32×32×3 展平 |
| 读出 | 线性读出，用 **delta 规则**（局部、有教师）逐任务继续训练 | 与检索线同一个局部规则，便于横向比较 |
| 种子 | 0–4（5 个） | 沿用其他线的口径；**结果报中位数与区间** |

## 两个指标（定义写死，不许事后改）

设 `a_{t,i}` = 学完任务 `t` 后在任务 `i` 的测试类上的准确率（`i ≤ t`）。

```text
平均增量准确率  ACC = mean_{t=1..T} ( mean_{i=1..t} a_{t,i} )
遗忘            AF  = mean_{i=1..T-1} ( max_{t≥i} a_{t,i} − a_{T,i} )
```

* `ACC` 只看"学完 t 时对见过的类的平均表现"；
* `AF` 是**每个旧任务在其历史最好成绩上的回退**的平均，单位是百分点。

⚠️ 两个都必须报。只报 ACC 会让"学新忘旧"看起来还行——ACC 里每加入一个新任务，分母变大，
旧任务的退化被稀释。

## 对照（三条，缺一不可）

| 对照 | 作用 |
| :--- | :--- |
| **联合训练**（一次性在 100 类上训练同一个读出） | 上界：没有遗忘压力时能到多少 |
| **朴素增量**（就是上面的协议，无任何防护） | 本基准的主要测量对象 |
| **随机基线**（1 / 已见类数） | 确认指标没有算术错误 |

## 判据与解释边界

* 若朴素增量的 `ACC` 低于联合训练的 **一半**，说明遗忘是主导现象；若 `AF` 接近 0，
  说明 delta 规则在本设定下**根本没学**（更该先查实现）。
* **不承诺达到 65% / AF < 8%**。达不到就照实报，并说明是特征、读出还是任务顺序的问题。
* ⚠️ **与 PS-SNN 的 76.42% 不可直接比较**：架构、协议、评测口径都可能不同。报告里只写
  "参考值"，不写"差距"。

## 边界情况

* **评测时不提供任务 id**（类增量），但如果实测发现任务内准确率正常、跨任务混乱，
  要额外报"提供 oracle 任务 id"的上界——它能区分"特征不分辨类"与"读出被任务间干扰"。
* CIFAR-100 下载约 170 MB，走 `scripts/download_data.py`，**逐文件校验**；不入库。
* 训练时间按第一阶段 MNIST 的量级外推**不可靠**（台账实测慢 1.61×），先跑 1 个任务的滑窗
  探针量出每任务耗时，再决定 5 个种子是否跑满。
