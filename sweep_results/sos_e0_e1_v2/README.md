## E1：不过，而且原因不是模型

| # | 判据 | 门槛 | 实测 | |
| :--- | :--- | :--- | ---: | :--- |
| E1-1 | 世界模型能学（格子命中） | ≥ 0.85 | **0.627** | ✗ |
| E1-2 | 方差携带信息 | ρ ≥ 0.30 | **0.768** | ✓ |
| E1-3 | 方差追踪"不熟" | ≥4/5 种子 | **5/5** | ✓ |
| E1-4 | 不是常数 | CV ≥ 0.10 | **1.964** | ✓ |

**0.85 这个门槛在这份数据上不可达。** 跑完之后的诊断（不是重跑判据）：

| 测法 | 格子命中率 |
| :--- | ---: |
| v2 的 5 个子集岭回归 | 0.592 |
| 全量岭回归（λ=1.0） | 0.717 |
| **查表取众数**（同一批数据的上限） | **0.789** |

所以这是**门槛设错**，不是模型不行。而且这条诊断暴露了更根本的一点：
「预测期望下一位置再四舍五入」在滑移下本来就是坏的点估计——真实分布是双峰的
（90% 走成、10% 滑到别处），期望落在两格之间，四舍五入没有意义。

**处理：** 按预注册的死亡条件，不换 k、不换 λ、不调门槛重跑；另写
[`prereg-e0-e1-v3.md`](../../research/sos/prereg-e0-e1-v3.md)，把世界模型改成
「下一格的分布」（计数 + 拉普拉斯平滑），判据改成**相对边际基线**。

## 记录到的一个更深的问题（v3 跑之前要处理）

同一组 `(状态, 动作)` 在**不同迷宫**里的下一格可能不同（墙不一样）。也就是说，
`p(下一格 | 状态, 动作)` 在混网格数据上**不是良定义的**——世界模型看不到墙。

这可能是查表上限只有 0.789（而不是滑移给出的 ~0.9）的一部分原因。
v3 的实现要么给模型**迷宫身份**（per-maze 建模），要么改成**在线**（每个 episode 自己建表）。
这一条不写清楚，v3 的熵会混进"墙的不确定性"，E1-3 的解释就不干净。
