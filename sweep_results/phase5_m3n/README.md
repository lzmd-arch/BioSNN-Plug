# 阶段五 M3n：换分数——`Rmean` / `Rcentroid` 过线，但仍需新语料复测（2026-10-29）

**预注册：** [`../phase5_m3n_prereg.md`](../phase5_m3n_prereg.md)。
数据与 M3l/M3m 同一份冻结 fixture（sha256 `4fc74296…`），**触发器不动**（M3m 的众数参数
`k=1.5`、`n_hits=3`、每轮 100 ms，只作参考工作点）。本轮只比五个 embedding 新颖度分数。

## 结果

| 分数 | 池化 AUC | 逐会话 AUC（0–4） | ≥0.70 的会话 | 过线 |
| :--- | ---: | --- | ---: | :---: |
| `R5`（现状，最近 5 轮最大相似度） | 0.7475 | 0.56 / 0.71 / 0.87 / 0.87 / 0.69 | 3/5 | ✗ |
| `Rall`（与全部历史的最大相似度） | 0.7581 | 0.63 / 0.75 / 0.87 / 0.87 / 0.60 | 3/5 | ✗ |
| **`Rmean`**（最近 5 轮的**平均**相似度） | **0.8005** | 0.56 / 0.77 / 0.93 / 0.97 / 0.80 | **4/5** | **✓** |
| **`Rcentroid`**（与**会话质心**的相似度） | **0.8325** | 0.63 / 0.88 / 0.93 / 1.00 / 0.73 | **4/5** | **✓** |
| `Rz`（`R5` 的会话内 z） | 0.7141 | 0.60 / 0.68 / 0.84 / 0.88 / 0.71 | 3/5 | ✗ |

`score_family_found = true`，过线的是 **`Rmean` 与 `Rcentroid`**。

触发器参考工作点（同一套参数、5 种子 × 5 会话）——**不作判据**，只用来对照「分数变好会不会
把触发也带好」：

| 分数 | 命中中位 | 误触发中位 | 触发器 AUC 中位 |
| :--- | ---: | ---: | ---: |
| `R5` | 3 | 1 | 0.733 |
| `Rmean` | 3 | 1 | 0.760 |
| **`Rcentroid`** | **4** | 1 | **0.827** |

## 读法

1. **"最大值"这个算子是错的**：`R5` 与 `Rall` 都取「与某一条历史的最大相似度」——只要会话里
   有一条几乎一样的闲聊，目标轮就被判成不新颖。换成**平均**（`Rmean`）或**质心**（`Rcentroid`）
   后，池化 AUC 从 0.75 抬到 0.80 / 0.83。
2. **会话 0 仍然是最差的一段**（0.56 / 0.63）：它不是被"分数选错"拖坏的，而是那一段的目标轮
   与上下文实在太像。任何单一分数都救不了这一段——这提示**语料本身**有界限。
3. **分数变好会顺带把触发带好**：`Rcentroid` 下触发器的 AUC 中位 **0.827**、命中中位 **4/5**、
   误触发 1——三项同时到线。这与"M3m 的失败在分数不在触发器"一致。
4. **但这是同一批 5 段上的描述性比较**：5 个分数里挑最好的，天然乐观。按预注册，`true` 只表示
   **值得复测**，不表示成立。

## 边界

- 5 段 × 20 轮、25 个正例；单段 AUC 的不确定度很大；
- 分数的定义里没有用到任何标签，但**选哪个分数**用的是这批数据；
- `Rz` 的会话内标准化没有带来收益（0.714）——跨会话不可比的不只是尺度，还有**排序**；
- 触发器参数是 M3m 选的众数，**没有**为 `Rmean`/`Rcentroid` 重新标定。

## 下一步（需新预注册）

**M3o：在新语料上复测 `Rmean` 与 `Rcentroid`。** 用同一脚本、同一判据（池化 ≥0.80、
≥4/5 会话 ≥0.70），换一批生成对话（不同话题与不同生成种子），并报触发器在同一参数下的
工作点。只有复测也过，才能写「这条线的分数问题解决了」。
