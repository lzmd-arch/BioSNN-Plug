# 线 A v4：换掉读出之后，32k 还买不买得到精度（A4）

**日期**：2026-11-04
**预注册**：[`research/brainregions/prereg-a4-readout-scale.md`](../../research/brainregions/prereg-a4-readout-scale.md)
**原始数据**：[`a4.json`](a4.json)

## 一句话

**4 倍神经元、配上同样的 28 抽头读出：0.917 → 0.914，−0.3pp。规模在这个读出下也买不到精度。**

（**分辨率警告**：本实验只跑 seed 0，而 8k 那一档的种子噪声是 **sd 2.2pp、极差 4.4pp**
（0.873 / 0.906 / 0.917）。所以准确的说法是"**买不到大于种子噪声的精度**"，
不是"一点都买不到"——2pp 的门槛本身就在噪声里。）

## 结果

| 臂 | 神经元 | 抽头 | 准确率 | 发放率 | 峰值显存 | 训练墙钟 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| A3（对照，不重跑） | 8,192 | 28 | **0.917** | 0.1187 | 766.2 MiB | 1,467.6 s |
| **A4** | 32,768 | 28 | **0.914** | 0.1167 | 2,418.1 MiB | 1,825.3 s |

两臂同代码、同种子、同预算（sMNIST、2 epoch、batch 8、fan_in 32），**只差神经元数**。

## 判据

| # | 判据 | 门槛 | 实测 | 判定 |
| :--- | :--- | :--- | ---: | :--- |
| C-0 | 发放率与 8k 同量级（前置） | [0.06, 0.24] | 0.1167 | ✅ |
| C-1 | 规模仍买得到精度 | `acc(32k) − acc(8k) ≥ 2pp` | **−0.3pp** | ❌ |
| C-2 | 装得下 | <8,000 MiB | 2,418.1 | ✅ |
| C-3 | 没练坏 | ≥0.907 | 0.914 | ✅ |

**C-1 不过 → 容量饱和与读出无关。** 预注册写的分支是："C-1 不过 → 容量饱和与读出无关，
ADR-0033 的结论在两种读出下都成立，补注可以再加一句'已复验'。"就按这条写。

## 这条结论的分辨率

A4 只有**一臂、一个种子**（32k / seed 0）。要判断它能证伪多大的效应，得看 8k 那一档的种子分布——
补种之后 A3 的三种子是 **0.873 / 0.906 / 0.917**，**sd 2.2pp、极差 4.4pp**
（[`../brainregions_a3/README.md`](../brainregions_a3/README.md)）。

所以：

- **能说**：32k 相对 8k 的增益**小于种子噪声**，没有证据支持"规模有用"；
- **不能说**："规模绝对一点用都没有"。本实验的**分辨下限约 4pp**，小于 4pp 的效应它看不见；
- 预注册把 C-1 的门槛定在 2pp，**那个数当时就在噪声之内**——这是预注册本身的一个弱点，
  照登，不改判据。

要真的排除 2–4pp 的效应，需要 32k 也补三个种子（约 1.5 小时），目前**没做**。

## 2×2：读出效应与规模效应

| | 抽头 = 1 | 抽头 = 28 | 读出效应 |
| :--- | ---: | ---: | ---: |
| **8,192** | 0.774 | 0.917 | **+14.3pp** |
| **32,768** | 0.805 | 0.914 | **+10.9pp** |
| **规模效应** | **+3.1pp** | **−0.3pp** | |

（抽头 = 1 那一列来自 S6 的 2 epoch 记录，另一套脚本；抽头 = 28 那一列来自 A3/A4，
同一套脚本。**跨列比较有脚本差异**，同列比较是干净的。）

**读出来的东西**：S6 里 32k 在 2 epoch 下领先 8k 的 **3.1pp**，在把读出补全之后**整个消失**。
也就是说那 3.1pp 本身也是"最后一步读出"的产物——不是"大网络学得更好"。

## 边界

- 单种子、单任务（sMNIST）、2 epoch；**没有** 5 epoch 对照；
- 只测了 32k，没有 16k / 64k；没有换任务（SHD）复验；
- 抽头数与读出参数数仍然没有分离（32k 的读出是 `32768 × 28 × 10 ≈ 9.2M`）；
- 8k 那臂的数字来自 A3 的同预算记录，不是本次重跑。

## 成本更正（照登）

预注册里我按神经元数线性外推 ETA **1.6 小时**；开跑前用单次 update 冒烟标定又改成 **4.1 小时**。
**实际 1,825 s ≈ 30 分钟。** 单次 update（0.992 s）比稳态（约 0.122 s）高 8 倍——
那是第一次调用的 CUDA 上下文与内存分配开销。**冒烟单步不能用来排期。**
