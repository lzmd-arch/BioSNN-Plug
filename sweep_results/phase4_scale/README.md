# 阶段四规模：现有 e-prop 管线的容量边界（2026-10-29）

**性质：对已有 W2 规模扫描的复算 + 外推，不是新训练。** 输入是
`sweep_results/w2_scale_n*/seed*.json`（2 epoch、种子 0、β=0；不是准确率测量）；
复算脚本 `scripts/analyze_scale.py`，产物 `summary.json`。

## 实测曲线

| n_rec | 峰值显存 | s/epoch |
| ---: | ---: | ---: |
| 64 | 603.9 MiB | 46.3 |
| 128 | 966.1 MiB | 44.3 |
| 256 | 1,688.6 MiB | 55.6 |
| 512 | 3,116.2 MiB | 133.3 |
| 1,024 | 5,989.7 MiB | 435.3 |
| 2,048 | 11,744.8 MiB | 2,646.8 |

log-log 斜率：显存 **0.863**、耗时 **1.153**。

## 8 GB 容量与外推

按最大实测点外推（**外推，不是实测**）：

- 8,192 MiB 下最大约 **1,349 个循环神经元**；
- 4,096 → 约 21.4 GB；10,000 → 约 46.1 GB；100,000 → 约 336 GB；
- **500,000 → 约 1.38 TB**。

## 结论：500k 不能用当前实现“补齐”

- 现有 e-prop 的资格痕迹仍是**按突触存储**（即使 LIF 下 ε_v 已因式化，ε_a/权重梯度仍
  O(N²) 量级），显存随 N 近线性（0.863 斜率）已经是在 8 GB 上的硬墙；
- 500k 目标需要**事件驱动 / 稀疏连接 / 线性痕迹**的实现，而不是换 n_rec 或 batch；
- 按计划书 §6.2 的降级路径，本轮只能报告 **8 GB 下的最大可承载规模 + 规模-资源曲线**，
  不能写“达到 500k”。

## 能效：当前无法验收

- 仓库没有硬件功率计，也没有逐样本能耗采集；历史记录只有峰值显存与墙钟；
- 因此“比等效 ANN 降低 10×”**不能**用现有数据声称；
- 若要补，最小可行动作是：在推理循环里统计**脉冲数/synaptic operations**，与同形状
  ANN 的 MAC 数做代理比较，并明确“代理，不是硬件能耗”；这需要新的预注册，不在本文件
  里冒充结果。

## 后续选项

1. **实现事件驱动 e-prop**（Korcsák-Gorzo 路线）：只在该突触收到脉冲时更新，先把
   10k–100k 的可行性做出来，再谈 500k；
2. **稀疏连接**（固定 fan-in）：把 O(N²) 的痕迹降到 O(N·k)，需要新的 e-prop 推导；
3. **降级验收**：明确接受 8 GB 下的 ~1.3k 神经元，报告曲线与边界，不设 500k 门槛；
4. **能效代理**：脉冲数 vs MAC 的代理曲线，标注不可与硬件能耗混报。
