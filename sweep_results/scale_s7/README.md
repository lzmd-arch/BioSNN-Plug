# 规模实验 S7：SHD 上两臂都贴着地板——**这一轮没有回答任何问题**（2026-11-03）

**预注册：** [`research/scale/prereg-s7.md`](../../research/scale/prereg-s7.md)

## 判决

| # | 判据 | 门槛 | 实测 | |
| :--- | :--- | :--- | :--- | :--- |
| S7-0 | 都放得下 | < 8,000 MiB | **7,393.4 MiB**（32k） | ✅ 只剩 607 MiB |
| **S7-1** | 容量在这个任务上有用 | `acc(32k) − acc(8k) > 2pp` | **−1.9pp** | ✗ |
| **S7-2** | 两臂都不是随机 | 均 ≥ 0.20 | 8k **0.207** ✅ / 32k **0.188** ✗ | ✗ |

| n_rec | 准确率 | 峰值 | 耗时 |
| ---: | ---: | ---: | ---: |
| 8,192 | **0.207** | 3,530.8 MiB | 517 s |
| 32,768 | **0.188** | 7,393.4 MiB | 554 s |

## 结论：**S7 无效，不是负结果**

S7-2 是**前置条件**：两臂都必须明显高于随机（20 类，随机 0.05），否则比较的是两个"都没学会"的模型。

实测 0.207 / 0.188——**离 0.20 的地板一个刚过、一个没过**。这不是"容量没用"，
是**2 个 epoch 在 SHD 上根本不够**（同一个 runner 在 sMNIST 上 2 epoch 能到 0.8，
SHD 只有 8,156 个训练样本、T=100）。

所以：

- **S7-1 的 −1.9pp 不能读成"换硬任务后容量也没用"**；
- 只能说：**这个预算下 SHD 太难以至于测不出任何容量效应**。

## 这一轮的产出

1. **一条明确的边界**：SHD 的 2 epoch 是无效预算，要谈容量必须先把训练推到能离开地板的程度；
2. **两个实现修正**（冒烟阶段抓到）：runner 加 `--dataset`；输出类别数从标签推导
   （原来硬编码 10，SHD 20 类 → CUDA device-side assert）；
3. 32k 在 SHD 上峰值 7,393 MiB——**分块评测在 T=100 时也不便宜**，这是 S8 要留意的。

## 下一步（S8，先写预注册）

把 SHD 的预算加大到**能在两臂上都明显离开地板**（参照：默认训练是 30 epoch），
再问同一个问题。但要先解决成本：10 epoch ≈ 50 分钟/档，两档 ≈ 1.7 小时。

若 S8 里两臂仍然贴着地板，那说明这条管线在 SHD 上就不适合做规模对比，
该换的是**任务**而不是预算。
