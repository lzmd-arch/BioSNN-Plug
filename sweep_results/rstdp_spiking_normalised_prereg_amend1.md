# 预注册修正 1：W3 D18——校准窗口定反了，改成「匹配已工作的三条轴」（2026-10-30）

**对 [`rstdp_spiking_normalised_prereg.md`](rstdp_spiking_normalised_prereg.md) 的修正。**
训练协议、判据（slope ≥7/10、Δ 极差中位 ≥0.5、末次中位 ≥30）**一字不改**；只改**校准步**的
选 σ' 规则。

## 发现了什么（校准步，任何训练之前）

按原预注册的窗口（`rel ∈ [0.30, 0.90]` 且 `cos ≤ 0.95`）跑校准，**三个候选 σ' 全不过**：

| σ' | 归一化编码在 θ 上的 `rel` 中位 | 端到端 `cos` 中位 |
| ---: | ---: | ---: |
| 0.2 | 2.68 | ≈0 |
| 0.35 | **1.40** | 0.0008 |
| 0.5 | 0.96 | 0.041 |

三个都比 0.90 大。原因是**窗口本身定反了**：D17 里那三条"已经工作正常"的轴，`rel` 就是
**1.09 / 1.38 / 1.34**（中位 **1.34**）。也就是说，一条**完全可分辨**的轴，`rel` 天然 ≳ 1；
把上限定在 0.90 等于要求它"可分辨但不能太可分辨"，与 D17 的参考值自相矛盾。

## 修正后的选法

```
目标 rel* = 1.34        # D17 里 x / ẋ / θ̇ 三条正常轴的 rel 中位
在 σ' ∈ {0.2, 0.35, 0.5} 里选 |rel − rel*| 最小的那个，且要求 cos ≤ 0.95
```

按上表：0.2 → |2.68−1.34| = 1.34；0.35 → **|1.40−1.34| = 0.06**；0.5 → |0.96−1.34| = 0.38。
**选 σ' = 0.35**。

## 为什么这不是「看训练结果改判据」

- 这一步发生在**任何训练之前**，也没看 slope/成绩；
- 判据、网格、训练超参、种子数**都没动**；
- 改的只是"怎么挑一个编码器参数"，而旧规则与 D17 自己量出来的参考值矛盾——这是**口径自洽**
  问题，不是结果好坏问题。
