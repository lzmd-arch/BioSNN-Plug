# SEL は召回（検索）とゲートに適用できるか

[中文](sel-applicability.md) · [English](sel-applicability.en.md) · [日本語](sel-applicability.ja.md)

**日付**：2026-11-03
**結論**：**適用できない。** SEL（スパイク表現層）が解くのは「系列生成における口調」で、
召回はランキング、ゲートは二値分類です。共通するのはスパイクニューロンという部品だけで、
その部品についてはこの二つの系で一貫した負の結果が三つあります。SEL 自体は取り組む価値が
ありますが、召回やゲートの根拠にしてはいけません。

## 一段落版

- **召回**：クエリと記憶は静的な集合で、時間ステップは人為的なものです。発火率は点積の
  量子化であり、情報は減る一方です。512 個の ALIF で hit@1 は 0.024（字句 0.259）、
  TI-LIF では **0.012** です。
- **ゲート**：特徴は 3 つだけで、kNN も単一閾値も AUROC **1.000** に達します。この 3 特徴
  だけを使う決定的な写像は相互情報量を増やしません（データ処理不等式）。512 群体は gold で
  0.41、字句の単一閾値は 0.825 です。
- **移せるのは方法**：事前登録、ベースライン、ホールドアウト、負の結果の登録、両側基準。
  アーキテクチャではありません。

## 召回

**なぜ仕組みが合わないか。** 召回は候補集合を採点して並べる問題で、答えは上位数件にあります。
SEL の時間構造・トークン間状態・スパイク注意はすべて「出力が系列である」ことを前提にしますが、
召回には生成すべき系列がありません。クエリをスパイク電流に符号化し T ステップ回して発火率を
読むのは、同じ点積に閾値・不応期・量子化をかける非線形変換であり、情報は減るだけです。

**証拠。**

| 実験 | 結果 |
| :--- | :--- |
| `research/spiking_512`（512 ALIF、gold） | hit@1 **0.024** 対 字句 **0.259**、hit@5 0.094 対 0.424 |
| 同上、TI-LIF D=1/D=2（2026-11-03、シード 10） | hit@1 **0.012**、hit@5 0.047 |
| 同上、ALIF + K 窓平均（独立投影 5 本） | hit@1 **0.035**（+2.3pp、陽性対照は成立） |
| 同上、TI-LIF D=2 + K 窓 | hit@1 **0.012**（K 窓の利得なし） |
| Axo 基質補完（512 ALIF） | hit@1 0.000 対 線形 0.025、遅延 +40.7 ms |

K 窓の行が重要です。これまで有効と示された唯一の読み出し改善（∝K^0.6）で、ALIF では
再現しますが（0.012 → 0.035）、TI-LIF は利得を得ません。問題は「二値か符号付きか」ではなく、
発火率がランキングに必要な分解能を捨てていることです。

**再開条件**：本当にストリーム型の召回課題（クエリが時系列で届き、前向き 1 回のみ、
並べ替える候補リストがない）があり、線形/字句ベースラインが床（0.10 以下）でないこと。

## ゲート

**なぜ仕組みが合わないか。** ゲートは「この文はライブラリに裏付けがあるか」を 3 つの
スカラー（`top_score` / `mean_topk` / `density`）で二値判定します。kNN(5) 密度ゲートも
`top_score` 単一閾値も AUROC **1.000** です。AUROC は順位だけを見るので、この 3 特徴の
決定的な写像（スパイク群体符号化を含む）は情報を増やせません。有限標本で境界を動かすのは、
むしろ過学習の可能性が高いです。

**証拠。**

| 実験 | 結果 |
| :--- | :--- |
| Axo メタ認知ゲート（実ライブラリ 217 件） | kNN **1.000** 対 単一閾値 **1.000**、難正例 0.996 対 0.996、基準 2 不合格、未接続 |
| `research/spiking_512` ゲート（gold） | 512 ALIF **0.535**、TI-LIF D=2 **0.410**、字句 top-1 コサイン **0.825** |
| 製品経路 | 閾値 0.20 一つ（ADR-0028）、実分布で較正済み |

**再開条件**：近域の難 OOD を人手でラベル付けした集合（単一閾値 AUROC < 0.95）があり、
まず速率型ベースラインに改善余地が示されていること。両方がなければ、どんな「スパイクゲート」
も 1.000 の天井の下で同じ閾値を書き直すだけです。

## SEL との関係

- SEL と召回/ゲートは**ニューロン実装を共有**するだけで（`biosnn_bus.AdaptiveMembrane` /
  `TernaryMembrane`）、課題構造は共有しません。
- これらの負の結果で **SEL を否定してはいけません**。SEL は生成で、評価は口調と事実保持です。
  リスクはデータ・規模・教師 logits にあり、「スパイク」という語にはありません。
- 逆に、SEL の物語で召回/ゲートを裏付けてはいけません。事前登録・ベースライン・報告は
  別々に書きます。本ファイルはそのためにあります。

## 移せる部分

1. **実行前に基準を書く**（S1–S3、A1/A2/B1/B2、T1–T5 はすべて先に固定）；
2. **陽性対照と平凡解を一緒に報告する**（今回の K 窓 +2.3pp）；
3. **負の結果を登録する**（`research/spiking_512`、`benchmarks/substrate_spiking.md`）；
4. **両側基準**（B1/B2：スパイクが勝つかだけでなく、負けるかも見る）。
