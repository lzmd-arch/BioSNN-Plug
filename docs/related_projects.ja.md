# 関連プロジェクト対照表

> この表は**ライセンスの境界**と**証拠の強さ**の台帳であり、関連研究のレビューではありません。
> 各項目は三つの問いに答えます：その学習規則は何か（純局所か）、**そのコードを本リポジトリに
> 入れられるか**、そして自己申告の数値に第三者の再現があるか。

## なぜこの表が必要か

三つの理由で書き留めておく必要がありました：

1. **計画書 §八 の技術選定は、これらのプロジェクトから直接来ています**（EMBER → §四 の LLM 連携、
   MEMBRAIN → §4.3 の符号化の代替案、eprop-PyTorch → §1.4／§八 の e-prop 実装の参考）。
   選定を計画書に書く以上、「それは今どういう状態か」に答えられなければなりません。
2. **本リポジトリは Apache-2.0 で、CI にライセンス監査があります**（`scripts/check_licenses.py`、
   計画書 §12.1）。この欄には MIT（vendoring 可）もあれば、**非商業ライセンス**（一行も写せない）
   もあります。印象で埋めてよい欄ではありません。
3. **本リポジトリの引用規律**は、自己申告の数値と第三者が再現した数値を分けて書きます。
   ここには**目標を能力として書いてしまった**プロジェクトも、**自分のベンチマークに反駁された**
   プロジェクトもあります——その種の情報のほうが、見栄えの良い精度より価値があります。

## 同名の罠（ライセンスを書く前に必ず）

本リポジトリは引用で一度「A の結論を B に帰属させる」間違いを犯しています（Khacef → Hajizada）。
そのため同名プロジェクトは独立の節にします：

- **Javis**：GitHub には **`JuliaAnimators/Javis.jl`（Julia のアニメーション／可視化ライブラリ、MIT、star 800 超）**
  もあります。「Javis = MIT」とだけ記録すると完全な誤帰属になります——本表の Javis は
  `BEKO2210/Javis`（PolyForm 非商業）です。他に `JavisVerse/JavisGPT`、`JavisVerse/JavisDiT` や、
  まったく別系統の「JARVIS」もあります。
- **EMBER**：`Starlight-Unit-Studio/coreui`（"Ember CoreUI … E.M.B.E.R. cognitive architecture"）も
  ローカル LLM の Web UI で、**SNN も STDP もありません**。GitHub API のライセンス欄は
  `NOASSERTION` です——「`NOASSERTION` は人を騙す」の典型例です。`pandeyAnush/ember`（RAG 補助）も同様。
- **MEMBRAIN**：PyPI の `membrain` は**別の**プロジェクトのパッケージです（クライオ電子顕微鏡の
  膜タンパク質局在、BSD-3-Clause）。本表の MEMBRAIN とは無関係で、しかも後者は PyPI にありません。

## この表の使い方

- **結論を引用する** → まず「活動度と証拠の強さ」の欄を見てください。「第三者の再現なし」とあれば、
  引用時にその旨を明記し、[`references.md`](references.ja.md) の規律に従って検証状態を登録します。
- **コードを使う** → まず「ライセンス」の欄を見てください。**非商業／非 OSI ライセンスは読むだけ、
  写すのは禁止**。MIT は著作権表示を残せば vendoring できます（MIT に特許許諾が無い点に注意）。
- **その路線が成立するか判断する** → 学習規則が純局所か、どのハードウェアで動くかを見てください。
  本プロジェクトの命題は**純局所 + 代理勾配なし**なので、BPTT で得た見栄えの良い数値はここでは先例になりません。

## 保守

プロジェクトを追加するときは、四つの重要な欄を**実際に開いたファイル／ページ**（LICENSE、
`pyproject.toml`、CI 設定、論文 PDF）から取ってください。記憶や又聞きから書いてはいけません。
開けないときは「未見」と書きます。検証そのものはコミットメッセージに残します。
