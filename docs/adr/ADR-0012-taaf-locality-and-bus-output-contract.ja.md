# ADR-0012：TAAF の局所性のレッドライン、射影層の学習規則（未決）、および SpikeBus 出力形状のインターフェース契約

[中文](ADR-0012-taaf-locality-and-bus-output-contract.md) · [English](ADR-0012-taaf-locality-and-bus-output-contract.en.md)

- **状態**：部分採用（局所性と出力契約は採用済み；射影層の学習規則は**第二段階に持ち越し**）
- **日付**：2026-10-13
- **関連**：プロジェクト計画書 §2.2（スパイクバス：TAAF ＋二重チャネル融合）、§3.1、§七 第二段階；[ADR-0002](ADR-0002-numpy-core-torch-optional.ja.md)（スケルトンライブラリは torch に依存しない）、[ADR-0006](ADR-0006-plugin-interface-fidelity.ja.md)（プラグインインターフェースの忠実性）

## Context

プロジェクト計画書 §2.2 はスパイクバスに「TAAF 時間注意誘導の適応的融合」を統合するとし、§七 第二段階ではそれを「TAAF の高速微調整」というタスクに置いています。しかし実態は違います：`FusionStrategy` の実装は `ConcatenateFusion` 一つだけで、`bus.py` の注釈には「`FusionStrategy` は TAAF の**将来の挿入位置**」と書かれています——**TAAF は一度も実装されていません**。計画書の「高速微調整」という言い回しはそれが既にあることを前提にしていますから、記述と実態が食い違っています。

着手時に三つの制約が明示されました：

1. **注意重みの局所性**：TAAF の time-attention 重みは**局所的に計算可能な信号**（例：各経路の発火率）で駆動され、**逆伝播で学習してはならない**——さもなければ「純粋な局所学習」という主張が融合層で抜けてしまいます；
2. **射影層の学習規則は ADR で決める**：膜層に IB-Hebbian を使うか、単純な局所正規化か——**いま決めないにしても選択肢は列挙する**。これは第二段階の核心問題であって、ついでに答えられる類いのものではない；
3. **`bus` の出力形状をインターフェース文書に書く**：融合出力 = **統一されたコア次元** ＋ **モダリティラベルの保持**。

## Decision

### 1. 局所性のレッドライン（採用済み、硬い制約）

融合層の注意重みは**各経路自身の発火率からその場で計算**します（rate-based gating）。実装は `TemporalAttentionFusion.attention_weights`：

```text
rate_i = mean(|data_i|)          # 各経路の平均発火率——ニューロンごとに局所的に読める
w      = softmax(rate / tau)
out    = sum_i w_i * projected_i
```

**backward はなし、学習可能なパラメータはなし、torch はなし。** `test_taaf.py::TestLocalityRedLine` がこれを **AST による構造的アサーション**で固定します（ソースを目視するのではなく import と呼び出しを検査）。このレッドラインが迂回されると「純粋な局所学習」は成立しなくなるからです。

**なぜ Hebbian ではなく rate-based か**：どちらもレッドラインを満たします（どちらも局所的に計算可能）が、rate-based のほうが単純で、重みをデータからその場で計算し直せてテストで主張できます。Hebbian 版は時間にわたって痕跡を蓄積するため、検証しにくくなります。**これは排他的な裁定ではありません**——後日 Hebbian の重みのほうが良いと実験で分かれば実装を差し替え、レッドラインはそのままです。

注意：**スケルトンライブラリが製品になったあとも、このレッドラインはより一層守る必要があります。** 製品側では「融合重みを学習させれば」という誘惑が生じます。それは性能と引き換えに「純粋な局所学習」という主張を手放すことです。

### 2. 出力形状のインターフェース契約（採用済み、硬い制約）

`SpikeBus.step()` の返り値：

| 項目 | 値 |
| :--- | :--- |
| 形状 | `(T, bus_dim)` —— **第二次元は常に** `bus_dim`。何個のモダリティが登録されていようと、それぞれの `spike_dim` がいくつであっても**関係ありません** |
| チャネル | チャネルをまたいだ和。以降 `channel` フィールドは無意味で、モダリティごとのチャネル情報は `describe()` にのみ残ります（`modalities_by_channel` でまとめて） |
| dtype | `float64`：±1 重みのスパースランダム射影による入力電流 |

**第二次元が `bus_dim` であることは約束であって偶然ではありません**：下流の認知コアは、上流にモダリティがいくつあるかを知らなくても `bus_dim` で次元を決められます。融合戦略を変えても**変わりません**——二つのワークポイントの差は**どう一つの経路を作るか**であって、出力次元ではありません。

**モダリティラベルの保持**：融合後の単一の列に「どれがどのモダリティか」を表すビットはありません。したがってラベルは `SpikeTrain.channel` には置きません（そのフィールドの意味は「どの融合チャネルか」であって「どのモダリティか」ではない）。正しい場所は `describe()` の `modalities_by_channel` です——**すでに実装済み**で、本 ADR はそれをインターフェース文書に加えるものです。

### 3. 射影層の学習規則（**第二段階に持ち越し**）

これは第二段階の核心問題であり、本 ADR は**決めません**。選択肢の登録だけを行います。候補は三つ：

| 選択肢 | 内容 | 代償 | 注記 |
| :--- | :--- | :--- | :--- |
| **A. 固定シードのランダム射影**（現状） | `SparseRandomProjection`、±1 重み、`zlib.crc32` で派生したシード | 学習不可。距離保存は Johnson–Lindenstrauss ですが、**どのタスクにも最適化されていません** | 現行実装。**学習なし・逆伝播なし**、レッドラインと整合 |
| **B. IB-Hebbian の局所学習** | 射影行列を kernel 化 IB-Hebbian でオンライン更新（`research/ib_hebbian` と同じ） | 学習率・HSIC 核・除法正規化などのハイパーパラメータが増える；**しかし依然として局所的** | 既存の感知層の選択と同じ系統 |
| **C. 単純な局所正規化** | 固定射影 ＋ ニューロンごとの局所正規化（除法正規化 / 膜層） | 最も軽い；ただし「正規化」は学習ではなく安定化にすぎない | `Membrane` プロトコルと `PassThroughMembrane` のプレースホルダが既にあります |

注意：**三つの候補はいずれも局所性のレッドラインを満たします**（逆伝播を使うものは一つもない）。したがってこれはレッドラインの問題ではなく**表現力**の問題です。固定射影が最も弱く、IB-Hebbian が最も強いがハイパーパラメータも多い。どれを選ぶかは、跨モダリティ検索 R@1 50%+（§七 の成功基準）を達成できるかどうかに依存します。

注意：**`SparseRandomProjection` の意味論は、これが決まるまで動かさないでください。** その「±1 射影は距離を保存する」という性質は `research/` の三検証ラインの前提です。変える前にその性質を再検証してください。今回の C3 の変更は経路ごとの次元で射影を取る `_projection_for` を**追加しただけ**で、射影行列そのものとシード派生には**触れていません**。

## Consequences

**採用済みの二つの制約**（局所性のレッドライン、出力契約）は、今後のすべての融合戦略を拘束します。新しい戦略は必ず `test_taaf.py::TestLocalityRedLine` の AST アサーションを通し、出力の第二次元は `bus_dim` でなければなりません。

**未決の第三の制約**は第二段階の実際のギャップです：現行の射影行列はランダムで、**いかなるタスクにも最適化されていません**。跨モダリティ検索 R@1 50%+（§七 の成功基準）に届かない場合、まずここを疑ってください。

**プロジェクト計画書の言い回しは変える必要があります**：§七 第二段階の「TAAF の高速微調整」は「**TAAF 時間注意融合の実装**（rate-based gating、逆伝播なし）」にすべきです——「高速微調整」は TAAF が既にあることを前提にしています。
