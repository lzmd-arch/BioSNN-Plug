# ADR-0033：容量轴归档——加神经元与加连接都买不到精度

[English](ADR-0033-capacity-axis-archival.en.md) · [日本語](ADR-0033-capacity-axis-archival.ja.md)

- **状态**：已采纳
- **日期**：2026-11-03
- **相关**：[ADR-0031](ADR-0031-mainline-to-scale.md)（主线切到规模实验）、[ADR-0032](ADR-0032-sel-research-track.md)、
  `sweep_results/scale_s2` … `scale_s9`

## Context

ADR-0031 把主线切到规模实验，问题只有一个：**精度随规模怎么长，代价多少。**

S2–S9 把它走完了，两条轴分别给答案：

| 轴 | 证据 | 结果 |
| :--- | :--- | :--- |
| **加神经元** | S2 1k→8k +14.6pp；S6 8k→32k 只 +0.5pp（5 epoch）；S5 64k 相对 16k **−0.3pp**；S8 换 SHD、10 epoch 时 8k **0.338** vs 32k **0.348** | 8k 之后买不到 |
| **加连接** | S9 固定 8k，fan_in 32→128：**0.774 → 0.766（−0.8pp）**，时间 **3.2×** | 同样买不到 |

同时 S4 更正了此前的显存判断：**8 GB「上限」是评测批次造成的**，训练一次 update 在 64k
神经元上只要几百 MB。所以容量饱和**不是资源限制**，是这条管线的容量本身吃满了。

**补注（2026-11-04，A3）**：以上全部在**最后一步读出**这个前提下测得。线 A 的 A3 在**同样 8,192 神经元**上
只把读出从 1 个时间点改成 28 个（同一套局部规则），sMNIST 从 **0.759 到 0.917**。因此"容量吃满了"
要读作"**在最后一步读出下**吃满了"。本 ADR 的决定**不变**——加神经元与加连接仍然买不到精度，
也没有任何规模实验需要重跑；但 **0.83 不能当作这条管线的能力上限引用**。
依据：`sweep_results/brainregions_a3/README.md`。

S6 还给出机制层面的读数：**多训练会让小网络追上来**——2 epoch 时 32k 领先 8k 3.1pp，
5 epoch 时只剩 0.5pp。"规模有用"里有一份是"大网络学得快"，不是"学得好"。

## Decision

1. **容量轴归档。** 不再把"加神经元"或"加连接"当作提升精度的方向，也不再为它分配算力。
2. **保留现行工作点**：**8,192 个循环神经元 + fan_in 32**，作为这条管线的默认配置写进基准。
3. **规模实验的资产照常保留并可引用**：滑移迷宫基准（`benchmarks/maze/`）、
   评测分批（`--predict-chunk`）、runner 的 `--dataset`、以及 S2–S9 的全部结果目录。

## 重新开启条件

| 条件 | 说明 |
| :--- | :--- |
| **组织方式**改变 | 脑区特化、异构神经元参数等"不靠数量靠结构"的改动落地后，容量曲线可能移动——那要新预注册，不能拿本文当挡箭牌 |
| **训练预算**证据 | 5/10 epoch 下的斜率是"差距在缩小"；若 250 epoch 下反转，本文的结论要写 amend |
| **新任务族** | 若出现一个在 8k 上明显欠拟合（训练损失仍高）的任务，容量轴对该任务重新成立 |

三条都要求**新预注册**，不得把旧结果重新解释成通过。

## Consequences

- 算力从"加宽"转向"组织"与交付；
- 一条可复用的结论：**这条事件驱动管线的容量膝点在 8k 神经元附近**，再往上时间线性涨、精度不涨；
- 代价：**不能再用"我们只是规模不够"解释任何失败**。8k 之后的每一次不达标都必须归因到
  别的轴（组织、任务、学习信号）；
- 代价：默认配置固化在 8k，意味着以后若有人要跑 32k，需要**显式说明为什么**，而不是默认更大更好。

## Alternatives

- **继续加神经元**：S5（64k 无增益）、S8（SHD +1.0pp）已否。否决。
- **继续加 fan-in**：S9（−0.8pp、时间 3.2×）已否。否决。
- **换任务再试容量**：S7/S8 已经做过一次（SHD），结论同样是 +1.0pp。否决。
- **把饱和写成资源限制**：S4 已证明不是（显存由评测批次决定）。否决——那是错误归因。
