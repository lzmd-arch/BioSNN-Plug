# ADR-0009：W3 の行動方策を Boltzmann サンプリングにし、サンプリング確率で痕跡を中心化する

[中文](ADR-0009-w3-behaviour-policy-and-trace-centring.md) · [English](ADR-0009-w3-behaviour-policy-and-trace-centring.en.md)

- **状態**：採用済み
- **日付**：2026-09-23
- **関連**：計画書 §3.2、§七 第 1 フェーズ；[ADR-0007](ADR-0007-td-ltp-critic-provenance.ja.md)；
  `research/rstdp/rstdp.py`、`research/rstdp/cartpole.py`、`research/rstdp/README.ja.md`

## Context

W3（CartPole 上の R-STDP + TD-LTP Critic）は長く受け入れ基準に未達だった：≥10 シードの中央値
**100.0 歩**、基準は 200。失敗モードをきちんと測定した結果、**二つの問題が重なっている**ことが
見えた。

### その一：確定方策では学ぶべき目標が存在しない

`learn_step` は**非探索ステップ**でのみ Actor を更新し、そこでは `action = argmax` が状態の
**決定論的**関数である。したがって更新は選ばれた列だけに落ちる——実測
`U が一列しか触らない状態の割合 = 1.0000`（離散事実、閾値に依存しない）。

さらに根本的に `A(s, π(s)) ≡ 0` は**恒等式**である（方策自身が選ぶ Action を強制してから方策に
従うことが、`V^π` の定義そのもの）。よって「優勢重み付き方向」という目標は**訪問する状態で
恒等的にゼロ**である——実測 `逐状態 |T| 中央値 = 0.0000`。理由は、良い方策が訪問する状態では
棒がほぼ直立しており、**二つの Action がほぼ等価**だからである。

合わせると：規則が直面しているのは「向きが違う」ことではなく、**学ぶべき目標が存在しない**
ことである。選ばれた列が受け取るのは、Action に依存しない残差 δ によるドリフトである。
これは長く観察されてきた二つの事実も説明する：方策が全行程で大きく遊走すること（二十本の
曲線すべてが隣接チェックポイント間で 5〜30 倍振れる）、そして `|U|/|T|` が大きいこと
（**分子が小さい**——目標がほぼゼロ——のであって、分母が大きいのではない）。

### その二：評価経路そのものに欠陥があった

`select_action` は `boltzmann` 分岐で **`exploration` を見ず**、無条件に softmax から
サンプリングする。一方 `_greedy_score`（訓練途中の曲線と最終受け入れの**両方**が使う）は
`exploration=0.0` を渡している。したがってそのアームの「貪欲評価」は**確率方策**を測っていた。
その尺度の天井は極端に低い：**満点**の方策（ヒューリスティック、500 歩）でも行動正確度 70% で
97.4 歩、60% では 36.3 歩しかない。これは打ち切り、RNG 汚染、サンプリングプール上限、誤った
符号の議論に続く**同種の第五の欠陥**であり、しかも代償は具体的だった——本フェーズ唯一の有効な
レバーを「無効」と判定させ、その判定が三言語 README に入った。

## Decision

1. **`action_sampling="boltzmann"`**：`softmax(logit_scale · スコア)` からサンプリングし、
   **毎ステップ Actor を更新する**（「探索ステップ」というものは存在しない）。`logit_scale` は
   必須——L1 正規化後、二列のスコア差は 0.05〜0.5 しかなく、拡大しない softmax はほぼ一様になる。
2. **`trace_center="sampling"`**：痕跡の第二因子を `a_j − π_j` にする（π は**サンプリング**
   分布）。期待値がゼロなので、`E[dw] = η·E[x·(a−π)·S]` の中の「Critic の逐状態無偏性を要求する」
   バイアス項が厳密に消える。さらに**選ばれなかった列が弱められる**——これこそが構造的に
   欠けていた**Action の比較**である。
   **アサーション**：`trace_center="sampling"` は `boltzmann` の下でのみ意味を持つ。ε-貪欲では
   `a_j − π_j ≡ 0` となり Actor が完全に停止する——コードは黙ってそうなることを許さず
   `ValueError` を投げる。
3. **逆温度アニーリング**：`logit_scale` を **log 空間**で **2** から 20（または 40）へ補間する。
   一定値は両端で損をする：ほぼ一様（5）は学べるが鈍いまま（中央値 141.4）、鋭い（20）は上限が
   高い（ホールドアウト 177.3、最大 434）が**およそ十本に一本の軌跡が最初から起動しない**
   （ピークが 10〜12 歩のみ）。アニーリングは鈍→鋭で進み、最小値を 9 から 90〜123 へ引き上げる。
   log 空間補間をするのは、`logit_scale` が温度の逆数だからである——線形補間は温度に対する
   双曲スケジュール（前半が遅すぎ、後半が速すぎ）になる。
4. **`select_action(greedy=True)`**：**サンプリング方式に関わらず** `argmax` を返す。評価経路は
   必ずこれを使う。ε-貪欲では旧来の `exploration=0.0` 経路とビット単位で一致するので、記録済みの
   数値はすべてそのままである。
5. 受け入れ設定は本リポジトリの慣例どおり**明示指定**（`actor_lr_final_fraction=0.1` と同じ層）
   だが、上記四点を既定値にする——これにより既定の実行がそのまま合格設定になる。

## Consequences

- **§七 の二つの基準を満たす**：ホールドアウトシード（25〜44、二十個、いずれも選択に一切関与
  していない）で中央値 **260.0**（基準 200）、偏移比の最大 **0.0359**（基準 0.10、全シード通過）。
  選択セット（0〜9）は中央値 250.4——近い値であり、シード選択効果ではない。
- **「安定」という追加条件は満たさない**：最小値は **74**（自ら事前登録した口径は ≥100 を要求）、
  二十シード中二個が 100 未満。診断：その二つは**ピークが 90〜124** であり、「十分に学べていない」
  のであって**崩壊ではない**（一定温度下での本当の崩壊はピークが 10〜12 歩のみだった）。
  失敗モードの種類が変わったのである。
- **「W3 が検証しているもの」が変わる**：訓練時の行動方策が「ε が 0.02 まで減衰する ε-貪欲」から
  「Boltzmann サンプリング + 逆温度アニーリング（2 → 20）」へ変わる。**展開と受け入れは依然
  `argmax`** なので、§七 が測る対象は変わらない。
- **局所性は不変**：非局所量は依然としてスカラー δ のみ。追加されたのは各 Action セル**自身の**
  π_j——そのセル自身の入力から計算されるスカラーであり、`trace_center="sampling"` が既に
  使っていた量である。
- 既定の挙動が変わるため、`--seed 0` の 114.6 といった歴史的な数値は**旧既定**に対応する。
  それらは README の台帳に比較対照として残るが、もはや「既定設定が出す値」ではない。

- **後日談（2026-09-23、同じ決定の下での数値の再調整）**：上記 Consequences に記録された数値は
  決定当時の設定——アニーリング 2 → 20、学習率の末期比 0.1、シード **25–44** で測った 260.0 /
  最小 74——に対応する。その後**ホールドアウトシード**で調整を続け、最終設定は
  **アニーリング 1 → 40、学習率の末期比 0.01** となり、新品シード 45–64 で中央値 237.8・
  最小 121 を得た（二批とも合格）。本 ADR の**決定**——Boltzmann サンプリング + サンプリング
  確率による痕跡の中心化 + 逆温度アニーリング——は変わっておらず、そのうち二つの数値が
  再調整されただけである。リポジトリの慣例（`docs/adr/README.md`：ADR の本文は記録後に
  変更しない）に従い本文はそのままにし、ここに注記する。現在の数値は README の
  「現時点の結論」とコードの既定値を正とする。

## Alternatives

- **Action 混合 `π = (1−κ)·onehot(argmax) + κ/n`**（固定 κ で方策の鋭さと少数 Action の
  サンプリング率を分離する）：**却下**。敵対的レビューにより、κ=0.2 の分布 `(0.9, 0.1)` は
  ε-貪欲 ε=0.2 と**同一の分布**であり、展開方策も両者とも argmax であること、そして boltzmann
  分岐には**そもそもゲートが無い**ことが示された。よって現状に対する追加分は評価の修正だけで、
  それには混合は不要である。さらに、それが自ら定めた合格線（逐状態余弦 > 0.95）は自身の規則の
  下で**数学的に到達不能**（恒等的に `1/√2`）である。
- **Critic を Action ごとに分割する（二つの Q 群体で `A = Q − V` により Actor を駆動）**：
  **却下**。Frémaux の Actor 規則はもともと「Action の選択に直接責任を持つものだけが強化される」
  と述べており、これは逸脱ではない。また δ を A に置き換えるのは**変調量を変えるだけで痕跡は
  変えない**ため、Actor の信用構造はビット単位で同一である。その族も既に測定済み
  （中心化なしの Boltzmann：対応差 −26.0、2/10 改善）。
- **論文 Eq. 37 の性能駆動学習率スケジュール**：**保留**。レビューにより、現状の形式は 7 倍の
  因子が欠けており `eta/peak ∈ [0.871, 1.000]` となるため、「性能が崩れたら再び大きな歩幅」という
  機構が実装では**起こり得ない**ことが示された。因子を戻しても、後期の η は唯一有効なレバーの
  終点 3e-4 を上回ったままである。加えて論文の `eta_act = 0.5·eta_crit`（Critic が Actor の
  二倍）は、本リポジトリの「Critic を速くすると 0/10 の破滅」と直接衝突するため、別途の考証と
  ADR を要する。
- **固定の符号付き読み出し（`readout="random"`）**：**却下**。Frémaux の Eq. 13 は価値を群体の
  **平均発火率**と定義している——`readout="uniform"` こそが論文であり、符号付き読み出しが逸脱で
  ある。説明分散を −1.00 から −0.21 へ動かし平均絶対誤差を半減させたが、**10 シード中 0 しか
  改善しなかった**（対応差 −50.7、σR 補償後も −40.6）。
