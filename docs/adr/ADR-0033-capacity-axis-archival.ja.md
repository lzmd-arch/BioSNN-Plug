# ADR-0033：容量の軸をアーカイブ——ニューロンも接続も精度を買えない

[中文](ADR-0033-capacity-axis-archival.md) · [English](ADR-0033-capacity-axis-archival.en.md)

- **状態**：採用済み
- **日付**：2026-11-03
- **関連**：[ADR-0031](ADR-0031-mainline-to-scale.ja.md)（メインラインを規模実験へ）、
  [ADR-0032](ADR-0032-sel-research-track.ja.md)、`sweep_results/scale_s2` … `scale_s9`

## Context

ADR-0031 はメインラインを規模実験へ移し、問いを一つに絞りました：**精度は規模とともにどう伸び、
代償はいくらか。**

S2–S9 がそれを二つの軸で答えました：

| 軸 | 根拠 | 結果 |
| :--- | :--- | :--- |
| **ニューロンを増やす** | S2：1k→8k は +14.6pp；S6：8k→32k は +0.5pp（5 epoch）；S5：64k 対 16k は **−0.3pp**；S8 の SHD・10 epoch：8k **0.338** 対 32k **0.348** | 8k 以降は買えない |
| **接続を増やす** | S9：8k ニューロンで fan-in 32→128 は **0.774 → 0.766（−0.8pp）**、実時間 **3.2 倍** | こちらも買えない |

S4 は以前のメモリ判断も訂正しました：**8 GB の「上限」は評価バッチが作っていたもの**で、
64k ニューロンでも訓練 1 update は数百 MB。つまり飽和は**資源の制約ではなく**、このパイプラインの
容量そのものが使い切られているということです。

S6 は機構も示しました：**訓練を増やすと小さいネットワークが追いつく**——2 epoch では 32k が 8k を
3.1pp リード、5 epoch では 0.5pp。"規模が効く"の一部は"大きい方が速く学ぶ"であって、
"大きい方が良く学ぶ"ではありません。

## Decision

1. **容量の軸をアーカイブ。** ニューロン数も接続数も精度を上げる方向としては扱わず、計算資源も配分しない。
2. **現在の動作点を維持**：**循環 8,192 ニューロン + fan-in 32** をこのパイプラインの既定として基準に記す。
3. **規模実験の資産は引用可能なまま残す**：滑り迷路ベンチマーク（`benchmarks/maze/`）、
   評価の分割（`--predict-chunk`）、runner の `--dataset`、そして S2–S9 の全結果ディレクトリ。

## 再開の条件

| 条件 | 補足 |
| :--- | :--- |
| **組織**の変更 | 脳領域特化や異種ニューロンパラメータは容量曲線を動かしうる——それは新しい事前登録が必要で、本 ADR を盾にしてはいけない |
| **訓練予算**の証拠 | 5/10 epoch の傾きは「差が縮む」方向。250 epoch で反転するなら本 ADR に amend が要る |
| **新しいタスク族** | 8k で明らかに未学習（訓練損失が高いまま）のタスクが現れれば、そのタスクについて容量軸は再び有効 |

いずれも**新しい事前登録**を要求します。古い結果を通過と読み替えてはいけません。

## Consequences

- 計算資源は「拡幅」から「組織」と提供へ移る；
- 再利用できる結論：**このイベント駆動パイプラインの容量の膝は 8k ニューロン付近**。それ以上は
  時間が線形に伸び、精度は伸びない；
- 代償：**「単に規模が足りない」で失敗を説明できなくなる**。8k 以降の不達はすべて別の軸
  （組織・タスク・学習信号）に帰属させなければならない；
- 代償：既定が 8k に固定されるので、32k を走らせる人は**理由を書く**必要がある。

## Alternatives

- **ニューロンを増やし続ける**：S5（64k で利得なし）と S8（SHD で +1.0pp）が否定。却下。
- **fan-in を上げ続ける**：S9（−0.8pp、実時間 3.2 倍）が否定。却下。
- **タスクを替えて容量を再試行**：S7/S8 で SHD を使って既に実施、同じく +1.0pp。却下。
- **飽和を資源制約として書く**：S4 が否定（メモリは評価バッチで決まる）。誤った帰属なので却下。
