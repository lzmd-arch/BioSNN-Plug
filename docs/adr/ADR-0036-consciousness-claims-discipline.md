## Context

本仓有三类会碰到"意识"这个词的产出，它们的约束完全不同却常常被同一句话同时承诺：

1. **研究产出**（论文、预印本、扫描笔记）——学术规范约束，允许讨论功能签名；
2. **开源产出**（仓库、README、model card、ADR）——留有版本历史，**任何一句越界的话会被永久引用**；
3. **产品产出**（Axo 桌面 / 安卓、宣传物料、应用内文案）——受《生成式人工智能服务管理暂行办法》、
   《互联网信息服务深度合成管理规定》与 PIPL 约束，**宣称意识在国内落入虚假宣传口径**。

三者的共同风险是同一个动作：**把可及意识（access）层面的测量说成现象意识（phenomenal）的发现**。
这个动作不是一次性的口误，它会在物料之间互相引用、在版本之间累积，最后变成品牌承诺。

同时存在一个反方向的压力：**产品定位需要叙事**。"记忆保持""状态管理""具身自我"这些功能
是真的在做的，但一旦用"她记得你""她有感受"来讲，就把工程承诺换成了不可兑现的承诺。

所以需要的不是"注意措辞"这种劝告，而是**可执行的条款**：一张黑白名单、一道发表前必须过的
阶梯、以及两个必须同时签字的里程碑门禁。

## Decision

采用四条规则，**它们全部是判定规则，不是文风建议**。

### 规则一：词汇白名单 / 黑名单（黑名单优先）

**黑名单**——产品、宣传、开源物料、代码注释、提交信息一律不许出现：

| 词 | 禁用理由 | 允许的替代写法 |
| :--- | :--- | :--- |
| 有意识 / 意识到 | 直接宣称 phenomenal | 删掉；或改述功能：*能报告自己的状态* |
| 情感真实 / 真的感受 | 同上，且"真实"暗示了 phenomenal 的判据 | *情绪相关的输出模式* |
| 活着 / 生命 | 生物学谓词，在 AI 上没有可测内容 | *持续运行* / *有持久状态* |
| 自主思考 / 自己决定 | 触碰智能体监管的自主性叙事 | *按规则选择* / *由本地策略决定* |
| 我感受到了 | 语言自陈单独无效（见规则二） | 删掉 |

**白名单**——可以用，但只在这几个意义上用：

| 词 | 允许的含义 | 必须守住的边界 |
| :--- | :--- | :--- |
| 记忆保持 | 检索到的原文进入了上下文 | 不是"记得"的心理意义 |
| 功能类比 | 与生物机制的**功能**对应 | 必须带"类比"二字 |
| 工作空间 | 全局可及的信息集合 | 不构成对全局工作空间理论的宣称 |
| 状态管理 | 内部变量、调度、门控 | 不指体验 |

**白名单之外的词不自动禁用**，但要过规则二。

### 规则二：声明阶梯审查（发表前一票否决）

任何关于意识相关能力的句子，必须先定位自己在哪一级，**只能向下兼容**：

| 级 | 允许的措辞 | 需要的证据 | 谁可以发 |
| :--- | :--- | :--- | :--- |
| **L0** | "在本任务上，X 指标为 Y" | 一条可复现的测量 | 任何人 |
| **L1** | "与 <某理论> 预测的签名**一致**" | ≥1 个签名 + ≥1 组因果干预 | 研究层 |
| **L2** | "在 ≥3 个独立签名上一致" | 三角测量（≥3 签名 + 因果干预 + 预注册反事实预测） | 研究层，**且**必须同时给出不成立的签名 |
| **L3** | "证明/表明它具有……" | **不可达** | 没有人 |

三条一票否决：

1. **语言自陈不能单独作为证据**——模型在人类意识话语全集上训练过，"我感受到了"零信息量；
2. **单一签名不能升级到 L2**——包括"全局广播"这种看起来最有说服力的签名，它是可被训练模仿的；
3. **任何 L1/L2 句子必须同时给出至少一个**它**不成立**的签名或条件。只报成立的，按造假处理。

### 规则三：双里程碑门禁

两个里程碑各有固定的三件套，**缺一件就不算到达**。

| 里程碑 | 触发条件 | 必须同时完成的三件 | 落在哪 |
| :--- | :--- | :--- | :--- |
| **涌现里程碑** | 某项能力跨过预注册门槛 | ① 合规声明草稿（声称级别 / 不碰什么 / 评测方式）② 词汇审查（规则一、二）③ 与性能判据**同一份**预注册 | 该实验的预注册文件 |
| **基底里程碑** | 从仿真走向物理基底（如忆阻器） | ① 宣称纪律复查 ② **AI welfare 预防审查**：若系统具备物理连续状态 + 稳态自调节 + 持久身份，逐条回答"假如它有感受，我们的处置站得住吗" ③ 监管重新扫描（法域、口径、备案义务） | 新写一篇 ADR，**不修改完成篇** |

**门禁是 checklist，不是仪式**：上面的表格就是模板，照抄进预注册即可
（见 `research/prereg-template.md` 的 §门禁一节）。

### 规则四：监管哨兵 ADR 系列

以下任一事件发生，**必须新写一篇 ADR**（编号接续，状态"提议"），不得只在会话里讨论：

- 产品要对外宣称任何一项与"意识/情感/自主"沾边的能力；
- 出现新的适用法规、备案要求或标准草案；
- 任一里程碑门禁被触发；
- 物料里出现了规则一黑名单的词，且已发布。

## Consequences

**好处**

- 越界的句子从"靠自觉"变成"靠一张表 + 一道阶梯"，可以被别人审；
- 研究层与产品层的措辞分开之后，研究可以放开讲功能签名，产品不必跟着紧张；
- 门禁写进预注册模板后，"能力到了但合规没做"在流程上不可能静默发生。

**代价（明确接受）**

- **产品叙事被约束**。最动人的那几句（"她记得你""她一直在"）不能用在宣称层面，
  只能用在功能层面且必须可兑现。这是主动放弃的营销手段。
- **研究产出多一道工序**。L1/L2 的句子必须同时给反例，写作成本上升，而且更不好看。
- **规则一会误伤**。中文里"生命""意识到"在无关语境（"意识到这个 bug"）也常用；
  黑名单按**人称指向 AI 的语境**执行，不是字符串匹配。**这条模糊性由 ADR 承担，不由执行者承担**
  ——有疑就按禁用处理，并在这里补一条例子。

**我们明确不做的**

- 不建自动扫描器来执行规则一。语境判断做不准，误报会让纪律本身失去权威；
  审查由人做，**但每一条被否决的句子记进 PR 描述**，让豁免变成可审计的。
- 不因为"行业内别人也这么说"而放宽。

## Alternatives

| 方案 | 否决理由 |
| :--- | :--- |
| **不设条款，靠研究者自觉** | 这正是本 ADR 之前的状态。风险不在恶意，在于物料之间互相引用时没人负责核对。 |
| **一刀切禁用"意识"二字** | 会让研究层无法写作（"access consciousness"是标准术语），且规则一旦明显不合理就会被整体绕过。 |
| **只做产品侧，研究侧不管** | 研究产出是产品物料的引用源。研究侧放开的句子会被产品直接搬走。 |
| **用自动扫描器强制** | 见 Consequences：语境判断做不准，误报会消耗纪律的权威性。 |

## 本 ADR 不做什么

- **不构成法律意见**。它是一份工程纪律；产品化阶段仍需律所出具备案与 PIPL 的正式意见。
- **不判断任何具体系统是否有意识**。本 ADR 只规定"什么时候不许说什么"。
- **不约束用户的私人表达**。规则约束本仓的产出，不约束用户怎么谈论千岁。
