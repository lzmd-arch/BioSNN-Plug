# ADR-0024：まず stub-LLM で自律トリガの探針を行う

[中文](ADR-0024-stub-llm-probe.md) · [English](ADR-0024-stub-llm-probe.en.md)

- **状態**：採用済み
- **日付**：2026-10-29
- **関連**：[ADR-0023](ADR-0023-llm-ablation-arm.ja.md)、第 5 フェーズ M2/M3b/M3g–M3k

## Context

本プロジェクトで最も反証可能な主張は「SNN が LLM をいつ呼ぶかを自律的に決める」ことですが、12 か月ロードマップの終盤に置かれています。既にある二つの証拠は、それを完了扱いすることを支えません：

- M2/M3b のトリガは**規則ゲート**（検索スコア閾値）であり、学習されたものではありません。M3b の「初回トリガ第 3 ターン、精度 1.000」は構造的な結果です；
- M3g の ES スケジューリングは全基準を満たしましたが平凡解（初期点に停滞）でした。M3h は識別可能なデータでのみ非自明な通過を得ました。M3i–M3k の STDP 側方トリガは合成ストリームで 1–2/4 から 4/4 へ改善しましたが、なおプロトコル層です。

実 LLM と製品形態を待つ限り、この主張は検証不能のままです。

## Decision

実 LLM の前に **stub-LLM 探針**を行う：プレースホルダ回答だけを返すアダプタで、次の三つに測定可能な証拠を得る：

1. **スケジューリング**：ES が学んだ呼び出し方策が規則ゲートより厳密に優るか（M3h が識別可能なプロトコルを与えている）；
2. **トリガ**：スパイク集団が呼ぶべき時に呼び、呼ぶべきでない時に黙るか（M3k の ROC 型評価）；
3. **コスト**：呼び出し回数と遅延が許容範囲か。

探針の結論は「経路とスケジューリングが成立／不成立」とのみ書き、**「自律トリガ能力が成立」とは書かない**。

## Consequences

- 最も反証可能な主張が数週間先に前倒しされる；
- 実 LLM は探針通過後にのみ接続され、モデル品質がスケジューリングの欠陥を隠せない；
- 代償：開放ドメイン対話は検証できず、構造とコストのみ。

## Alternatives

- **実 LLM に直行（M3b の路線）**：実施済みだが最初の三基準は構造的で帰属不能；終点としては却下。
- **規則ゲートのみを続ける**：最も安価だが「自律」が無意味になる；却下。
