# ADR-0013：協同性ベンチマークを P0 に引き上げ、共有インターフェース案を却下し、三者混合は第 5 フェーズ据え置き

[中文](ADR-0013-synergy-benchmark-priority-and-arbiter-scope.md) · [English](ADR-0013-synergy-benchmark-priority-and-arbiter-scope.en.md)

- **状態**：採択済み
- **日付**：2026-10-18（裁定）· 2026-10-24（記録）
- **関連**：計画書 §12.7（外部参考）；[`sweep_results/arbiter_synergy_task_spec.md`](../../sweep_results/arbiter_synergy_task_spec.md)（タスク仕様と判定基準の変遷）；[research/arbiter](../../research/arbiter/README.ja.md)（実装と結論）；[ADR-0010](ADR-0010-eprop-quadratic-storage-and-trace-propagation.ja.md)

## Context

P4 論文の骨子に関する議論で、ロードマップを変える二つの提案が出た：

1. **共有インターフェース**：Hebbian と e-prop を、同一の重みを共有させるのではなく、
   明示的な共有インターフェースを通じて協調させる；
2. **優先順位の前倒し**：第 5 フェーズの三者混合とスケジューリング次元を現フェーズへ引き上げる。

どちらも「協同」という語の意味の境界に関わる。ここを先に固定しないと、以後の「協同」の
数値は、検証可能性の異なる二つの機構を混ぜたまま報告されることになる。

## Decision

**① 共有インターフェース案は却下。** 意味の変形である——二つの表現の間の橋を測っており、
二つの規則が同一のシナプス上で協調することを測ってはいない。**明確にラベル付けされた
counterfactual アームとしてのみ**存続し、原生点の結果と並べて述べてはならない。

**② 優先順位の反転：協同性ベンチマークが P0。** 基準の点位は **Hebbian ↔ e-prop の原生点**、
すなわち二つのラインがもともと共有している重み（入力 → 隠れ層）。判定基準の原意は
「単独では失敗し、混合でのみ成功する」。e-prop ↔ R-STDP の反対事実アームは**ベンチマークの
後**に回し、ベンチマークの結果が出てから設計する。

**③ 三者混合とスケジューリング次元は第 5 フェーズのまま動かさない。** ベンチマークの都合で
前倒しはしない。

**④ 維持事項**：43 件のテストが通る基盤は維持する。衝突判定の per-row cosine と retention の
**併記**も従来どおり。

## Consequences

- **原生点の形はタスクが決める**：sMNIST は 1 ステップにつき画素 1 行しか入力しないため、
  共有重みは `28 → 256` であり、静的 MNIST の `784 → 256` ではない。モデルを小さくしたのでは
  なく、タスクの形態がそう決めている。
- **判定基準の変遷は記録しなければならない**：当初の基準は「H 単独で失敗、E 単独で失敗」を
  要求したが、実測はそれを否定した——純 Hebbian が Fisher 比を 0.309 から 0.472 へ押し上げた。
  2026-10-18 に **協同量の基準**（`Fisher(MIX) − max(Fisher(H), Fisher(E)) ≥ δ = 0.05`）へ
  差し替えた。これは **MIX の数値を見る前に**書かれたものである。基準の変更を ADR に残さなければ、
  後から読む者は結論が変わった理由を説明できない。
- **反対事実アームは消えないが、ラベルが付く**：共有インターフェースの路線は実行してよいが、
  結果は counterfactual として書かなければならず、「協同が成立するか」の答えには使えない。
- **第 5 フェーズの境界は清いまま**：三者混合とスケジューリング次元は、現フェーズのいかなる
  実験にも現れない。
