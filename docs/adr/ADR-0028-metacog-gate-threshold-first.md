# ADR-0028：元认知门控——机制照实落地，产品先量阈值

[English](ADR-0028-metacog-gate-threshold-first.en.md) · [日本語](ADR-0028-metacog-gate-threshold-first.ja.md)

- **状态**：已采纳
- **日期**：2026-11-01
- **相关**：元认知 v8–v11、[ADR-0021](ADR-0021-criterion-death-conditions.md)、
  `BioSNN-Plug_项目计划书_v6.3_amend1.md`、Axo 的 `docs/prereg-metacog-v1.md`

## Context

一份外部集成任务书把「元认知门控」写成一个**已经验证的 512 神经元 SNN 组件**
（"MG v11 已验证（三维门 OOD 全过）"）。核对之后，事实是：

- MG v11 是 4 维情景记忆任务上、由读出残差 `[max_errors, errors, state_norm]` 三个标量
  驱动的 **kNN(5) 密度门**，没有脉冲、没有 ALIF、没有 e-prop，也没有留下任何权重文件；
- 它自己的 README 写明「四族全过」只覆盖四种**合成输入变换**，不是通用 OOD 的证明；
- `biosnn_bus` 的 `SpikeBus` 目前是骨架（无 `state()`、无层）。

Axo 里按**真实机制**落地了一版（三特征换成召回账本上的 `top_score` / `mean_topk` /
`density`），在 217 条真实库副本上离线评测：门控 AUROC **1.000**，而单特征
`top_score` 阈值也是 **1.000**（难正样本 0.996 vs 0.996）。按预注册判据（需 +0.05 增量）
**未通过**，未接线。

## Decision

1. **机制照实落地，不照名字落地。** 任何"接入 MG v11 / 元认知 SNN"的要求，先按
   `research/cognitive/run_metacognitive_gate_v11.py` 的真实形态核对；把不存在的组件
   当前提的方案一律重写。
2. **产品路径先量阈值。** Axo 的"弱记忆不注入"用召回层的一个融合分阈值实现；阈值由
   真实库分布标定（陌生话题 top 分最大 0.163、正样本 p5 0.211 → 取 0.20），不用三特征门。
3. **判据写死"必须有增量"**：任何新门控在接线前，AUROC 必须比最佳单特征基线高 ≥ 0.05；
   达不到按平凡解处理（[ADR-0021](ADR-0021-criterion-death-conditions.md) 的同类纪律）。
4. **脉冲版本进排期、不实现**：进入条件（bus 有层 / 有标注的自然语言 OOD 集 /
   速率型版本已落地量过）写在计划书 amend1 里。

## Consequences

- 研究层的 MG v11 保留在仓库里，作为"特定基准上可行"的组件；产品层不走它；
- 少一层看不懂的复杂度；阈值可解释、可回退、有曲线可核；
- 代价：元认知这件事在产品上退化成"一个门槛"，而不是"一个认知机制"——这是**当前配置下
  证据支持的唯一结论**。

## Alternatives

- **照任务书接 SNN 门控**：组件不存在，等于把研究从零做起并跳过验证；否决。
- **接三特征门（不比阈值强）**：AUROC 相同，只增加复杂度与调参面；否决。
- **不做任何过滤**：陌生话题每轮注入约 60 条弱相关记忆，是真实的产品伤口；否决。
