# ADR-0018：第 3 フェーズの CL ゲートをタスク認識 CIL（task-incremental）へ変更

[中文](ADR-0018-task-aware-cl-gate.md) · [English](ADR-0018-task-aware-cl-gate.en.md)

- **状態**：採用済み
- **日付**：2026-10-26
- **関連**：計画書 §7 第 3/4 フェーズ；[ADR-0017](ADR-0017-cl-main-route-switch-and-replay-first.ja.md)；
  [`continual_v2/README.md`](../../sweep_results/continual_v2/README.md)；
  [`task_inference_strong_prereg.md`](../../sweep_results/continual_v2_task_inference_strong_prereg.md)

## Context

第 3 フェーズの CL ゲートは**純粋な CIL**（タスク id を渡さず、既知の全クラスで argmax）で、
**AF < 8% かつ ACC ≥ 65%** でした。2026-10-26 までに、すべての機構をこの口径で測っています：

| 機構 | ACC | AF | 備考 |
| :--- | ---: | ---: | :--- |
| R-delta-mini（参照） | 0.2466 | 0.8047 | リプレイも隔離もなし |
| replay ρ0.3 | 0.3630 | 0.7399 | リプレイだけでは不足 |
| 正規化 N1 / N1-scale | 0.269 / 0.315 | 0.903 / 0.792 | `no_signal` |
| 出力行の隔離 P1 | 0.5426 | 0.1739 | 獲得が崩れる |
| P1 + リプレイ | 0.4310 | **0.0291** | AF は通るが ACC は通らない |
| 特徴マスク F1 | 0.2343 | 0.7727 | Fisher ≈ ランダム |
| タスク推論（プロトタイプ / 対角 Mahalanobis / 全共分散 / delta 分類器） | 0.42 / 0.461 / 0.586 / 0.242 | 0.17 / 0.157 / 0.128 / 0.808 | 最終ルーティング 0.30 / 0.35 / 0.53 / 0.10 |
| **oracle のタスク別ヘッド + タスク id** | **0.8195** | **0.0** | 上界 |

結論は [`continual_v2/README.md`](../../sweep_results/continual_v2/README.md) に封存済みです：
**この特徴空間では CIFAR-100 の 10 タスクは単純な局所判別器では分離できず、タスク id を
与えない純粋な CIL は ACC ≥ 65 / AF < 8 に到達しません。**

## Decision

1. **第 3 フェーズの CL ゲートをタスク認識 CIL（task-incremental）に変更**します：
   **推論時にタスク id を渡してよい**（訓練時のタスクラベルは元々利用可能）。ACC ≥ 65% /
   AF < 8% の定義は変えず、argmax を**真のタスクのヘッド内**で取ります。
2. この口径では oracle のタスク別ヘッドが **ACC 0.8195 / AF 0.0** に達し、第 3 フェーズの
   CL ゲートは**この口径に限り**通過と記録します。
3. **「タスク推論 CIL」は主張しません**：局所ルーター 4 種（プロトタイプ、対角/全共分散
   Mahalanobis、delta 分類器）の最終ルーティングは 0.10–0.53 で、90% には遠く及びません。
   推論のみの口径は**通過しておらず**、本 ADR の主張には含めません。
4. **純粋な CIL の公開済み数値と陰性結論はそのまま保持**します。本 ADR はゲートの口径だけを
   変え、履歴は書き換えません。
5. 第 4 フェーズの入口は引き続き**第 3 フェーズの受け入れ**です：タスク認識 CL ゲート（本 ADR）
   と「規則変更後の再学習が 3 倍速い」（未実行、設計は事前登録済み）の両方が必要です。

## Consequences

- **AF = 0 は構成的**です：各タスクのヘッドは訓練後に凍結され、タスク id も既知なので、
  古いヘッドは上書きされません。これは**プロトコル上の通過**であり、抗忘却アルゴリズムの
  結果ではありません。数値の隣に必ずそう書かなければなりません。
- プロジェクトの主張は "class-incremental" から "task-incremental" に変わります。論文・
  計画書・対外資料を同期させ、oracle の 0.82/0.0 を「純粋な CIL 達成」と書いてはいけません。
- 純粋な CIL の境界は本フェーズの実質的な成果です：**タスク境界の情報を推論に入れる必要が
  ある**ことを示す、価値のある陰性結果です。
- **「再学習 3×」**は未実行です（設計：
  [`relearn_3x_prereg.md`](../../sweep_results/relearn_3x_prereg.md)）。本 ADR はそれを
  通過させません。
- W3 のスパイク化と世界モデルの下地は影響を受けず、各自の事前登録／バックグラウンド待ちで
  進みます。

## Alternatives

- **純粋な CIL のまま未達と記録**：最も誠実ですが、試験したどの構成でも届かないゲートで
  第 4 フェーズを塞ぎます。境界なのか目標なのかを決める必要があります。
- **タスク推論 CIL に切り替える**（入力からタスクを推論）：局所ルーター 4 種は最終 0.10–0.53
  で、通過口径としては実測で否定済みです。
- **表現を変えて純粋な CIL を続ける**（特徴の訓練、より強い骨干、非局所手法）：新しい研究線で
  最も高コスト、かつ「純粋に局所」という主張と緊張します。本フェーズでは開始しません。
- **AF = 0 をアルゴリズムの成果として提示**：拒否。凍結したタスク別ヘッドと既知のタスク id に
  よる構成的な結果です。
