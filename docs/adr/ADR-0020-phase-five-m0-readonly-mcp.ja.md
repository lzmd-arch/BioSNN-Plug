# ADR-0020：フェーズ5 M0——読み取り専用 MCP 骨格、自主性より先にインタフェース

## Context

フェーズ4 は厳格な口径で収束した：E2E v18 は状態レベル 18/18、P3 v6 のローリング時域
閉環は ready、WM v9／エピソード v5／メタ認知 v11 も ready。**500 ステップの純粋想像 P3
閉環は、証明済みの構造的境界として残る**。フェーズ5（LLM 統合と協調）は未開始で、リポジトリに
MCP Server、LLM adapter、トリガモジュール、対話 trace はない。

タイマーで LLM を呼ぶスクリプトは、自律に見えて監査不能な系を作る：ツール schema も
トリガ定義も、毎ターンの状態／検索／呼び出し／固定化の記録もない。フェーズ5 の成功基準
（10 ターン以内の初回自律呼び出し、トリガ精度 70%+、固定化 80%+、タスク完了率 +50%）は
いずれも観測可能なパイプラインを前提とする。

## Decision

1. **フェーズ5 M0 を開始：読み取り専用 MCP 骨格**。`packages/biosnn-mcp` を追加し、
   依存なしの JSON-RPC 2.0 over stdio で三つの読み取り専用ツール `state.query`、
   `memory.search`、`trigger.status` を公開する。認知核は `InMemoryCore` の代替。
2. **M0 は LLM に接続せず、記憶を書かず、トリガを武装しない**。`trigger.status` は常に
   未武装を返す。M0 で「自律トリガ」の結論は成立しない。
3. **LLM は外部推論エンジンに限る**：シナプス学習経路に入れず、勾配も渡さない。API key は
   リポジトリに入れない。すべてのツール呼び出しは記録・再生可能でなければならない。
4. **フェーズ5 の正式受入は M1–M3 の新しい事前登録で定義する**：M1 トリガ + mock LLM
   adapter、M2 結果の再符号化／固定化、M3 対話評価。M0 は成功基準に数えない。
5. **フェーズ4 の境界は変えない**：500 ステップ純粋想像 P3 は未解決のまま。フェーズ5 の
   開始を「解決済み」とは書かない。

## Consequences

- MCP クライアントが列挙でき、テストが駆動できる最小インタフェースが得られる。ネットワーク
  依存なし。ツール schema と読み取り専用境界を先に固定し、実認知核を差し替えても名前/引数は
  変えない；
- 代価：M0 に「知能」はない。`trigger.status` は常に false で「機能欠落」と誤読されうる。
  これは意図的で、スクリプト呼び出しを自律トリガと誤認しないための既定値である；
- 次のマイルストーンは実 LLM の前に mock LLM adapter と対話 trace を補うこと；
- 新パッケージは CI でテストする；`biosnn-bus` の骨格独立性（ADR-0001）には影響しない。

## Alternatives

- **今すぐ実 LLM をタイマーで呼ぶ**：最短で「呼び出し」を見せられるが、自律トリガと
  スケジュールを区別できず、key／監査も未定。却下。
- **スクリプト/関数だけ書き MCP を立てない**：実装は少ないがツール schema とクライアント
  契約がなく、フェーズ5 の「交換可能な推論エンジン」が成立しない。却下。
- **HTTP サービスから始める**：MCP stdio の方が小さく、ポート/認証面がない。HTTP は
  デプロイ段階で評価。M0 では却下。
- **純粋想像 P3 が解けるまで待つ**：その境界はビット一致しない任意のモデルには到達不能
  （P3 v6 README）。待てばフェーズ5 が無限に遅れるため、境界を記録して M0 を開始する。
