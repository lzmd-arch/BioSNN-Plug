# ADR-0012：TAAF 的局部性红线、投影层训练规则（待决），以及 `SpikeBus` 输出形状的接口契约

[English](ADR-0012-taaf-locality-and-bus-output-contract.en.md) · [日本語](ADR-0012-taaf-locality-and-bus-output-contract.ja.md)

- **状态**：部分采纳（局部性与输出契约已采纳；投影层训练规则**留待阶段二裁决**）
- **日期**：2026-10-13
- **相关**：计划书 §2.2（脉冲总线：TAAF + 双通道融合）、§3.1、§七 第二阶段；[ADR-0002](ADR-0002-numpy-core-torch-optional.md)（骨架库不依赖 torch）、[ADR-0006](ADR-0006-plugin-interface-fidelity.md)（插件接口保真）

## Context

计划书 §2.2 说脉冲总线集成「TAAF 时间注意力引导的自适应融合」，§七 第二阶段把它列为
任务「TAAF 快速微调」。但仓库实况是：`FusionStrategy` 只有 `ConcatenateFusion` 一个
实现，`bus.py` 的注释写着「`FusionStrategy` 是 TAAF **未来插入**的位置」——
**TAAF 从未实现**。计划书那句"快速微调"假设它已经存在，所以措辞与实况不符。

三条约束在开工时被明确：

1. **注意力权重的局部性**：TAAF 的 time-attention 权重必须由**局部可计算的信号**驱动
   （如各路发放率），**不允许反向传播训练**——否则"纯局部学习"的声明在融合层就被戳穿；
2. **投影层的训练规则要在 ADR 里定死**：膜层用 IB-Hebbian 还是简单的局部归一化，
   **现在不定也要列出选项**——这是阶段二的核心问题，不是一次能顺手答的；
3. **`bus` 输出形状写进接口文档**：融合输出 = **统一核心维度** + **模态标签保留**。

## Decision

### 一、局部性红线（已采纳，硬约束）

**融合层的注意力权重只由各路自己的发放率现算**（rate-based gating），实现为
`TemporalAttentionFusion.attention_weights`：

```text
rate_i = mean(|data_i|)          # 每路的平均发放率——每个神经元局部可读
w      = softmax(rate / τ)
out    = Σ_i w_i · projected_i
```

**没有任何 `backward`、没有可训练参数、没有 torch。** `test_taaf.py::TestLocalityRedLine`
用 **AST 结构断言**钉死这一点（查 import 与调用，不是肉眼看源码），因为这条红线
一旦被绕过，"纯局部学习"就不再成立。

**为什么用 rate-based 而不是 Hebbian**：两者都满足红线（都在本地可算），但 rate-based
最简单、且权重能从数据当场算出来写测试断言。Hebbian 版本的权重要跨时间累积痕迹，
可检查性更差。**这条不是排他性裁决**——若后续实验表明 Hebbian 权重更好，可换实现，
红线不变。

⚠️ **这条红线在骨架库进产品之后更要守住。** 产品侧可能有"学一学融合权重"的诱惑，
那是用训练换来的性能，代价是"纯局部学习"这条声明失效。

### 二、输出形状接口契约（已采纳，硬约束）

`SpikeBus.step()` 的返回值：

| 字段 | 取值 |
| :--- | :--- |
| 形状 | `(T, bus_dim)` —— **第二维恒等于** `bus_dim`，与注册了几个模态、各模态 `spike_dim` 多少**无关** |
| 通道 | 跨通道求和后的结果；`channel` 字段已无意义，模态的通道信息只在 `describe()` 里保留（按 `modalities_by_channel` 归组） |
| dtype | `float64`，稀疏随机投影带 ±1 权重的输入电流 |

**第二维恒为 `bus_dim` 是承诺，不是巧合**：下游认知核心可以按 `bus_dim` 建维度而
不必知道上游有几个模态。这一点在换融合策略时**都不变**——两条工作点的差异只在
**怎么合成一路**，不在输出维度。

**模态标签保留**：融合之后单一序列上没有"哪一路是哪个模态"的位，所以标签不放在
`SpikeTrain.channel`（那条语义是"走哪条融合通道"，不是"哪个模态"）。标签的正解是
留在 `describe()` 的 `modalities_by_channel` 里——**这已经实现**，本次补进接口文档。

### 三、投影层的训练规则（**留待阶段二裁决**）

这是阶段二的核心问题，本次**不拍板**，只登记选项。三条候选：

| 选项 | 内容 | 代价 | 备注 |
| :--- | :--- | :--- | :--- |
| **A. 固定种子随机投影**（现状） | `SparseRandomProjection`，±1 权重，`zlib.crc32` 派生种子 | 不可学习；保距离是 JL 引理的性质，但**不是为任务优化的** | 当前实现。**无训练、无反向传播**，与红线一致 |
| **B. IB-Hebbian 局部学习** | 投影矩阵用核化 IB-Hebbian 在线更新（同 `research/ib_hebbian`） | 引入学习率、HSIC 核、除法归一化等超参；**但仍是局部的** | 与"感知层用 IB-Hebbian"的既有选择同源 |
| **C. 简单局部归一化** | 固定投影 + 每神经元局部归一化（除法归一化 / 膜层） | 最轻；但"归一化"不是学习，只是稳定 | 已有 `Membrane` 协议与 `PassThroughMembrane` 占位 |

⚠️ **三条候选都满足局部性红线**（都不用反向传播），所以这不是红线问题，是
**能力**问题：固定投影的表征能力最弱，IB-Hebbian 最强但超参最多。选哪条要看
跨模态检索 R@1 那个成功标准能不能过（§七 第二阶段）。

⚠️ **裁决前不要动 `SparseRandomProjection` 的语义。** 它的"±1 投影保距离"是
`research/` 三条验证线的前提；改它之前要重新验性质。本次 C3 的改动**只加了**
按单路维度取投影的 `_projection_for`，**没有改**投影矩阵本身或它的种子派生。

## Consequences

**已采纳的两条**（局部性红线、输出契约）会约束后续所有融合策略的实现——
任何新策略都必须通过 `test_taaf.py::TestLocalityRedLine` 的 AST 断言，并且输出
第二维恒为 `bus_dim`。

**待决的第三条**是阶段二的一个真实缺口：现在的投影矩阵是随机的，**没有为任务
优化过**。跨模态检索 R@1 50%+（§七 成功标准）如果够不到，第一个要查的就是这里。

**计划书措辞要改**：§七 第二阶段「TAAF 快速微调」应改为「**实现 TAAF 时间注意力
融合**（rate-based gating，无反向传播）」——"快速微调"这个词假设 TAAF 已经存在。
