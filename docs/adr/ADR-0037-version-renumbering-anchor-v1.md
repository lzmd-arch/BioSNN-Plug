# ADR-0037：版本重编号——旧 V1 降为 V0.5 存档，人格与记忆核成为 V1

[English](ADR-0037-version-renumbering-anchor-v1.en.md) · [日本語](ADR-0037-version-renumbering-anchor-v1.ja.md)

- **状态**：已采纳
- **日期**：2026-11-15
- **相关**：`research/sel/design-semprea-v2-architecture.md`、`research/sel/prereg-persona-in-weights.md`、ADR-0017（Route R）

## Context

2026-11-14 之前，"V1" 指的是 **Semprea-4.5B**：千问 4B（冻结）+ 0.5B 局部规则快半，
在**输出分布**上做 token 级融合。该版本已冻结，并留下三条不可动摇的负结果：

1. 四种 token 级融合算子**全部没有超过温度对照**；
2. SNN 做生成 / 编码 / 判别 / 序列四测四负（0/543、0.015、0.763、0.562）；
3. 加性条件偏置在真实骨架上两次为零（S0）。

随后方向改变：**融合从"输出分布"移到"人格与记忆"**——本地不再争当生成器，
而是做**锚**（身份、记忆、行为约束），生成交给云端。这条路线已经拿到正结果：
池状态解码 0.64–1.0、读出层持续学习 AF 0.80→0.22、危机门召回 0.996 @ FPR 0.11。

于是出现命名冲突：**两个完全不同的东西都叫 V1**。继续沿用会让"V1 的效果如何"
变成一个没有指认对象的问题——而这正是本项目一直在防的那类错误。

## Decision

1. **旧的 Semprea-4.5B（千问 + 0.5B 快半的输出级融合）重编号为 `V0.5`**，
   **存档，不再对外发布**。它的结果、预注册、负结论**全部保留**，引用时必须写 `V0.5`。
2. **人格与记忆核成为 `V1`**，模型名 **Semprea-Anchor-0.5B**（中文：锚核）。
3. 本 ADR 之前文档里的"V2"一律读作"V1"；"V1"一律读作"V0.5"。
   **不逐份改写历史文档**（那会破坏它们的时间戳语义），只在新文档与索引里用新编号。
4. `dist/semprea-4.5b-v1.0/` 与 `dist/v1.0/` 原地保留，各加一份 `ARCHIVED.md` 指向本 ADR。

## Consequences

- 对外只能说："V0.5 是输出级融合，已存档，四个算子均未超过温度对照"；
- **V1 的判据不再是 token 级增益**，而是 `prereg-persona-in-weights.md` 的 I-1…I-7；
- `persona-core` 这个包名**不变**——它是机制，不属于任何一个版本；
- 版本行统一写成 `Anchor v1 · persona v8 · birth 2026-11-16`。

## Alternatives

- **继续叫 V1、把新的叫 V2**：两个 V1 同时存在，或者要为一个尚未成型的东西预留 V2，
  两种都让"V1 怎么样"失去唯一指认对象；
- **把旧的叫 V1-final、新的叫 V1-next**：同样的歧义，只是藏得更深。
