# ADR-0024：先用 stub-LLM 做自主触发探针

[English](ADR-0024-stub-llm-probe.en.md) · [日本語](ADR-0024-stub-llm-probe.ja.md)

- **状态**：已采纳
- **日期**：2026-10-29
- **相关**：[ADR-0023](ADR-0023-llm-ablation-arm.md)、阶段五 M2/M3b/M3g–M3k

## Context

本项目最可证伪的主张是「SNN 自主决定何时调用 LLM」，但它在 12 个月路线里排得很后。
已经跑出来的两项证据都不支持把它当已完成：

- M2/M3b 的触发是**规则门**（检索分阈值），不是学习到的；M3b 的「首触发第 3 轮、准确率 1.000」是构造性的；
- M3g 的 ES 调度判据全过但是平凡解（停在初始点）；M3h 用可辨识数据才得到非平凡通过；
  M3i–M3k 的 STDP 侧向触发在合成流上从 1–2/4 做到 4/4，但仍是协议层。

如果继续等真实 LLM 与产品形态，这条主张会一直不可检验。

## Decision

在真实 LLM 之前先做 **stub-LLM 探针**：用一个只返回占位回答的 LLM 适配器，
在以下三项上取得可测证据，再谈真实模型：

1. **调度**：ES 学到的调用策略是否严格优于规则门（M3h 已给出可辨识协议）；
2. **触发**：脉冲群体触发是否在该调用时调用、不调用时不调用（M3k 的 ROC 式评估）；
3. **代价**：调用次数与延迟是否在可接受范围。

探针的结论只写成「管道与调度成立/不成立」，**不**写成「自主触发能力成立」。

## Consequences

- 最可证伪的主张被提前到几周内，而不是路线终点；
- 真实 LLM 只在探针通过后接入，避免用模型质量掩盖调度缺陷；
- 代价：探针不能在开放域对话上验证，只能验证结构与代价。

## Alternatives

- **直接上真实 LLM（M3b 路线）**：已做过，前三条判据构造性，无法归因；否决作为终点。
- **继续只做规则门**：实现最省，但「自主」二字无从谈起；否决。
