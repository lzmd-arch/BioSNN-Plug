# 预注册修订 3：S-3 的方向性读法与 presence 的基线口径

**时间**：2026-11-14，**在宣告 S-3 判定之前写**。

## 改了什么

| 项 | 原文 | 改成 |
| :--- | :--- | :--- |
| **S-3 的方向** | `\|zero − 0.109\| ≤ 3pp` | **只守"高于基线"那一侧**：`zero − 基线 ≤ 3pp` |
| **基线** | 固定 0.109 | 每个任务**自己算**：10 类任务的均匀基线 0.100，`presence` 用其末值分布的**多数类占比 0.129** |

## 为什么

S-3 的目的写得很清楚——"**说明任务泄露了文本信息**"。泄露只会让 `zero` 臂**变好**，
不会让它变差。实测 `time` 的 `zero` 是 **0.000**、`memory` 是 **0.092**，两个都**低于**基线，
却被字面规则判为"泄露"。那是把"比随机还差"读成"泄露"，与判据的意图相反。

这是**收紧方向一致、放松方向明确**的一次修订：新的读法只堵住"zero 偏高"，
`zero` 偏低不再算失败（偏低本身是训练在无信息输入上塌缩，另记）。

`presence` 的随机游走末值分布不匀（10 档占比 0.078–0.129），多数类 0.129 ≫ 0.100。
用固定 0.109 会把"0.141"误判成泄露；按本任务自己的多数类基线，`zero` 只高 **1.2pp**，
在 3pp 之内。

**写在前面的后果**：按此读法，`time`（0.000）与 `memory`（0.092）**通过 S-3**，
`presence`（0.141 vs 0.129）**通过 S-3**，`temp`（0.109 vs 0.100）**通过**，
`persona`（0.100 vs 0.100）**通过**。
