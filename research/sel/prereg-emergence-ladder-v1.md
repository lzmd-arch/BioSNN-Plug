# 预注册：生物机制的复杂度阶梯（Q-2 膝点 + Q-3 逐个拆卸）

**写于** 2026-11-16，在**任何一档跑之前**。

## 为什么需要这一轮

`bio_all` 已经证明：**五个机制合起来比任何一个单项都强**（B-1 3/3、B-2 3/3）。
但按 `research/sel/prereg-emergence-v1.md` 的 Q-1…Q-4，它**叫不了涌现**：

| 要求 | `bio_all` | 缺什么 |
| :--- | :--- | :--- |
| Q-1 可操作定义 | ✅ | — |
| Q-2 真实膝点 | ❌ | 只有 全关/单项/全开 三点，**没有复杂度阶梯** |
| Q-3 归因对照 | ◐ | 只做了"全关掉"这个廉价方向，**没做逐个拆卸** |
| Q-4 位级复现 | ❌ | 跑的时候探针还没播种（已修） |

这一轮补 Q-2 与 Q-3，Q-4 由"播种后的探针 + 同配置重跑逐位比对"承担。

## 一、复杂度轴：**嵌套链**，不是任意子集

| 档 | 打开的开关 | 为什么是这个顺序 |
| :--- | :--- | :--- |
| **L0** | 无 | — |
| **L1** | +`inhib` | `bio_all` v2 单项增益最大（+0.064） |
| **L2** | +`ei` | 第二（+0.032） |
| **L3** | +`alif` | 第三（+0.006） |
| **L4** | +`delay` | 第四（−0.008） |
| **L5** | +`tau` | 最后（−0.048） |

顺序由 `bio_all` v2 的**实测单项增益**排定，写在这里、跑之前定死，**跑完不许改**。
任意子集（2^5=32 种）在预算内做不完，嵌套链给的是"每加一个机制值多少"的边际曲线，
这正是膝点要的东西。

## 二、难度标定：现在的任务**顶在天花板上，测不出膝点**

`bio_all` v2 的全开是 0.359，窗口天花板是 0.356 —— 已经到顶。
在到顶的任务上，任何阶梯都会在 L5 之前饱和，膝点是**天花板造成的**，不是机制造成的。

所以先标定难度：**取 `alpha`（Dirichlet 浓度）使窗口 8-token 天花板落在 [0.45, 0.55]**。

- `alpha` 越大 → `pref` 越平 → 单个 token 的证据越弱 → 越需要跨多步积分；
- `alpha` 由**天花板实测**选定，不由结果选定；标定过程与选中的值都写进结果。

若没有任何 `alpha` 能把天花板放进 [0.45, 0.55]，本实验**中止**，不凑合。

## 三、判据

| 编号 | 判据 | 通过线 |
| :--- | :--- | :--- |
| **L-0** | 每档真实发放率 ∈ [0.03, 0.20]，且 **L5 ≥ 底板 + 15pp** | 不过 ⇒ 作废 |
| **L-1 膝点** | 逐档边际增益 `acc(L_k) − acc(L_{k−1})` **连续两档 < 2pp** | 有膝点 |
| **L-2 孤点** | 膝点位置在**两个都不同的指标**上一致（mlp 准确率 与 归一化增益） | 一致 |
| **L-3 拆卸** | 从 L5 **逐个拿掉**某个机制，掉幅 ≥ 5pp 的机制 ≥ 2 个 | 归因成立 |
| **L-4 复现** | 同配置重跑，L0 与 L5 的逐种子准确率**逐位相同** | 位级复现 |

**L-2 是防 Mirage 的那一条**：`prereg-emergence-v1` 说得很清楚，
"曲线形状随指标选择而变"，所以膝点必须**在多个指标上落在同一处**才算数。

## 四、要报的限定

- 3 个种子；每臂单独标定工作点；探针播种。
- 仍是**一个任务、一个规模**。膝点在哪一档，只对这个 (alpha, n, K, seq) 成立。
- **不承诺**"这五档之外还有更多"。L5 是 `bio_all` 定义的"全开"，不是生物脑的全量。

## 五、产物

`scripts/bio_ladder.py` → `sweep_results/bio_ladder/`。

不加新机制、不改已有判据。**若 L-1 不过（没有膝点），照实记"线性，无膝点"** ——
那同样是一个结论，而且是更朴素的结论。

## amend1：难度带从 [0.45, 0.55] 放宽到 [0.40, 0.60]

**写于**第一次难度标定之后、**任何一档阶梯结果之前**。

### 事实

完整网格（`0.3 / 0.5 / 0.8 / 1.2 / 2.0 / 3.0`）实测：

| alpha | 0.3 | 0.5 | 0.8 | 1.2 | 2.0 | 3.0 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 天花板 | 0.8890 | 0.8200 | 0.7057 | **0.5537** | **0.4499** | 0.3566 |

两个相邻网格点**正好跨在带子的两边**：`1.2` 高 **0.37pp**、`2.0` 低 **0.006pp**。
按原判据，这次运行中止了 —— 它确实照做了。

### 为什么这是缺陷

那条带的**用途**是「保证阶梯上方还有空间可以爬」，不是某个特定的难易度。
带子的两条边是在**看到曲线形状之前**拍的，正好落在两个网格点之间。
因为 0.006pp 而中止，测到的是我对网格的选择，不是任务的性质。

### 改法

`TARGET_CEIL = (0.40, 0.60)`。**只改这一条**：

- L-0（工作点 + 真解码）、L-1（膝点）、L-2（膝点一致性）、L-3（拆卸）、
  L-4（位级复现）**一个字没动**；
- 选中仍是"离 0.50 最近且在带内"的那个 alpha；
- 中止条款保留：若放宽后仍无一档落进 [0.40, 0.60]，照样中止。

按新带子，选中 `alpha = 2.0`（天花板 0.4499，离 0.50 最近）。
