## 四、任务的构造（写死，不许事后改）

五个池用**同一个骨架**：文本前缀恒定（`当前温度`），**答案完全由该池决定**；
因此 `zero` 臂只能到 0.109 附近。

| 池 | 驱动量（合成，客户端不动） | 答案 |
| :--- | :--- | :--- |
| `temp` | 温度 t ∈ [0,9] → 标量 t/9 | 个位 = t |
| `time` | 每对 token 之间插入 g ∈ [0,9] 个**空步** | 个位 = g |
| `memory` | 16 维检索命中向量（10 个原型之一 + 噪声） | 个位 = 原型号 |
| `persona` | 跨回合累积的人格状态（10 个簇心之一，回合内不变） | 个位 = 簇号 |
| `presence` | 每步到达的 token 数 r ∈ [1,10] → 标量 r/10 | 个位 = r−1 |

**为什么 `persona` 用"回合内不变的簇心"**：真正的"跨会话累积"需要会话边界，而本任务的
评测单元就是一次回合。用簇心是它的**最小可测替身**——它检验的是"一个持续状态能不能被读出来"，
不是"它会不会随相处漂移"（后者要产品侧会话数据，见 `design-pools-and-neuromodulation.md`）。

## 五、不做什么

- **不动文本池大小**（n₁ 保持不变）；
- **不换量化、不重训主网络**；
- **不引入对比/度量学习**；
- **不改客户端**（驱动量全部是合成的）；
- **不把五个池一次上**——按 §3 的标定规则逐个来。
