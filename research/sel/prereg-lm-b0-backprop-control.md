# 预注册：B0——同尺寸反向传播对照（2026-11-08）

**状态：判据先落盘，随后立即开跑。**

## 为什么要有这一轮

这条支线的**所有**实验，对手都只有 **bigram**（一张计数表）。它证明了"局部规则的 SNN 在真语料上输给 bigram 10pp"，
但**没有告诉我们一个同尺寸、同数据、同分词、用反向传播训的网络会不会也输**。

这个问题不回答，过去所有"局部规则输/赢"的结论都缺基准；而 R3/R4/R5/R6q 测的是架构细节，
若真正的限制是数据，那些实验测的就是错的东西。

**这不是"SNN vs Transformer"的架构比较**——两者归纳偏置、信用分配、优化器都不同。
它只回答一件事：**这 3.4 万字，够不够任何一个 1.6M 参数的网络学到超过 bigram？**

## 设计（跑之前定死）

| 项 | 局部规则臂（R0b） | **B0（本轮）** |
| :--- | :--- | :--- |
| 语料 | `D:/AxoData/sel/lm/v1/real.jsonl`，大折（训练 252 对、测试 13 对） | **相同** |
| 分词 | 字符级，`MAX_VOCAB=800` + `<unk>` = 801 | **相同** |
| 截断 | `MAX_LEN=192` | **相同** |
| 数据暴露 | 8,000 updates × batch 16 × 192 字（与 R0b 曲线第 8,000 步对齐） | **相同** |
| 模型 | 前馈 LIF，N=1,024，1.64M 参数 | **单层 GRU，emb 128 / hidden 512，约 1.50M 参数** |
| 优化 | 逐时刻局部规则（e-prop），`lr_in=1e-3`、`lr_out=0.5`（NLMS） | **Adam，lr ∈ {1e-3, 3e-3}，weight_decay=1e-4，dropout=0.1，梯度裁剪 1.0** |
| 种子 | 0 | **0** |

**学习率跑两个**，取较好的那个报告——**不许用一个没调过的 lr 当稻草人**。

**参考点**：bigram top-1 = **0.1669**；SNN（τ=20）第 8,000 步 = **0.0657**。

## 判据

| # | 情形 | 判定 | 后果 |
| :--- | :--- | :--- | :--- |
| **B0-1** | BP 的 top-1 **≥ bigram** | **数据够用** | SNN 输 10pp 是**学习规则**的账；局部分支的核心命题受到直接挑战 |
| **B0-2** | BP 的 top-1 **< bigram** | **数据不够** | 任何 1.5M 参数的网络在这个语料上都学不过 bigram ⇒ 架构实验（R3/R4/R5/R6q）测的是错的东西，该转向数据与分词 |
| **B0-3** | BP 赢 SNN ≥ 3pp 但**仍 < bigram** | 两者都有份 | 报出"规则"与"数据"各占多少 |

**B0-1 与 B0-2 之间没有"平"的地带**：bigram 是一条明确的线（0.1669），BP 要么在线上要么在线下。

## 必须一起报的量（防稻草人）

1. **两个 lr 的结果都报**，不只报好的那个；
2. **参数量对齐**：GRU 1.50M vs SNN 1.64M（差 9%）——若 BP 赢，这 9% 不足以解释量级差；
3. **数据暴露对齐**：同样 8,000 个 batch、batch 16、长度 192；
4. **BP 的优势要说明**：BPTT 有 192 步的完整信用分配，SNN 是逐时刻在线更新——**这是"规则"的定义性差异，
   不是不公平**，但解读时必须写出来。

## 不做的事

- 不扫架构（GRU vs Transformer vs LSTM）——第一轮只回答"数据够不够"；
- 不调正则到最优——dropout 0.1、wd 1e-4 是默认值，两个 lr 是唯一的手调；
- 不在合成语料上跑（问题只出在真语料）。

## 边界

- 单折、单种子；13 对测试（与 R0b / R5 / R6q 同折，可直接并排）；
- **这不能证明"局部规则不行"**：即使 B0-1 成立，也只说明"在这个数据量与预算下 BP 行"；
- 字符级 next-token，**不代表能闲聊**。

## 成本

8,000 updates × 192 步 × batch 16 ≈ **5–10 分钟/臂**（两个 lr 共 10–20 分钟）。
