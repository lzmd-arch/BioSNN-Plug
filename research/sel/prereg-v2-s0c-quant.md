# 预注册 S0c：换量化算不算「调千问权重」——Q4_K_M vs Q6_K 的标定对照

**日期**：2026-11-14，在看到 Q6 的任何数据之前。

## 为什么这条是本轮唯一能执行的"改权重"

S0/S0b 暴露：**Q4_K_M 的最优全局温度是 T=3.65**（极度过度自信），
而自适应温度能在此基础上再拿 **+0.26 nats**。

于是出现一个直接的问题：**这个过度自信是量化造成的，还是模型本身的？**
如果是量化造成的，那"改权重"最便宜的落点就是换精度，不是加算子。

**能执行 / 不能执行**（写清楚，免得被当成推脱）：

| 做法 | 能不能做 | 原因 |
| :--- | :--- | :--- |
| 全参数微调 4B | ❌ | 8 GB 卡：fp16 权重就 8 GB，没有余量放优化器与激活 |
| QLoRA / LoRA | ❌（**规则排除**） | 用户明令"强来自 LoRA 就不要做 LoRA" |
| 权重平均 / 模型合并 | ❌ | 本机只有 GGUF，没有可训练的 HF 权重 |
| **换量化（Q4_K_M → Q6_K）** | ✅ | 本地已有 `Qwen_Qwen3-4B-Instruct-2507-Q6_K.gguf`，**这是真实的权重改动** |

## 装置

- 同一批 **540 个位置、同一划分、同一 p、同一算子**；
- 只把服务端的模型从 `Qwen3-4B-Q4_K_M` 换成 `Qwen_Qwen3-4B-Instruct-2507-Q6_K`；
- 其余参数（`temperature=0`、`n_probs=100`、上下文 2048）完全相同。

## 判据

| # | 判据 | 阈值 |
| :--- | :--- | :--- |
| **S0c-1** | Q6 的 B0 相对 Q4 的 B0 | 报差值（配对，同一位置），**不设方向** |
| **S0c-2** | Q6 的最优全局温度 | 报数值；**离 1 更近 ⇒ 过度自信主要是量化造成的** |
| **S0c-3** | Q6 上自适应温度相对全局温度还有多少余量 | 报数值 |

**这一条是描述性的，不设通过/不通过**——它回答的是"下一分钱花在哪"。

## 边界

- **Q6_K 是 2507 版本**（`Qwen_Qwen3-4B-Instruct-2507-Q6_K`），与 Q4_K_M 那个可能不是同一代；
  **版本差与精度差混在一起**，结论只能说"换了权重文件之后如何"，不能说"精度本身的因果"；
- 换服务端要**短暂停掉 8081 上的 Q4 进程**，跑完立刻按原命令行恢复。
