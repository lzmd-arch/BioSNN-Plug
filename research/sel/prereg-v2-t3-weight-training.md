# 预注册 T-3：在 8 GB 上真正改千问权重（4-bit 底座 + 只训输出头）

**日期**：2026-11-15
**前置**：`prereg-v2-training.md` §T-3。S0c 已证明**换量化不是杠杆**，所以这里不是"再换一个量化文件"，
而是"**用 4 位量化当底座去训**"——这是唯一能在 8 GB 上改变权重形状的路径。

---

## 一、为什么是"4-bit 底座 + 只训输出头"

| 方案 | 显存 | 结论 |
| :--- | ---: | :--- |
| 全参 bf16 | 8.04 GB 权重 + 优化器 | **放不下** |
| LoRA / QLoRA | 可以 | **被规则排除**（"强来自 LoRA 就不要 LoRA"） |
| **NF4 4-bit 底座（冻结）+ `lm_head` bf16 可训** | ≈3.5 GB | **可行，且不是 LoRA** |

`lm_head` 是唯一直接改变输出分布的那一层；它可训不等于"给模型加个补丁"——
它换的是**词表上每个 token 的偏置**，这正是 S0 里加性偏置想做而没做到的那件事
（那时是在**外部**加偏置、没有任何可学信号；这里是在**模型内部**、用真实梯度训）。

## 二、装置

| 项 | 值 |
| :--- | :--- |
| 底座 | `Qwen/Qwen3-4B`（已下载 7.6 GB），NF4 双重量化，**body 冻结** |
| 可训 | `lm_head`（tied embeddings 需解绑）+ 可选 final norm |
| 数据 | FineWeb-2 `cmn_Hani`（ODC-By），512 token 窗口，训练/留出**按文档分片分开** |
| 优化 | AdamW，lr 1e-4，batch 2，梯度累积 8，**2000 步** |
| 评测 | **同一份 540 个位置的 S0 协议**（ECE / 平均 log p / top-1） |
| 显存 | 预计 ≈3.5 GB；需先停掉 8081 上的 llama-server（同一模型，跑完恢复） |

## 三、判据（写死）

| # | 判据 | 阈值 |
| :--- | :--- | :--- |
| **T3-1** | 留出集 **ECE** | **< 0.0425**（= 全局 T=1.5 的标定水平，但**不引入温度**） |
| **T3-2** | 固定 T=1 的真值平均 log p | 提升 **≥ 0.05 nats** |
| **T3-3** | top-1 | **不低于基线 0.463**（不许用牺牲排序换标定） |

**三条全过 ⇒ 权重量化训练这条路有头寸，V2 的融合多一个接口；
任一不过 ⇒ 结论是"8 GB 上改权重买不到标定"，照登，不换判据重跑。**

## 四、当前阻塞（写清楚，别当成推脱）

本机 `.venv` 的 **numpy 元数据损坏**（`dist-info/METADATA` 缺失，`importlib.metadata.version('numpy')` 返回 None），
`transformers` 的版本检查直接报错；修复需要重装 numpy，而 `.pyd` 被正在运行的服务（Axo 的
llama-server / TTS）占用，返回"拒绝访问"。

**两条路**（都需要用户决定）：

1. **停掉占用 numpy 的本机服务**（Axo 的 llama-server、TTS），重装 numpy，再跑训练；
2. **换一个干净的 venv 或机器**做 T-3，本仓只保留代码与判据。

训练栈本身**已装好**：`transformers 5.23 / peft 0.21 / accelerate 1.15 / bitsandbytes 0.50`。
`bitsandbytes` 的 CUDA 4-bit 后端**尚未验证**（同一道 numpy 阻塞挡住了 `import`）。
