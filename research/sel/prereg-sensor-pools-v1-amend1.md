# 预注册修订 1：驱动尺度的标定网格

**时间**：2026-11-14，**在跑正式 S-1 之前**。原判据见 `prereg-sensor-pools-v1.md`。

## 改了什么

**只改标定的扫描网格，不改判据本身**（"取发放率最接近 0.275 的那档"这条规则原样保留）。

| | 原网格 | 改成 |
| :--- | :--- | :--- |
| `init_scale` | {0.5, 1, 2, 4} | **{2, 4, 8, 16, 24, 32, 48, 64}** |

## 为什么

原网格全部落在**静默区**：`init_scale ≤ 8` 时温度池发放率恒为 0.00，判据退化成
"所有候选都一样差"，没有信息量。原因是本模型的 `sensor_proj` 初值是
`randn · init_scale / √n_rec`，而驱动电流还要乘传感器读数（温度任务里均值 0.5）、
再过 α=0.951 的膜积分 ⇒ 有效驱动被压掉约一个数量级。

**这不是阈值不达标所以放宽**——判据（rate ∈ [0.05, 0.50]、取离 0.275 最近的一档）
一个字没动，只是把网格覆盖到工作区。

## 顺带记下的一条

扫描时发现：`init_scale = 32`、**完全不学习**（`lr-sensor=0`）时温度池 top-1 已经是 **0.289**，
而 `init_scale ≤ 16` 时无论学多久都是 0.100。这是对
"**信息来自结构（随机投影 + 阈值），不是来自学习**"（F4）的第四次独立印证，
写结果时必须带上。
