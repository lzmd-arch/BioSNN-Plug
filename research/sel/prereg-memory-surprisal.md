# 预注册：用局部规则模型给真实记忆库打"惊讶度"分（2026-11-11）

**状态：判据先落盘**（本文件写于第一次完整打分**出数之前**；此前那次 150 更新的试跑只用来验证管线，**不作数**——它相对均匀只降 1.3%，模型基本没学到）。

## 动机

这个模型当聊天模型落后 BP 约 23pp，但当"**用户自己的文本分布模型**"未必不够用。
惊讶度（逐条 CE）作为"该不该记 / 重不重要"的打分器，**不需要模型会聊天、不需要 1B、不需要 GPU、不需要流式**。

Axo 的真实库里有现成的结局变量：`access_count`、`reinforce_count`、`weight`。

## 做法

- **只读**：打开 `D:/AxoData/memory/snapshots/mem-20261110T100005.db`（`mode=ro`），主库一个字不碰；
- 334 条真实记忆，字符级，词表取自库本身；
- **2 折**：每折在 167 条上训练 1,200 次更新，给另外 167 条打分（**打分条目模型没见过**）；
- 指标：逐条 CE，与 `access_count` / `reinforce_count` / `weight` 求 Pearson 相关。

## 判据

| # | 结果 | 结论 |
| :--- | :--- | :--- |
| **M-0** | 中位 CE 相对均匀分布降 **< 10%** | **打分器太弱，整轮作废**；先加训练量/模型，不许解读相关系数 |
| **M-1** | 与 `access_count` 的相关 **≥ +0.25** | 惊讶度 ≈ 重要性 ⇒ 可做"该不该记"的打分器 |
| **M-2** | 相关 **≤ −0.25** | 惊讶度 ≈ 新颖度 ⇒ 可做**去重/新颖性**信号，不是重要性 |
| **M-3** | **\|相关\| < 0.15** | 与真实使用无关，**这条路否**，不再投入 |

**M-0 是前置**：模型没学到东西时，任何相关系数都是噪声。

## 必须一起写的限定

- 相关系数**不等于因果**，也不等于"打分器可用"；它只回答"这个分数和真实使用有没有单调关系"；
- `access_count` 受**查询分布**影响（同一个查询会命中多条），不是纯粹的"重要性"标签；
- 单库、334 条、单种子族；**这是产品探针，不是研究结论**。
