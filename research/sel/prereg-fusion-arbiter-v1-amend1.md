# 预注册修正 1：位置数与区间口径（2026-11-14）

原文：[`prereg-fusion-arbiter-v1.md`](prereg-fusion-arbiter-v1.md)（**原文不改，本文件覆盖下列三条**）。

**触发时机**：开跑前核对数据量时发现，**没有看到任何结果**。下面三条都是协议缺陷，
不是"结果不好所以放宽"。

## 一、数据量：真库只有 102 条，不是 218

`mem.db` 里 `length(content) > 40` 的只有 **102** 条（218 是更早快照的数）。
按原协议（每条约 10 个位置、步长 12）留出集只有 **302** 个位置 < Q-0 要求的 500。

**改**：

- 记忆门槛 `length(content) > 40` → **`> 24`**；
- 每条位置数上限 10 → **16**，步长 12 → **6**。

口径不变：位置仍是"第 20 字起、上下文截 256 字、真值 = 之后的原文、前缀匹配判命中"。

## 二、区间口径：按位置 bootstrap 是错的，改成按记忆聚类 bootstrap

原协议写的是"配对 bootstrap 95% 置信区间"。**配对重采样位置是错的**：
同一条记忆里相邻位置几乎同一句话，命中与否高度相关，按位置重采样会把区间算窄，
从而把噪声读成显著。

**改**：**聚类 bootstrap——重采样"记忆条目"，条目内所有位置一起进出**。
这会**放大**区间，是更严格的判据。Q-3 的门槛（区间下界 > 0）不变。

## 三、顺带记录两条不变的东西

- **特征集不变**（原文那 7 个，一个不加、一个不减）；
- **模型不变**（带类别平衡的 L2 逻辑回归，阈值只在训练集上选）。

无论 Q-3 过不过，结果 README 必须写明"位置数与区间口径按 amend1 调整过，
调整发生在看到任何结果之前"。
