# Semprea-4.5B（2026-11-12 命名）

**Semprea = semper（始终）+ -ea。** 一个**总在该场**的组合模型：
云端在时它是影子，云端不在时它是唯一的回答者。

> 版本顺序（V1 打包 → V2 加语料续训）、包里必须有哪几件、以及 V2 的冻结项与判据，
> 见 [`plan-semprea-versions.md`](plan-semprea-versions.md)。

## 一、组成

| 半 | 是什么 | 参数量 |
| :--- | :--- | ---: |
| **慢半** | 千问 Qwen3-4B（GGUF / llama.cpp，只出分布，**一个字不改**） | 4.0B |
| **快半** | 局部规则脉冲模型（层次 softmax 树读出） | 0.5B |
| **合计** | | **≈4.5B** |

## 二、融合（已经建成）

```
score(token) = log q_千问(token) + α · log p_SNN(token)
      ↓  并集上 softmax → argmax → 一个 token
```

- **同一个分布、同一次采样**——去掉任何一半都会改变输出；
- 千问的词表一个字节不动，只在**输出侧**叠加；
- 跨分词器靠**字符串前缀归并**（千问候选 "同时" ← 我们所有是它前缀的 token 概率之和）；
- **α 是唯一旋钮**。

## 三、当前状态：α\* = 0，而且是剂量–反应

文本-only、留出分片、40 个位置：

| α | top-1 | 真值平均 log p |
| ---: | ---: | ---: |
| **0（千问单独）** | **0.2250** | **−10.651** |
| 0.1 | 0.2250 | −10.675 |
| 0.25 | 0.2000 | −11.082 |
| 0.5 | 0.1000 | −12.980 |
| 1.0 | 0.0750 | −18.443 |

配套 F-0：**"千问错而 SNN 对" = 0/30**。

**原因**：两边吃的是同一份公开语料 ⇒ 同一分布上的更弱模型，偏离就是噪声。

## 四、唯一能让 α 离开 0 的通道：**传感器**

产品里的 SNN 还能读**环境与多模态数据**（温度、气体、光照、噪声、屏幕、设备状态）。
**这些数据不出设备，云端永远拿不到**——这是 Semprea 与"千问 + 任何公开模型"的**结构性差别**：

```
p(下一个 token | 文本, 传感器)   ← 只有快半有
q(下一个 token | 文本)           ← 慢半
```

### 实现（已完成）

| 件 | 位置 | 状态 |
| :--- | :--- | :--- |
| 模型的传感器通道 | `model.py`：`sensor_dim`，`sensor_proj`（**零初始化**），作用于**电流** | ✅ |
| 服务的入参 | `serve_snn` 的 `/complete` 接受 `sensors: [float]` | ✅ |
| 等价守卫 | `tests/test_sensor_channel.py`：零向量/无向量时**逐位一致** | ✅ 3 条 |

**为什么加在电流而不是特征**：它与输入通路正交，不影响 e-prop 的资格痕迹（那些乘的是 `w_in` 的输入）。

## 五、判据（写死）

| # | 判据 | 不过怎么办 |
| :--- | :--- | :--- |
| **S-1** | 有传感器数据后重扫 α，**存在 α>0 使 top-1 高于 α=0** | 传感器没有信息量，Semprea 的融合部分收口 |
| **S-2** | 传感器**可解释**：同一文本换传感器值，argmax 的变化方向与语义一致（人工看 20 例） | 学了个无意义的偏置，收口 |
| **S-3** | 配对数据累积 N 天后，α\* 单调上升 | "在设备上持续学"没兑现 |

**S-1 在拿到配对数据之前无法测**——这是写死的阻塞项，不是可以绕过的细节。

## 六、必须同时说清的三件事

1. **今天的 α\*=0 不是失败**，是"慢半与快半此刻没有信息差"的**正确测量**；
2. **Semprea 现在不是一个更强的模型**，是一个**机制成立、权重为 0** 的组合模型；
3. **它的未来全押在传感器通道上**——若那条通道也没有信息量（S-2 不过），
   它就该退回"断网兜底"，而不是冒充一个融合模型。

# 第七节：用户头（User Head）——Semprea 里"学这个人"的那一块

## 一、它是什么

Semprea-4.5B 的包里除了两个半，还有**第三个组件**：

```
Semprea-4.5B
  ├─ 慢半  Qwen-4B       冻结，会说话
  ├─ 快半  SNN-0.5B      局部规则，会说"下一个词"
  └─ 用户头 user_head.pt  **在设备上、从这个人自己的数据里持续学**
```

**用户头不是插件，是包的一部分**：它随模型分发、随使用更新、离开这台机器就没有意义。

## 二、它学什么——不是"怎么干活"，是"这个人"

| 维度 | 载在哪个参数上 | 容量 | 一天的数据够不够 |
| :--- | :--- | ---: | :--- |
| **用词与话题偏好** | `tokens: (V,)` 对数先验 | 32,000 | ✅ 10⁵ token/天 ≈ 3 token/参数 |
| **环境与情境** | `sensor: (d_sensor, V)` | 16×32,000 = 512k | ✅ 读数稠密 |
| **工作方式**（先用哪个工具、拆几步） | 复用 `sensor` 的同一张表，把 agent 轨迹的标量特征接进去 | 同上 | ✅ 轨迹 10⁵–10⁶/天 |

**三样共用一套参数、一个更新规则**——这就是"属于用户自己的独特的东西"能落在一个包里的原因。

## 三、它怎么进到输出里（第三个融合项）

```
score(token) = log q_慢半(token) + α·log p_快半(token) + γ·log u(token) + u_sensor(env)[token]
                  └─ 会说 ─┘        └─ 会猜下一个词 ┘      └────── 懂这个人 ──────┘
```

- **α** 需要"快半知道慢半不知道的"（今天为 0，等传感器配对数据）；
- **γ 和 u_sensor 不需要那个前提**：它们直接编码**这个人的语言分布与自己这台机器的环境**，
  而**慢半的 8k 上下文装不下跨月的时间尺度**——这是它天然拿不到的信息。

## 四、怎么学（局部规则，不需要反向传播）

```
每夜：
  for 当天的每段文本 x_t:
      u ← u * decay + onehot(x_t)        # 指数遗忘，窗口 ≈ 30 天
  for 当天每条传感器读数 s 与随后窗口内的 token:
      u_sensor ← u_sensor + η · (onehot(x) − softmax(u_sensor·s)) ⊗ s   # 局部 logistic
```

- 全是**逐位置的局部更新**，不需要梯度穿过任何东西；
- `decay` 决定"忘得多快"，是**唯一的时间常数**；
- **旧的不许被无声丢掉**：每次更新前后各算一次在留出片段上的 log p，掉了就回滚（写进判据）。

> **命名冲突（2026-11-12 记）**：本节的 U-1/U-2/U-3 是**用户头**的判据；
> [`design-inseparability.md`](design-inseparability.md) §一里另有一套同名判据（换快系统 /
> 换慢系统 / 去持续学习）。引用时一律带括注「（用户头）」或「（不可分割）」。

## 五、判据（写死）

| # | 判据 | 不过怎么办 |
| :--- | :--- | :--- |
| **U-1** 冷启动无害 | `u` 为均匀、`u_sensor` 为 0 时，输出**逐位等于慢半** | 实现错，先修 |
| **U-2** 有增益 | 用一个人自己的前 80% 文本训 `u`，在**后 20%** 上 `γ` 的最优值使 log p **高于 γ=0** | 用户头没学到东西，收口 |
| **U-3** 不遗忘 | 连续 30 次夜间更新后，第 1 天的留出片段 log p 掉 **不超过 5%** | 加长 `decay` 或加回滚 |

**U-2 是这个组件唯一的生死线**：如果"这个人的语言分布"对下一个 token 没有预测力，
那它就不该出现在包里。

## 六、必须写死的三条边界

1. **用户头只在本地更新**，不外传、不上云——它编码的就是这个人的文本；
2. **它是可删除的**：删掉 `user_head.pt`，Semprea 退化成"两个半"的融合，不损坏任何东西；
3. **它不冒充"更聪明的模型"**：它只是一个**先验**，作用是让这个人的常用词更容易被选中，
   不改变慢半的知识与推理。
