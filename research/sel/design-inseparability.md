# 组合模型的独特性与不可分割性（2026-11-12）

**先说今天的事实**：它们**是可分割的**。SNN 通道 hit@1 0.4416，词法 0.8961——
把 SNN 换成 nomic，组合行为只会变好。**"不可分割"不是声明出来的，是测出来的。**

## 一、"不可分割"必须先有操作性定义

否则它只是修辞。定义成一条**替换测试**：

| # | 判据 | 不过说明什么 |
| :--- | :--- | :--- |
| **U-1（换掉快系统）** | 把 SNN 换成 nomic（或随机向量），**组合指标掉 ≥5pp** | SNN 是可替换的 ⇒ 它不构成模型的一部分，只是可选插件 |
| **U-2（换掉慢系统）** | 把千问换成另一个同级模型，**SNN 侧的特化指标掉 ≥5pp** | SNN 没有对这一个慢系统特化 ⇒ 耦合是假的 |
| **U-3（去掉持续学习）** | 冻结 SNN 权重、不做夜间更新，**一段时间的用户指标掉 ≥3pp** | "在设备上持续学"没兑现 ⇒ 只是又一个冻结的编码器 |

**三条全过，才叫不可分割。** 今天是 0/3。

## 二、三层"不可分割"，可行性差很多

### 第一层：结构层——共享词表/嵌入空间

- 已做：千问的 `token_embd` 几何迁进了我们的 `emb`（32,000/32,000 覆盖）；
- 但它只是**初始化**，训完之后就各自飞了。**不构成不可分割。**
- 若要真的共享，得让两边**同一套 token**——那会把读出宽度从 20,833 砍到 4,388，R3 说宽度是绑定 Δ 的。**不划算。**

### 第二层：行为层——**针对这一个慢系统特化**

这是唯一有机会做到 U-2 的层。做法是**黑盒特化**：

```
SNN 的头 → 一个信号（风格 / 触发 / 检索集）
        ↓
   千问（黑盒，不出梯度）
        ↓
   结果打分（人工或规则）
        ↓
   局部规则更新 SNN 的头
```

**关键**：千问只当黑盒，不做反向传播。这样既绕开了"没有梯度内存"的硬约束，
又让 SNN 的头**只对这一个是正确的**——换一个千问，它的输出就失去意义。

这是 U-2 唯一可行的技术路径，也是别人没做过的：**router / adapter 通常是用反向传播
训的，而这一层是纯局部规则、可以在用户设备上继续训。**

（软提示词那条更彻底，但 Ollama / llama.cpp 的服务栈不暴露输入嵌入，
**今天做不到**，不写进计划。）

### 第三层：部署层——**只有它能常驻 6 W 并持续学**

这一层不靠训练技巧，靠物理事实：

| | 千问 | SNN |
| :--- | :--- | :--- |
| 常驻 | ❌ 2.5 GB、GPU、15 tok/s | ✅ CPU、每 token 265 KB |
| 持续学 | ❌ 无梯度就学不了；有权重也回不去 | ✅ 局部规则，设备上就能更新 |
| 隐私 | ❌ 云端 | ✅ 从不联网 |

**这正是 U-3 要测的东西**：如果"持续本地学习"真的让用户指标变好，
那 SNN 就**在功能上不可替代**——不是因为它更强，而是因为**只有它做得到**。

## 三、独特性到底在哪

不是"把两个模型装在一起"。是这一句：

> **一个能在用户设备上持续学习、并且针对某个大模型特化的控制层。**

同业做 router 的是：用另一个大模型的反向传播训一个分类器，部署时冻结。
我们的是：**纯局部规则、在设备上、边用边学**。这条路线的唯一性来自它的约束
（没有反向传播），而不是来自它更大。

## 四、要兑现它，必须先过的三关

| 关 | 现状 | 缺什么 |
| :--- | :--- | :--- |
| G-B 记忆编码 | hit@1 **0.4416** vs 词法 0.8961 | 模型还在 5.5% 进度；且需要改述集才有分辨力 |
| G-C 风格 | 阻塞在标签 | 千问可以当标注器 |
| **U-3 的载体**：一个能"边用边学"的闭环 | **不存在** | 需要模拟流：模拟 N 天对话 → 每天更新 → 测指标 |

## 五、我的建议：先做最小闭环，别先谈打包

```
1  模拟流：把 208 条记忆切成 N 天的"新增"，模拟一个用户的写入
2  每天：SNN 编码新记忆 → 写入索引 → 冻结基线（nomic）做同样的事
3  第 N 天：在同一批改述查询上比 —— **动态索引 vs 冻结索引**
4  判据 U-3：动态的 hit@1 高于冻结 ≥3pp
```

**这条跑通，"不可分割"就有了第一个真证据；跑不通，就该承认它只是一个便宜的本地插件，
而不是一个组合模型。**

## 六、写死的一句

**在 U-1/U-2/U-3 全部为 0 的今天，把这两个东西打包成一个"组合模型"，
是在用一个不存在的整体性做产品承诺。** 我不会那样做——除非判据先过。

# 第四部分：F-0 —— 融合在结构上就死了（2026-11-12）

## 一、判据与结果

`scripts/f1_complementarity.py`：在**训练集之外的分片**上取 30 个位置，
比"千问 top-1 错而 SNN top-1 对"的比例。

```
n=30
  两个都对 3   只千问对 4   **只 SNN 对 0**   都不对 23
  千问 top-1 0.233      SNN top-1 0.100
判据 F-0（只 SNN 对 ≥5%）：**0.000% ⇒ 不过**
```

## 二、为什么这是结构性的，不是训练不够

| | SNN | 千问 |
| :--- | :--- | :--- |
| 训练数据 | **SkyPile 网页文本** | 中文网页文本（同一类） |
| 规模 | 0.5B、7.5% 进度 | 4B、充分训练 |

**同一份公开语料、更弱的模型。** 弱模型在同一分布上的偏离就是噪声：

> `log q + α·log p_snn` 只会把正确的分布**往错的方向拉**，α 取什么值都一样。

例子最直白：上下文"夏凉产品的需求大大增加。"，真值"届时"，SNN 给 `，`/`。`，
千问给 `同时`/`因此`——**千问答错的地方，SNN 也答错，而且错得更没信息量。**

## 三、唯一能打破它的信息，数据量上不成立

融合要有用，SNN 必须知道千问不知道的东西。**唯一可能的来源是用户本地的私有数据**
（它从不出设备，云端永远拿不到）。

而 U-3 已经量过那条墙：

```
一个人一天 ≈ 10⁴ token，0.5B 权重需要 10⁹ 才动得起来  ⇒ 差五个数量级
```

⇒ **"它知道你不知道的"这个承诺，在数据量上不成立。**

## 四、结论（写进结论段，不再软化）

**"组合模型"不是"一个更强的模型"，是"一个能在断网时不说谎的降级方案"。**

- L3（logits 融合）**不做**，F-0 已经判死，不必再花 3–4 天；
- 该做的是断网兜底：**检索直出（主力）+ 候选补全（弱，但诚实）**；
- 三条不可分割判据的最终账：**U-1 = 0、U-2 = 0（F-0 即其反面证据）、U-3 = +0.27pp**。

**F-0 这条实验比任何架构设计都更根本：它把"融合值不值得"从几周的工程变成一个 2 分钟的测量。**
