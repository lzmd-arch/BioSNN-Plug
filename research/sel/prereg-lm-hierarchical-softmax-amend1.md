# 预注册修正 1：层次 softmax 的**成本模型**与 H-2 的评测点（2026-11-11）

**本文不改 H-0/H-1/H-2 的判据，只补两条原预注册没写、但决定"在哪测"的事实。**

## 一、树省的是「按行取权重」的次数，比值是 `V / (B·depth)`

稠密路径一步要**读整张 `(M, V)` 表**三次（前向 / 信号 / 更新，更新还要写回一次）。
树路径一步只碰 **`B·depth` 行**（每个样本走 `depth` 个内部节点）。于是

```
省下的倍数 ≈ V / (B·depth)
```

**这条式子有两个后果，原预注册都没写：**

1. **词表小时没有收益。** KdConv 的 `V = 3001`、`B = 256`、Huffman 平均深度 ~11–12
   ⇒ `B·depth ≈ 3,000 ≈ V`，**比值 ≈ 1.0**。H-0 那 7× 是在 `V = 32,000` 上测的
   （`32,000 / 3,840 ≈ 8.3`，实测 7.1，扣掉 gather 的固定开销后对得上）。
2. **批量越大收益越小。** `B = 4,096` 时 `B·depth ≈ 49,000 > V`，树**比稠密还慢**。
   层次 softmax 是「小批量 + 大词表」的优化，不是普遍优化。

**因此 H-1（质量）与 H-2（速度）必须分开测，且报的数字不能互相替代。**

## 二、H-2 的评测点钉死

| 项 | 值 | 理由 |
| :--- | :--- | :--- |
| `V` | **32,000** | 1B 模型的词表规模；也是 H-0 通过时的形状 |
| `B` | **256** | 现行训练批量 |
| `M` | **16,384** | 1B 读出宽度 |
| depth | 实测平均深度（Huffman，按训练频次） | 不写理论值 |

**在 KdConv（V=3001）上跑到 3× 是不可能的，别拿那个数说 H-2 不过。**

## 三、补充三条实现事实（不影响判据，但影响读数）

1. **必须加 `n_nodes` 个标量偏置。** 零权重时每个节点都是 0.5，于是每个 token 的先验是
   `2^-深度`——高频短路径词的先验会远离真实一元分布。按训练频次的 `right_share` 取
   log-odds 后，零权重处恰好复现经验一元分布（守卫 `test_zero_weight_with_bias_reproduces_unigram`）。
   代价是 `V-1` 个标量，相对 `(V-1)·M` 可忽略，**但"参数量不变"这句话要改成"权重参数量不变"**。
2. **Huffman 树用旧实现建错过。** 子树频次只在两侧都是叶子时累加、否则记 0，
   建出的树只是一棵合法二叉树、不是最优树（`[0.5,1,1.5,4,20,21,23]` 上成本 157.5 对 153.5、最深 6 对 5）。
   已修，并加了 `test_huffman_matches_brute_force`（V=6/7 与暴力枚举比对）。
3. **树路径不走 tensor core。** gather + 逐元素乘加是**访存受限**的；稠密 matmul 走 tensor core。
   所以模型给出的 `V/(B·depth)` 是**上界**，H-0 实测 7.1 对模型 8.3 的差就是这部分。

## 四、这一步没改的事

- H-1 仍然是 **top-1 掉 ≤ 2pp**，在 KdConv、16,000 步、2 抽头上测；
- H-2 仍然是 **≥ 3×**，只是评测点按上表钉死；
- 没有引入学习型 router；没有改 τ、K、精度。
