# Semprea V2：真正的深度改进（方案，未预注册）

**V1 已训完、权重冻结。** 本文分两段：V1 在不重训前提下还能榨出什么，以及 V2 要改什么。

## 零、先把 V1 的天花板说清楚

V1 能拿到的**最好**成绩，是逼近 oracle：

```
oracle = 慢半 ∪ 快半 的命中并集
```

在 52 个位置的样本上它比千问单独高 **+5.8pp**，而 V1 现有的仲裁规则只多 1 个位置。
⇒ **V1 剩下的全部工作是"更会用它"，不是"让它更聪明"。** 任何声称 V1 能大幅超越
千问的说法，都必须先越过 oracle 这条线——那是不可能的。

## 一、V1 还能做什么（不重训，按性价比排）

| # | 项 | 状态 | 预期 |
| --- | --- | --- | --- |
| V1-a | **学出来的仲裁器** | 在跑 | 判据 Q-3：留出集 Δ 的聚类 bootstrap 下界 > 0 |
| V1-b | **n-best 序列级重排** | 未做 | 小模型在"整句打分"上常能帮大模型；机制已写（`scripts/fuse_nbest.py`），从未跑完 |
| V1-c | **候选补全的 top-5 召回** | 可直接用已有缓存算 | 产品真用得上的指标：真值是否落在给出的 5 个候选里 |
| V1-d | **α 在"用户记忆分布"上重扫** | 已有 0.03 | 现在的 0.03 是在 34/52 位置上选的，样本太小 |
| V1-e | 用户头 | 已测 | 无增益（γ\*=0，单调），不重跑 |
| V1-f | PMI 去偏 / 集成 / 置信门 | 已测 | 全部无效或噪声内，不重跑 |

**V1 的收口条件**：V1-a ~ V1-d 全部有结论（正或负），然后 V1 冻结，不再动。

## 二、V2 要解决的根本问题

V1 的快半和千问**吃同一份公开语料**（FineWeb-2）。同一分布上的更弱模型，偏离就是噪声——
这正是 **F-0 只有 3/52（旧快半 0/30）** 的原因。

> 融合增益的上限，由两半信息的**差集**决定。差集不扩大，怎么调仲裁器都是在噪声里捞。

所以 V2 的唯一主线：**让快半拥有千问没有的信息**。

## 三、四条差异化路线（按可落地性排）

### 路线 1：用户自己的文本（今天就有数据）

真库 116 条可用记忆 / 约 5–6 万 token，加上会话记录与笔记。量小，但**分布是产品的目标分布**，
而且千问从没在这上面训练过。

- 做法：在 V1 检查点上**继续预训练**（不是从零）；
- 风险：5 万 token 对 0.5B 模型是"几个 epoch 就记住"，**极易过拟合**。
  ⇒ 必须先量"留出记忆上的 CE 是否下降"，而不是"训练集 CE"；
- 判据 `V2-A`：留出记忆上的 top-1 比 V1 高 **≥ 2pp**，且**训练/留出 CE 不脱钩**。

### 路线 2：传感器 / 环境（真正的独占信息，但今天没有配对数据）

SNN 有传感器输入通道（`sensor_dim=16`，投影头零初始化，没有向量时逐位无副作用）。
温度、气体、光照、噪声、设备状态——**这些数据不出设备，云端永远拿不到**。

- 今天**没有**配对的 (传感器, 文本) 数据，只能靠产品跑起来积累；
- ⇒ 这一条不能作为 V2 的主线，只能作为"数据到位后重开"的挂起项；
- 判据（将来）：同一文本、有无传感器向量，**α\* 从 0 变成 > 0**。

### 路线 3：换分词粒度（最便宜的一条，且不依赖新数据）

现在的快半用千问词表的 32k 子集——从构造上最大化了它与千问的**误差相关性**。

- 字符级语料已在建（7744 字符 + 256 字节回退，`scripts/build_char_corpus.py`），**未开训**；
- 词表小 ⇒ 读出的宽度可以更宽而总参数不变；
- 错误结构与子词模型天然不同 ⇒ **F-0 有机会变大**；
- 判据 `V2-B`：同预算下 **F-0 ≥ 2×V1（≥ 6/52）**；top-1 允许下降（它的角色是补差异，不是单独最准）。

### 路线 4：目标函数改成"融合后最准"（最深的一改）

V1 的快半是照 next-token CE 训的，目标是**自己最准**。但它在融合里的角色是
"在千问不确定的地方提供不同意见"——**这两件事不是一回事**。

- 做法：训练时把 `log q_slow` 当成**固定偏置**加进来：
  `loss = CE(softmax(log q_slow + α·log p_fast), truth)`，`q_slow` 从缓存里取；
- 等价于直接优化"融合后的 CE"，而不是"快半自己的 CE"；
- 副作用：这样训出来的快半**单独会更差**（它不再追求自己最准），这是预期行为，不是缺陷；
- 判据 `V2-C`：融合后的留出 CE 比 V1 的融合低 **≥ 0.1 nats**，且 top-1 不降。

## 四、臂的顺序与代价

| 臂 | 改什么 | 训练成本 | 先决条件 |
| --- | --- | ---: | --- |
| **V2-B** | 分词粒度 → 字符级 | ~38 h（同 V1） | 语料已就绪（在建） |
| **V2-C** | 目标函数 → 融合 CE | ~38 h | 需要缓存好的慢半分布 |
| **V2-A** | 继续预训练 → 用户分布 | ~4–8 h | 需要先解决过拟合 |
| V2-D | 传感器通道 | 挂起 | 需要配对数据 |

**先做 B 再做 C**：B 改的是"信息的形状"，C 改的是"优化的目标"。若 B 已经把差集拉开，
C 的收益要在新的差集上重测——两臂不能并行，否则互相盖住。

## 五、V2 的失败预案（先写死）

- **V2-B 的 F-0 没有翻倍** ⇒ 说明"换粒度"不足以拉开差集，V2 回到路线 1/2，
  并且要在 README 里写清"分词粒度不是差集的来源"；
- **V2-C 的融合 CE 没降 0.1 nats** ⇒ 写"目标函数不是瓶颈"，并把这条从候选里划掉；
- **两臂都失败** ⇒ 结论是"在纯文本、无独占信息的条件下，融合增益上限就在 V1 附近"，
  这仍然是一个**有信息量的负结果**——它把 V2 的必要条件钉死在"独占数据"上。

## 六、不做什么

- **不重训慢半**（千问的权重一个字节不动，这是硬边界）；
- **不引入新的大模型**（那就不是"组合模型"了）；
- **不为 V2 改 V1 的已发布判据**。
