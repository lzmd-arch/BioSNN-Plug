# 预注册：流式协议 —— 在 BPTT 结构性做不到的地方评测（2026-11-11）

**状态：判据先落盘，随后开跑。**

## 为什么换协议

我们今天所有的数字都是**固定语料、离线、batch=16、单机**。这四条恰好是 **BPTT 最强的四条**，
也是局部规则四条优势全部归零的设定。**我们主动选了一个必输的赛场，然后花五轮证明自己输。**

文献里局部规则真正赢的地方不在这里（准确率上最好的结果是 tPC-RTRL 的 **1.865 vs 1.864 BPC——追平**），
而在 **BPTT 结构上做不到**的地方：在线流式、常数内存、无回放、持续学习。

## 协议（写死）

| 项 | 值 |
| :--- | :--- |
| 批 | **1** |
| 更新 | **每个 token 一次** |
| 回放 | **无** |
| 状态 | **不增长**（实测 10,169 个标量，与流长无关） |
| 指标 | **prequential**：先预测、再更新，不允许偷看当前标签 |
| 边界 | 跨对话对（`\x01`）的步跳过 |

## 判据

| # | 门槛 | 判什么 |
| :--- | :--- | :--- |
| **STREAM-0** | 流后 top-1 显著高于流前 | 流式学习确实发生了（不是"跑完没学"） |
| **STREAM-1** | **常数状态**：状态标量数不随流长变化 | BPTT 在同协议下是 O(L·B) |
| **STREAM-2** | 分十分位报 top-1 | 看**持续学习**：后面的十分位是否比前面高 |
| **STREAM-3**（下一步） | 同协议下 **T=1 截断 BPTT** 的对照 | 这才是"结构性赢"的证据 |

**STREAM-3 是判决点**，但它需要另一套实现，本轮只出 STREAM-0/1/2。

## 必须一起写的限定

1. **流式数字不能和 batch=16 的数字直接比**：更新次数不同（batch=16 一步更新一次，
   流式每个 token 更新一次，同样 token 数下流式更新次数多 16 倍）。
   所以流式 top-1 可能**高于**离线结果，那是**更新次数**的功劳，不是"流式更好"。
2. 单种子、单折；
3. **不含 BPTT 对照 ⇒ 本轮只能证明"我们能在这个协议下学"，不能证明"我们赢"**。

## 成本

30 万训练 token + 15 万测试 token ≈ 半小时（batch=1，受内核启动限制）。
