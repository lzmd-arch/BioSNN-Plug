# 预注册：规模预算——这台 8 GB 机器能训练多大（2026-11-10）

**状态：判据先落盘。** 目标：把"1B 训到可用"从推算变成**可判的真/假**。

## 机器与现状

RTX 5060，**8 GB 显存**（桌面占 2.3 GB，可用 ~5.8 GB）、31.8 GB 内存、单卡、cc 12.0。
现状：KdConv 上 15.4M 参数、batch 16、**0.47 秒/更新**、每更新 ~656 token
⇒ **~1,400 token/s ≈ 0.08 TFLOPS**。

## 三笔账

### 内存（可行，但要分块）

1B 的构成（字符级 V=5,000）：`w_in` 5k×40k = 200M；`w_out` (4×40k)×5k = **800M**；合计 **1.0B**。

- bf16 权重 = **2.0 GB**；**局部规则没有梯度、没有优化器状态**（相对 BP 的结构性优势）；
- **致命项**：读出更新 `features.T @ gradient` 分配 `(M,V)` = 160k×5k×4B = **3.2 GB/步**
  ⇒ **必须按 V 分块**（分 8 块 → 400 MB）。

### 吞吐（当前差 100 倍以上）

每 token ≈ `2·M·V + V·N` = **1.8 GMAC ≈ 3.6 GFLOP**。

| 有效吞吐 | 20B token 的时间 |
| ---: | ---: |
| 0.08 TFLOPS（现在） | ~28 年 |
| 1 TFLOPS | ~2.3 年 |
| 10 TFLOPS | ~83 天 |
| 20 TFLOPS | ~42 天 |

### 数据

20B token = **200 亿字**；中文维基 ~4 亿字、LCCC ~10 亿字 ⇒ 差 20–50 倍；
只有 WuDao / SkyPile 一类百亿字级语料才够。

## 改动清单（按投入产出）

| # | 改动 | 解决什么 | 预期 |
| :--- | :--- | :--- | :--- |
| **T1** | `bench_train.py`：batch × N × V 的吞吐/显存扫描 | 现在没有吞吐基线 | 唯一可信的外推依据 |
| **T2** | 读出更新按 V 分块 | 1B 下 3.2 GB/步临时 | 3.2 GB → <0.5 GB |
| **T3** | bf16 权重 + fp32 阈值/累加 | 显存减半、tensor core | 吞吐 2–4× |
| **T4** | `torch.compile` 包住 step 循环 | Python 逐时刻开销 | **5–20×** |
| **T5** | batch 16 → 256（l_r 重标） | 小矩阵利用率 | 2–5× |
| **T6** | 低秩读出 `w_out = A(M×r)·B(r×V)`，r=512 | 读出占 80% 参数却只是查表 | 参数 800M → 85M，算力降 ~8× |

## 判据

| # | 判据 | 门槛 | 不达标怎么办 |
| :--- | :--- | :--- | :--- |
| **B-0** | 吞吐基线出数 | 三档 batch × 两档 N 全跑完 | 实验无效 |
| **B-1** | 编译不改变数值 | `torch.compile` 前后 100 步 CE 逐位一致（1e-6） | 放弃 T4，退回 T3+T5 |
| **B-2** | 1B 档内存可行 | batch 256 下跑满 100 步不 OOM，峰值 < 5.5 GB | 降 N 或降 batch，报实测上限 |
| **B-3** | **1B 档每步耗时** | **< 30 ms/步**（batch 256） | **> 100 ms ⇒ 判 1B 不可行**，转 ~100M |

**B-3 是判决点**：用实测吞吐把"1B 训到可用"变成可判的真/假。

## 已知结论（写在前面的判断）

1. **1B「训到可用」在这台机器上边缘不可行**：内存可以（2 GB bf16），算力即使打到 20 TFLOPS 也要 42 天；
2. **这台机器上"可用"的现实规模是 ~100M 参数 / ~2B token ≈ 33 小时**（按 10 TFLOPS）；
3. **50 系「算力解锁」这条路已排除**：Blackwell 用 RISC-V FSP 作信任根、SEC2 移出初始化链，
   20/30/40 系那套（4090 165→331 TFLOPS）**无法移植**；而且我们只在半速峰值的 0.2–0.3% 上跑，
   **解锁翻倍的天花板与我们无关**。

## 不做的事

- 不追 Chinchilla 最优比例；不上 CPU offload；不改架构主干（低秩读出可开关，默认关）；
- 不在 1B 上跑收敛验证——只做 100 步上限探针。

## 边界

- 单卡 8 GB；所有外推都建立在**实测吞吐**上；
- "可用"没有定义（困惑度目标取决于语料），本轮只判**可行性**。
