# 千问 × SNN 的组合模型：设计与取舍（2026-11-11）

## 一、先说结论

**能做出"独特模型"，但独特性不在"更大的网络"，在分工。**

做不到的：把两边权重融成一个可端到端训练的模型。训练方式互斥——Qwen 要反向传播
（权重 4 GB + 梯度 4 GB + Adam 8 GB），我们一个梯度都不存；权重也没有可同构的层。

做得到的：**一个常驻、低功耗、能在线继续学的快系统，配一个按需调用的慢系统。**

## 二、分工

| | **快系统**（局部规则 SNN，0.5B） | **慢系统**（Qwen 4B） |
| :--- | :--- | :--- |
| 硬件 | N100，~6 W，常驻 | GPU / 云端，按需 |
| 每 token 权重触碰 | **1.02 MB**（树） | 2.5 GB（Q4 全量） |
| 吞吐 | 28k tok/s（带宽界） | ~15 tok/s（本机） |
| 训练 | **纯局部规则，可在设备上持续学** | 冻结，我们不训它 |
| 能力 | 下一个 token 候选 / 触发 / 风格 / 记忆编码 | 真正的对话 |
| 记忆长度 | ~64 步 | 32k 上下文 |

**快系统负责"要不要想"，慢系统负责"想"。**

## 三、接口：三个头决定要不要惊动慢系统

```
输入流 → SNN 基底 (N=10,417) → ┬ 触发头 (M×2)      → 调不调 Qwen
                              ├ 风格头 (S×M)      → 用什么语气
                              └ 记忆编码头        → 把这段编码进记忆库
```

三个头的参数加起来 **不到 LM 的 1%**（实测：0.04M / 0.17M / 5.33M vs 667M）。

## 四、为什么这算"独特"——四条别人不容易同时具备

1. **门控用局部规则训** ⇒ 可以在用户设备上**持续更新**，不需要 GPU、不需要反向传播；
2. **门控与记忆编码共享基底** ⇒ 一套特征、三个头，不是三个独立小模型；
3. **树读出让快系统在 6 W CPU 上跑** —— 每 token 1.02 MB，稠密读出是 2.67 GB（2,600×）；
4. **夜间巩固 = 快系统在慢系统空闲时自己回放**（"做梦"），这正是局部规则最自然的用法。

## 五、但三个部件各自都有前科，不能靠"架构对"就上线

| 部件 | 之前的结果 | 风险 |
| :--- | :--- | :--- |
| **触发器** | ADR-0029 暂缓：语料被脚本写成"表面线索可解"（目标轮下标在 20 段里完全相同，`len(text)` AUC 0.877） | **高——是数据问题** |
| **记忆编码** | M-3：LM 的惊讶度与"哪条记忆真被用到"无关（Pearson +0.023） | **高** |
| **风格** | ADR-0034：蒸馏路径 P4-3 = 1.148× | 中——已换窄方案（加性风格向量） |

## 六、判据（先写，各一条）

| # | 判据 | 不过怎么办 |
| :--- | :--- | :--- |
| **G-A 触发** | 相对"总是调用慢系统"，**在质量不掉 >1pp 的前提下，调用次数降 ≥30%** | 门控没有价值，砍掉 |
| **G-B 记忆** | **基线不是 TF-IDF**：Axo 现网是 lexical+semantic(nomic 768d) 融合，实测 **hit@1 0.8312 / hit@5 0.9091 / MRR 0.8565**（208 语料、85 查询，本机复现）。判据：SNN 通道把 **hit@1 抬 ≥2pp**，或 **paraphrase 子集 hit@1 从 0.20 抬 ≥10pp** | 记忆编码退回现网，SNN 不碰这条 |
| **G-C 风格** | S-1 / S-2 / S-3（`prereg-sel-reopen.md`） | 收口 |

## 七、"优化千问"在 8 GB 卡上能做到什么

| 想法 | 判断 |
| :--- | :--- |
| Q4 再压到 Q3/Q2 | 质量掉得比显存省得多，不值 |
| 换更小的千问（0.6B/1.7B） | 值得试——快系统 + 小慢系统可能比大慢系统更划算 |
| 本地跑 4B 做聊天 | 15 tok/s，产品上不可用 |
| **当标注器 / 离线教师** | ✅ **最值钱**：出标签，不出 token |
| 词嵌入几何迁移 | ✅ 见 `scripts/transfer_embedding.py` |

## 八、落地顺序

```
1  千问标注器（风格/触发标签）          ← 解 SEL 的 S-1 阻塞，过夜可跑
2  词嵌入几何迁移（Qwen → emb 初始化）   ← 分钟级，长尾 token 的初始化质量
3  0.5B 正式训练                        ← 产品形态的底
4  G-A / G-B / G-C 逐个验               ← 谁不过砍谁
5  组装：快系统常驻 + 慢系统按需         ← 产品集成
```

**顺序不能颠倒**：3 没过就没有快系统；4 没过就不能承诺"组合模型"。

# 第二部分：深度协同（2026-11-11 晚）

**"双系统"如果只做成一个触发开关，那只是一个便宜的分类器。** 深度协同要的是四个接口，
从浅到深：

| 层 | 接口 | 谁给谁什么 | 能不能立刻做 |
| :--- | :--- | :--- | :--- |
| **L1 触发** | 快 → 慢 | "要不要惊动你" | ✅ |
| **L2 上下文交接** | 快 → 慢 | SNN 的滚动状态，作为慢系统的**压缩上下文** | ✅ |
| **L3 草稿-验证** | 快 ⇄ 慢 | SNN 出 k 个 token，Qwen 一次前向验证（speculative decoding） | ⚠️ **需要同一套词表** |
| **L4 回写学习** | 慢 → 快 | Qwen 的输出成为 SNN 的输入/监督，SNN 用局部规则在线更新 | ✅（但要有节制） |

**L3 是唯一能直接改善产品延迟的**：Qwen 4B 在本机 15 tok/s，如果 SNN 的草稿接受率能到
60–70%，等效吞吐翻 2–3 倍。这也是"深度协同"最有说服力的形态——不是分工，是**一起出词**。

## 一、一个必须先做的决定：**词表对齐**

L3 和 L4 的最强形态都要求两个系统**用同一套 token**。现在我们是 BPE-32k、千问是 152k，
**L3 根本做不了**。

| 词表 | V | N（1B 预算） | M | 每 token 树读出 | 备注 |
| :--- | ---: | ---: | ---: | ---: | :--- |
| 我们的 BPE-32k | 32,000 | 10,417 | 20,833 | **1,015 KB** | 读出宽，但和 Qwen 不通 |
| **千问 152k** | 151,936 | 2,194 | **4,388** | **255 KB** | **能通**，但读出只有 4,388 宽 |

字符/token 两者同量级（我们实测 1.685；千问中文约 1.5–1.6），**压缩率不是决定因素**。

**代价很清楚**：换成千问词表，读出宽度从 20,833 掉到 4,388，而 R3 早就量过
**绑定 Δ 的是读出宽度**。所以这是一个真实的取舍：

- **要 L3（草稿-验证）与共享记忆文本** ⇒ 必须换词表，接受窄读出；
- **要读出宽度** ⇒ 保持 32k，放弃 L3，协同只到 L2/L4。

**建议：先量一次再定**——用千问词表重训一个同参数量的 15M 小模型，和 32k 那版比 top-10。
差 ≤1pp 就换；差得多就保宽度、放弃 L3。

## 二、和 Axo 各组件的对接（每个都要一条判据）

| Axo 组件 | 现状 | SNN 的介入 | 判据 | 风险 |
| :--- | :--- | :--- | :--- | :--- |
| **记忆召回** | lexical + semantic(nomic) 融合，**hit@1 0.8312 / hit@5 0.9091**；最弱的是 **paraphrase 子集 hit@1 0.20** | SNN 特征做**第三个通道**（不是替代词法） | hit@1 +2pp，或 paraphrase +10pp | M-3 已证明"LM 惊讶度 ≠ 记忆重要性" |
| **触发器** | M3b 通过；M3p 诊断出语料混杂，**暂缓** | 触发头 | 调用次数 **降 ≥30%** 且质量掉 ≤1pp | 高——是数据问题 |
| **语域路由** | CHAT 阈值 0.7 | 同一基底加一个路由头 | 不低于现网准确率 | 低 |
| **人设/风格** | 内置 v5 + 用户层 | 风格头 `f' = f + s[style]` | S-1/S-2/S-3 | 中 |
| **夜间巩固** | **无** | 回放当日对话 → 写记忆 | 次日召回 hit@5 提升 | 高，但也是最有想象空间的 |
| **语音** | ZipVoice + vosk | **不碰** | — | — |
| **工具/MCP** | 13 写 / 9 读 | 工具选择先验（可选，最后做） | 选择准确率 | 低 |
| **安全锁 / 数据隔离** | PBKDF2、`AXO_ISOLATED_STATE` | **不碰** | — | — |

**"深度优化"的落地含义**：不是把 SNN 塞进每一个组件，而是**同一个基底喂多个头**，
每个头都有一条独立判据，不过就砍。

## 三、协同的物理约束（不改就是空谈）

1. **显存**：Axo 现在跑 Ollama（Qwen3-4B Q4 = 2.5 GB）+ 嵌入。再加 0.5B fp32 的 SNN（2.0 GB）
   ⇒ 8 GB 卡装不下。**SNN 常驻侧应该跑在 CPU/N100 上**，这正是它的强项（每 token 1 MB）。
2. **延迟**：SNN 在 N100 上 28k tok/s（带宽界，实测会低到千级）——做草稿足够，做聊天不够。
3. **隐私**：L4 回写要求"把对话喂回 SNN"，而 SNN 在本地 ⇒ **正文仍然不出本机**，
   这与云端 Qwen 的现有路径不冲突。

## 四、判据（先写，各一条）

| # | 判据 | 不过怎么办 |
| :--- | :--- | :--- |
| **C-1 词表** | 千问词表的 15M 小模型 vs 32k 版，top-10 差 **≤1pp** | 保 32k，放弃 L3 |
| **C-2 草稿接受率** | L3 的接受率 **≥50%** | 放弃 L3（低了不如不做） |
| **C-3 状态交接** | L2 的压缩状态让 Qwen 的首 token 延迟降，且质量掉 ≤1pp | 放弃 L2 |
| **C-4 回写** | L4 在线更新 30 天后，记忆召回 hit@5 提升 ≥3pp | 只保留离线巩固 |

## 五、落地顺序（每一步都能单独判死）

```
0  0.5B 正式训练（32k 词表）          ← 产品形态的底，先有快系统
1  C-1 词表对照（15M 小模型，1 小时）  ← 决定走不走 L3 这条深协同
2  G-B 记忆召回：SNN 特征 vs TF-IDF 0.898
3  G-A 触发：调用降 30% 不掉质量
4  G-C 风格：S-1/S-2/S-3
5  L2 / L3 / L4 逐个接
6  夜间巩固
```

**不要跳步。** 第 0 步没过，后面全是空谈；第 1 步的结论决定架构走哪一支。

# 第三部分：部分融合的可行性（2026-11-12）

**先更正一个数**：本文早前写的"TF-IDF 0.898"是**未经核实的**。本机跑
`tools/bench_recall.py` 得到的现网基线是：

```
通道 lexical + semantic(nomic-embed-text 768d)
hit@1 0.8312  hit@5 0.9091  hit@8 0.9221  MRR 0.8565  AUC 0.9393
最弱子集：paraphrase hit@1 = 0.20（n=5）
```

**融合不能假设"词法弱、语义强"——现网已经是两路融合。**

## 五种"部分融合"，两种活、三种死

| # | 融合层 | 结论 | 理由 |
| :--- | :--- | :--- | :--- |
| **F1 通道级** | 召回时多一路打分 | ✅ **唯一可做** | Axo 的 `recall()` 本来就是多通道加权；加一路是配置级改动 |
| **F2 表示级** | 千问词嵌入几何 → 我们的 `emb` | ✅ **已做** | `scripts/transfer_embedding.py`，32,000 token 全覆盖 |
| F3 决策级 | SNN 起草、Qwen 验证 | ❌ 死 | N100 只做夜间/兜底，**没有交互延迟可优化**；且要求同一套词表 |
| F4 训练级 | Qwen 当教师做蒸馏 | ❌ 死 | 4B 教师在本机 15 tok/s，出 4B token 要 8.4 年 |
| F5 存储级 | 千问的 KV 当记忆库 | ❌ 不适用 | 与 Axo 的记忆库不是一回事，且 KV 不跨会话持久 |

## F1 为什么是唯一值得做的一条

它同时满足三个条件：
1. **不需要改模型**——召回本来是 `lexical + semantic + time` 的加权和，加一路即可；
2. **可判**——同一个 harness、同一批 85 条查询、同一个 hit@K 口径；
3. **有明确的靶子**——`paraphrase` 子集 hit@1 只有 0.20，这是语义编码真正能拉开差距的地方。

**它也是 G-B**。也就是说：**"SNN 与千问的部分融合"在这个产品定位下，答案收敛成"在召回层加一条 SNN 通道"**——其余四种融合各有硬理由出局。

## 一个必须接受的前提

SNN 通道要赢，前提是**它的特征里真的有语义**。M-3 已经给过一次反例（惊讶度与记忆重要性无关，
Pearson +0.023）。所以 F1 的判据必须是**在同 harness 上的 hit@1**，不能是"特征看起来合理"。
