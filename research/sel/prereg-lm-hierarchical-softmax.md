# 预注册：层次 softmax —— 把 `M·V` 换成 `M·logV`（2026-11-11）

**状态：判据先落盘。第一道是「实现前的微基准」，不是实现。**

## 动机

每 token 的成本是 **三个 `M·V`**（前向 / 反传 / 更新），今晚已经试死了四条降 M 的路
（低秩 −1.3pp、候选剪枝慢 25x、cuSPARSE 慢 0.76x、K=1 −5pp）。
**降 V 是唯一没动过的出口。**

二叉树上每个 token 只走 `log2(V)` 个内部节点：

| V | 稠密读出 `M·V` | 树路径 `M·log2V` | 理论比 |
| ---: | ---: | ---: | ---: |
| 5,000 | M×5000 | M×12.3 | **406x** |
| 32,000 | M×32000 | M×15.0 | **2133x** |

## 但必须先把反方证据摆在最前面

> **A1 候选剪枝做的是同一件事：按行选列。而它实测慢 25 倍。**

原因不是"选列"本身，而是**每行的候选集不同**，于是 `W[:, cols]` 要物化成
`(M, B, C)` —— batch=256、C=256 时那是 **4.3 GB**。

层次 softmax 的路径**同样是逐 token 的**，所以同一个陷阱就在前面：
`(M, B, logV)` = 16384 × 256 × 12 × 4 B ≈ **201 MB**。

**比 A1 小 21 倍（12 个节点 vs 256 个候选），所以可能过，也可能不过。**
——这就是为什么第一道必须是微基准，而不是实现。

## H-0：**实现前的微基准判死**（本轮核心）

在 batch=256、M=16384、V=3001、log2V=12 下，比较：

| 路径 | 做什么 |
| :--- | :--- |
| **稠密** | `features @ W`，`W` 是 `(M, V)` |
| **树路径（gather）** | 每行 12 个节点 ⇒ 取 `W` 的 12 列再逐行算 |
| **树路径（cuSPARSE 选择矩阵）** | 用一个 `(V, B·12)` 的选择矩阵乘 `W` 再按行取 |

**判据**：

| # | 门槛 | 不过怎么办 |
| :--- | :--- | :--- |
| **H-0** | 树路径（任一实现）比稠密 **快 ≥ 3x** | **判负，整轮不实现**；与 A1、事件驱动读出并列归档 |
| **H-1** | 实现后 top-1 掉 **≤ 2pp** | 树结构或质量不可接受，收口 |
| **H-2** | 端到端每 token 成本降 **≥ 3x**（三个矩阵乘都算） | 只保留 H-0 的局部收益，不进训练栈 |

**H-0 是一票否决**：它只花 10 分钟，却能省掉一整轮实现。

## 设计（仅当 H-0 过才展开）

- **树**：按 token 频率建 Huffman 树（高频词路径短 ⇒ 平均路径 < log2V）；
- **读出**：路径上的每个内部节点一个 `M` 维向量，`logit = features · w_node`；
- **损失**：路径上每个节点的二分类交叉熵之和；
- **学习规则**：**仍然是局部的** —— 每个节点的梯度只依赖 `features` 与该节点的标签，
  不经反向传播；`features` 侧的信号按路径求和（与多抽头求和同构）；
- **不做**：不改 τ、不改 K、不改精度。

## 必须一起写的限定

1. **层次 softmax 在工业界被全 softmax 取代过**（大模型大语料的经验）。我们是非标准的
   极小模型 + 局部规则，**这条经验未必适用，但也未必不适用** —— H-1 就是量它的；
2. **参数量不变**（V−1 个内部节点 × M），省的是**算力**不是显存；
3. **Huffman 树依赖频率**，词表变化要重建；跨语料比较时要重建两次；
4. 单折、单种子；预算与基线一致（16,000 步、2 抽头）。

## 成本

- **H-0：10 分钟**（微基准，不写模型代码）；
- 若过：实现约 1 天 + 1 条臂约 50 分钟。
