## 一、V1 是什么

| 半 | 内容 | 谁来训 | V2 里变不变 |
| :--- | :--- | :--- | :--- |
| **慢半** | Qwen3-4B（GGUF / llama.cpp，只出分布） | 不训 | **不变**（"千问一个字不改"是写死的边界） |
| **快半** | 局部规则脉冲模型 + 层次 softmax 树读出 | 我们训 | **变**——V2 就是它 |

所以"加大语料续训第二版"，动的**只有快半**。

## 二、V1 的"打包"= 一个能直接放进 Axo 的模型包

打包不是"把 .pt 拷过去"。包里必须有下面九件，少一件 V2 就接不上、或者产品就跑不起来：

| # | 件 | 路径 | 为什么必须在包里 |
| :--- | :--- | :--- | :--- |
| 1 | 快半检查点 | `run05b_ckpt.pt` | 权重本体 |
| 2 | **冻结的树** | `run05b_tree.pt` | **V2 续训的承重件**（见 §三）。缺了它，V2 只能重训 |
| 3 | 本地 id ↔ 千问 id 的桥 | `subset_32k.json`、`id_map.json` | 跨分词器的前缀归并全靠它 |
| 4 | 千问侧标识 | GGUF 文件名或 Ollama 模型 id + 版本 | 慢半的版本必须钉住 |
| 5 | 用户头冷启动快照 | `*.npz`（`UserHead.cold_start`） | 首启没有历史时要有个合法的空头 |
| 6 | 传感器通道维度 | `--sensor-dim`（16） | 服务端与产品端要同一个数 |
| 7 | 服务启动参数 | `serve_snn.py` 的命令行 | 复现"当时是怎么起的" |
| 8 | model card | 见 §五 | 按 ADR-0036 规则二只能写到 L0 |
| 9 | 许可清单 | 千问 Apache-2.0、语料来源、自有代码 Apache-2.0 | 发布门禁（framework §7 第 6 项） |

**打包时**：`run_1b.py` 现在会把树写成 `<tag>_tree.pt`（见 §三），打包脚本直接收这一份即可。

## 三、V2 能"接着训"的前提：三样东西必须冻结

这条是本次改动里唯一有工程风险的地方，**已经修好并加了守卫**。

### 3.1 已修的坑：树不是语料的函数，节点 id 会重排

内部节点 id 是按**合并顺序**发的（`build_huffman_paths`），而合并顺序由频次决定。
V2 换更大的语料 → 重算频次 → 合并顺序变 → **节点 id 整体重排** →
检查点里那 4 GB 读出权重会接到**错误的节点**上。

**这个过程不报错，只会悄悄变差。** 之前 `--resume` 正是这么做的。

现在的行为（`research/sel/lm/run_1b.py`）：

- 训练开始时把树写进 `<out>/<tag>_tree.pt`（含 `nodes/bits/length/n_nodes/right_share` 与语料指纹）；
- `--resume` 时**优先读这份树**，不再重算；
- 没有树文件时看**词频从哪来**：从 `counts_<V>.npy` 缓存读 ⇒ 与上次同频次 ⇒ 建出来的树
  逐位相同，**允许**并顺手把树写下来（老检查点因此能自己长出树文件）；
  **现算频次**（缓存不存在）⇒ 语料可能换过，**直接报错退出**，除非显式
  `--allow-tree-rebuild`；
- `--tree-from` 可以显式指定任意一份树文件（跨语料续训就用它）；
- 守卫：`tests/test_run_1b_infra.py` 里有三条——换语料节点 id 确实会动、树文件往返**逐位**相同、语料指纹会变。

### 3.2 三样冻结项

| 冻结什么 | 冻结在 | 动了会怎样 |
| :--- | :--- | :--- |
| **词表顺序**（32k 子集的 ids 序列） | `subset_32k.json` | 读出权重的行与 token 的对应整体错位 |
| **树结构** | `<tag>_tree.pt` | 同上，且**不报错** |
| **本地 id ↔ 千问 id** | `id_map.json` | 融合时的前缀归并全错 |

**这三份文件按字节算进包的哈希**，V2 开跑前与 V1 的清单比对，不一致就停。

### 3.3 可以动的

- 语料量与来源配比（V2 的全部意义）；
- 步数、学习率曲线（续训要重启一次，见 §四）；
- **不可以**改读出宽度 M 或神经元数 N——改了就不是"同一个模型接着训"，而是另一条臂，
  得按 R3/R4 的口径重新报数。

## 四、V2 怎么训

1. **数据配比**：V2 语料里**保留 V1 语料的一个固定比例（建议 ≥30%）**。
   这不是保守，是防灾难性遗忘——只喂新语料，V1 学到的分布会掉，而产品用的是两边的混合。
2. **学习率重启**：从 V1 的终点学习率起步，短预热（~200 步）后回到 V1 的**参考工作点**
   （`--lr-in` 的参考口径，实际值仍按 `16/(batch×scale)` 折算）。
3. **评测探针必须固化**：V1 打包时就把评测窗口（`--eval-windows` 的种子与位置）钉下来，
   V2 用**同一批窗口**评，否则"掉没掉"没法比。
4. 每 2,000 步同时报**两组**数：V1 探针、V2 新留出集。

## 五、判据（先落盘）

### V2-0 前置闸门（跑之前判）

- [ ] 树文件与 V1 清单**逐位相同**（`load_paths` 往返比对）；
- [ ] 词表顺序与 `id_map.json` 的哈希与 V1 一致；
- [ ] V1 检查点能在**未开始训练**时加载并复现 V1 的评测数（差 0）；
- [ ] V1 语料在新配比里占比 ≥30%。

任一条不过 ⇒ **不跑**，先修。

### V2-1 主判据

| 判据 | 阈值 | 为什么是这个 |
| :--- | :--- | :--- |
| V2-1a 旧能力不退 | V1 探针 top-1 **≥ V1 − 0.5pp** | 比噪声地板（±0.6–0.9pp）小一档，允许"持平" |
| V2-1b 新能力有涨 | 新留出集 top-1 **≥ V1 + 3pp** | 与 R4/R8 同量级的"值得做"门槛 |

**两条都过才算 V2 成立。** 只过多一条按单边指标报（四问第 3 条）。

### V2-2 kill

- V1 探针掉 **> 2pp** 且新集涨 **< 1pp** ⇒ 回滚到 V1，判
  "在这条管线上加大语料不划算"，写进负结果并停；
- 语料扩了但新集涨幅落在 ±1pp 内 ⇒ 按"与零不可分辨"记，**不追加语料去凑显著**。

### 发版前必须解决的红项

1. **语料许可已核，结论是"不覆盖我们这种情况"**（2026-11-12 核）。
   查证过程与原文要点：

   - 数据集是 `Skywork/SkyPile-150B`（HuggingFace），我们用的是 `zh_head` 档；
   - **HF 上的 `license` 字段为空**（`cardData.license = None`，也没有 license 标签）；
   - 卡片正文写："The community usage of SkyPile dataset requires **Skywork Community License**"；
   - 该协议（仓内 `Skywork Community License.pdf`）的授予对象是 **"Skywork Model"= Skywork-13B
     及其 Model Derivatives**。`Model Derivatives` 的定义是：基于 Skywork 模型做修改，或**把
     Skywork 模型的权重/参数/激活/输出模式迁移到别的模型上**（含用它生成合成数据去训别人）；
   - 协议**通篇没有授予数据集本身的再分发权**；唯一提到数据的一句是第 9 条：
     "…you must train your own model and **comply with the respective dataset's licensing
     agreements**"——它把数据许可**推回给数据集自己的协议**，而数据集自己没写；
   - 管辖法与争议解决：中华人民共和国大陆法律。

   **对我们的判定**：快半是**从零训练**的（随机初始化，不含任何 Skywork 权重），按定义
   **不是 Model Derivative**；但也没有任何文本授予"用这份数据训出来的模型"可以再分发。
   ⇒ **这是一片空白，不是一条许可。** T-5 据此判红，权重只放私有仓。

   **可选出路**（按代价从低到高）：① 保持私有；② 发布时带 "Skywork Community License" 副本
   并标注来源（clause 4/15 的类推，可辩护但不干净）；③ **V2 换一批许可明确的语料**（要重训）；
   ④ 向天工智力要书面澄清。**这条不建议由我替用户拍板。**
2. **专有数据红线。** 气体传感器插件在仓外且专有（合作方要发论文），
   **它的代码与参数不进任何模型仓**，`licenses/` 也不许出现它的具体实现。
3. **T-3 依赖数值格式。** 若为压体积把权重转 bf16，输出**不再逐位相同**，
   必须在 T-3 上重验，不能默认"差不多"。

## 十、模型仓库的形态

0.5B fp32 = **2.04 GB** 单文件。这决定了仓库怎么建：

| 方案 | 硬限制 | 结论 |
| :--- | :--- | :--- |
| GitHub Releases 资产 | 单文件 **≤2 GB** | 2.04 GB **刚好超**，要拆包或转 bf16 |
| Git LFS | 免费 1 GB 存储 + 1 GB 流量/月 | 不够，每月一超就断 |
| ModelScope（魔搭） | 支持大文件、国内快 | **推荐做主渠道** |
| 对象存储 / 网盘 | 无 | 兜底 |

**推荐的形态**：GitHub 仓库只放**清单、文档、脚本、小件**（subset 映射、id_map、用户头空快照、model card、manifest）；
**权重走 ModelScope（首选）或 GitHub Release 的 bf16 版**，仓库里放下载链接 + sha256。

**三条写死的规矩**：

1. **仓库里每个文件都必须有 sha256 进 manifest**，权重也不例外——下载回来要能核对；
2. **版本号只在 manifest 与 tag 里出现一次**，别在文件名里再写一遍（`semprea-1.0-final-final.pt` 这种）；
3. **1.0 的哈希一旦发出去就不改**；要换权重就发 1.1，不覆盖。

### 附：字节回退的事故与守卫（2026-11-12）

千问 token → 32k 子集下标的映射，早先在**三个脚本里各写过一遍**。子集外 token 的
字节回退写成了 `tokenizer.decode([qwen_id]).encode("utf-8", "ignore")`——对**只覆盖
某个汉字一部分字节**的 token（如 `b"\xa0\x80"`）会先得到替换字符，再把原始字节
永久换成 `EF BF BD`。**不报错，只是把语料悄悄写坏。**

**实测影响**（1 亿字符样本 / 7095 万 token）：子集外 token **0.291%**，其中字节
真的被换掉的只有 **0.001%**（6B token 里约 6 万处）。所以第一版语料**不重做**。

**改法不是"再修一遍"，是收敛**：

1. 映射只有一份实现 `research/sel/lm/subset_tokenizer.py`（`to_local` / `decode`）；
2. `scripts/build_qwen32k_full.py` 与 `build_qwen_subset_corpus.py` 改为调用它，
   连同自带的 `bytes_to_unicode` 副本一起删掉；
3. 守卫 `research/sel/lm/tests/test_no_ad_hoc_byte_fallback.py`：
   - **静态扫描**仓库里是否又出现 `decode(...).encode(...)` 式回退（CI 会跑）；
   - 断言映射只在**一个**模块里实现；
   - 先断言扫描器**确实扫到了文件**——第一版把根路径写成了 `parents[3]`，
     实际指到 `research/`，两条断言双双假绿，靠这条才暴露；
   - 回归测试：对每个"字节单独不合法"的子集外 token，`to_local` 必须落回**它自己的字节**。

守卫验过红：往 `research/` 里放一个含该写法的探针文件，静态扫描立刻失败；删掉即恢复。
