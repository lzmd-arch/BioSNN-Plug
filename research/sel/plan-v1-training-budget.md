## 三、理论最大训练量：**瓶颈不是算力，是数据多样性**

这一点必须先说清楚，否则"把预算拉长"会变成把同一批模板过 100 遍。

三条上界，取最小者：

| 上界 | 估计 | 依据 |
| :--- | :--- | :--- |
| **数据多样性上界** | **≈ 5–10 万条"独立行为"** | 崩溃过一次：15 条危机句 + 换前后缀 ⇒ recall 1.000 是假绿（记句子） |
| **模型容量上界** | 0.5B × 20 token/param ≈ 10 B（Chinchilla 口径） | 但那是**通用预训练**口径，不是行为微调 |
| **遗忘上界** | 通用能力掉 ≤2pp（判据 D-2） | 窄数据训久了必然掉 |

**结论：行为微调的有效区间远小于通用预训练。** 在现有生成器能提供的多样性下，
**50–100 M token（≈2–4 天）就是"理论最优"的量级**；再往上，收益来自**换数据**，
不是加时长。

⇒ **V1.5 = 在 100 M token 量级上、用最大多样性的可验证数据训出来的那一版。**
它不是"训练最久"，是"**数据最厚**"。

## 四、V1.5 的判据（先写死）

| # | 判据 | 阈值 |
| :--- | :--- | :--- |
| **B-1** | 身份/行为探针 I-1…I-3（含"删掉 persona.md 仍成立"） | 全过 |

**B-5 是这版的守门条件**：判定"训练量是否还有效"，必须在**没见过的模板族**上测。

## 五、V1.1 的定位

- **1 天 / 20.8 M token**，只做一件事：**把身份与行为约束训进权重**（I-1…I-3）；
- 不做伦理三层、不做心理学技能——那些等 V1.5；
- 它是一次**可行性验证**，不是"更好的版本"。

## 六、排期：**V1.1 / V1.5 暂不开训**

先做三件优化，做完再定日程：

| # | 优化 | 为什么它先于训练 |
| :--- | :--- | :--- |
| **O-1** | **数据生成器**（四类可机检 + 伦理三层 + 心理学技能，按模板族切分） | 没有它，加时长只是把模板背更熟 |
| **O-2** | **吞吐**：序列打包（去 padding）、按空闲卡重测 batch、Adafactor/8-bit 优化器 | 直接把 24 h 的 token 预算乘上去 |
| **O-3** | **评测 harness**：I/E/D/B 四组判据一键跑 | 没有它，训完也判不了"值不值" |

**O-2 的量级**：若打包 + 更大 batch 把吞吐做到 500 tok/s，同样的 24 h 就是 **43 M token**，
相当于把 V1.1 的预算翻倍——**这比把日程拉长两天更便宜**。

## 八、"以前两天能训 6B token，现在为什么不行"——**不是同一件事**

| | **0.5B SNN**（V0.5 的快半） | **0.5B Transformer**（V1 的底座） |
| :--- | :--- | :--- |
| 学习规则 | **e-prop，局部，无反传** | 全参反向传播 |
| 每步做什么 | 一次前向 + O(参数) 的权重更新 | 前向 + 反向 + Adam |
| 结构 | emb(32000×256) + proj(256×7812) + 树，**无注意力** | 24 层 attention + MLP |
| 激活内存 | 不保留（没有反传图） | 必须保留（或做检查点） |
| batch | 256 | 2–4 |
| **实测吞吐** | **33.9k tok/s**（4.92B token / 38.5 小时） | **241 tok/s** |

**比值 ≈ 140 倍。** 这就是"两天 6B"与"1B 要 48 天"的全部差距——
不是硬件变了，是**换了一个贵 140 倍的工作负载**。

那 6B 是**一次 `.backward()` 都没有**的局部规则模型跑出来的。

### 这条对比真正的意义

**要在这个硬件上两天训 B 级 token，只有回到局部规则这一条路。**
而我们手上正好有那个模型（V0.5 的快半，0.5B SNN）。

问题是它**语言能力不够**：top-1 0.110，四测四负（生成 0/543、编码 hit@5 0.015、
判别 0.763 过拟合、序列 0.562 无增益）。

所以真正的岔路口是：

| 路线 | 训练成本 | 语言能力 | 与云端的关系 |
| :--- | :--- | :--- | :--- |
| **Transformer 人格核**（现在这条路） | 贵 140× | 好（0.5B 底座可用） | 出摘要，云端生成 |
| **SNN 人格核** | 便宜 140× | **弱**（有四次负结果） | 只能做状态/调制的载体 |

**二者交叉点——SNN 做状态、Transformer/云端做语言——才是我们还没测过的组合。**
这一轮把 transformer 侧的数据与评测都建好了，那条交叉路线现在有现成的仪器。
