# P3 预注册修正之一：重复率与提示词回显（跑第二轮之前写死）

**日期**：2026-11-03
**父文档**：[`prereg_p3.md`](prereg_p3.md)（D1–D4 与教师口径）。

## 第一轮发生了什么（原始读数，照登）

400 条请求 → styled 306（76.5%）→ 去重后 **101 条**（D1 要求 ≥300，**不过**）。
两个成因都写进代码与测试，不是"再跑一次"：

1. **提示词回显**：0.5B 偶尔不写正文，把渲染提示词整段抄回来（`action\n要点：…`）。
   它**能通过事实核对**——事实确实在里面——所以第一轮有这种样本混进配对。
   修法：`ExpressionLayer` 增加回显检测（命中两个以上提示词字段名即退回草稿），
   生产路径同样生效；另加单测。
2. **短拒绝语去重塌缩**：拒绝类的正确输出本来就是"不知道。/没印象。"，按正文去重会
   把几十条合法样本压成几条；ask 族也因为教师复读而只剩 1 条。

## 修正（只改数据设计，不改阈值）

- **意图配比**：answer / ask / emotion / action 各 22.5%，**refuse 10%**（第一轮是按
  5 意图均分，拒绝族的重复把 ask 挤掉了）。
- **每条 SIR 带唯一序号**（"第 N 号"）写进要点，非拒绝族不可能意外撞车。
- **去重与 D3 只看非拒绝族**；拒绝族最多占最终配对的 5%，超出部分丢弃。
- **D1 不变（≥300）**、D2 不变（styled ≥70%）、D4 不变（切分零重叠）。
- 教师仍是 **qwen2.5-0.5b**、`temperature=0.7`。**若修正后 D1 仍不够**，下一份修正
  才允许换 1.5B 教师，并同时报它的 1.11 s 渲染延迟。

## 记分方式

`manifest.json` 增加 `refusal_share` 与 `unique_ratio_non_refusal`；报告里两个数一起报，
避免"把拒绝族剔掉之后数字变好看"这种单侧优化。
