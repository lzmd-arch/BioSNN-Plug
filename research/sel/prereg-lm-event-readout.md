# 预注册：事件驱动的读出——**算力的 25× 与 F2 的正确性是同一件事**（2026-11-10）

**状态：判据先落盘。**

## 一句话

读出看的是 `h_k = EMA_k(z)`，而 **z 只有约 4% 的神经元发放**。现在我们把 h 当稠密向量算，
等于把 96% 的零也乘了一遍。把「EMA」与「线性投影」交换顺序，**前向只碰发放的神经元**；
而反向那一半，**恰好就是 R12 里 F2（读出滤波的反向 EMA）修的那一项**。

## 推导（两步都只用到线性）

```
h_k,t = d_k · h_k,t−1 + z_t            （EMA）
L_k,t = h_k,t @ A_k                     （投影到秩 r）
⇒  L_k,t = d_k · L_k,t−1 + z_t @ A_k    （交换顺序）
```

- **前向**：`z_t @ A_k` 只取发放的神经元 ⇒ 成本 `nnz·r`，而不是 `N·r`。密度 4% ⇒ **25×**；
  `L_k`（K×V）每步只做一次衰减加法，可忽略。
- **反向**：第 n 行在 t 时刻的梯度贡献是 `Σ_{u≥t} d_k^{u−t} · g_u · 1[n 在 t 发放]`。
  **那正是 g 的反向 EMA（F2）**，并且在发放时刻只更新那一行。

⇒ **事件驱动的读出 = F2 的正确性 + 稀疏的省算力**。这种重合很少见，所以值得单独一轮。

## 必须写死的近似（这是本轮的核心风险）

增量式 `L_{k,t} = d_k L_{k,t−1} + z_t A_k` **假设 `A_k` 在 EMA 窗口内不变**；而 A 每步都在更新。
误差是 `O(lr)` 量级，而 NLMS 的 `lr_out=0.5` 不小。两条应对，**本轮两条都实现、分别测**：

| 方案 | 做法 | 代价 |
| :--- | :--- | :--- |
| **R（定期重算）** | 每 `T` 步用精确式 `L = h @ A` 重置一次（T=100 起） | 每 100 步多一次稠密乘，可忽略 |
| **F（窗口冻结）** | A 冻结 `T` 步，窗口末统一更新 | 与在线学习略有差异，要在预注册里承认 |

## 2026-11-10：**实现前的微基准判死**（10 分钟，省掉一整轮实现）

预注册里 E-3 的风险（"gather 会打折"）不用等到实现——先量一把就够了。

B=256、N=40,000、r=512，按实测的 4% 密度造 `z`：

| 密度 | 稠密 `z @ A` | 稀疏路径（nonzero + gather + index_add） | 比 |
| ---: | ---: | ---: | ---: |
| **4%**（1,600/神经元） | **1.04 ms** | **9.86 ms** | **0.11×** |
| 10% | 1.03 ms | 24.99 ms | 0.04× |

**稀疏路径慢 9–25 倍。** 原因和 A1 一模一样：`nonzero()` 是**设备端扫描 + host 同步**，
`index_select` / `index_add` 是**访存受限**且合并差；而稠密 matmul 走 tensor core。

⇒ **事件驱动读出在 PyTorch 里不可行**（要它划算得写自定义稀疏内核，超出本仓范围）。
**本轮不实现**——预注册的 E-0/E-1/E-2 都不再执行；E-3 的答案已经有了，而且是负的。

**这已经是第三条"稀疏在 PyTorch 里不划算"**（A1 候选剪枝、本条、以及 bf16 之外的隐式稀疏），
它们合起来说明一件事：**这个模型的算力便宜只能来自调度（batch / 去同步 / CUDA graph），
不能来自"少算零"**。

## 设计

基线 = **A3 低秩读出**（r=512，稠密前向 + 在线更新）；对照 = **事件驱动版**（同样的 A、B、超参）。

| 项 | 值 |
| :--- | :--- |
| 语料 / 预算 | KdConv、test 留出、16,000 步、每 2,000 评测（与 P1 同口径） |
| 模型 | N=1,024、4 个 τ、`max_vocab=3000`、`lr_in=1e-3`、`lr_out=0.5`、种子 0 |
| 读出 | r=512（A 可学、B 固定随机） |
| 新增开关 | `--event-readout`（事件驱动）、`--recompute-every T`（R 方案）、`--freeze-window T`（F 方案） |

## 判据

| # | 门槛 | 判什么 | 不过怎么办 |
| :--- | :--- | :--- | :--- |
| **E-0** | **A 冻结时**，事件驱动的前向与 `L = h @ A` **逐位一致**（1e-6） | 推导没错、实现没漏 | 修实现 |
| **E-1** | 训练中 `L` 的相对误差（每隔 500 步用精确式对一次）**< 1%** | R/F 方案压住了漂移 | 减小 T |
| **E-2** | top-1 相对 A3 基线**掉 ≤1pp** | 稀疏与近似不伤精度 | 换 F 方案或减小 T |
| **E-3** | 实测 tokens/s **≥ 4×**（目标 25×，密度 4% 时） | 省算力真的兑现 | 报实测并说明瓶颈（可能是 scatter 访存） |
| **E-4** | CE 一并报 | 防止"排序不掉、校准崩" | — |

**E-0 是硬前置**：推导的等价性必须先在冻结 A 上钉死，否则 E-2 里的差异分不清是近似还是 bug。

## 与 F2 的关系

F2（R12 的 CA 修法）**只改学习信号、不省算力**；本轮的更新式在数学上与 F2 相同，
但**把它实现成"只在发放时刻更新那一行"**——于是同一个修正顺带把读出更新从 `N·r` 降到 `nnz·r`。
**R12 的 F2 臂若先跑出来，本轮的 E-2 可以直接拿它做预期**。

## 预期

**押 E-2 过、E-3 在 4–10×（不是 25×）**。理由：A1 已经演示过一次"稀疏不一定更快"——
`gather` 是访存受限的；这里的 `A[active_ids]` 同样要 gather（4% × 40k × 512 ≈ 0.8M 浮点/步，比 A1 小得多），
**但仍是 gather**。所以 25× 是 FLOP 比，**墙钟大概率打折**。

## 不做的事

- 不叠加 A2（低秩输入）——本轮只改读出，保持单变量；
- 不改 τ、不改动力学；
- 不在 1B 上验（先在 KdConv 上把等价性与收益量清楚）。

## 边界

- 单折、单种子；字符级；**不代表能聊**；
- 稀疏收益**依赖放电密度**——当前测得 4%，若训练后密度升高，收益按比例缩水；
- 反向 EMA 需要**一个序列的延后**（与 F2 同一条集成约束）。
