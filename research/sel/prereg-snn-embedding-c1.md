# 预注册：SNN 的 `/encode` 值不值得接进记忆检索（C1，2026-11-14）

**跑全量之前落盘。** 对应 `plan-semprea-v1-optimization.md` 的 C1。

## 一、为什么测这个

候选补全不是产品形态（用户 2026-11-14 明确），所以**快半作为"第二个下一个 token 预测器"
在 V1 上没有产品面**（真实上下文长度上融合 top-1 −0.92pp、快半命中 0/543）。

它剩下的位置是 `snn_embed.py` 里写明的那个：**把文本编成向量，喂记忆通道**。
而那份代码**写完了、没接线**——`axo/llm/snn_embed.py` 在仓内没有任何地方 import。

所以问题很具体：**把它接进召回，召回会变好还是变坏？**

## 二、协议（写死）

- 数据：LoCoMo10，sha256 `553cd5a15e25f2ceccc6ed185221eba645080c93e5b91087560a91aa5961f365`
  （与已发布的三臂**逐字节同一份**）；
- 金标准、切分、指标全部沿用既有 benchmark（`tools/bench_locomo.py`），**不改口径**；
- 新臂：`--arm snn`，`SnnEmbeddingBackend(dim=15624, host=本方 SNN 服务)`；
- 已有的三臂作为对照，**不重测它们的数字**（nomic hit@5 0.495 / bge-zh 0.263 / 纯词法 0.139）。

**跨语料要写明**：SNN 在 FineWeb-2 上训练，LoCoMo 是对话记忆——**不是同分布**。
这是一条不利条件，写进结果而不是当成借口。

## 三、判据

| # | 判据 | 不过怎么办 |
| --- | --- | --- |
| **C1-0** | 全量跑通，向量维度 = 服务端报的 `readout_width` | 修管线，不写结论 |
| **C1-1** | 单通道 `hit@5` **≥ 0.263**（最弱的嵌入臂 bge-zh） | 写"单通道不可用"，**不做 C1-2**，不接线 |
| **C1-2** | **互补性**：`union(nomic top-5, snn top-5)` 的 `hit@5` 比 nomic 单独高 **≥ 2pp**，且按 conversation 聚类的 bootstrap 95% 区间下界 > 0 | 写"已有通道不需要它"，不接线 |

C1-2 需要**逐查询**的命中结果；现有三臂的 JSON 只存了聚合值。所以：
nomic 与 snn 两臂都要用 `--dump-outcomes` 重跑一次（同一数据、同一口径），**只为了拿到并集**。

## 四、可能的负结果怎么写

- C1-1 不过 ⇒ 「SNN 编码器单通道 hit@5 = x，低于最弱的嵌入臂 0.263，**不值得接**」；
- C1-1 过、C1-2 不过 ⇒ 「单通道可用但**与 nomic 高度冗余**，并集增益 +x.xpp（CI [a,b]），**不接线**」；
- C1-2 过 ⇒ 写清增量与区间，并说明**接线的代价**（多一个常驻进程、每条约 40–120 ms 编码）。

**不许的读法**：拿单通道数字和 nomic 比"谁强"就下结论——第三通道的价值是**互补**，不是替代。
也不许因为 SNN 是"我们自己的东西"而放宽 C1-2。

## 五、这次不做什么

- 不重训快半，不调它的编码方式（`encode_texts` 取的是各位置读出特征的均值，改它等于换模型）；
- 不改回忆层的融合权重（那是另一个预注册）；
- 不因为结果不好而改判据。
