# 认知池（前额叶）该怎么设计——以及为什么现在**测不出来**

**日期**：2026-11-15
**状态**：设计草案，**未预注册、未实现**。本文要回答的是"值不值得做、怎么才测得出来"。

---

## 一、现在缺的是什么

现有五个池（temp / time / memory / persona / presence）有一条共同结构：

> **每个池只接自己的传感器，池与池之间零连接。**

这是"功能分离"的代价，也是它的功劳——它把混杂因素一次扫干净了。但它同时意味着：
**这个网络里没有任何一个地方在做"整合"**。生物上，前额叶做的恰恰是这件事。

前额叶的四条职能，逐条对到本仓已有的机制：

| PFC 职能 | 对应到我们这个模型 | 现有证据 |
| :--- | :--- | :--- |
| 多模态整合 | 一个池接收其它池的脉冲 | **没测过** |
| 工作记忆维持 | 池内有递推、跨步保持 | S1/A9：递推是拖累（但任务不需要它） |
| 任务集选择（门控） | 增益调制别的池 | **测过，失败**：门控 0.109 对加性 0.306 |
| 抑制 | 侧抑制 | **测过，失败**：不降冗余、`time` −20pp |

⇒ **四条里两条已经被否，一条没测，一条的负面结论有前提未验证。**

## 二、三种候选设计，按"能不能测出差别"排序

### 方案 A：整合池（接其它池的脉冲）

`I_pfc = z_prev[其它池] @ W_cross`，`W_cross` 固定随机或可学。

**先验：几乎一定没用。** 因为读出层本来就同时看到所有池的特征，
一个线性整合层 `W2·f(W1·z)` 表达不出读出层没有的东西。**先验强负，不建议先做。**

### 方案 B：门控池（乘性地调别的池）

已经试过同族（`sensor_mode="gate"`）：0.109 对 0.306。**负结论已有，不重跑。**

### 方案 C：**工作记忆池**（唯一值得做的）

不是"再多一个池"，而是"**一个能把信息留住若干步的池**"。

它的价值只有在**需要跨越延迟**的任务上才显形。而我们现在的任务**一共两步**
（`当前温度` 两个 token + 一个数字位），**根本没有可以维持的东西**。

⇒ **这是关键：PFC 测不出来，不是因为它没用，是因为任务没有它要解决的问题。**

## 三、要做什么才测得出来

### 一个"延迟匹配"任务（写死在下面）

```
t=0        呈现线索 c ∈ [0,9]（一个标量，走 temp 池）
t=1..D     延迟：只有空步，没有新信息
t=D+1      呈现查询：答案 = 线索 c
```

- 读出的输入取 **t = D+1 时刻的池特征**；
- 无记忆的解码器在延迟期只能看到衰减后的残迹；
- **延迟 D 是唯一自变量**，D ∈ {2, 10, 30}。

### 判据（先写死）

| # | 判据 | 阈值 |
| :--- | :--- | :--- |
| **C-1** | 有递推的 PFC 池，在 **D=30** 上相对"无递推池 + 线性读出" | **≥ +10pp** |
| **C-2** | 在 D=2 上不能比基线差 | ≤ −2pp |
| **C-3** | 两种读出（欧氏原型 / 岭回归）**都要过** | 缺一不算 |

**C-2 是防"用递推换短期精度"**；**C-3 是这一轮学到的那条硬规矩。**

## 四、为什么这条值得做（而不是又一次"加个生物名词"）

1. 它是**唯一**一条"任务真的需要它"的生物学机制——前面 16 次失败里，
   有相当一部分是"机制存在，但任务用不上"；
2. 它直接**重测一个已归档的结论**（S1/A9 说递推是拖累）——那两条的结论是
   **在不需要记忆的任务上**得出的，前提没被验证过；
3. 若 C-1 不过，结论是干净的："在我们的工作点上，递推连需要它的任务也救不了"，
   这比"递推没用"强得多。

## 五、不做什么

- 不做方案 A/B（先验负、或已测过）；
- 不把 PFC 做成"更大的池"——池大小已被证明不是杠杆（16 = 64）；
- 不在 32K 上做——32K 的收益只可能来自文本路径，与 PFC 无关。
