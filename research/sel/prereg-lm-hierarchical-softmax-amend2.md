# 预注册修正 2：树上**实测**的深度与打平点（2026-11-11）

**amend1 里的深度是估的（"~11–12"）。本文把实测数写进来，并据此钉死"在哪测才可能过 3x"。**

## 一、实测（KdConv 训练集，V=3,609，1,457,372 token）

| 量 | 值 |
| :--- | ---: |
| 深度（**不加权**，评测成本用它） | 平均 **16.11**，最大 22 |
| 深度（**按训练频次加权**，训练成本用它） | **8.34** |
| 节点数 | 3,608 |
| Huffman 相对均匀树的收益 | `log2(3609) = 11.8` → 加权 **8.34** |

**两个深度必须分开报**：训练时按数据分布抽 token，稀有字的长路径很少被走；评测要把
**全部** V 个 token 的概率都算出来，那些长路径全在账上。

## 二、打平点与 3x 点（B = 256）

```
训练成本之比 = V / (B · 8.34)          ⇒ 打平 V ≈ 2,136，3x 需要 V ≈ 6,407
```

| 形状 | 预测倍数 |
| :--- | ---: |
| V=3,609（KdConv），B=256 | **1.69x** |
| V=8,000 / 16,000 / 32,000 / 64,000，B=256 | 3.75x / 7.49x / 14.98x / 29.97x |
| V=32,000，B=512 / 1,024 / 2,048 | 7.49x / 3.75x / 1.87x |

**这张表最重要的一行是最后一行**：树省的是「按行取权重的次数」，**批量越大越不值**。
`V=32,000` 时 B 从 256 涨到 2,048，收益从 15x 掉到 1.9x。**这是树方法的硬边界，
不是实现问题。**

## 三、因此 H-1 与 H-2 的测法

| 判据 | 在哪测 | 为什么 |
| :--- | :--- | :--- |
| **H-1（质量，≤2pp）** | KdConv，V=3,609，16,000 步，2 抽头 | 这是**唯一**有语料、有基线（P1 的 0.2973 / K=2 的 0.3090）的地方；那里 1.69x 的收益不重要，**质量才是门** |
| **H-2（速度，≥3x）** | V ≥ 6,407（B=256）；1B 的形状 V=32,000 ⇒ 预测 ~15x | 在 KdConv 上跑不到 3x 是**算术事实**，不是 H-2 不过 |

**H-2 因此在 KdConv 上不判**，只在 1B 形状（V=32,000、B=256、M=16,384）上判。

## 四、一条必须先说的代价

**评测慢 16.1x**（`Σ 全部深度 = 58,143` 个节点 vs 稠密 3,609 列）。
`run_r0` 每 4,000 步评测一次，所以 H-1 这一臂的墙钟时间会明显长于 P1 ——
**这不是训练变慢，是评测变慢**。报 tokens/s 时必须把两者分开，否则会把评测成本记到训练头上。

## 五、amend1 的更正

- amend1 写"平均深度 ~11–12""打平点 ≈ 3,000" ⇒ 实测是 **8.34（加权）/ 16.11（不加权）**、
  **打平 V ≈ 2,136**。方向不变（小词表没有收益、批量越大越不值），**数字以本文为准**。
