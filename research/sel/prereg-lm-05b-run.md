# 预注册：0.5B 正式训练（2026-11-11）

**状态：判据先落盘。** 这是本项目第一次「正式训练」，不是消融实验——所以判据写的是
**产物能不能用**，不是「比某个基线高几个点」。

## 一、为什么是 0.5B，不是 1B

实测（同一套代码、`--tree-packed`、window=192）：

| 参数 | B=128 | B=1024 | 峰值显存 | 两天 token | token/参数 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0.50B | 25.7k | **26.8k tok/s** | 2.92 GB | **4.42B** | **8.8** |
| 0.75B | 22.0k | 30.5k tok/s | 4.27 GB | 4.86B | 6.5 |
| 1.00B | 2.8k | —（换页） | 4.68 GB | 0.48B | 0.48 |

**1B 越过显存悬崖**（权重 4 GB + 工作集 > 8 GB 留不出余量），吞吐掉 8 倍。
0.75B 更快但只有 6.5 token/参数；**0.5B 给到 8.8 token/参数**，是"充分训练"那一档。
按用户决定取 **0.5B**。

## 二、配置（冻结）

| 项 | 值 | 依据 |
| :--- | :--- | :--- |
| 读出 | M=15,625 × V=32,000 = **500M 参数** | `--params 5e8` |
| 神经元 | N = M/K = **7,812**，K=2 抽头 {2, 128} | R11：τ 轴在 4–8 之间饱和 |
| 输入 | 低秩 `emb(V×256) · proj(256×N)` | −0.62pp（过），换掉稠密 `V·N` |
| 读出结构 | **Huffman 树**（按语料词频），`signal_scale=3` | 三种子 top-1 +0.91pp / top-10 +3.22pp |
| 数据 | `corpus.u16 + corpus_b.u16` = **10.64B token**，memmap 多分片 | |
| 窗口 / 批 | 192 / **1024** | 批扫实测：+39% |
| 学习率 | **`lr_in = 1e-3 × 16 / (batch × signal_scale)`**；`lr_out=0.5`（NLMS，天然 batch 无关） | 见下方「学习率的 batch 折算」一节 |
| 检查点 | 每 500 步，**4 GB（含树权重）** | |
| 预算 | 两天，约 **4.42B token = 8.8 token/参数** | |

## 三、判据（写死）

**主判据（产品口径）**

| # | 判据 | 说明 |
| :--- | :--- | :--- |
| **P-1** | 评测点的 **`mean_rank_cost` ≤ 4.5** | 10 格候选条上「选中正确答案要按几下」；全打字是 11 下，最好已知是 5.65–5.78。4.5 意味着省 59% |
| **P-2** | **top-10 ≥ 0.65** | 栏里有答案的比例；已知最好 0.6378 |

**过程判据**

| # | 判据 | 不满足怎么办 |
| :--- | :--- | :--- |
| **Q-1** | 训练 CE 在 24 小时内**单调下降**（允许噪声） | 上升超过 0.3 nats 且持续 → 停，记录 |
| **Q-2** | 按规则③ v3 跟踪 running max；**回落 >1pp 即判过峰** | 报峰值不报终点 |
| **Q-3** | 吞吐 ≥ 20k tok/s | 否则先查是不是又踩了显存 |

**评测协议**：每 2000 步在**留出切片**（corpus 尾部 1%）上跑全词表 top-1/5/10 与
`mean_rank_cost`。评测用独立 trace、不更新权重。

## 三之二、学习率的 batch 折算（2026-11-12 补，**开跑前必须成立**）

**隐层更新 `w_in += eps_inᵀ @ post` 是对 batch 求和的，不是平均。** 所以有效步长

```
∝ lr_in × batch × signal_scale
```

P1 的 `lr_in=1e-3` 是在 **batch=16、signal_scale=1** 上标的。直接拿到 batch=1024、scale=3 上
等于把步长放大 **192 倍**。

**实测后果**（0.5B、SkyPile、400 步）：发放率 **0.0087 → 0.0006**，
CE **8.21 → 51.4**（均匀是 10.4）。**模型完全塌掉，一步都没学到。**

**写死的规则**：`run_1b` 把 `--lr-in` 解释为**参考工作点上的值**，内部按
`lr_in_ref × 16 / (batch × signal_scale)` 折算。开跑前必须确认这条在代码里生效
（`tests` 里没有守卫，靠这行字）。

**附带的事实**：在此之前所有 1B/0.5B 的训练跑，训的都是塌掉的模型。吞吐与显存数字仍然有效
（它们由访存与算力决定），但"模型在学"从未被验证过。

## 四、四条限定（先写后跑）

1. **单折、单种子**。0.5B 这一跑没有多折复现的预算，结论只能当"这次训练到了什么水平"，
   不能当"这个配置的期望水平"；
2. **`signal_scale=3` 是在 KdConv（V=3,001）上选的**，搬到 V=32,000 的真实语料上未必最优。
   这是本跑最大的未验证假设；
3. **语料 10.64B token 里有 14.5B 字来自 SkyPile 网页文本**，与产品形态（对话）不同分布；
4. **两天是机时预算，不是收敛保证**。到点看曲线，不看步数。

## 五、不做的事

- 不在训练中改超参（要改就停下、写 amend、重开）；
- 不为让判据变绿调阈值；
- 不把这次的结果和 BPTT 比——**只报产品口径**（按键数 / 候选条命中）。
