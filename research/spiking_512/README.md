# 512 个 ALIF 神经元：召回与门控的可行性试验（**负结果**）

判据见 [prereg.md](prereg.md)（跑之前写死）。脚本 [run_512.py](run_512.py)。

## 结果（gold 语料，3 个投影种子，预筛前 50 条）

| 指标 | 512 群体 | 基线（关联码余弦） | 差 |
| :--- | ---: | ---: | ---: |
| hit@1 | 0.024 | **0.259** | **−0.235** |
| hit@5 | 0.094 | **0.424** | **−0.329** |
| 门控 AUROC | 0.535 [0.518, 0.555] | 未达 +0.05 判据 | — |

**两条判据都不过**（A1 要求 ≥ +0.05，实际 −0.235）。按预注册记为负结果，不调参。

## 为什么失败（写在结果之后，属事后解释，与判据分开）

- 关联码是 64 位稀疏码，余弦能直接量“共享了几个位”；而 512 个 ALIF 神经元做的是
  **重合发放的加分**，被阈值与不应期压得很粗，分辨不出“差一个数字”的近邻
  （gold 的 `name_number` 类正是这种设计）。
- 换言之：**线性点积在这个任务上已经是强基线**，把同一份信息压成发放率只会丢信息。

## 两处试的结论

- **召回**：不建议接。差 0.235，不是调增益能补的距离。
- **门控**：AUROC 0.535 接近随机；既有的单阈值门（0.20）已经过真实分布标定，
  没有理由换成一个更差且更贵的实现。

## 复现

```bash
uv run python research/spiking_512/run_512.py --seeds 3
```

## 编码器改过两次，都记在脚本注释里

① 整句哈希 → 共享词不重叠（基线 hit@1 = 1/85）；
② `re.split(r"\W+")` 对中文无效（整句一个 token）→ 改字符二元组。
两次改的都是**编码**，判据没动；改完基线才回到可信区间（0.259）。

## TI-LIF 修订（2026-11-03，10 个投影种子，预注册见 [prereg_tilif.md](prereg_tilif.md)）

有符号多值脉冲（TI-LIF，D=1/2）与 K 窗平均（K=5，**5 套独立投影**）各试一臂：

| 臂 | hit@1 | hit@5 | 门控 AUROC |
| :--- | ---: | ---: | ---: |
| ALIF K=1 | 0.012 | 0.082 | 0.410 |
| TI-LIF D=1 K=1 | 0.012 | 0.047 | 0.406 |
| TI-LIF D=2 K=1 | 0.012 | 0.047 | 0.410 |
| ALIF K=5 | **0.035** | **0.100** | 0.412 |
| TI-LIF D=2 K=5 | 0.012 | 0.059 | 0.369 |
| 词法基线（关联码余弦） | **0.259** | **0.424** | **0.825** |

判据 A1′ / A1″ / A2′ / B1 / B1′ **全部不过**。K 窗的阳性对照 R0b 过了：
ALIF 从 K=1 到 K=5，hit@1 0.012 → 0.035（+2.3pp），说明 K 窗确实引入了差异；
TI-LIF 没有从这个改进里获益。门控基线这里用词法 top-1 余弦（AUROC 0.825），
不是 1.000——脉冲臂仍然差 0.41 以上。

**结论不变**：TI-LIF 没把召回或门控救回来；两条线继续不接。原始 json 在
`sweep_results/spiking_512_tilif/`。
