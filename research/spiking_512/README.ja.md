# 512 個の ALIF ニューロン：召回とゲートの実現可能性試験（**負の結果**）

[中文](README.md) · [English](README.en.md)

判定基準は [prereg.md](prereg.md)（実行前に固定）。スクリプトは [run_512.py](run_512.py)。

## 結果（gold コーパス、投影シード 3、前段で上位 50 件）

| 指標 | 512 群体 | ベースライン（連想コードのコサイン） | 差 |
| :--- | ---: | ---: | ---: |
| hit@1 | 0.024 | **0.259** | **-0.235** |
| hit@5 | 0.094 | **0.424** | **-0.329** |
| ゲート AUROC | 0.535 [0.518, 0.555] | +0.05 の基準に届かず | -- |

**二つの基準とも不合格**（A1 は +0.05 以上を要求、実際は -0.235）。負の結果として記録し、
後から調整はしていません。

## なぜ失敗したか（結果の後に書いた説明。基準とは分けてある）

- 連想コードは 64 ビットの疎なコードで、コサインは「何ビット共有しているか」を直接測ります。
  一方 512 個の ALIF は「同時発火の加点」を計算し、しきい値と不応期で粗くならされます。
  gold の `name_number` は数字一つだけ違う近傍で、群体はそれを見分けられません。
- 要するに、**この課題では線形の内積がすでに強いベースライン**であり、同じ情報を発火率に
  押し込むと分解能を落とすだけです。

## 二つの用途への結論

- **召回**：接続しない。0.235 の差はゲイン調整で埋まる距離ではありません。
- **ゲート**：AUROC 0.535 はほぼ偶然の水準。既存の単一しきい値（0.20）は実分布で校正済みで、
  より劣り高コストな実装に置き換える理由がありません。

## 再現

```bash
uv run python research/spiking_512/run_512.py --seeds 3
```

## エンコーダは二度直した（どちらもスクリプトのコメントに残した）

(1) 文全体のハッシュ → 共有語が重ならず（ベースライン hit@1 は 1/85）。
(2) `re.split(r"\W+")` は中国語に効かない（文全体が 1 トークン）→ 文字バイグラムへ。
どちらも直したのは**エンコーダ**で、基準は動かしていません。直して初めてベースラインが
0.259 に戻りました。

## TI-LIF 改訂（2026-11-03、投影シード 10、事前登録は [prereg_tilif.md](prereg_tilif.md)）

符号付き多値スパイク（TI-LIF、D=1/2）と K 窓平均（K=5、**独立した投影 5 本**）を各 1 アーム試しました：

| アーム | hit@1 | hit@5 | ゲート AUROC |
| :--- | ---: | ---: | ---: |
| ALIF K=1 | 0.012 | 0.082 | 0.410 |
| TI-LIF D=1 K=1 | 0.012 | 0.047 | 0.406 |
| TI-LIF D=2 K=1 | 0.012 | 0.047 | 0.410 |
| ALIF K=5 | **0.035** | **0.100** | 0.412 |
| TI-LIF D=2 K=5 | 0.012 | 0.059 | 0.369 |
| 字句ベースライン（連想コードのコサイン） | **0.259** | **0.424** | **0.825** |

基準 A1′ / A1″ / A2′ / B1 / B1′ は**すべて不合格**。K 窓の陽性対照 R0b は合格：
ALIF は K=1 から K=5 で hit@1 が 0.012 → 0.035（+2.3pp）となり、K 窓が実際に差を
生んでいます。TI-LIF はその改善から利益を得ませんでした。ゲートのベースラインは
字句 top-1 コサイン（AUROC 0.825）で、1.000 ではありません——それでもスパイク側は
0.41 以上劣ります。

**結論は変わらない**：TI-LIF は召回もゲートも救いません。両方とも接続しません。
生の json は `sweep_results/spiking_512_tilif/` にあります。
