# 预注册：A4——换掉读出之后，规模还买得到精度吗（2026-11-04）

**状态：判据先落盘，代码随后。**

## 为什么要单开一轮

A3 只改读出（1 个时间点 → 28 个），8,192 神经元从 **0.759 到 0.917**。这直接动了一条已归档的结论：
[ADR-0033](../../docs/adr/ADR-0033-capacity-axis-archival.md) 说"8k 之后买不到精度"，
而那一组 S2–S9 全部是在**最后一步读出**下测的。

A3 已经给 ADR-0033 打了补注：0.83 是"最后一步读出的上限"。但补注只是**措辞**上的；
**"32k 配 28 抽头会不会超过 8k 配 28 抽头"这个问题，我们没测过。**

**这一轮只回答这一个问题**，不是重开容量轴：不扫规模、不换任务、不改连接。

## 设计（跑之前定死）

- **一臂**：`n_rec = 32,768`，`taps = 28`，其余与 A3 的 `k=28` 完全一致
  （fan_in 32、sMNIST、2 epoch、batch 8、seed 0、同一个 `build`）；
- **对照不重跑**：8,192 / 28 抽头 = **0.917** 已在 A3 实测（同代码、同种子、同预算）；
- 如果 32k 臂的发放率跑到 A3 的 8k 臂（0.1187）两倍以外，说明网络进入了不同的发放区间，
  这一臂作废重议（不是调参重跑）。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **C-0** | 前置：32k 臂的发放率与 8k 臂同量级 | 落在 [0.06, 0.24] |
| **C-1** | 换掉读出之后规模仍买得到精度 | `acc(32k) − acc(8k) ≥ 2pp` |
| **C-2** | 装得下 | 峰值显存 < 8,000 MiB |
| **C-3** | 没练坏 | `acc(32k) ≥ 0.907`（比 8k 低不到 1pp） |

**C-1 过** → ADR-0033 的"容量饱和"在换读出之后**不成立**，要另写 ADR 重新评估容量轴；
**C-1 不过** → 容量饱和与读出无关，ADR-0033 的结论在两种读出下都成立，补注可以再加一句"已复验"。

## 跑之前的预期

**倾向 C-1 不过，差 +0.5～+1pp。** 理由：S6 在 2 epoch 下 32k 只领先 8k **0.5pp**；
读出修正抬高的很可能正是"最后一步丢掉的那部分信息"，而两个规模丢的是同一部分，
所以抬升会大致同幅度地落在两臂上，差距不变。

若 C-1 大幅通过（> 4pp），说明规模与读出的交互比我想的强，那要立刻报告，不能自行扩实验。

## 成本与边界

- ETA：A3 的 8k 臂是 1,468 s；按神经元数近似线性外推，32k 约 **1.6 小时**（**外推值，未实测**）；
  **更正（开跑前的冒烟标定）**：32k 上一次 update 实测 **0.992 s**（8k 是 0.098 s，10×），按 7,500 update/epoch × 2 算约 **4.1 小时**——远超线性外推的 1.6 h。**以 4.1 h 为准**。
- 单种子、单任务、2 epoch；**没有** 5 epoch 对照；
- 读出参数在 32k 上是 `32768 × 28 × 10 ≈ 9.2M`；
- 不扫 `k`，不试 16k / 64k。

## 不做的事

- 不改 fan_in、不改学习率、不改 epoch；
- 不因为 C-1 不过就换种子找显著；
- 不把这一轮写成"容量轴重开"——那要新 ADR。
