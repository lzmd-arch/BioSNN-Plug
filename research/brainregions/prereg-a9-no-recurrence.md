# 预注册：A9——A 线去掉递推之后，绝对数字是不是被低估了（2026-11-06）

**状态：判据先落盘，代码未写。**

## 由来

S1（[`../sweep_results/lm_eprop_s1/README.md`](../../sweep_results/lm_eprop_s1/README.md)）发现：
语言模型那边，递推/输入电流比 0.56× 与 1.02× 时 top-1 分别掉 1.9pp / 4.9pp，**无递推最好**。

顺带量到 A 线用的 `EventDrivenEProp`（sMNIST、N=8192、fan-in 32、未训练）**比值 = 1.106**，
正好落在"掉 4.9pp"那一档附近。所以有一个具体的猜想：

> **A 线那些绝对数字（0.899 / 0.757）可能被递推拉低了。**

本轮回测这个猜想。**不改 A 线任何已有结论**——A3–A8 的两臂用同一个递推，相对比较仍然成立。

## 设计（跑之前定死）

- **模型**：`MultiTapEProp`（A3 同款），N=8,192、fan_in 32、**taps=28**、τ=20、阈值 0.62；
- **唯一改动**：`w_rec` 置零且**冻结**（不学）。此时循环电流恒为 0，等价于纯前馈；
- **种子**：**0、1、2**——与 A3 的三种子**同一组**，这样 A9 的中位数才能与 0.899 配对比较；
- 其余与 A3 的 `k=28` 臂**逐字相同**：sMNIST、2 epoch、batch 8、同一数据切分；
- 测试：1,000 条，分块 100。

## 判据

**逐种子对照**（写死）：A3 的 k=28 三种子是 0.917 / 0.873 / 0.906（seed 0/1/2），中位 0.899。
A9 报同样的三个种子 + 中位，**逐种子差值一并报**，不挑好看的。

## 预期

**押 A9-1 或 A9-2，不押 A9-3。** 具体：中位落在 **0.90–0.94**。

理由：S1 里 1.02× 掉 4.9pp 是在**语言模型**上测的；sMNIST 是"同一张图按行喂"，
时序结构简单得多，递推的坏处可能小一些。**所以我把"必然提升"写成"可能提升"**，
不预设方向。若 A9 与 A3 持平甚至更低，照登。

## 不做的事

- 不改 A3 的任何数字或结论（A9 是**补一列**，不是重跑 A3）；
- 不调 τ、不加层、不换读出；
- 不进 A9-3 的分支去"再分析"——那要先由用户拍板。

## 边界

- 单任务（sMNIST）、2 epoch、一个规模（8,192）；
- A9 与 A3 的唯一差别是 `w_rec`，但**那也意味着 A9 少了一大块参数**（8,192×32）——
  若 A9 更好，严格说不能全部归因于"去掉电流淹没"，也可能是"少了那部分参数反而正则化"。
  这个混杂**无解**（除非再补一臂随机冻结但非零的 w_rec，而 S1 已经做过类似的），写进结论即可。
