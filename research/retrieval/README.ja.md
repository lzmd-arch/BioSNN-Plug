# 検索ライン：クロスモーダル R@K

[中文](README.md) · [English](README.en.md)
**⚠️ 破壊的変更の免責期間：2027-09 まで**（計画書 §12.5、ADR-0005）。

## 何を検証するか

計画書 §七 第二段階で唯一まだ ❌ の成功基準：**クロスモーダル検索 R@1 50%+**。

事前登録は
[`sweep_results/retrieval_procedural_prereg.md`](../../sweep_results/retrieval_procedural_prereg.md)
にあり、**データより先に**書かれている。結論を読む前にそちらを読むこと。

## 第 1 ラウンド：外積 Hebb（2026-10-17、5 シード）

**基準には届いていない。R@1 = 0.141**（シード間 0.121–0.172）、ランダム基準 0.034；
**R@5 = 0.528**。

| 欄 | 結果 | 意味 |
| :--- | :--- | :--- |
| 同一モダリティ検索（読み方 a） | テキスト 1.000；画像 0.759–0.931 | 符号化そのものが同一性を保っている |
| バスの直接比較（連想なし） | 0.034 / 0.000–0.069 | **ランダム基準と同じ**——二経路は別の射影であり、事前登録の予想どおり |
| 外積 Hebb 連想（合格ライン） | **R@1 0.141 / R@5 0.528** | ランダムの 4 倍だが、50% には遠い |

R@5 が 0.528 で R@1 が 0.141 ということは、連想がクロスモーダル情報を**運んではいる**が、
順位の上位が散っていることを意味する。正解は近くにあるが、一位には稀にしか来ない。

## 第 2 ラウンド：delta 規則への置き換え（2026-10-17）

事前登録：[`retrieval_delta_prereg.md`](../../sweep_results/retrieval_delta_prereg.md)。
データ、分割、シード、符号化は同じで、連想規則だけを差し替える。

| 連想規則 | R@1（5 シード平均） | R@5 |
| :--- | ---: | ---: |
| 外積 Hebb（第 1 ラウンド） | 0.141 | 0.528 |
| **delta（Widrow–Hoff、今回）** | **0.359** | **0.845** |

**依然として 50% には届いていない。** ただし R@5 は 0.528 から 0.845 へ、R@1 は 0.141 から
0.359 へ上がった。第 1 ラウンドの診断——外積和は訓練目標を類似度で重み付けして平均するだけで、
近傍を抑制する仕組みを持たない——が正しかったことを示している。誤差修正は順位の上位を
確かに締めた。

⚠️ **delta は教師なし Hebb ではない**：誤差項 `v − W·t` の `v` は、ペア学習時に与えられる
教師信号である。したがってこれは**教師ありの局所規則**であり、各シナプスは自分の前後活動と
誤差だけを使い、連鎖律は通らない。この境界は曖昧にしてはならない。

⚠️ **大きなステップ幅は発散する**：グリッドの η=0.1 の一部は inf/NaN に溢れる。現在は発散を
明示的に記録し、交差検証では 0 点として扱うので、平均を NaN に汚染しない。最初の版には
この処理がなく、ログに `RuntimeWarning: invalid value encountered` が出ていた——**この警告は
ノイズではなく、パラメータ選択が NaN に汚染されている合図である**。

## 第 3 ラウンド：線形上界の探針——ボトルネックは表示であり、規則ではない（2026-10-17）

事前登録：[`retrieval_ridge_prereg.md`](../../sweep_results/retrieval_ridge_prereg.md)。
閉形式のリッジ回帰（`W = (TᵀT + λI)⁻¹ Tᵀ V`）で、二つのバス表示の間の**線形写像の能力上限**を測る。

| 連想規則 | R@1（5 シード平均） | 局所性 |
| :--- | ---: | :--- |
| 外積 Hebb | 0.141 | あり |
| delta（Widrow–Hoff） | 0.359 | あり（教師あり） |
| **リッジ回帰（線形上界）** | **0.466** | **なし——訓練集合全体を見て逆行列を解く** |

**線形上界でも 50% に届かない。** これで問題の所在が決まる：**ボトルネックは連想規則ではなく表示にある。**
delta はすでに線形上界の大半（0.466 のうち 0.359）を得ており、規則を磨いても余地は小さい。
50% を越えるには表示そのものを変える必要がある——プーリング、バス次元、あるいは二つの
チャネルで射影を共有すること。

⚠️ **これはあくまで「線形」上界である**：非線形な読み出しならさらに高くなる可能性があるため、
「50% は不可能」と読んではならない。読めるのは「線形に見る限り、この表示では足りない」だけである。
リッジ回帰は局所規則ではなく、**合格欄には一切入らない**。

## 記録しておくべき発見：この規則には調整できるハイパーパラメータがない

事前登録は `η`（学習率）と `λ`（忘却）の二つを挙げた。実測では**どちらも選べない**：

* 変換は `η·(t ⊤ Σ v t⊤) / (1+λ)` であり、**η も λ も全体のスケーリング**にすぎない；
* コサインは全体スケーリングに不変 → グリッド上のすべての点が leave-one-out で**完全に同点**になり、
  「選ばれた」点は同点の先頭にすぎない。

つまり選択の工程は何も選んでいない。これは実装の欠陥ではなく、コサイン順位付けの下での
この規則の代数的性質である。本当に調整するなら擬似逆行列を使う連想になり、それはもはや
純粋な Hebb ではない——新しい事前登録の対象になる。

## 再現方法

```bash
uv run pytest research/retrieval -q                  # 36 件のテスト
uv run python -m research.retrieval.run_retrieval --seeds 0,1,2,3,4
```

テキスト側はローカルの Ollama `nomic-embed-text`（凍結フロントエンド）を使い、トークン単位の
埋め込みは `data/embeddings/nomic-embed-text.json` にキャッシュされる。**Ollama が使えないときは
実験を実行しない**。偽のバックエンドに退避することはない。

## 既知の境界

1. **データセットはプログラム生成**（4 形状 × 3 明度 × 6 位置 × 2 サイズ = 144）であり、
   文献と比較できない。Flickr8k の**ローダーは用意済み**（`flickr8k.py`：読み込みのみ、ダウンロードは
   しない。ディレクトリ構成と r が一つの `Flicker8k_Dataset` という綴りはモジュールの docstring に
   ある）だが、**実データでの実行はまだない**——ダウンロード元とファイルごとのチェックサムは
   未登録である。
2. **バスの二経路は同じ空間にない**：`semantic` と `temporal` はそれぞれ独立のシードを持つ
   ランダム射影を通るため、直接コサインを取ると常にランダム水準になる。対照の実測値 0.034 = 1/29 は
   この記述と一致する。
3. **連想は方向ごとに別**：各方向が自分の `W` を学習し、互いに転置であることは仮定しない。
4. **報告するのは R@1 と R@5 のみ**。事前登録が定めたのはこの二つだけである。
