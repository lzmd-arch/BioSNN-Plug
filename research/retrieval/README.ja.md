# 検索ライン：クロスモーダル R@K

[中文](README.md) · [English](README.en.md)
**⚠️ 破壊的変更の免責期間：2027-09 まで**（計画書 §12.5、ADR-0005）。

## 何を検証するか

計画書 §七 第二段階で唯一まだ ❌ の成功基準：**クロスモーダル検索 R@1 50%+**。

事前登録は
[`sweep_results/retrieval_procedural_prereg.md`](../../sweep_results/retrieval_procedural_prereg.md)
にあり、**データより先に**書かれている。結論を読む前にそちらを読むこと。

## 第 1 ラウンド：外積 Hebb（2026-10-17、5 シード）

**基準には届いていない。R@1 = 0.141**（シード間 0.121–0.172）、ランダム基準 0.034；
**R@5 = 0.528**。

| 欄 | 結果 | 意味 |
| :--- | :--- | :--- |
| 同一モダリティ検索（読み方 a） | テキスト 1.000；画像 0.759–0.931 | 符号化そのものが同一性を保っている |
| バスの直接比較（連想なし） | 0.034 / 0.000–0.069 | **ランダム基準と同じ**——二経路は別の射影であり、事前登録の予想どおり |
| 外積 Hebb 連想（合格ライン） | **R@1 0.141 / R@5 0.528** | ランダムの 4 倍だが、50% には遠い |

R@5 が 0.528 で R@1 が 0.141 ということは、連想がクロスモーダル情報を**運んではいる**が、
順位の上位が散っていることを意味する。正解は近くにあるが、一位には稀にしか来ない。

## 第 2 ラウンド：delta 規則への置き換え（2026-10-17）

事前登録：[`retrieval_delta_prereg.md`](../../sweep_results/retrieval_delta_prereg.md)。
データ、分割、シード、符号化は同じで、連想規則だけを差し替える。

| 連想規則 | R@1（5 シード平均） | R@5 |
| :--- | ---: | ---: |
| 外積 Hebb（第 1 ラウンド） | 0.141 | 0.528 |
| **delta（Widrow–Hoff、今回）** | **0.359** | **0.845** |

**依然として 50% には届いていない。** ただし R@5 は 0.528 から 0.845 へ、R@1 は 0.141 から
0.359 へ上がった。第 1 ラウンドの診断——外積和は訓練目標を類似度で重み付けして平均するだけで、
近傍を抑制する仕組みを持たない——が正しかったことを示している。誤差修正は順位の上位を
確かに締めた。

⚠️ **delta は教師なし Hebb ではない**：誤差項 `v − W·t` の `v` は、ペア学習時に与えられる
教師信号である。したがってこれは**教師ありの局所規則**であり、各シナプスは自分の前後活動と
誤差だけを使い、連鎖律は通らない。この境界は曖昧にしてはならない。

⚠️ **大きなステップ幅は発散する**：グリッドの η=0.1 の一部は inf/NaN に溢れる。現在は発散を
明示的に記録し、交差検証では 0 点として扱うので、平均を NaN に汚染しない。最初の版には
この処理がなく、ログに `RuntimeWarning: invalid value encountered` が出ていた——**この警告は
ノイズではなく、パラメータ選択が NaN に汚染されている合図である**。

## 第 3 ラウンド：線形上界の探針——ボトルネックは表示であり、規則ではない（2026-10-17）

事前登録：[`retrieval_ridge_prereg.md`](../../sweep_results/retrieval_ridge_prereg.md)。
閉形式のリッジ回帰（`W = (TᵀT + λI)⁻¹ Tᵀ V`）で、二つのバス表示の間の**線形写像の能力上限**を測る。

| 連想規則 | R@1（5 シード平均） | 局所性 |
| :--- | ---: | :--- |
| 外積 Hebb | 0.141 | あり |
| delta（Widrow–Hoff） | 0.359 | あり（教師あり） |
| **リッジ回帰（線形上界）** | **0.466** | **なし——訓練集合全体を見て逆行列を解く** |

**線形上界でも 50% に届かない。** これで問題の所在が決まる：**ボトルネックは連想規則ではなく表示にある。**
delta はすでに線形上界の大半（0.466 のうち 0.359）を得ており、規則を磨いても余地は小さい。
50% を越えるには表示そのものを変える必要がある——プーリング、バス次元、あるいは二つの
チャネルで射影を共有すること。

⚠️ **これはあくまで「線形」上界である**：非線形な読み出しならさらに高くなる可能性があるため、
「50% は不可能」と読んではならない。読めるのは「線形に見る限り、この表示では足りない」だけである。
リッジ回帰は局所規則ではなく、**合格欄には一切入らない**。

## 第 4 ラウンド：表示グリッド——次元を増やしても効かない（2026-10-17）

事前登録：[`retrieval_representation_prereg.md`](../../sweep_results/retrieval_representation_prereg.md)。

| 連想 | bus@128 | bus@256 | bus@512 | plugin（バス射影なし） |
| :--- | ---: | ---: | ---: | ---: |
| ridge（線形上界） | 0.466 | 0.476 | 0.469 | **0.479** |
| delta（局所） | 0.359 | **0.393** | 0.407 | 0.403 |

**バスの次元はボトルネックではない。** `bus_dim` を 128 から 512 に上げ、さらにはバス射影を
完全に迂回して（画像 1152 / テキスト 256 の生のプラグイン出力）も、線形上界は 0.47–0.48 に留まる。

事前登録の判定規則に従えば、これは**符号化を変える**分岐に入る：画像側のイベント符号化は
3 フレーム（空 → 画像 → 画像）だけで、立ち上がりのエッジを一度だけ保持する；テキスト側は
各トークンを単独の文として埋め込み、z-score top-k をかける。それぞれが失うものを、線形写像で
埋め戻すことはできない。

⚠️ 先験的な制約：**クロスモーダルは同一モダリティを超えられない**。画像側の同一モダリティ
R@1 は 0.759–0.931 であり、クロスモーダルの 0.48 は「画像同士がそもそも分離しきらない」
という上限にすでに近い。

## 第 5〜7 ラウンド：非線形の上界と「より局所的な」二つの規則（2026-10-17）

| 読み出し | R@1（5 シード平均） | 学習規則か |
| :--- | ---: | :--- |
| delta（線形・局所） | 0.393 | はい |
| 固定ランダム特徴 + delta | 0.383 | はい（特徴は固定） |
| 競合連想記憶（M ≤ 64） | 0.114（5 シード） | はい |
| **k 近傍（非線形上界）** | **0.555 / 0.562** | **いいえ——何も学習しない** |

重要な順に三つ：

1. **50% を越えたのは kNN だけで、kNN は学習しない。** 写像を作らず、「最も似た訓練例」を
   見つけてその画像コードを平均するだけである。これは達成ではなく、訓練集合を持ち歩いている。
2. **固定ランダム特徴は助けにならなかった**（0.383 < 0.393）。kNN の利点は非線形性ではなく、
   **事例ごとの局所投票**である。
3. **競合記憶は M ≪ n で過小適合する**（0.103）。ユニットが少なすぎると、各ユニットが無関係な
   複数の画像コードを平均し、ぼやけたコードを返す。kNN に近づけるには M を訓練サンプル数に
   近づける必要があり、**それは記憶化であって学習ではない**。

⚠️ **この基準の問いは書き換えねばならない**：手続き生成のペア集合では「R@1 ≥ 50%」は
**記憶化**で満たせてしまい、満たしても局所学習が成立することを何も示さない。これは本リポジトリが
繰り返し記録してきた罠——**合格した数字が自明解でありうる**——そのものである。

## 第 8・9 ラウンド：実データ（Flickr8k）——現行の前端はランダム水準（2026-10-17）

事前登録：[`retrieval_flickr8k_prereg.md`](../../sweep_results/retrieval_flickr8k_prereg.md)、
[`retrieval_frozen_frontend_prereg.md`](../../sweep_results/retrieval_frozen_frontend_prereg.md)。
公式分割（train 6000 / test 1000）、ランダム基準は **0.1%**。

| 前端 | 読み出し | R@1 | 備考 |
| :--- | :--- | ---: | :--- |
| 現行プラグイン（24×24 DVS + トークン単位） | kNN | **0.002** | ほぼランダム |
| 現行プラグイン | — | — | 上界がすでにランダム水準なので局所規則は不要 |
| **凍結 ResNet18 + 文単位 nomic**（共同学習なし） | ridge（線形上界） | **0.076** | ランダムの 76 倍だが 50% には遠い |
| 凍結 ResNet18 + 文単位 nomic | kNN | 0.052 | 非線形は助けにならない |

二つの結論：

1. **現行の符号化器は実データでクロスモーダル信号を持たない。** 3 フレームの 24×24 グレースケール
   差分とトークン単位の文埋め込みの組み合わせは、1000 択の検索ではランダム水準である。
2. **それぞれ強い凍結前端に替えても、線形上界は 7.6% に留まる。** 両者は**共同学習されて
   いない**ため、二つのモダリティを繋ぐ仕事は依然として連想層にあり、連想層が回復できるのは
   これだけである。

⚠️ **この 50% の基準はここで識別力を失っている。** Flickr8k で本当に 50% に届く唯一の現実的な道は
**共同学習済みのクロスモーダル符号化器**（CLIP など）だが、その場合アラインメントは事前学習が
済ませており、局所連想規則の出番はない。合格しても「局所学習が成立した」ことを何も示さない。
**これは実装の不出来ではなく、判定基準そのものの問題である。**

続けるなら次は**基準の書き換え**——たとえば整列済み符号化器の oracle を零点として、局所規則が
どれだけ整列を回復するかを測る——であり、区別できない指標での調整ではない。

## 第 10 ラウンド：基準の書き換え——回復率（2026-10-17）

事前登録：[`retrieval_recovery_prereg.md`](../../sweep_results/retrieval_recovery_prereg.md)。

元の基準（絶対 R@1 ≥ 50%）は、符号化器の強さ・符号化器間の整列・連想層の良し悪しという
三つを同時に含んでいる。それらを分離するため、**回復率**に切り替える：

```text
回復率 = (R_局所 − R_ゼロ) / (R_上界 − R_ゼロ)
```

| データセット | 局所（delta） | 線形上界（ridge） | ゼロ連想 | **回復率** |
| :--- | ---: | ---: | ---: | ---: |
| 手続き生成ペア集合（bus@128） | 0.359 | 0.466 | 0.034 | **0.752** |
| Flickr8k（凍結 ResNet + nomic） | 0.052 | 0.076 | 0.001 | **0.673** |

**両方のデータセットで 50% を超えた。** 九ラウンドの中で初めて、**データセットをまたいで
安定した**結論である：純粋に局所的で教師信号を用いる規則は、線形上界の三分の二から四分の三を
取り戻せる。

⚠️ 三つを併せて読むこと：
1. **旧基準をこっそり緩めたのではない。** 絶対 R@1 は ❌ のままで併記される。回復率が高くても
   その判定は変わらない。
2. **Flickr8k の delta は学習不足**（`epochs ∈ {1,3}`、3 分割、単一シード＝事前登録に書いた
   計算量の上限）。したがって 0.673 は**下界**である。
3. **上界自体が低い**（7.6%）。回復率が答えるのは「局所規則が線形上界からどれだけ離れているか」
   であり、「この前端で十分か」ではない——後者は未解決のままである。

## 第 11 ラウンド：前端の受け入れ基準——線形プローブ（2026-10-17）

事前登録：
[`retrieval_frontend_probe_prereg.md`](../../sweep_results/retrieval_frontend_probe_prereg.md)。
㉟ が残した穴を埋める：回復率は「規則」の基準を与えたが、前端には基準がなかった。

**定義**：キャプションに 50 回以上現れる上位 50 の内容語について、**線形プローブ**（閉形式リッジ）
で画像特徴から「その語がキャプションに含まれるか」を予測し、テスト分割で AUC を測る。

| 側 | AUC 中央値 | 語数 |
| :--- | ---: | ---: |
| **画像（ResNet18）** | **0.790** | 45（陽性が少ない 5 語は除外） |
| テキスト（文単位 nomic、自己点検） | 1.000 | 45 |

事前登録の基準（画像側 ≥ 0.75）に対し、**ResNet 前端は合格**：キャプションが述べる意味を
確かに保持している。

⚠️ **回復率と併せると、より情報量の多い像が見える**：意味は**線形に読める**（AUC 0.79）が、
二つの空間の**事例レベル**の整列は弱いまま（線形上界 0.076）。前端は見えているが、テキストと
同じ座標系にない。これが連想層の存在理由であり、回復率（67%）が高く絶対 R@1 が低い理由である。

⚠️ プローブは**線形**で、測るのは**必要性のみ**：AUC が高くてもクロスモーダル整列は保証されず、
低くても非線形解を排除できない。

## 記録しておくべき発見：この規則には調整できるハイパーパラメータがない

事前登録は `η`（学習率）と `λ`（忘却）の二つを挙げた。実測では**どちらも選べない**：

* 変換は `η·(t ⊤ Σ v t⊤) / (1+λ)` であり、**η も λ も全体のスケーリング**にすぎない；
* コサインは全体スケーリングに不変 → グリッド上のすべての点が leave-one-out で**完全に同点**になり、
  「選ばれた」点は同点の先頭にすぎない。

つまり選択の工程は何も選んでいない。これは実装の欠陥ではなく、コサイン順位付けの下での
この規則の代数的性質である。本当に調整するなら擬似逆行列を使う連想になり、それはもはや
純粋な Hebb ではない——新しい事前登録の対象になる。

## 再現方法

```bash
uv run pytest research/retrieval -q                  # 36 件のテスト
uv run python -m research.retrieval.run_retrieval --seeds 0,1,2,3,4
```

テキスト側はローカルの Ollama `nomic-embed-text`（凍結フロントエンド）を使い、トークン単位の
埋め込みは `data/embeddings/nomic-embed-text.json` にキャッシュされる。**Ollama が使えないときは
実験を実行しない**。偽のバックエンドに退避することはない。

## 既知の境界

1. **データセットはプログラム生成**（4 形状 × 3 明度 × 6 位置 × 2 サイズ = 144）であり、
   文献と比較できない。Flickr8k の**ローダーは用意済み**（`flickr8k.py`：読み込みのみ、ダウンロードは
   しない。ディレクトリ構成と r が一つの `Flicker8k_Dataset` という綴りはモジュールの docstring に
   ある）だが、**実データでの実行はまだない**——ダウンロード元とファイルごとのチェックサムは
   未登録である。
2. **バスの二経路は同じ空間にない**：`semantic` と `temporal` はそれぞれ独立のシードを持つ
   ランダム射影を通るため、直接コサインを取ると常にランダム水準になる。対照の実測値 0.034 = 1/29 は
   この記述と一致する。
3. **連想は方向ごとに別**：各方向が自分の `W` を学習し、互いに転置であることは仮定しない。
4. **報告するのは R@1 と R@5 のみ**。事前登録が定めたのはこの二つだけである。
