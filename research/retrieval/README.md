# 检索线：跨模态 R@K

[English](README.en.md) · [日本語](README.ja.md)
**⚠️ 破坏性变更免责期：至 2027-09**（计划书 §12.5、ADR-0005）。

## 在验证什么命题

计划书 §七 第二阶段那条唯一还是 ❌ 的成功标准：**跨模态检索 R@1 50%+**。

预注册写在 [`sweep_results/retrieval_procedural_prereg.md`](../../sweep_results/retrieval_procedural_prereg.md)，
**先于数据**。读结论之前先读它。

## 第一轮：外积 Hebb（2026-10-17，5 个种子）

**没有达标。R@1 = 0.141**（种子间 0.121–0.172），随机基线 0.034；**R@5 = 0.528**。

| 栏目 | 结果 | 说明 |
| :--- | :--- | :--- |
| 同模态检索（读法 a） | 文本 1.000；图像 0.759–0.931 | 编码本身保住了身份 |
| 总线直接比（零联想对照） | 0.034 / 0.000–0.069 | **与随机基线相同**——两路是不同投影，正是预注册预期 |
| 外积 Hebb 联想（验收线） | **R@1 0.141 / R@5 0.528** | 高于随机 4 倍，但离 50% 很远 |

R@5 到 0.528 而 R@1 只有 0.141，说明**联想确实带上了跨模态信息，但排序头部很散**——
正确项常常在附近而不在第一位。

## 第二轮：换成 delta 规则（2026-10-17）

预注册：[`retrieval_delta_prereg.md`](../../sweep_results/retrieval_delta_prereg.md)。同样的数据、
切分、种子与编码，只换联想规则。

| 联想规则 | R@1（5 种子均值） | R@5 |
| :--- | ---: | ---: |
| 外积 Hebb（第一轮） | 0.141 | 0.528 |
| **delta（Widrow–Hoff，本轮）** | **0.359** | **0.845** |

**仍然没有达到 50%。** 但 R@5 从 0.528 抬到 0.845、R@1 从 0.141 抬到 0.359，说明第一轮那句
诊断是对的：外积和只是把训练目标按相似度加权平均，没有抑制近邻的机制；误差修正确实把
排序头部收紧了。

⚠️ **delta 不是无监督 Hebb**：误差项 `v − W·t` 里的 `v` 是配对训练时给出的教师信号，
所以它是**有教师的局部规则**——每个突触只用自己两端的前后活动加一个误差，不走链式法则。
这条边界不许含糊。

⚠️ **大步长会发散**：网格里 η=0.1 的部分配置会溢出成 inf/NaN。现在发散被显式标记、在
交叉验证里记 0 分，不让它把平均值污染成 NaN。第一版没有这一步，日志里出现过
`RuntimeWarning: invalid value encountered`——**这条警告不是噪声，是选参被 NaN 污染的信号**。

## 第三轮：线性上界探针——瓶颈在表示，不在规则（2026-10-17）

预注册：[`retrieval_ridge_prereg.md`](../../sweep_results/retrieval_ridge_prereg.md)。
用**闭式岭回归**（`W = (TᵀT + λI)⁻¹ Tᵀ V`）量两条总线表示之间**线性映射的能力上限**。

| 联想规则 | R@1（5 种子均值） | 是否局部 |
| :--- | ---: | :--- |
| 外积 Hebb | 0.141 | 是 |
| delta（Widrow–Hoff） | 0.359 | 是（有教师） |
| **岭回归（线性上界）** | **0.466** | **否——一次看整个训练集，要矩阵求逆** |

**线性上界也没到 50%。** 这一条把问题定位了：**瓶颈不在联想规则，在表示。**
delta 已经拿到线性上界的大半（0.359 / 0.466），继续在规则上打磨的空间不大；
要越过 50%，得动表示本身——池化方式、总线维度、或者让两个通道共享一个投影。

⚠️ **这只是一个"线性上界"**：非线性读出可能更高，所以它不能被读成"50% 不可能"，
只能被读成"线性地看，这套表示不够"。岭回归不是局部规则，**不进任何达标栏位**。

## 第四轮：表示网格——加维度也没用（2026-10-17）

预注册：[`retrieval_representation_prereg.md`](../../sweep_results/retrieval_representation_prereg.md)。

| 联想 | bus@128 | bus@256 | bus@512 | plugin（不经总线投影） |
| :--- | ---: | ---: | ---: | ---: |
| ridge（线性上界） | 0.466 | 0.476 | 0.469 | **0.479** |
| delta（局部） | 0.359 | **0.393** | 0.407 | 0.403 |

**总线维度不是瓶颈。** 把 `bus_dim` 从 128 加到 512、甚至完全绕过总线投影直接用插件输出
（图像 1152 / 文本 256），线性上界都停在 0.47–0.48。

按预注册的判据，这触发的是**改编码**那一条：图像侧的事件编码只有三帧（空帧 → 图像 → 图像），
只保留一次跳变的边沿；文本侧是逐 token 的**句子** embedding 再做 z-score top-k。两条编码各自
丢的东西，一个线性映射补不回来。

⚠️ 一个先验的约束：**交叉模态不可能超过同模态**。图像侧同模态 R@1 只有 0.759–0.931，
所以 0.48 的跨模态已经接近"图像侧自己都分不太开"的天花板。

## 第五至七轮：非线性上界与两种"更局部"的规则（2026-10-17）

| 读出方式 | R@1（5 种子均值） | 是学习规则吗 |
| :--- | ---: | :--- |
| delta（线性、局部） | 0.393 | 是 |
| 固定随机特征 + delta | 0.383 | 是（特征是固定的） |
| 竞争联想记忆（M ≤ 64） | 0.114（5 种子） | 是 |
| **k 近邻（非线性上界）** | **0.555 / 0.562** | **不是——没有学习** |

三条结论，按重要性排：

1. **真正越过 50% 的只有 kNN，而它没有学习。** 它不做任何映射，只是"找最像的训练样本、
   把它们的图像码投出来"。这不是达标，是把训练集带在身上。
2. **固定随机特征没有帮上忙**（0.383 < 0.393）。所以 kNN 的优势不是"非线性"，而是
   **按实例局部投票**。
3. **竞争联想记忆在 M ≪ n 时欠拟合**（0.103）。单元太少时，每个单元平均了好几个互不相关
   的图像码，投出来的是模糊码。要让它逼近 kNN，得让 M 接近训练样本数——**那就是记忆化**，
   而不是学习。

⚠️ **这一格的问题因此被改写**：在程序生成配对集上，"R@1 ≥ 50%" 可以被**记忆化**满足，
满足它并不能说明局部学习成立。这正是本仓库反复记的那类陷阱——**达标数字可能是平凡解**。

## 第八、九轮：真实数据（Flickr8k）——现有前端在随机水平（2026-10-17）

预注册：[`retrieval_flickr8k_prereg.md`](../../sweep_results/retrieval_flickr8k_prereg.md)、
[`retrieval_frozen_frontend_prereg.md`](../../sweep_results/retrieval_frozen_frontend_prereg.md)。
官方切分（train 6000 / test 1000），随机基线 **0.1%**。

| 前端 | 读出 | R@1 | 说明 |
| :--- | :--- | ---: | :--- |
| 现有插件（24×24 DVS + 逐 token） | kNN | **0.002** | 基本等于随机 |
| 现有插件 | — | — | 上界已在随机水平，局部规则无需再测 |
| **冻结 ResNet18 + 整句 nomic**（未联合训练） | ridge（线性上界） | **0.076** | 76× 随机，但离 50% 很远 |
| 冻结 ResNet18 + 整句 nomic | kNN | 0.052 | 非线性没有帮上忙 |

两条结论：

1. **现有编码器在真实数据上没有跨模态信号。** 24×24 灰度三帧的帧差，配逐 token 的句子
   embedding，在 1000 选 1 的检索里就是随机水平。
2. **换成两个各自很强的冻结前端，线性上界也只有 7.6%。** 它们**未经联合训练**，所以
   "把两个模态接起来"这件事仍然完全落在联想层——而联想层能恢复出来的，就这么点。

⚠️ **这条 50% 的验收线在这里失去了区分力。** 要在 Flickr8k 上真的到 50%，唯一实际的路是
用**联合训练过的跨模态编码器**（CLIP 一类）——但那时对齐已经由预训练完成，局部联想规则
无事可做，达标也就说明不了"局部学习成立"。**这是判定标准本身的问题，不是实现没做好。**

下一步（若继续）应当是**重述这条标准**，例如：以"对齐编码器 oracle"为零点，量局部规则
能恢复多少对齐；而不是继续在一套无法区分的指标上调参。

## 一个必须记下来的发现：这层规则没有可调超参

预注册写了两个超参 `η`（学习率）与 `λ`（遗忘）。实测**两个都选不动**：

* 外积和的变换是 `η·(t ⊤ Σ v t⊤) / (1+λ)`，**η 与 λ 都只是全局缩放**；
* 余弦对全局缩放不敏感 → 网格上所有组合的留一分数**完全并列**，选中的只是并列里的第一个。

所以「选参」这一步实际上什么也没选。这不是实现缺陷，是这条规则在**余弦排序**下的
代数性质。真要调，得换成带伪逆的联想（那就不再是纯 Hebb，留作下一个预注册）。

## 怎么跑出来

```bash
uv run pytest research/retrieval -q                  # 36 条测试
uv run python -m research.retrieval.run_retrieval --seeds 0,1,2,3,4
```

文本侧走本机 Ollama 的 `nomic-embed-text`（冻结前端），token 级 embedding 缓存在
`data/embeddings/nomic-embed-text.json`。**Ollama 不可用时实验不跑**，不退回假后端。

## 已知边界

1. **数据集是程序生成的**（4 形状 × 3 明度 × 6 方位 × 2 尺寸 = 144），不能对标文献。
   Flickr8k 的**加载器已就位**（`flickr8k.py`：只加载、不下载，目录结构与那个少一个 r 的
   `Flicker8k_Dataset` 都写在模块文档里），**真实数据上的运行还没做**——下载来源与逐文件
   校验和尚未登记。
2. **总线两路不在同一空间**：`semantic` 与 `temporal` 各自经过独立种子的随机投影，
   直接比余弦恒在随机水平。对照实测 0.034 = 1/29，与这句话一致。
3. **联想层是单向的**：两个方向各拟合一个 `W`，不假设互为转置。
4. **只报 R@1 / R@5**，不报平均精度之类的其它口径——预注册只写死了这两个。
