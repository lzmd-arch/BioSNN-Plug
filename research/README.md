# 研究代码（`research/`）

## ⚠️ API 不稳定声明

**本目录下的代码在头 12 个月内（至 2027-09）不做任何兼容性承诺。**

计划书 §12.5 给了研究代码一个破坏性变更免责期：

> 破坏性变更免责期：研究代码前 12 个月明确标注 API 不稳定，骨架库独立 semver
> 不受影响。

取舍的理由见 [`docs/adr/ADR-0005`](../docs/adr/ADR-0005-versioning-policy.md)。

**要拿来用的东西请用 [`biosnn-bus`](../packages/biosnn-bus/)**，它遵循 semver
并且刻意不依赖本目录的任何代码（见 [`ADR-0001`](../docs/adr/ADR-0001-skeleton-as-separate-library.md)）。

## 当前规模

**这个项目现在跑在 256 个脉冲神经元上。**

三条验证线各自的网络（数字取自各线 CLI 的默认值，也就是验收配置）：

| 线 | 网络 | 规模 | 类型 |
| :--- | :--- | ---: | :--- |
| W1 感知层 | 3 层 × 1024 | **3,072** 单元 | 速率型 LReLU——**不是**脉冲神经元 |
| W2 认知层 | 单层循环 | **256** 神经元 | **ALIF 脉冲神经元**（β=0.07） |
| W3 执行层 | 群体 Critic + Actor | **64** 单元（+2 个动作） | 速率型单元 |
| 骨架库演示 | 脉冲总线 | 128 维（插件 32 + 128 通道） | 插件编码单元，**不是**神经元 |
| W3 脉冲化（第三阶段） | LIF 输出层 + 群体 Critic | 64 单元 | **脉冲**（LIF），10 种子下 0/10 过 200 |
| W4 跨模态检索 | 冻结前端 + 联想层 | 512 / 768 维特征 | 无脉冲神经元；联想层是外积或 delta 规则 |

**真正意义上的脉冲神经元**：W2 的 **256** 个，加上第三阶段那条脉冲化执行线的 **64** 个（未达验收，10 种子 0/10）。W4 没有脉冲神经元——它是冻结前端 + 局部联想。

⚠️ **这与计划书的目标差约两个数量级**，写在这里免得读者以为规模已经跟上了：

| | 神经元规模 |
| :--- | ---: |
| **现在（实测）** | **256** |
| §2.2 认知核心「初始约 5 万神经元」 | 50,000 |
| §九 第二阶段目标 | 100,000 |
| §九 第四阶段目标 | 500,000 |

差距约 **195 倍**。W1 那 3,072 个单元虽然数量最多，但它是速率型的，
**不能算进「脉冲神经元规模」这个指标**。放大规模的路径、显存约束与三条降级路径写在
计划书 §6.2/§6.3；**规模的实测实验尚未开始**（§九 把「10 万」排在第二阶段）。

## 这里会有什么

按计划书 §七 的阶段划分，本目录从**第一阶段**开始填充：

| 阶段 | 内容 | 对应计划书 |
| :--- | :--- | :--- |
| 第一阶段（1-3 月） | e-prop 认知核心（ALIF + 自适应阈值；计划书点名的 Trace Propagation 经考证**不适用**，见 [ADR-0010](../docs/adr/ADR-0010-eprop-quadratic-storage-and-trace-propagation.md)）；核化 IB-Hebbian 感知层（含除法归一化）；R-STDP 执行层（含 Critic） | §七 第一阶段、§三 |
| 第二阶段（4-8 月） | 双规则协同、TAAF 快速微调、ES 元学习仲裁器 | §七 第二阶段 |
| 第三阶段（9-15 月） | 三规则闭环、持续学习基准 | §七 第三阶段 |
| 第四阶段起 | 神经发生、规模扩展、元认知门控 | §七 第四阶段 |
| 第三阶段（部分） | **执行层脉冲化**（`rstdp_spiking/`：LIF + 带真实 Δt 的 STDP + 线性 TD / TD-LTP 群体 Critic）与**跨模态检索**（`retrieval/`：数据集、编码、五种联想、恢复率口径） | §七 第三阶段 |
| 第三阶段（未开始） | 音频插件、持续学习基准、仲裁器扩展到三规则 | §七 第三阶段 |

每个模块的 docstring 顶部都要标注免责期与到期日期。

## 目录约定

```text
research/
├─ common/                  # 无领域知识的基建（种子 / 设备 / 指标 / 复现记录）
├─ components/              # 可参数化的领域零件（CartPole 状态编码……），不出结论
├─ <主题>/
│  ├─ README.md
│  ├─ <实现>.py
│  └─ tests/
└─ ...
```

**有对外结论的主题必须有 README**，写清三件事：**在验证什么命题**、**当前结论**、
**怎么跑出来**。计划书 §9 的评估指标表是这些结论的验收标准。

两类豁免，都登记在这里，不在别处另写一份：

* `common/`——纯基础设施（种子 / 设备 / 指标 / 复现记录），用法规约在各模块 docstring 里，
  目录级 README 只会把它们复述一遍；
* **结论已经落在证据层的主题**——结论跟着数据走，目录里不再复制一份。目前是 `continual/`
  （结论见 [`sweep_results/continual_cifar100/README.md`](../sweep_results/continual_cifar100/README.md)）；
  `cognitive/` 还在铺设、尚无对外结论，出结论时按上面第一条补 README。

**依赖只朝一个方向：主题 → `components/` → `common/`。**

* `common/` 是**无领域知识的基建**，不 import 任何主题，也不 import `components/`；
* `components/` 是**可参数化、不出结论的领域零件**，只依赖 `common/`；
* **主题之间只有两种合法的边**：①`arbiter/`、`continual/` 这类**目的就是组合/基准**的
  主题，读对方**包根导出的名字**（`from research.eprop import EPropLearner`），不碰
  子模块；②什么都不 import。

不满足这两条的共用需求，正确答案是把那段东西提升成 `components/` 里的零件、用**显式参数**
区分两边的取值——不是复制一份代码。`components/cartpole_encoding.py` 就是这么来的：
两条执行层线共用同一份编码实现，中心半宽 `(1.5, …)` 与 `CARTPOLE_HALF_WIDTHS` 是参数。
复制代码的代价已经付过一次：两个编码公式在文档里被说成「同构」，取值范围其实不同，
而没有任何检查能发现。

这条规则由 [`tests/test_architecture.py`](../tests/test_architecture.py) 用 AST 检查，
不靠自觉。

`research/` 是一个**包**，不是一堆散脚本——这样三条线才能共用 `common/` 里那套
口径必须一致的东西。所以入口脚本一律用**模块方式**跑：

```bash
uv run python -m research.<topic>.<script>
```
直接 `python research/<主题>/<脚本>.py` 也能跑，但那样 `sys.path` 上是脚本所在
目录而不是仓库根，`research.common` 就 import 不到了。

测试放在各主题的 `tests/` 下。`pyproject.toml` 的 `testpaths` 已包含 `research`，
所以本地 `uv run pytest` 会一并跑到；CI 上它们归 `research-smoke` job（要 torch），
骨架库与仓库工具链的测试归 `test` job，两个 job 各自跑得动的部分。

## 最小复现脚本

计划书 §12.3 要求"每篇核心文献对应一个 `examples/paper_<name>.py`"，用来拦截
"论文说能跑但仓库跑不通"。这类脚本放在 [`examples/`](../examples/)，不放这里——
它们要能被 CI 直接执行。

## 提交前的额外要求

除仓库通用的提交前核查清单（见 [`CONTRIBUTING.md`](../CONTRIBUTING.md)）外，
研究代码还需要：

- 实验结论附完整环境记录（见 [`docs/reproducibility.md`](../docs/reproducibility.md)）；
- 引用外部结论时，在 [`docs/references.md`](../docs/references.md) 里登记并标核验状态；
- 与代理梯度基线的对比要给出**量化差距报告**——计划书 §9 把"产出与代理梯度基线的
  量化差距报告"列为第二阶段的验收项，而不是要求追平。
