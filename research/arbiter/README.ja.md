# 仲裁器：規則間の衝突検出と重み調整

[中文](README.md) · [English](README.en.md)
**注意：破壊的変更の免責期間は 2027-09 まで**（プロジェクト計画書 §12.5、ADR-0005）。

## どの命題を検証しているのか

プロジェクト計画書 §3.4 の仲裁次元の**第 1 類**：Hebbian ↔ e-prop の**衝突検出と重み調整**。
（第 2–3 類は他の規則ペア、第 4 類は「自分で処理するか LLM を呼ぶか」という调度の決定で、
いずれも後の段階です。）

衝突の判定は §3.4 の原文に従います：

> 衝突の判定：同一のシナプス重みに対する二つの規則の更新方向のコサイン類似度を計算し、
> 角度が 90 度を超えたら衝突と判定する。

受入基準は第二段階の「仲裁器が双規則の衝突イベントを 50% 以上減らす」、および §九 の
「三規則協調 / 衝突イベント割合 < 20%」です。

## 現時点の結論

**衝突検出は完成し、ES 仲裁器も完成しましたが、「衝突イベントが 50% 減る」は合成データ上では
自明に成立しており、何も検証していません。**

1. **突触単位のコサインは退化する。角度の実義は行単位にしかない。** スカラー一つの
   「方向」は符号だけなので、突触単位のコサインは**常に ±1**、「角度が 90 度超」は
   「符号が逆」に退化し、閾値は意味を持ちません。角度に実義を持たせるには、**一組の
   突触**（例：あるシナプス前ニューロンの出力重み一式）に対してコサインを取る必要があります。
   両方の読みを実装しています（`axis=None` が突触単位 / `axis=1` が行単位、既定は行単位）。
   **混用してはいけません。**
   注意：**`axis` は numpy の慣例に従います**。`(n_pre, n_post)` の更新テンソルで
   `axis=1` は `n_post` を畳み込み、**行に一つ**の値（シナプス前ニューロンの出力）。
   `axis=0` は `n_pre` を畳み込み、**列に一つ**の値（シナプス後ニューロンの入力）。
   別の問題です。意識して選んでください。

2. **注意：自明解は `alpha → 0`、つまり規則 B を切ること。** 目的が「A との衝突を最小化する」
   だけなら、最適解は**常に B を使わないこと**です——それは仲裁ではなく退化であり、
   **50% の基準を自明に通過してしまいます**。合成トレース（`B = −A + ノイズ`、正面衝突）で
   5 シード実測：**毎回 100% 減**、`alpha` は 0.5 から 0.2–0.3 へ漂います。これは
   **症状であって、成績ではありません**。
   したがって**「衝突イベントが 100% 減った」だけでは情報量ゼロ**です。`retention`
   （B がどれだけ残ったか）と**一緒に**報告してください。`fit(..., min_retention=...)`
   がこの退化解を塞ぎます。
   注意：これは「平凡な性質を検証する緑のテスト」と同種の問題です——退化解の下で
   `reduction >= 50%` は常に成り立つので、何も測っていません。

3. **ES のパラメータ化はスカラー 1 つのまま。** Confavreux et al. は「共活性化規則が
   複雑になるほどメタ学習が**失敗し始める**」と報告しています。だから仲裁器は `alpha`
   一つだけを調整します——これは未完成ではなく、意図的です。

## どうやって実行して結果を出すのか

```bash
uv run pytest research/arbiter -q                  # 32 件
```

二つのモジュール：

| モジュール | 役割 |
| :--- | :--- |
| `conflict.py` | 衝突判定そのもの：`cosine_similarity` / `is_conflict` / `measure_conflict`。**Hebbian も e-prop も知りません**——二つの更新テンソルを受け取り、一つの問いに答えます |
| `es_arbiter.py` | ES メタ学習仲裁器：`blend`（`alpha` で二規則の更新を混合）+ `fit`（ES で `alpha` を調整）。**どの研究ラインにも依存しない**ので単体で試験できます |

## 既知の境界

1. **第 1 類（Hebbian ↔ e-prop）だけを実装。** 第 2–3 類（e-prop ↔ R-STDP、
   Hebbian ↔ R-STDP）と第 4 類（调度の決定）は未実装——計画書はそれらを第三段階に置いています。
2. **仲裁器はまだどちらの研究ラインにも接続されていません。** `research/ib_hebbian/` と
   `research/eprop/` は今も独立に検証されており、**両者の更新が同じ仲裁器に入る場所は
   どこにもありません**。したがって本モジュールは**部品**であって、「双規則協調」そのもの
   ではありません——`memterm-pure-layer-not-wired` と同種の問題です。
3. **`alpha` が混合するのは更新テンソルであって、学習率ではありません。** 別の手は各規則の
   学習率を調整するもので、「重み調整」の別解釈です。本実装は前者を採りました（§3.4 の
   文言に近い）が、**それが優れているという論証はありません**。
4. **衝突イベントの計数単位は「学習ステップ 1 つ」**であって突触ではありません。一歩に
   一つでも衝突があれば 1 イベント。これが §九「衝突イベント割合」の口径で、突触単位で
   数えるなら `ConflictReport.conflict_fraction` を使ってください。
