# 研究コード（`research/`）

[中文](README.md) · [English](README.en.md)

## ⚠️ API 不安定性に関する声明

**本ディレクトリのコードは、最初の 12 か月間（2027-09 まで）は互換性についていかなる
約束もしません。**

プロジェクト計画書 §12.5 は、研究コードに破壊的変更の免責期間を設けています：

> 破壊的変更の免責期間：研究コードは最初の 12 か月間、API が不安定であることを
> 明示し、スケルトンライブラリの独立した semver は影響を受けません。

このトレードオフの理由は
[`docs/adr/ADR-0005`](../docs/adr/ADR-0005-versioning-policy.ja.md) にあります。

**実際に使うものには [`biosnn-bus`](../packages/biosnn-bus/) を使ってください。** これは
semver に従っており、本ディレクトリのコードには意図的に一切依存していません
（[`ADR-0001`](../docs/adr/ADR-0001-skeleton-as-separate-library.ja.md) 参照）。

## ここに何が入るか

プロジェクト計画書 §七 のフェーズ区分に従い、本ディレクトリは**第 1 フェーズ**から
埋めていきます：

| フェーズ | 内容 | 対応するプロジェクト計画書 |
| :--- | :--- | :--- |
| 第 1 フェーズ（1-3 か月） | e-prop 認知コア（Trace Propagation + ALIF + 適応閾値）；カーネル化 IB-Hebbian 知覚層（除算正規化を含む）；R-STDP 実行層（Critic を含む） | §七 第 1 フェーズ、§三 |
| 第 2 フェーズ（4-8 か月） | 二規則の協調、TAAF 高速微調整、ES メタ学習アービタ | §七 第 2 フェーズ |
| 第 3 フェーズ（9-15 か月） | 三規則閉ループ、継続学習ベンチマーク | §七 第 3 フェーズ |
| 第 4 フェーズ以降 | 神経新生、規模拡大、メタ認知ゲーティング | §七 第 4 フェーズ |

各モジュールの docstring の先頭には、免責期間と満了日を明記する必要があります。

## ディレクトリ規約

```text
research/
├─ <フェーズまたはトピック>/
│  ├─ README.md
│  ├─ <実装>.py
│  └─ tests/
└─ ...
```

トピックごとに README を 1 つ用意し、次の 3 点を明確に書きます：**どの命題を検証して
いるのか**、**現時点の結論**、**どうやって実行して結果を出すのか**。プロジェクト計画書
§9 の評価指標表が、これらの結論の受入基準です。

## 最小再現スクリプト

プロジェクト計画書 §12.3 は「中核となる文献ごとに 1 つの `examples/paper_<name>.py` を
用意する」ことを求めており、これは「論文では動くと書いてあるのにリポジトリでは動かない」
を食い止めるためのものです。こうしたスクリプトは [`examples/`](../examples/) に置き、
ここには置きません——CI から直接実行できる必要があるからです。

## 提出前の追加要件

リポジトリ共通の提出前チェックリスト
（[`CONTRIBUTING.md`](../CONTRIBUTING.ja.md) 参照）のほかに、研究コードには次が必要です：

- 実験の結論には完全な環境記録を添付する
  （[`docs/reproducibility.md`](../docs/reproducibility.ja.md) 参照）；
- 外部の結論を引用する場合は、[`docs/references.md`](../docs/references.ja.md) に登録し、
  検証ステータスを記す；
- 代理勾配ベースラインとの比較では**ギャップの定量報告**を出す——プロジェクト計画書 §9 は
  「代理勾配ベースラインとのギャップの定量報告を出すこと」を第 2 フェーズの受入項目として
  おり、追いつくことまでは求めていません。
