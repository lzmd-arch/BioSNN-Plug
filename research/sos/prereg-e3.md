# 预注册：E3——按 SoS 原意做轨迹监督（`D_opt` vs `D_search`）（2026-11-02）

**状态：判据先落盘，代码未写，数据未跑。**

## 要检验什么

SoS 的核心主张是「**给搜索过程**比**给最优结果**更能让模型学会搜索」。
E3 把它变成两臂比较：

| 臂 | 训练数据 | 每迷宫样本数 |
| :--- | :--- | ---: |
| **opt** | 只含从起点到终点的最短路 | L |
| **search** | 完整 DFS 轨迹（含死路与回溯），**均匀抽 L 条** | L |

**样本数刻意对齐**（各取 L 条）：否则 `search` 只是"数据更多"，比的是数据量不是内容。
L = 该迷宫的最短路长度。

## 任务与环境

- 与 E0/E1 相同：滑移迷宫、9/11/13 三档、`p_slip = 0.10`、`T = 3L + 20`；
- **迷宫池**：0–99 = 训练（同时作 pilot），**1000–1099 = confirm（只判）**；
- 状态键：不裁剪的相对位移（E2 v2 已证明可用，不再动）；
- 模型：tabular softmax，**交叉熵**监督（不是 REINFORCE）；
- 训练：每个臂在训练池上跑固定轮数，两臂完全相同。

## 轨迹怎么生成（先定死）

- **opt**：BFS 最短路，逐格记录动作；
- **search**：从起点做 **DFS 带回溯**，目标为终点；记录每一步"尝试"的动作
  （进入死胡同的那些也在内），回溯本身不产生样本；
- 两者都只在**迷宫骨架**上生成（不含滑移）——训练信号描述的是"该往哪走"，不是"实际走到哪"。

## 判据（pilot / confirm）

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| E3-0 | 两臂都学到东西 | **两臂**在训练池上的成功率均 ≥ **0.50**（否则监督本身没学进去，比较无意义） |
| E3-1 | search 臂可用 | `search` 的 confirm 成功率 ≥ **0.7 × pilot 上 search 的成功率** |
| **E3-2** | **H1'：过程优于结果** | `search_confirm − opt_confirm ≥ 0.5 × (search_pilot − opt_pilot)` |
| E3-3 | 不是靠步数换成功 | `search` 的平均步数不高于 `opt` 的 **1.5 倍**（否则可能只是乱走撞上了） |

E3-0 用训练池、E3-2 的差门槛用 pilot 半——两处都是**同一半数据**里算的，
confirm 只做判定，不参与定门槛。

## 跑之前的预期

- **两臂都能学**（E3-0 应当过）：监督信号干净，迷宫也不难；
- **H1' 方向不确定**。理由：DFS 的死路样本教的是"这条路不通"，而迷宫形状差异大，
  这种局部知识未必迁移到新迷宫；相反，`opt` 样本每一步都是"朝终点正确的一步"，信号的
  信噪比更高。**我倾向 `opt` 不会输**——写在这里，是为了防止事后把它解释成意料之中。
- 若 `search` 明显输，那是对 ADR-0030 立论基础的一次真实打击，要写进结论。

## 死亡条件

- E3-0 不过（至少一臂训练池成功率 < 0.50）→ 监督学习本身有问题，停，不调网络结构重跑；
- E3-2 不过 → H1' 不成立，记为负结果；**ADR-0030 的"过程外显化"前提需要重新评估**，
  但不是自动放弃主线（还要看 E3-3 与步数分布）。

## 不做的事

- 不改迷宫、不改状态表示、不改模型类；
- 不因为 `search` 输了就加数据量重跑（那会把"内容"换成"数量"）；
- 不跑任何强化学习（E2 已经证明这条轴在本地跑不通）。
