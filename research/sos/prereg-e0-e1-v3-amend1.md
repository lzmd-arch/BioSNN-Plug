# 预注册 v3 amend 1：世界模型改成**每迷宫在线**（2026-11-02）

**状态：写在 v3 的代码运行之前。**

## 为什么要改

v3 写的是「计数表 `(状态, 动作) → Counter(下一格)`」——**全局一张表，混所有迷宫**。
可是同一个 `(状态, 动作)` 在不同迷宫里下一格是不一样的（墙不一样），所以
`p(下一格 | 状态, 动作)` **在混网格数据上不是良定义的**。

这不是猜测：v2 的查表上限只有 **0.789**，而按滑移强度（`p_slip = 0.10`）算，单迷宫内的
众数命中率应当在 0.9 左右。差的这一截，与"表里混进了别的迷宫的动力学"一致。

## 改成

**每迷宫在线学习**——这也正是 SoS 里世界模型的实际用法：

- 每个迷宫跑一条随机策略轨迹（`T = 3L + 20` 步）；
- **按时间切**：前 **60%** 的转移用来建表，后 **40%** 用来评估；
- 表只来自**本迷宫**的转移；
- 平滑的支撑集 = **几何上一步可达的格子**（自身 + 四个邻居里在界内的），
  **不含墙的信息**——墙正是模型要学的东西；
- 边际基线同样每迷宫：`p(下一格 | 动作)`，用同样的支撑集。

## 判据不变

E1-1…E1-4 的门槛一个字不动。改的只是"模型长什么样"，不是"怎么判"。

## 这条改动本身也要能被证伪

若每迷宫在线之后 E1-1 反而更差，说明 60% 的轨迹不够建表——那就是**数据预算**的问题，
届时要写的是"每个迷宫跑几条轨迹"，不是继续换模型。
