# 预注册：规模实验 S3——稀疏路径能走多远（12k / 16k）（2026-11-03）

**状态：判据先落盘，代码未跑。**

## 从 S2 读出来的两件事

1. **规模有效**（[`sweep_results/scale_s2/`](../../sweep_results/scale_s2/README.md)）：
   稀疏臂 1024 → 8192，准确率 **0.628 → 0.774（+14.6pp）**，而每步时间几乎不变。
   ADR-0031 那条"提升 ≤2pp 就停止加宽"的回退条件**不触发**。
2. **但显存是真的在涨**：8192 已经 **3,899.5 MiB**，约 **0.48 MiB / 神经元**。

按这个斜率线性外推：**16k ≈ 7.6 GB（贴着 8 GB）**、**32k ≈ 15.2 GB（放不下）**。
所以"能走多远"不是修辞问题，是**下一档就会撞墙**。

## 这一版问什么

**在 8 GB 上，稀疏路径的经验上限在哪，以及到那里还值不值。**

## 规模点与预算

- **12,288** 与 **16,384** 两个点（8192 已有，作为基准）；
- 预算与 S2 完全一致：**完整 sMNIST、2 epoch、种子 0、batch 8、fan-in 32**。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **S3-0** | 两个规模都能在 8 GB 内跑完 | 峰值 < 8,000 MiB；**OOM 如实记为该规模放不下**，不换 batch 去凑 |
| **S3-1** | 继续爬坡 | `acc(16384) − acc(8192) > 2pp` 才算"还值得加宽" |
| **S3-2** | 时间没爆 | 每个点的耗时 ≤ **1.5 ×** 8192 的耗时（S2 实测 1101 s） |

S3-0 若 16384 OOM，**不改 batch 重试**——那会把"显存上限"换成"batch 调参"。如实写：
冒烟版已经量到 8192 吃 3,899.5 MiB，16k 贴着上限，OOM 是**预期内的可能结果**。

## 跑之前的预期

- **12,288 应当跑得动**（外推 ~5.9 GB）；
- **16,384 可能 OOM**——如果 OOM，那就是这条路径在 8 GB 上的**经验上限**，比稠密的 1.35k
  高一个数量级，但仍不是无限；
- 准确率**应当继续涨**（S2 每翻倍约 +5pp），但边际可能变小。

## 死亡条件

- 16384 OOM 且 12288 也 OOM → 上限记在 8192–12288 之间，S3 结束，不再往上试；
- S3-1 不过（≤2pp）→ 边际收益已经掉到门槛下，**停止加宽**，主线换轴。

## 不做的事

- 不为了放下 16k 而偷偷把 batch 从 8 调到 4 或开梯度检查点——那是另一个变量；
- 不把 2 epoch 的精度与 W2 的 250-epoch 数字比较。
