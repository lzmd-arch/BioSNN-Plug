# 预注册：规模实验 S1——资源与可行性（稠密 vs 事件驱动稀疏）（2026-11-03）

**状态：判据先落盘，代码未跑。**

## 这一版只量"资源与可行性"

ADR-0031 把主线切到规模实验，并写下三条回退条件。其中两条（epoch 墙钟、能不能放得下）
**必须在跑精度之前先量**——否则会花几小时训练一个注定不可迭代的配置。

所以 S1 不回答"精度随规模怎么长"，只回答：

1. **每个规模能不能在 8 GB 上跑完**（显存峰值）；
2. **一个 epoch 要多久**（墙钟）；
3. **在共同规模上，稀疏实现相对稠密有没有明显退化**。

## 规模点与预算

| 臂 | 规模（循环神经元） | 说明 |
| :--- | :--- | :--- |
| **稠密** | 256 / 512 / 1024 | 2048 及以上由资源扫描外推会超 8 GB，不硬试 |
| **稀疏（事件驱动）** | 1024 / 2048 / 4096 / 8192 | fan-in 固定 32 |

- **预算**：sMNIST、**600 个训练样本、1 个 epoch、种子 0**。
  这是**资源探针**，不是精度测量——600 样本 1 epoch 的准确率没有意义，
  **不得**与 W2 的任何数字（0.8889 等）比较。
- 稀疏臂沿用 `scripts/run_event_driven_10k.py`，稠密臂沿用 `research/eprop/train_sequential.py`，
  参数写在结果 README 里。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **S1-0** | 所有配置都在 8 GB 内跑完 | 显存峰值 < **8,000 MiB**；超了就如实记为 OOM |
| **S1-1** | 稀疏 8192 的 epoch 墙钟可用 | **< 4 小时**（ADR-0031 的回退条件） |
| **S1-2** | 共同规模 1024 上稀疏不明显退化 | 稀疏准确率 ≥ **稠密 − 2pp** |

S1-0 有配置 OOM 不算失败——那是**结论**（"这个规模在这个卡上放不下"），照登。

## 跑之前的预期

- **稠密 1024 放得下**（资源扫描到过 2048），稀疏 8192 也放得下（10k 跑过）；
- **S1-1 应当过**：10k 在 6000 样本上 40 分钟，8192×600 样本按比例约 **4–5 分钟**；
- **S1-2 不确定**：稀疏实现与稠密"同 mask 逐位一致"只验过更新，没验过精度。

写下来，是为了防止事后把"资源都很充裕"说成意外。

## 死亡条件

- S1-1 不过（epoch > 4h）→ 按 ADR-0031 归档，不再谈 5k–8k；
- S1-2 不过 → 先修稀疏实现（ADR-0031 的第三条回退条件），规模问题往后放。

## 不做的事

- 不在 S1 里报精度结论（600 样本 1 epoch）；
- 不为了"跑得动"而偷偷缩小规模或样本数；
- 不把 S1 的资源曲线外推成精度曲线。
