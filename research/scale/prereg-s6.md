# 预注册：规模实验 S6——饱和是容量的，还是训练预算的（2026-11-03）

**状态：判据先落盘，代码未跑。**

## 为什么

S2/S3/S5 的**全部结论都建立在 2 个 epoch 上**。在那条预算下：

| n_rec | 2 epoch 的准确率 |
| ---: | ---: |
| 8,192 | 0.774 |
| 16,384 | 0.797 |
| 32,768 | 0.805 |
| 65,536 | 0.794 |

结论写成"精度在 16k–32k 饱和"。但这个结论有一个明显的替代解释：
**2 epoch 下所有配置都远未训练充分**（W2 的 256 神经元在 250 epoch 能到 0.8889）。
饱和可能是**容量的**，也可能是**训练量的**——两者在 2 epoch 上分不开。

## 这一版问什么

**把训练预算从 2 epoch 提到 5，8k 与 32k 的差距会变大、不变、还是缩小？**

- 若**变大**（>2pp）→ 2 epoch 的"饱和"是训练量造成的，容量还有用；
- 若**不变** → 饱和是真实的容量上限；
- 若**缩小** → 更大的网络在小预算下难训，长预算下会被追上。

## 设置

- **8,192 与 32,768**，各跑 **5 epoch**；其余与 S5 完全一致（完整 sMNIST、种子 0、batch 8、
  fan-in 32、test-samples 1000、`--predict-chunk 100`）；
- 2 epoch 的数字已有（0.774 / 0.805），直接对照。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **S6-0** | 都放得下 | 峰值 < **8,000 MiB** |
| **S6-1** | 预算确实起作用 | **两臂**各自比自己的 2-epoch 数高 **≥ 2pp**（否则 5 epoch 白加） |
| **S6-2** | 容量在长预算下还有没有用 | `acc_5ep(32768) − acc_5ep(8192) > 2pp` 才算"还有用" |

S6-1 不过 → 说明加 epoch 本身没效果，S6-2 无从解释，停；
S6-1 过而 S6-2 不过 → **饱和是容量的**，规模轴到此为止；
S6-1 过且 S6-2 过 → **饱和是训练量的**，S2/S3/S5 的结论要写 amend。

## 跑之前的预期

**倾向 S6-1 过、S6-2 不过**：2→5 epoch 只是 2.5 倍，而 W2 的对照是 250 epoch。
更大的网络在这个预算内大概率仍然追不平。

## 不做的事

- 不跑 250 epoch（75 小时，超出这次迭代的范围）；
- 不改学习率、不改 batch；
- 不把 5 epoch 的成绩与 W2 的 250 epoch 比较。
