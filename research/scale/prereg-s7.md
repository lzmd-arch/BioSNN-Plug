# 预注册：规模实验 S7——换更硬的任务，看容量上限会不会移动（2026-11-03）

**状态：判据先落盘，代码未跑。**

## 为什么换任务

S6 在 **sMNIST** 上给出：5 epoch 时 8k **0.824** vs 32k **0.829**——**差 0.5pp，容量饱和**。

但这个结论有一个明显的替代解释：**sMNIST 这个任务本身就不需要那么多容量**。
（同预算下 BPTT 也只到 0.9630；2 epoch 的 0.82 离任务上限还很远。）

所以换一个**更吃容量**的任务，看同一个"8k vs 32k"的对比会不会重新拉开。

## 任务：SHD（Spiking Heidelberg Digits）

- 20 类口语数字，700 输入通道，脉冲时刻栅格化到 **100 个时间箱**；
- 训练 ~8,156 段、测试 ~2,264 段（数据已在 `data/shd/`，`scripts/download_data.py shd` 的产物）；
- 已实现的加载器：`research.eprop.load_shd(..., max_time=100)`。

**为什么是 SHD 而不是自己造任务**：它是本仓库已经在用的旁证数据集，加载器与评估口径都是现成的，
换它不会引入"新任务没调好"这个额外变量。

## 设置

- **8,192 与 32,768** 两档（与 S6 同一对）；
- **2 epoch**（与 S2/S5 同预算；SHD 的样本数只有 sMNIST 的 1/7，所以每 epoch 的更新数也少得多）；
- 其余同上：batch 8、fan-in 32、种子 0、`--predict-chunk 100`；
- 需要在 `scripts/run_event_driven_10k.py` 加 `--dataset {smnist,shd}`（默认 smnist，行为不变）。

## 判据

| # | 判据 | 门槛 |
| :--- | :--- | :--- |
| **S7-0** | 都放得下 | 峰值 < **8,000 MiB** |
| **S7-1** | 容量在这个任务上有用 | `acc(32768) − acc(8192) > 2pp` |
| **S7-2** | 两臂都不是随机 | 两臂准确率均 ≥ **0.20**（20 类，随机 0.05） |

S7-1 过 → **sMNIST 的饱和是任务特性，不是管线的容量上限**，规模轴在更硬的任务上还有意义；
S7-1 不过 → 饱和在这条管线上是普遍的，规模轴真的结束。

## 跑之前的预期

**倾向 S7-1 不过**：S6 的机制是"多训练会让小网络追上来"，而 SHD 只有 2 epoch × 8,156 段，
两臂都可能远未训练充分，容量差可能同样被训练量掩盖。

若真是这样，下一条该动的轴是**训练预算**（S6 说预算会缩小差距，但没测"更长预算下会不会反转"）。

## 边界

- 2 epoch、单种子；SHD 的 2 epoch 只见过两遍数据，绝对精度会很低；
- 不与 README 里 SHD 的 30-epoch/250-epoch 数字比较。

## 不做的事

- 不改 `max_time`、不改学习率、不挑种子；
- 不为了"让差距出现"而调大 epoch——两臂必须同预算。
